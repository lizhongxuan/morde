# Correct

用于代码修复和实现任务。目标是用最少的新代码完整解决用户提出的问题，不扩展需求。遵循仓库及目标目录中的 `AGENTS.md`；本 skill 不覆盖其中的产品、授权、验收和安全约束。

## 修改前

1. 阅读需求及将要修改的代码，确认要达到的结果和边界。需求含糊时先按已有上下文推进可独立完成的部分；只有关键选择无法推断时才询问。
2. 找全改动影响面：调用方、相关测试和 fixture、配置、导出、接口及持久化数据。修复函数缺陷前先搜索该函数的所有调用方。
3. 检查可能破坏的兼容性、数据、权限或隐私；查看工作区现有改动，避免覆盖用户的未提交内容。

## 实施

- 先判断功能是否确有必要。跳过未被要求的选项、扩展和灵活性；宽泛需求只实现能完成核心目标的最小版本。
- 优先复用仓库已有 helper、组件、服务、依赖和项目惯例；用平台能力解决问题，除非仓库已有对应实现。不要为少量代码增加依赖。
- 在共享根因处修复一次，并完成所有受影响的调用方和接口适配。保持现有结构；避免无需求的抽象、包装层、类型转换、配置和样板代码。
- 保留被移动或合并代码已有的校验和错误处理。不得削弱安全、授权、隐私、无障碍或防止数据丢失的逻辑。
- 已知限制需要留下时，用一行注释说明：`shortcut: <限制>, <何时升级>`。其他注释只解释代码本身无法表达的原因。
- 项目文件只在本地工作区修改，不向外部发送或上传。

## 检查

- 完成修改需要的调用方、fixture、配置、导出和文档更新，不留已知的半成品。
- 新增非平凡逻辑（分支、循环、解析、金额或安全逻辑，或完整脚本/应用）时，提供一个小型测试或基于断言的自检；验证方式同时遵循仓库 `AGENTS.md` 和用户要求。
- 遵循项目指定的实际验收方式。尤其是影响 `morde-pc` 的改动，按根目录 `AGENTS.md` 从真实 PC 客户端入口验收，不能用独立 Web 页面、构建或单元测试代替。
- 汇报实际检查过的内容和未覆盖范围；没有执行的验证不得声称通过。

## 回复

简要说明改了什么、原因和验证结果。最终回复末尾用一到两行说明跳过或未检查的事项，以及用户需要知道的风险。
