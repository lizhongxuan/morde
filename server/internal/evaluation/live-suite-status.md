# 周套件 44 条：可跑 / 阻塞清单

- 套件：`testdata/suite-live-v1.json`，`morde-ai-conversation-live-v1.1.0`，`live-scripted`，44 条 = PC-CHAT 001–024 + 20 条专测（CLS/REC/APR/CST/MRG/RPL）。
- 日期：2026-11-25。清单与套件 JSON 同日生成；ID 以 JSON 为准，JSON 里的清单测试（`TestLoadLiveSuiteInventory`）锁死 44 个 ID。
- **周自动跑：44/44 阻塞。** 每周日 02:00 的全量自动跑需要 Inspect AI runner + Judge 接线（P1-3 未做）与 Judge key（Claude/GPT 家族，未配）。没有 runner，自动跑一条也跑不起来。
- **下表的状态是“手动在真实 PC 上可跑 / 阻塞”。** 可跑 = 今天就能在真实 PC + 真实模型上用手工跑一遍并判定通过/失败；阻塞 = 即使手工跑也被某个缺口拦住，原因写在表里。手动可跑不等于周跑可跑，也不等于通过——通过只能由一次真实执行判定，本表不写任何通过。
- 翻为可跑的规则：阻塞原因消除 + 在真实 PC 上实际跑过一次（只改代码不算）。

## 注意

- **CLS-01 同名不同义**：设计方案 §16.1 的 CLS-01 是“核心闭环验收”（收件 → 路由 → 多 Agent → 工具 → 审批 → 验证 → 原会话交付，在实际 PC + 真实 DSH 上跑通一次）；本套件的 CLS-01 是“分类鲁棒 1 号”（分类器收到 prose 走兜底链）。此处按评测计划 §4.2（分类鲁棒）为准。
- `cost_budget` 单位是 micro-units，与 `project.Budget.LimitMicros` / `PendingRequest.ThisCostMicros` 同单位；货币以项目费率快照为准，不在本表断言币种。CST-01/02 的 100000 是运行护栏（防失控循环），不是及格线。
- PC-CHAT 019/020 的“当前未闭环第 2/3 项”指核查报告里的未闭环项（审批卡本体字段、事件链本体），两项的 sit 实现尚未部署。
