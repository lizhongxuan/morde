# Morde PC AI 助手页面重新设计说明

日期：2026-11-10。设计稿：[Morde AI 助手页面重新设计稿](<设计图/Morde-AI助手页面重新设计稿.html>)。

> 任务动态的后续重设计建议见[任务动态重新设计方案](Morde任务动态重新设计方案.md)；采用该建议时，侧栏目标以新方案为准。本文的实现与验收记录仍描述当时版本。

## 目标与范围

根据现有 `/assistant` 页面及用户提供的 Muse iOS 对话截图，重新组织正式页面的会话、消息、任务和输入区，让对话成为主要阅读内容。设计借鉴参考中的浅蓝用户气泡、浅灰助手气泡、连续提问和嵌入对话的选择，同时保留 PC 端会话导航及执行设置。本次调整落在 Portal 助手页面，复用已有任务、会话和消息接口，不新增服务端接口或 Agent Runtime。

HTML 是单文件本地原型，使用虚构会话和任务；可直接用浏览器打开，不依赖外部资源。它不连接账号、真实 AI、模型、电脑或文件服务，所有演示操作仅作用于当前页面，刷新后不保留；切换示例会话会清空演示消息。设计稿中的“已发送”“进行中”等均是样例状态，不代表实际任务执行结果。

## 页面结构

| 区域 | 设计 | 对应现有能力 |
| --- | --- | --- |
| 全局导航 | 保留现有工作、设置与授权入口；突出当前“对话” | PC 用户端导航、通知、账号 |
| 会话列表 | 顶部直接显示唯一的“主会话”，不再重复显示分组标题；右侧刷新按钮作用于会话列表，旁路会话可展开和新建 | 主会话、旁路会话、刷新及历史加载 |
| 对话区 | 用户消息右对齐并可连续出现；助手回复放在浅灰气泡内，按话题分段 | 发送状态、附件及长文本 |
| 任务动态 | 标题栏入口打开右侧面板；集中展示当前账号有权查看的全部任务，跨会话保留列表 | 任务状态、工作过程、任务操作、结果整理与原始结果 |
| 输入区 | 文本为主，附件、语音、模型和目标电脑放在一行；选择电脑后显示 Workspace，工具连接按需出现 | 消息输入、附件、语音、模型、电脑、Workspace、MCP 工具连接 |

输入区显示的电脑和 Workspace 是下一条消息的目标选择；已有任务继续显示自己的绑定目标，不能因用户更改输入区选择而暗示任务已经迁移。电脑未选择时不显示 Workspace 选择。模型自动选择、无电脑目标和不附加 Workspace 都是明确选项。

## 从 Muse 参考借鉴的部分

- 连续发送的用户消息各自保留；助手可以在一条消息中按话题分段回应，时间按消息组显示。鼠标悬停或键盘聚焦助手回复时，在气泡下方显示该条回复时间；无悬停能力的设备直接显示时间。多个任务的最终结果组合为一条回复时，只展示已经发布的结果；任务仍各自独立，不能从显示形式推断后台执行顺序或并行方式。
- 澄清选项放在对应问题下方，选中状态清晰可见。原型只演示本地选择；正式使用时必须将答案提交给绑定的任务，并按服务端回执分别展示提交中、失败或已受理。选中选项本身不代表任务已经继续或完成；现有页面的澄清表单仍需保留。
- 对话区只呈现自然语言交流，不展示任务卡、任务状态或执行过程。任务名称、状态、过程和控制统一放在“任务动态”；参考图里的预定任务不据此视作已经创建。
- PC 保留侧边会话列表、模型、电脑、Workspace 和工具等操作，不照搬 iOS 的电话、礼物、悬浮头像或底部导航。

## 任务范围与正式页面实现

任务动态默认关闭，打开后展示当前账号在当前服务实例中有权查看的云端任务，包含主会话、旁路会话和其他可见来源，以及进行中、等待、完成、失败和已停止等状态；切换当前对话不改变任务列表。通过 `GET /api/tasks` 按服务端游标分页读取任务摘要，再按任务 ID 获取授权范围内的完整状态；保留任务所属会话和来源信息。共享项目中的其他成员任务仅在服务端明确授权并提供可见列表时展示。列表分页或任务详情读取失败时显示加载失败，明确当前结果不完整，不声称已展示全部任务。

正式页面把任务过程卡、状态、操作、审批与澄清表单、结果整理和原始结果集中放在独立的“任务动态”侧栏，不在消息列表内插入任务卡。侧栏中的任务操作均绑定对应服务端任务及其所属会话；切换当前对话不会重定向任务操作。设计稿本身仍是使用虚构数据的静态交互原型，与接入真实账号及服务端的正式页面相互独立。

## 任务、消息与异常状态

- 对话区展示用户消息、助手自然语言回复及服务端确认的消息投递状态，不显示任务名、任务卡、进度、原始 Task 结果、任务控制、任务 ID/修订/结果事件、关联消息元信息或朗读回复入口。任务动态展示服务端确认的任务状态与真实工作步骤，不用固定百分比或预设步骤冒充进度。
- 已完成任务在最终回复确实发布并可见时，才显示“最终回复已同步到对话”。整理中、整理失败或回复尚未取回时分别提示真实状态。原始 Task 结果放在折叠区并标明不是最终回复；任务 ID、修订和结果事件供需要追踪时查看。
- 每个活动任务有独立状态和操作。“补充任务”在侧栏对应任务内填写并提交，明确绑定目标任务及其所属会话，复用现有消息发送与回执机制，不在当前对话输入区插入任务标记；切换当前对话不能改变补充内容的目标。服务端仍校验账号、会话、任务权限和幂等性。“停止任务”也始终绑定明确的任务。多任务并行时分别展示，停止、暂停或继续后以服务端状态为准，不能将请求已受理显示为已经停止。暂停任务可提供继续入口。
- 任务等待审批时，在侧栏对应任务中展示操作对象、内容、影响及批准/拒绝；等待澄清时提供问题、输入与提交结果，也可在对话中以自然语言询问。电脑登录需用户接管时在侧栏给出打开目标电脑与交还提示；具备权限且电脑可用时可进入 Workbench 只读观察。依赖任务、子任务和成果按实际数据展开，无数据不展示。
- 消息发送状态与任务处理状态分别展示。待发送、发送中、结果待确认、发送失败和已发送应使用明确文字；失败或状态未知时保留内容并提供核对、重试。附件单独显示准备、上传或失败状态，不能把待上传附件显示为完整交付。
- 网络、模型、电脑、Workspace 或工具连接不可用时，在相关区域说明原因与可用操作；未确认无模型配置时，不把普通状态读取失败当作“未配置”。错误提示和重试入口不应遮住历史消息或导致已输入内容丢失。

## 布局与视觉

- 桌面端保留全局导航和会话列表，消息列最大宽度 770px，输入框最大宽度 714px。任务动态默认关闭，窗口宽于 1280px 时以 282px 独立侧栏显示；更窄时改为覆盖面板，避免压窄输入和消息。侧栏关闭时入口可显示真实待处理数量，让审批或澄清不会因侧栏收起而被忽略。
- 品牌区和助手头像使用用户提供的蓝色 Logo；原图内嵌在 HTML 中，按原比例显示。界面采用白色及浅灰背景、品牌蓝强调色、细边框和少量阴影。任务状态同时使用文字和颜色；按钮提供可见焦点，图标按钮应有可访问名称。
- 输入区与消息列表各自布局：历史消息可滚动，输入始终可见；任务过程展开、长回复、长文件名和较窄窗口不得遮挡发送按钮。用户滚离底部时，正式实现应提供回到最新消息的入口。
- 原型展示连续消息、分段回复、等待确认和已完成场景；审批、澄清提交、失败、恢复和多任务并行的具体数据及操作以正式接口和现有业务规则为准，不应仅凭样例页面推断已经实现。

## 原型可操作内容

可以展开/收起旁路会话、切换示例会话、新建空白旁路会话、选择示例选项、回到最新消息、打开/关闭任务动态、展开任务过程、在侧栏填写补充内容、选择模型或电脑、展示 Workspace、选择本地附件并发送演示消息。选项只改变本地选中样式；侧栏补充内容不会真实提交；发送只在当前页面添加一条演示消息，附件只展示文件名或数量，不读取或上传文件。语音、停止任务、全局导航等入口仅提示为视觉示意。

正式页面复用现有页面组件及数据接口，沿用当前授权、审批、消息持久化、任务隔离与恢复机制；本设计稿不定义新的 Agent Runtime 或新增后台功能。HTML 原型中的演示操作不代表正式页面的真实交互结果。

## 本次实现与验收记录

- 2026-11-11 按设计稿统一消息列和任务动态侧栏宽度；输入框宽度沿用设计稿值。
- Portal `/assistant` 已按上述结构改版：任务动态默认收起，读取当前账号全部任务并跨会话展示；任务详情按需读取，操作和补充消息绑定任务所属会话。对话区保留自然语言消息和投递状态，不再插入任务工作卡、关联消息元信息或朗读入口。
- Portal 类型检查、代码检查、全量单元测试及本地浏览器端到端测试通过；也验证了助手回复的悬停时间，以及任务面板打开时发送按钮的可用性。完整打包通过；打包所需的移动端模型目录引用修正为项目已有资源路径。
- 使用本机演示数据检查了宽屏三栏、普通窗口覆盖侧栏及窄窗口布局。上述结果不替代连接真实服务后的验收。
- 2026-11-11 本轮在 1280×720 内置浏览器的本地演示模式下确认任务动态可开关，展开时输入框与发送按钮仍可见；此项只核对布局交互，不验证真实 API。
- 2026-11-11 PC 壳层（[morde.html](../clients/desktop/harness/desktop/resources/morde.html)）移除了助手页上方重复导航；助手、账户设置和网页账号退出沿用 Portal 左侧入口，本机同步与“退出此电脑”放到 Morde 应用菜单“设置”，与网页账号退出区分。
- 2026-11-12 Portal PC 壳层将主菜单名称统一为“对话”，各工作页共用助手页的 Morde 图标，并为主菜单和助手会话历史栏增加独立折叠控制。云电脑卡片沿用紧凑布局，将旧数据迁移说明压成一行；电脑状态、文件冲突提示和操作入口仍保留。本机演示浏览器已核对导航与历史栏折叠、品牌图标和云电脑卡片布局；未连接真实服务。

## 验收重点

以下条目是正式页面的验收标准，不因设计稿展示或源码修改本身视作通过；宽屏、窄屏和键盘交互应以本地 Portal 页面实际验收结果为准。

1. 连续消息分别可见，助手长回复按话题分段；选项仅凭选中不能显示任务已继续，发送状态不能混同于任务状态。
2. 主会话与旁路会话可区分；新建旁路会话和切换会话不会丢失已持久化的消息。
3. 模型、电脑、Workspace、工具连接、附件、语音及任务控制入口在适用状态可找到，选择下一条消息的目标不改变既有任务目标。
4. 对话中没有任务卡和任务控制；任务动态跨会话展示有权查看的全部任务，切换会话不清空列表。进行中、等待确认、失败、完成以及并行任务分别展示真实状态；审批、澄清、停止和恢复均以对应任务及服务端结果为准。
5. 宽屏、窄屏和键盘操作下，任务侧栏可关闭，窄屏展开时不遮挡输入和发送按钮；控件名称、焦点和错误提示可被识别。
