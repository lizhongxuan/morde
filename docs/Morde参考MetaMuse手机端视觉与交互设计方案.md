# Morde 手机端参考 Meta Muse 的视觉与交互设计方案

> 2026-10-28。配套[可交互 HTML 设计稿](设计图/Morde-Meta-Muse手机端参考设计稿.html)。这是 Morde 的设计参考，不是 Meta Muse 的官方设计规范，也不表示相应功能已经实现。业务范围与数据归属以[客户端与服务端合并需求](nanoMuse客户端与Morde服务端合并需求文档.md)为准；已有[Muse 功能与设计风格说明](Muse功能与设计风格需求文档.md)提供更广的产品背景。

## 1. 依据与目标

- **截图观察**：本次用户提供的 19 张 Meta Muse 手机截图，按消息中的图片顺序记为 S1–S19。设计参考采用其中的聊天、输入、任务、浏览器接管、助手详情、侧边栏、记忆、审核和活动状态；截图中的其他能力不自动进入 Morde 范围。重复画面用于确认同一组件在不同状态下的稳定位置。
- **公开资料**：Meta 的[产品介绍](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/)说明个人 Agent、后台任务、独立浏览器和用户控制；[设计说明](https://introducing.muse.ai/)说明长期主对话、气泡分隔、头像下的工作状态、活动与权限可见性，以及需要明确按钮的审批。公开资料用于理解交互意图，界面细节仍以用户截图为准。
- **设计目标**：让 Morde 手机端以聊天为起点，在同一工作上下文里看见任务进度、执行证据、授权记录和云端电脑接管；用户在任何一步都能知道“谁在操作、做到了哪一步、下一步要我做什么”。

这份方案只规定视觉与交互方向。HTML 使用演示数据、原创 CSS 角色和模拟网页，不复制 Meta 的商标、吉祥物或用户截图中的二维码。不会把参考界面当作已经接通的功能。

## 2. 截图对应的页面与可复用模式

| 截图 | 可见模式 | 在 Morde 中的参考用法 |
| --- | --- | --- |
| S1、S4、S8、S16 | 主聊天：顶部悬浮头像、左右胶囊气泡、工具卡、底部输入与五项导航 | 主对话保持可读；浏览器或 Host 动作以卡片回到消息流；长结果可折叠，保留来源任务入口 |
| S2、S3、S5–S7、S9 | 发送反馈、处理中三点、停止按钮、软键盘、图片/二维码消息 | 发送、执行、等待用户、完成分别有文字状态；软键盘弹出时只上移输入区，不遮住当前输入和最新消息 |
| S10 | 黑色浏览器接管外壳、实时画面、停止与输入工具 | 清楚标示 AI 控制或用户控制；停止任务与接管控制是独立动作 |
| S11–S13 | 助手详情、任务分栏、运行中任务、底部圆角步骤抽屉 | 任务列表与详情共享状态；每步能查看动作、结果和时间，失败不能伪装成完成 |
| S14 | 左侧导航抽屉、旁聊、搜索和新建入口 | 主入口保持稳定；旁聊与主对话有明确区分；未实现功能不可用假入口承诺 |
| S17 | 助手详情中的记忆卡 | 显示记忆来源、访问说明与编辑入口；具体记忆能力按融合需求实现 |
| S18 | 审核记录列表 | 授权、拒绝、超时都显示对象、动作、时间和结果，能回到原任务 |
| S19 | 按日期分组的活动记录 | 同一任务的活动、聊天与步骤可相互定位，避免生成三套互不相干的历史 |

## 3. 信息架构与页面层级

1. **一级**：主要聊天、动态、点子、目标、资源库是截图中的五个导航入口；侧边栏重复这些入口，另列旁聊、搜索和设置。Morde 可沿用这种稳定导航，但要先核对原 nanoMuse 功能和新合并需求，不能仅按本稿删改已有入口。
2. **二级**：点击头像进入助手详情；详情内部用五个图标分栏承载任务、审核、浏览器、活动与记忆。图标含义是结合截图及公开设计说明做的 Morde 映射，不宣称是 Meta 的官方名称。
3. **临时层**：任务步骤和动作确认用底部抽屉；云端浏览器接管进入全屏深色工作现场。抽屉关闭后回到原滚动位置，浏览器退出后回到来源任务。
4. **对象一致性**：消息、任务、执行步骤、审批、Host 与产物由现有 Morde 服务端对象关联；客户端不建立第二套业务真相源。现有 nanoMuse 记忆/目标能力的保留与合并，以最新融合需求为准。

## 4. 视觉规格（建议值，非截图实测）

设计稿按约 390 × 844 逻辑像素的手机画布排版。以下是让后续实现有统一基线的建议令牌，应在 iOS 真机和 Android 真机上校准；系统状态栏、键盘和安全区由平台负责。

| 令牌 | 建议值 | 用途 |
| --- | --- | --- |
| `canvas` / `surface` | `#FAFAFA` / `#FFFFFF` | 主画布、悬浮控件和抽屉 |
| `ink` / `muted` | `#111214` / `#777B80` | 正文、次要信息；长日志不用过浅灰 |
| `agent` / `user` | `#ECEDEE` / `#B9DEFF` | 助手与用户消息气泡；角色由位置和文字共同区分 |
| `hairline` / `selected` | `#E5E6E8` / `#F1F2F3` | 圆按钮边线、导航选中和分段控件 |
| `action` | `#54B4F8` | 接管、可操作链接与当前浏览器位置 |
| `success` / `working` | `#2DBE73` / `#E8A43B` | 已完成、进行中；旁边必须同时有文字或图标 |
| 间距 | 8 pt 基础，页面左右 16–18 pt，组件间 8–24 pt | 消息间紧凑，区块间留白更多 |
| 字号 | 正文 16–17 pt，辅助 13–14 pt，区块标题 20–22 pt，页面标题 28 pt | 中文保持舒适行高，代码与路径允许换行 |
| 圆角 | 气泡 22–26 pt、胶囊 999 pt、抽屉顶部 30–36 pt | 同一层级保持统一 |
| 点击区域 | 至少 44 × 44 pt | 顶部图标、底部导航、关闭与接管工具 |

页面以白和浅灰为主，用户气泡的浅蓝是主要色块；不要把彩色品牌卡、渐变和阴影铺满聊天页。顶栏、输入框及底栏可用轻微磨砂与细边线，但正文层不依赖模糊效果保证对比。浏览器接管页用深色外壳与白色远程画面形成清晰边界。

## 5. 关键组件及行为

### 聊天与输入

- 顶部左侧菜单和中央助手头像与工作短句固定在安全区下方；滚动时内容可以从半透明顶栏下经过，但按钮的对比度要稳定。头像进入助手详情。
- 助手气泡左对齐、用户气泡右对齐；工具卡包含工具名、当前状态、预览和明确动作。结果链接采用蓝色文字，且在链接名之外给出来源或摘要。
- 输入区包含添加、文本输入、语音和发送/停止状态；键盘弹出后底部导航可以让位，输入框始终可见。仅出现“•••”不足以解释长时间执行，任务卡或状态文案须同步说明。
- 新消息可继续当前主对话；任务执行中允许追问。聊天的“已打开/已安装”文案必须由任务结果或可见证据支持。

### 任务与浏览器

- 任务列表显示标题、状态、最近一步与时间；详情抽屉显示同一任务的完成、进行中、等待用户、失败与停止状态。每步至少含动作、结果与时间，长技术输出按需展开。
- 浏览器接管页始终显示当前控制方。用户接管后，AI 对同一 Host/浏览器暂停输入；交还控制后重新核对控制权和当前页面。停止任务要有独立的结束确认或明确回执。
- 审批卡要展示本次动作、目标、风险及批准/拒绝按钮；记录页展示用户决定与结果。对会发送、付款或修改数据的动作，不用纯聊天文本代替确定性确认控件。
- 长截图里的二维码、网页内容和命令输出只证明“可展示执行证据”；设计稿不复用真实二维码、账号或命令，也不把读取网页等同于完成用户目标。

### 浮层、导航与状态

- 左侧抽屉覆盖主聊天，背景保持可辨；点击遮罩、返回或选择入口可关闭。底部抽屉有标题、关闭按钮和可滚动内容，关闭后焦点返回触发按钮。
- 连接、进行中、等待用户、完成、失败、停止应在聊天卡、任务列表、详情和系统通知使用一致的词语。颜色仅作辅助。
- 支持放大字体、窄屏、减少动态效果、系统键盘与安全区。交互控件提供无障碍名称，图标不能单独表达审批或停止等高影响动作。

## 6. 与现有仓库的实施边界

| 设计对象 | 将来接入位置 | 约束 |
| --- | --- | --- |
| 主聊天、任务卡、任务详情 | `project/nanoMuse/` 手机端 UI；Morde Conversation / Task / SSE | 使用同一账号与任务 ID，不复制独立历史；业务接口以 OpenAPI 和融合实施清单为准 |
| 远程浏览器/电脑 | 现有 Gateway / Workbench / 控制权协议 | 接管、交还、停止各有独立状态；手机不声称可操作本机系统 |
| 审批与活动 | Morde TaskAction、审计与任务步骤 | 不把视觉上的绿色勾选当作实际执行成功 |
| 记忆、目标、旁聊与资源库 | nanoMuse 原有能力和服务端融合结果 | 保留与迁移按[最新融合需求](nanoMuse客户端与Morde服务端合并需求文档.md)；本稿不决定删除或新建数据模型 |

这份 HTML 是无依赖的本地演示，不调用 Morde API，不保存输入。它覆盖本批截图能确认的主要状态；截图未展示的动态、点子、目标、资源库内部页面不在稿中猜造。

## 7. 开发验收基线

1. 在约 390 × 844 及 320 pt 宽的手机上，主聊天、任务抽屉、导航抽屉和浏览器接管不横向溢出；长消息可滚到最后一行。
2. 弹出软键盘后输入框、当前输入和发送/停止入口可见；安全区不遮挡底部工具。
3. 聊天 → 任务 → 步骤 → 浏览器接管 → 返回能回到同一任务；状态词在这些页面一致。
4. 用户接管后 AI 不同时向同一浏览器发输入；失去控制权、断线或任务停止时界面给出真实状态和恢复动作。
5. 审批必须明确动作和结果；活动、记忆与任务能追溯来源，撤权后不继续使用原权限。
6. 对照原 nanoMuse 功能基线验收，不能为追求 Muse 外观而移除现有可用能力。

**取舍**：本稿不制作 Meta 原版素材，也不补齐截图没有展示的所有页面。视觉令牌是设计建议，最终以真实设备与原生控件校准为准。
