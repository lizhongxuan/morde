# Morde Web 端账号注册、审核与权限需求文档

> 状态：需求设计，尚未按本文实施。适用于用户 Web、管理后台及其服务端权限校验。

## 1. 目标与边界

用户从登录页自行申请账号，管理员审核后才能使用。管理员可以禁用账号、授予或撤销其他账号的管理员权限；固定账号 `admin` 为超级管理员，不受普通管理员管理。

本需求采用一套账号、审核状态和权限规则，替代此前“只有一个由文件反复同步的管理员账号”的规则。用户 Web 登录页提供注册入口；后台登录页不提供注册入口。PC、手机正式客户端仍基于 nanoMuse 二次开发，不因本需求另建客户端。

## 2. 账号状态与页面流程

| 状态 | 用户能否登录与使用 | 管理员操作 |
|---|---|---|
| 待审核 | 不能登录；注册完成后显示“申请已提交，等待管理员审核” | 通过或拒绝 |
| 已拒绝 | 不能登录；使用正确密码尝试登录时提示“审核未通过” | 可重新审核并通过 |
| 已通过 | 可以登录；按自身角色访问用户 Web 或管理后台 | 可禁用、调整角色 |
| 已禁用 | 不能登录或继续使用已有会话；账号和数据保留 | 可恢复为已通过 |

- 用户 Web 的登录页显示“注册账号”。注册页填写用户名、密码和确认密码；用户名不可重复，`admin`（不区分大小写）不可注册。注册成功只建立待审核的普通用户账号，不自动登录。
- 用户名或密码不符合输入要求、两次密码不一致、用户名已占用时，页面就地提示且不创建账号。待审核、已拒绝、已禁用账号即使密码正确也不获得登录会话；密码错误时不泄露账号是否存在或审核状态。
- 管理后台的用户列表可按待审核、已拒绝、已通过、已禁用筛选。审核通过、拒绝、禁用、恢复和角色调整均显示操作结果；失败时保留原状态，不假装成功。
- 禁用立即阻止该账号继续访问用户 Web、管理后台和受保护接口，并使已有登录会话失效；恢复后须重新登录。禁用不删除账号、云端电脑或工作区数据。

## 3. 管理员与超级管理员

- 角色分为普通用户、管理员、超级管理员。审核状态与角色独立：只有“已通过”账号的角色权限才生效；待审核或已禁用的管理员也不能进入后台。
- 已登录管理员可审核其他账号、禁用或恢复其他已审核账号，并把已通过且未禁用的普通用户设为管理员，或撤销其管理员身份。角色变更后，目标账号的已有会话失效，重新登录后按新角色授权。管理员不得操作自己的审核状态或角色。
- `admin` 是唯一超级管理员，用户名固定，不允许用户注册占用。普通管理员无法对 `admin` 执行审核、拒绝、禁用、恢复、删除、改密、改名或改角色；页面禁用这些操作，服务端也必须拒绝直接请求。`admin` 始终有后台权限，不能被降级或禁用。
- 首次初始化时，`admin` 的默认密码为 `admin`。默认密码期间后台入口仅对本机或受信网络开放；首次登录必须先修改密码，完成前只能进入改密页面。以后 `admin` 可验证当前密码后自行改密。改密后旧密码和旧会话立即失效，重启服务不得把密码恢复为默认值或用配置文件覆盖。后台不展示任何账号的明文密码。
- 账号审核、禁用/恢复、角色变更及 `admin` 改密均记录操作者、目标账号、时间和结果，不记录密码。

## 4. 验收条件

1. 未登录用户从用户登录页进入注册页，提交新账号后看到“等待审核”；此时登录被拒绝。管理员审核通过后，该账号才能登录用户 Web。
2. 管理员拒绝账号后，该账号不能登录；管理员重新审核通过后可以登录。已通过账号被禁用时，现有页面和接口访问立即失效；恢复后重新登录可使用，原有数据仍在。
3. 管理员把已通过的普通用户设为管理员后，目标重新登录可进入后台；撤销角色后，目标重新登录只能使用普通用户权限。待审核和已禁用账号不能通过改角色绕过登录限制。
4. 普通管理员在页面和直接请求中均不能修改 `admin`；`admin` 不能被禁用或降级。其他用户无法注册 `admin` 或大小写变体。
5. 全新环境可用 `admin/admin` 完成首次登录，但在修改密码前看不到管理数据、不能审核用户；改密后旧密码及旧会话无效，服务重启后新密码仍有效。
