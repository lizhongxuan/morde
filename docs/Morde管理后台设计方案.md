# Morde 管理后台设计方案

> 状态：产品方案与界面设计依据，2026-10-25。文中的新增管理动作尚不代表服务端已实现。现有 Portal 管理接口仅覆盖用户创建/禁用、主机列表、总体容量与审计查询；主机和工作区禁用、资源池、调度策略与操作进度需要另行实现。

## 1. 目标与边界

管理员需要从“用户 → 该用户的云端电脑 → 该用户的工作区”追踪资源与操作，并能分别禁止用户操作、停用一台电脑、隔离一个工作区。后台还要统一管理物理机和 Kubernetes 集群提供的计算资源，决定新云端电脑允许在哪里、以什么规格创建，并能解释创建失败或资源迁移为何受阻。

本方案管理 Morde 的用户、权限、Host、workspace、资源池和策略。后台默认只展示工作区元数据，不提供管理员直接浏览用户文件的隐含权限。停止、禁用、迁移都不自动删除工作区数据；删除和数据保留另走独立流程。页面使用演示数据，真实效果以服务端执行状态为准。

## 2. 对象与页面

| 对象 | 管理员需要看见 | 主要动作 |
|---|---|---|
| 用户 | 账号状态、角色、配额、活动会话/任务、名下 Host 与 workspace、最近操作 | 创建、修改配额、冻结/恢复操作、禁用/启用登录、查看关联资源 |
| 云端电脑 Host | 所有人、所绑 workspace、运行状态、管理状态、资源规格、承载池/节点、控制者、任务与租期 | 禁用/启用、停止计算、续期、查看放置与故障；迁移须经预检 |
| workspace | 所有人、逻辑/实际占用、版本、绑定 Host、同步设备、数据可用性、管理状态 | 隔离/解除隔离、查看绑定与同步、调整配额、检查恢复点 |
| 资源池 | 类型、容量、预留量、健康、节点/集群连接、存储可达性 | 接入、暂停新分配、维护、恢复、查看受影响 Host |
| 创建策略 | 适用用户/角色、允许的池与模板、CPU/内存/存储限额、租期、放置约束 | 草拟、校验、发布、停用、查看命中与拒绝原因 |
| 管理操作 | 发起人、目标、影响范围、执行阶段、失败或未知项 | 查看、重试可重试阶段、取消尚未执行的动作 |

后台导航以“总览、用户、云端电脑、工作区、资源池、创建策略、操作记录、审计”为主。用户/Host/workspace 的详情从各自列表进入，不再把所有上下文常驻在一个页面。

## 3. 禁用规则

**业务运行状态与管理状态分开。** `running / stopped / failed` 描述 Host 实际运行；`允许 / 禁用中 / 已禁用` 描述是否准许操作。一个运行中的 Host 可能正被禁用；页面不能因为管理状态改变就声称进程已经停止。workspace 的 `已绑定 / 未绑定 / 同步中` 与 `允许 / 隔离中 / 已隔离` 也分别展示。

| 管理动作 | 立即阻止什么 | 已有活动如何处理 | 数据与恢复 |
|---|---|---|---|
| 冻结用户操作 | 该用户的网页、PC/手机设备、API Key、MCP 和受邀会话发起的新写入/控制/任务；旗下资源的其他入口也按所有者冻结规则拒绝新操作 | 撤销有效操作会话，暂停定时计划，请求停止受管 AI 任务；逐项核实桌面、终端、同步和原生进程，未确认停止则显示“处理中/未知”，不报完成 | 不删账号、Host 或 workspace；解冻后仅恢复准入，不自动重启任务或计划，也不覆盖单独禁用的 Host/workspace |
| 禁用用户登录 | 拒绝新登录并撤销现有登录与凭证；同时采用冻结操作规则 | 与冻结相同；不因浏览器退出就假设其他设备已断开 | 保留数据；启用账号后仍需按权限重新登录，独立资源禁用保持原状 |
| 禁用 Host | 拒绝该电脑的新进入、续期、任务、桌面/终端/文件/MCP 与共享操作 | 断开控制会话，请求停止受管任务；停止计算另作为明确动作。对仍在运行的原生 AI/网站或无法确认的进程列出待处置项 | 保留工作区及声明持久数据；启用后先核对运行/绑定状态，不自动恢复进程内存或任务 |
| 隔离 workspace | 拒绝新的读写、同步、挂载、绑定、下载及通过 Host 文件工具访问该工作区 | 中止/撤销在途同步的后续提交，等待受管写入退出；无法证明停止时保持“隔离中”，提示仍有风险 | 保留文件、版本和恢复点；解除隔离先检查容量、存储与绑定，设备需重新获得有效授权 |

生效优先级为：账号禁用或用户冻结、Host 禁用、workspace 隔离、资源池维护、创建策略限制。**上层恢复只撤销本层限制**，不隐式解除其他层。一个 Host 绑定多个 workspace 时，仅隔离其中一个不要求关闭整台电脑，但该 workspace 在终端/桌面内是否仍可被同一系统账号读取必须有实际文件隔离保证；保证不了时应阻止该 Host 的操作并明确影响范围，不能只隐藏文件按钮。

所有禁用动作先显示影响预览：目标 ID、所有人、关联资源、在线会话、任务/计划/同步/网站、共享成员、数据保留方式及预计不可用范围。管理员填写原因后确认；服务端生成可追踪操作 ID 和审计记录。重复提交同一操作不能重复停止或删除。失败或失联时保持目标的保护性准入限制，展示哪些步骤已生效、哪些未知，不允许把“已提交”展示成“已完全禁用”。恢复前再次检查当前状态与权限。不能禁用自己或最后一个可用管理员账号。

## 4. 资源池与云端电脑创建策略

Morde 使用统一的“资源池”表示可承载 Host 的环境，类型为**物理机池**或 **Kubernetes 集群池**。用户看到的是同一种 Host；后台展示真实承载位置与适配器状态。新 Host 的准入顺序为：用户/资源状态 → 用户配额 → 策略匹配 → 池与节点健康 → CPU/内存/磁盘及存储可达性 → 镜像/架构与网络兼容 → 预留资源 → 创建并核验。失败返回具体条件与可处理入口，不静默换池或绕过策略。

| 维度 | 物理机池 | Kubernetes 集群池 |
|---|---|---|
| 接入与健康 | 注册受信节点代理；显示心跳、系统/架构、运行时、磁盘、网络和工作区存储连通性 | 配置受限集群连接与目标 namespace；显示 API、节点、调度、存储类、网络入口与工作区存储连通性 |
| 容量 | 以节点可分配资源扣除系统预留、现有 Host 预留和安全余量；不把物理总量当可用量 | 同时检查 Morde 预留、节点可分配量、namespace ResourceQuota/LimitRange 及存储约束；K8s 配额不能替代 Morde 用户配额 |
| 放置 | 选择健康且兼容的节点，记录池/节点与拒绝原因 | 按允许的节点池、标签/亲和性、污点容忍、架构与存储类放置；Morde 的禁用和所有权规则仍在其网关与控制面执行 |
| 维护 | “暂停新分配”不影响现有 Host；维护前列出仍在运行的 Host，逐台迁移或停止并核验 | 先暂停 Morde 新分配，再处理相关工作负载；节点 drain 是否完成以实际驱逐结果为准，不能等同于 Host 数据已迁移 |

创建策略至少定义：名称/优先级/启用状态、适用用户或角色、允许的资源池与镜像模板、单台规格上限、用户并发 Host 数、租期上限、允许的存储/网络能力，以及物理机或 K8s 专有放置条件。冲突策略须显示命中顺序与最终结果；无匹配规则时拒绝创建并解释原因。发布新策略仅影响新建或明确重建的 Host；现有 Host 不被静默迁移或缩容。策略保存前模拟至少一名目标用户和一种 Host 请求，展示准入结果、候选池及拒绝原因。

节点失联、集群不可达、容量不足、存储不可达分别告警。失联不代表 Host 已安全停止，也不能直接在别处启动同一可写 workspace。迁移先确认来源停写/隔离、目标数据可达、检查点与版本，再切换位置和 Host 代次；任一步未知则留在待处理状态，避免双活写入。

Kubernetes 的 ResourceQuota 约束 namespace 的资源总量，[官方说明](https://kubernetes.io/docs/concepts/policy/resource-quotas/)；节点放置还受[亲和性](https://kubernetes.io/docs/concepts/scheduling-eviction/assign-pod-node/)与[污点/容忍](https://kubernetes.io/docs/concepts/scheduling-eviction/taint-and-toleration/)影响。节点维护使用 drain 时应以[实际驱逐完成](https://kubernetes.io/docs/tasks/administer-cluster/safely-drain-node/)为准。这些机制用于底层执行，不代替 Morde 的所有者权限、workspace 版本和管理动作状态。

## 5. 页面行为与验收

1. 从用户列表进入某用户详情，能看到该用户的全部 Host、workspace、活动任务和登录/操作状态，并能跳到每个资源详情；反向从 Host/workspace 详情可返回所有者。
2. 冻结用户前有影响预览与原因输入；确认后新网页、设备、API Key、MCP、计划触发和受邀操作均无法继续以该用户身份执行。活动项逐项显示停止/撤权结果。解冻不自动重启计划，也不解除单独禁用的资源。
3. 单独禁用一台 Host 后，其他 Host 可继续使用；该 Host 的桌面、终端、文件、任务和共享入口被拒绝。Workspace 不被自动删除。Host 失联时后台显示未完成步骤与实际运行状态未知。
4. 隔离一个 workspace 后，与其绑定的上传、下载、同步、文件工具和新 Host 绑定被拒绝；同一用户的其他 workspace 可继续。若多 workspace 共用系统账号而无法隔离文件，界面扩大并解释受影响 Host 范围。
5. 物理机池和 K8s 池分别显示健康、可分配/已预留资源、节点与承载 Host。暂停新分配不自动终止已有 Host；维护流程显示剩余待迁移/待停止项。
6. 创建策略可预演“允许、拒绝、容量不足、存储不可达、架构不兼容”结果；新 Host 的放置记录命中策略、池和节点。K8s 的底层配额拒绝显示为创建失败原因，不伪装成成功。
7. 每个禁用、恢复、维护、迁移和策略发布动作都能在操作记录和审计中按目标、操作者、时间、结果检索；管理员不能直接读取用户凭证或工作区正文。
8. 管理页保持表格为主，筛选、关联详情和影响确认按需展开；状态含文字、原因和最后核验时间。设计稿中的动作仅演示流程，不调用真实管理 API。

## 6. 需要产品确认的两点

- **用户冻结的原生进程处理：**本方案默认阻止新操作并请求停止受管任务；对未登记的原生 AI/网站进程显示待处置，不擅自强停。若要求冻结即全部停机，需明确共享成员和线上网站的影响规则。
- **K8s 租户映射：**namespace 按用户、团队还是资源池划分，影响配额与隔离粒度；本方案先按池配置映射，不预设“一用户一 namespace”。
