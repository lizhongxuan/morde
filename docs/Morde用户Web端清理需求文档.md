# Morde 用户 Web 端清理需求文档

> 本文描述清理目标和验收条件，不表示清理或下线已经完成。

## 目标与范围

清理独立的普通用户 Web 和手机 Web，使普通用户通过 `morde-pc` 或 iOS 客户端使用 Morde；浏览器保留管理后台。清理不得影响后台 Web、PC、iOS 和服务端的现有功能、权限及数据。

当前 [Portal](../web/portal/src/App.tsx) 同时包含用户和后台界面，PC 也打包其用户界面；[工作台](../web/workbench/)及其网关页面仍被 PC、iOS 使用。因此按实际用途清理，不能把整个 `web/portal`、`web/workbench` 目录或工作台网关当作独立用户 Web 删除。本次检查的本地后台构建引用 `/assets/`，而按[现有服务端路由](../server/internal/api/static.go)关闭旧 PC 兼容后这些地址会返回 404；实际部署资源路径须一并验证。

## 功能与规则

1. **清理独立入口及遗留物。** 最终停止由服务端向独立浏览器提供普通用户 Portal 和手机 Web 页面；旧页面地址（包括 `/`、`/assistant`、`/login`、`/register`、`/download` 和 `/app/*`）返回 404，不回退到用户 SPA。清理仅服务于独立用户 Web、且已无其他引用的代码、资源、构建与部署配置、测试和使用说明；避免旧发布资源或回退规则重新暴露这些页面。
2. **保留后台和客户端依赖。** 管理后台的登录、权限、现有可用管理操作及 `/admin/*` 深链继续可用；其实际引用的脚本、样式和图片必须可加载。PC 所需的用户界面仍可构建、打包并从客户端使用；iOS 保持现有原生功能。PC、iOS 当前依赖的工作台、授权网关、页面资源和连接继续可用，不因为清理普通用户 Web 而统一关闭。安装包清单 `/downloads/manifest.json` 和允许的 `/downloads/files/<安装包>` 路径按原有权限与校验规则保留，不把安装包下载当成普通用户 Web。
3. **清理失效引导。** 后台截图中的“PC 用户端”链接当前指向 `/`，下线后不得继续指向失效的用户网页；移除该链接或改为已有可用的 PC 获取入口。检查后台无权限页、客户端及使用说明中指向已下线用户 Web 的链接与提示，清除失效引导，保留其他管理和设备功能。
4. **保留服务与数据。** 后台、PC、iOS 和 Agent 使用的认证、业务 API、事件流、网关及授权规则继续有效；不得因页面下线删除账号、会话、任务、文件或业务配置，也不得放宽权限。客户端升级时保留有效凭证和可识别的本地草稿、待发送内容；状态或结果无法确认时保留并提示，不自动重发或删除。
5. **先过渡再下线。** 先核对现有用户 Web 功能及实际 PC/iOS 依赖，确保普通用户功能在 PC 端有对应可用入口，iOS 已有功能不受影响；确认旧 PC 用户能够获得并升级至不依赖服务端用户页面的版本，且既有[下线清单](<实施/Morde PC端设计稿对齐与用户Web下线实施任务todo清单文档.md>)的相关准出条件满足后，才停止旧入口。过渡未完成或无法确认时，保留旧 PC 所需兼容入口并记录待验证项；下线造成客户端或后台异常时应能恢复。旧方案中停止工作台页面的描述如与客户端实际依赖冲突，以保留已授权工作台能力为准。

## 验收条件

- 在本机受控服务中使用拟部署的真实构建产物验证：普通用户网页和旧深链返回 404，手机 Web 不可访问；管理后台登录、各管理页面及直接刷新深链正常，页面实际引用的静态资源均可加载。安装包清单及允许的下载路径仍可用，其他非授权资源不因此开放。
- 从真实 `morde-pc` 客户端入口验证登录、对话与任务、项目和文件夹同步入口、云端电脑及工作台等清理前可用功能；从 iOS 客户端验证登录、对话和工作台等受影响功能，并检查两端同账号会话、进度和结果接续。客户端受影响功能不能用浏览器预览或构建成功代替实测。
- 使用本机隔离测试数据核对服务端认证、业务接口、授权隔离及既有会话、任务和文件状态；清理前已受理任务不会因页面下线而取消或重复执行。后台无权限页和各端入口不再引导至失效用户网页。
- 旧 PC 的升级路径和过渡状态有可核查证据；过渡未完成时兼容入口仍可用且不标记最终下线完成。构建、部署和使用说明与最终保留的入口一致，未引用已删除资源。

实施和验证仅限本机或本机隔离环境，不发送或外发文件、不修改远端环境。受此限制无法完成的真实服务、旧版升级或文件传输验收应标记为待验证，不得宣称下线完成。
