# Morde 云端 Agent 运行时统一化需求

> 状态：目标需求。引擎选型、会话级实例和个人历史按[AI 助手对话需求](Morde%20AI助手对话与任务执行体验需求文档.md)于 2026-11-05 更新，覆盖此前账号级常驻 Runtime 的要求。现有融合架构、公共约定和实施清单尚未按本次要求同步，不能据此认为开发或验收已完成。

## 目标与范围

PC 和 iOS 手机端作为云端 Agent 的客户端，统一由 Morde 服务端运行 Agent Runtime。客户端负责发起会话、查看对话与任务记录，以及查看和操作用户有权访问的云端电脑。客户端关闭或离线不影响已受理的云端任务继续运行。本期继续改 PC 和 iOS；Android 源码、配置、构建和验收保持不变。

用户于 2026-11-01 另行确认：云端 Agent 可在目标 PC 授权并通过各项门禁后请求单次截图、文件查看和命令操作；文件写入只允许目标 PC 已选择的 Workspace，沿用同步限额与覆盖前安全副本，F02-T10 通过后开放。目标 PC 接受受控设备调用不等于承载本机 Agent 或模型/工具循环；客户端不能将云端 Task 转成在本机自主运行的 Agent。设备动作按[融合 04 分项设计](实施/融合04-例程设备与记录分项设计.md)分别实施、验收。

本需求覆盖现有融合方案中“保留 PC 本机 dsh Agent 和 iOS 本机 Agent”的要求。客户端不再启动或承载 Agent Runtime、模型与工具循环、本机任务执行器或子 Agent；原有本机 Agent 能力不属于本需求目标。PC/手机上的会话界面、云端状态查看、远程电脑控制和用户主动选择的文件上传仍可保留。

## 功能与规则

1. **统一云端执行。** 用户从 PC 或手机发送消息后，Morde 服务端创建或续接唯一的云端会话与 Task，并由云端 Agent Runtime 执行。模型调用、工具选择与调用、检查点和任务恢复均由服务端负责；不能由客户端逐步代跑云端任务。只有服务端持久受理后，客户端才显示任务已提交。关闭页面、退出应用、断网或切换设备只结束客户端连接，不等同于停止任务；停止须由用户明确操作或服务端安全控制触发。
2. **会话级 Runtime。** 每条个人对话按需自动启动或恢复一个独立 Runtime 实例，归属至少由服务实例、用户和会话确定；同一对话同时最多一个活动实例。同一账号从 PC 和手机打开同一会话时接续同一会话及其执行记录；同账号不同会话和不同账号的会话可在配额内并发，同一 Task 同一时刻只能有一个有效执行者。不同账号的资料、会话、记忆、检查点、凭据与授权必须隔离；同一账号各个人对话可按授权使用该用户的资料和历史。
3. **运行时与云端电脑分离。** Agent Runtime 运行在 Morde 管理的云端执行环境。Host 是 Runtime 按用户授权操作的电脑目标，不是 Agent Runtime 的宿主，也不负责维持 Agent 会话。没有可用 Host 时，纯模型/会话能力仍可按已配置能力使用；需要云端电脑操作时必须显示 Host 不可用或无权限，不能静默改在客户端或 Runtime 宿主环境执行。用户明确选择并授权的 PC 设备动作是单独能力，不得当作云端 Host 的自动回退。
4. **共享记录与跨端接续。** 会话、消息、Task 状态和事件以服务端为唯一权威记录。PC 与手机打开同一会话时展示相同的会话/Task 标识和最新状态；查看、刷新或重新连接不创建或重跑 Task。用户可以在任一有权客户端查看任务进度、处理待办并继续同一会话。
5. **受控操作和结果反馈。** 用户通过客户端操作云端电脑时，继续使用 Morde 现有 Host 权限、控制权与 Workspace 规则。服务端分别维护 Agent 与 Host 的状态，管理端可查看诊断；助手聊天页面用用户可理解的语言说明任务和目标电脑的状态。无权限、等待审批、保存失败、无法执行或状态未知等情况必须如实显示，不得当作成功；任务有文件产物时，只有服务端确认已保存后才显示文件已保存或任务完成。
6. **文件交付由服务端判定。** 服务端根据 Task 文字（包括批次输入及后续追加要求）自动判断是否需要交付文件；客户端不提供“需要文件”开关或预期路径。明确要求文件时，只有服务端核验文件已持久保存后才可完成；普通问答可不生成文件；无法确定时暂停并请用户确认。
7. **统一业务权威。** 账号、会话、任务、审批、用量、授权与云端电脑仍由 Morde 管理。引入 Agent Runtime 引擎不得另建一套面向用户的账号、会话历史或任务调度权威，也不得绕过 Morde 的授权、预算、撤权与审计规则。
8. **模型连接。** 支持用户配置的个人模型连接和管理员配置的平台模型连接，云端 Agent 使用所选的可用连接；此前移除个人模型连接的要求由用户后续需求覆盖。用户已确认删除各 PC/iOS 设备上本应用保存的旧自带模型供应商 API key，包括 iOS 可同步的对应 Keychain 项；删除同步项可能同步影响同一 Apple ID 的其他设备。只按可识别的旧模型密钥条目清理，保留 Morde 服务端个人和平台模型凭据、登录/同步凭据、MCP OAuth、其他应用数据及用途不明的共享变量；无法确定归属或删除失败时明确记录并处理，不宣称已清理。

## 已确认的运行方式

从 DSH 或 Hermes-agent 中选择一个开源项目作为唯一 Agent Runtime，使用其 Agent 执行及工具调用能力；Morde 负责账号、会话、模型和授权的集成，不自写另一套 Agent Runtime。既有 DSH 集成可作为选型依据，最终选型及其隔离、恢复与工具接入能力仍需实施验证。

各会话的 Runtime 和 Task 独立管理执行与恢复；并行 Task 必须能够分别停止和核验，停止一个 Task 不得误停或悄悄重跑其他 Task。运行环境须满足用户隔离、工具授权和资源配额，不要求每条会话拥有一台云端电脑。

## 验收条件

- PC 与手机客户端均不会启动本机 Agent Runtime 或本机 Agent 执行循环；发起云端会话后，服务端承担模型调用、工具选择和调用编排。获准的 PC 单次设备动作按目标设备授权及其门禁执行，不变成本机 Agent 循环。
- 手机提交任务并关闭应用、PC 也退出后，已受理 Task 仍由服务端推进；之后从任一客户端登录可读取同一会话、Task、事件和已保存产物，不产生重复执行。
- 同一账号在 PC 与手机打开同一会话时接续同一执行记录；用两个不同账号验证时，彼此不能读取对方的会话、记忆、检查点、凭据、Task 或 Host 授权。
- 所选引擎仅有一种；每条会话同一时刻最多一个活动 Runtime 实例。同账号不同会话和不同账号的任务可按配额并行，停止一项不应停止其他任务；资源不足时显示真实状态。
- 同账号的个人对话可读取该用户有权访问的资料和过去的个人对话；已删除或撤销访问的内容不再用于新任务，其他账号不可读取。
- 升级后的 PC/iOS 按已确认范围清理本应用的旧自带模型 API key，包含 iOS 同步与非同步条目；删除失败可见且可重试，Morde 服务端的个人和平台模型凭据及其他用户数据不受影响。
- 同一 Task 不会被多个 Agent 执行者同时推进；服务端或 Runtime 重启后可按已保存检查点恢复，无法安全恢复时显示明确状态，不静默重跑未知副作用。
- 获准用户可从 PC 或手机查看并操作其云端电脑；Runtime 与 Host 可分别停止、恢复和报告状态。无权或不可用时拒绝操作并显示原因。
- 明确停止 Task 后，客户端显示服务端确认的停止状态；只有客户端断开时任务不被误报为已停止。

本期手机端仅修改 iOS，Android 保持现状、不改动，也不作为交付验收门槛；PC 仍在融合范围内。
