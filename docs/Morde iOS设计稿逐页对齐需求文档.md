# Morde iOS 设计稿逐页对齐需求文档

更新时间：2026-11-05

## 1. 目标

把当前 Morde iOS 页面按 `docs/Morde iOS设计稿.html` 逐页核对并调整，使页面入口、组件层级、按钮集合、按钮所在位置和页面间跳转对应设计稿。界面继续沿用 nanoMuse iOS 已有的颜色、字体、头像、列表、圆角、动效和系统适配方式；设计稿决定页面内容与布局，nanoMuse 决定 iOS 原生视觉表现。

本次修改范围是 iOS 客户端。复用现有 Morde 数据与接口；不把 HTML 原型里的静态数据或本地演示行为当成后端能力，也不为视觉对齐伪造操作成功。

## 2. 已确定的范围与优先级

1. **页面和按钮以本需求及 HTML 设计稿为准。** 本需求明确覆盖的页面入口、按钮、相对位置和跳转方式优先于旧融合方案中把页面合并或藏入其他页面的决定；例如事件链、工作项、文件库按设计稿保留抽屉入口。
2. **视觉风格沿用 nanoMuse iOS。** 不复制 HTML 演示用的浏览器画布、手机外框或固定状态栏。布局按设计稿组织，控件使用项目已有的 iOS 组件和样式。
3. **用户可见品牌统一为 Morde。** 界面、设置和空态中不向用户显示 nanoMuse 品牌名。代码类型名、目录名和工程标识不在本需求的批量改名范围内。
4. **不显示预算。** 任务、聊天中的任务摘要、审批、事件链和应用生成的任务信息中，不显示预算、额度、成本或费用金额。不得为了对齐 HTML 样例恢复这些内容。用户打开的原始文件内容不在此规则内。
5. **不恢复已删除入口。** 动态、点子、目标和例程入口不出现在新导航中；这不要求删除已有数据。
6. **好友与 AI 工具会话先做占位。** 抽屉中保留设计稿对应的好友和 AI 工具会话入口。打开后显示标题及“暂未接入”说明；不显示静态好友、好友申请或假工具对话，不实现添加、通过、忽略、分享、撤销等动作，也不显示成功反馈。这是已确认的阶段性例外，不要求照搬原型中的样例数据和按钮。
7. **按钮集合严格受控。** 每页只保留设计稿中出现的可见按钮及已确认例外。不得自行添加刷新、上传、语音、搜索筛选、关闭、帮助、溢出菜单或快捷操作按钮。任何页面确实需要设计稿以外按钮时，先把按钮名称、图标、所在位置、解决的问题及不加按钮的影响告知用户，等待用户明确回复后再加入；不能先加后补说明。
8. **不改变服务端合同。** 有现成接口的能力按真实数据和权限接入。若功能缺接口、缺数据或需要新增服务端能力，保留该项为未完成并说明原因，不以本地状态、Toast 或样例数据冒充完成；需要扩大到服务端时先征求用户意见。

## 3. 逐页核对与修改要求

每页开始前，先读取 HTML 对应的 `data-view` 及相关弹层，列出设计稿的可见按钮、输入框、筛选项、行点击入口和相对位置；再对照当前 iOS 页面，记录缺少、增加、位置不同和不可用的项目。一次只处理一页及它直接依赖的共享组件，完成该页核对后再进入下一页。不得因批量改造漏掉尚未检查的页面。

### 3.1 主导航与侧边抽屉

- 底部主导航按设计稿保留四个图标入口：聊天、任务、审批、资源；选中态和审批待处理数量提示取真实状态。图标可访问名称齐全。
- 页面左上角的菜单按钮打开设计稿侧边抽屉。抽屉顺序为：主要聊天、任务、审批、事件链、资源、文件库、工作项、好友；其后为旁聊列表、AI 工具会话区；底部依次为设置、搜索、新聊天。
- 旁聊和工具会话只从真实已有数据生成。无数据时使用空态或已确认占位，不复用 HTML 的示例会话。
- 不把工作项塞回任务分段，不把文件库藏成资源页额外按钮，不把事件链变成只能从任务详情进入；这些入口按设计稿从抽屉打开。
- 动态、点子、目标、例程不出现在抽屉或底部导航中。

### 3.2 聊天页（`data-view="chat"`）

- 顶部左侧只有菜单按钮；头像和一行状态文字位于页面上方中间区域。状态取当前智能体/任务的真实状态，不固定显示原型样例“努力工作中”。
- 中部为消息时间流；用户消息、Morde 回复和真实任务进度/审批摘要保持可区分。任务或文件卡片只关联真实消息及真实资源。
- 底部保留设计稿中的单行消息输入框和发送按钮。除非设计稿包含，否则不增加附件、语音、相机、工具栏或额外的发送方式；若现有聊天功能依赖这些入口，先按第 2 节第 7 条询问是否保留。
- 发送走现有 Morde 会话能力。创建任务后展示服务端返回的任务状态；失败时显示真实错误，不追加虚构的“已拆解/已完成”回复。
- 消息中的文件卡片打开文件详情；预算文字和费用金额不得显示在应用生成的任务摘要中。

### 3.3 任务列表（`data-view="tasks"`）

- 页头左侧为菜单按钮和“任务”标题，右侧为设计稿的“＋新建任务”按钮；不以刷新按钮替代。
- 列表行按设计稿显示任务图标、标题、步骤或当前执行者摘要、状态/进度。百分比只能在服务端提供可信进度时展示；没有进度字段时显示真实步骤或状态，不推算百分比。
- 点任务行进入任务详情。点“＋”按设计稿进入聊天并聚焦输入框，不额外弹出未设计的创建表单。
- 空态、加载失败和分页状态沿用真实 Morde 数据状态，不放入设计稿中的固定样例任务。

### 3.4 任务详情（`data-view="task"`）

- 顶部左侧为返回任务列表按钮，右侧显示当前任务标题。正文按顺序呈现任务目标/摘要和经理拆解的时间线。
- 时间线只显示该任务真实可读取的步骤、事件、结果与待处理项；事件文本使用服务端已提供并经过现有安全处理的内容。
- 底部“急停这个任务”按设计稿的位置呈现。只有当前任务状态及权限允许时才可操作；调用真实 Morde 控制流程，并展示成功或失败的真实结果。不得只改本地按钮文字来模拟停止。
- 不显示预算、费用金额。暂停、继续、取消、重试等设计稿未出现的额外可见按钮，必须先询问用户是否保留；现有底层能力不因此自动删除。

### 3.5 审批页（`data-view="appr"`）

- 页头左侧为菜单按钮、标题和真实待处理数量。正文按请求卡片排列，显示真实来源、操作对象、风险/影响、当前状态和已有证据。
- 每张卡片按设计稿顺序展示驳回、批准，以及对应请求类型的第三种动作（发布请求为“灰度”，权限请求为“改 3 天”）；第一张卡片保留“看事件链”入口。每个可用动作必须关联真实服务端决策。审批数量徽标随服务器状态更新，不通过点击本地减数。
- 当前 iOS/实施记录表明任务审批已有批准/拒绝合同；HTML 的“灰度”与“改 3 天”不是已确认的 iOS/API 能力。不得将这些动作做成本地成功提示。先检查当前合同；若仍不支持，向用户说明需要选择：仅保留不可用的设计稿按钮，还是另行授权增加服务端能力。此问题未确认前，不把审批页标记为完成。
- “已自动处理”只展示真实可查询记录；没有接口或记录时不生成样例区块。所有预算和成本数字移除。

### 3.6 事件链页（`data-view="chain"`）

- 从侧边抽屉独立进入。页头为菜单按钮和“事件链”标题；正文先显示关联任务名称，再按时间顺序显示事件节点、状态和说明。
- 事件节点来自真实任务事件；未发生的未来步骤不得显示成已完成，缺失数据不得用固定样例填充。
- 页面不增加执行、暂停、批准等设计稿未放置的按钮；跳转审批只在设计稿给出的关联入口出现。
- 隐去预算、费用和成本金额。

### 3.7 资源页（`data-view="res"`）

- 页头左侧为菜单按钮和“资源”标题，右侧为设计稿的“＋添加资源”按钮。不得额外增加 Library/文件库按钮。
- 正文按设计稿分组显示云端主机、云手机、Workspace、AI 工具。列表行显示真实名称、挂载关系和服务端状态；容量、使用率、任务名称和运行状态不得使用原型假数据。
- 点云端主机行进入云电脑页；点 Workspace 行进入 Workspace 文件页。添加资源按钮只可进入已存在的真实添加流程；若目前没有流程，点击需明确告知“添加资源暂未接入”，不得提示资源已添加。
- 当前实施记录未确认云手机数据源和 AI 工具全局运行状态接口。必须先核实本机当前合同；没有真实数据时不显示 Codex/Claude 运行中等样例状态，也不把连接器配置当作工具运行状态。
- 空分组按真实空态呈现，不用样例资源填充。

### 3.8 工作项页（`data-view="work"`）

- 从侧边抽屉独立进入。页头左侧为菜单按钮和“工作项”标题，右侧为设计稿的“＋新建工作项”按钮。
- 筛选项顺序和名称为：全部、缺陷、需求、待认领。列表卡片显示真实类型、标题、状态和当前负责人/关联任务；点按操作不得超出设计稿中的操作位置。
- 新建工作项弹层只含缺陷/需求类型切换、一行标题输入框和“创建·团队可见”按钮。创建走现有工作项接口，失败保留输入并反馈真实错误。
- 设计稿样例出现待验收流程；当前工作项合同记录的状态为 open、blocked、delivered，未确认 review/验收、通过或拒绝状态。不得用前端标签伪造验收状态；需用户授权扩展接口前，明确列出该差距。
- 不新增筛选按钮、排序菜单、刷新按钮或行内快捷操作。

### 3.9 好友占位页（`data-view="friends"`）

- 抽屉入口位置和页面标题对应设计稿。页面只呈现已确认的“好友功能暂未接入”占位说明和返回/菜单导航。
- 不显示 HTML 中的静态好友申请、好友列表、添加好友、通过/忽略、详情分享范围或撤销分享控件；不发请求、不造数据、不显示成功 Toast。
- 当前 checkout 的 `MordeRegistrationUITests.swift` 仍断言好友入口不存在，而实施 TODO 的 MIF-10 记录称占位页已完成。修改时以本需求为目标，现场检查源码和运行页面并修正过时断言/状态，不能把 TODO 勾选当作页面已存在的证据。

### 3.10 文件库页（`data-view="lib"`）

- 从侧边抽屉独立进入。页头左侧为菜单按钮和“文件库”标题；正文筛选项为全部、AI 产物、我上传的。
- 每行显示真实文件名、类型和来源；点行进入可用的真实预览/详情。没有读取权限、文件证明或本地文件时，不展示可预览成功的按钮或状态。
- 将当前 iOS 的本机/产物/云端来源分类映射到设计稿分类前，必须按数据来源与权限核对，不能把云端元数据错误归为“我上传的”。无法确定归属时显示真实来源或空态，不编造归类。
- 不在页面额外加入上传、下载、分享、删除按钮；现有能力若因此失去入口，按第 2 节第 7 条先询问用户。

### 3.11 文件详情页（`data-view="file"`）

- 顶部为返回按钮和文件标题，正文显示真实可访问文件内容或受支持的预览。由聊天打开时按钮含义为“返回聊天”。
- 若复用同一预览器从文件库打开，返回按钮回到文件库并保留原筛选/滚动位置；不再增加第二个关闭/返回按钮。
- 不添加编辑、分享、下载或关闭等设计稿没有的按钮；文件无法打开时说明实际原因，不显示空白的成功预览。

### 3.12 AI 工具会话占位页（`data-view="toolchat"`）

- 抽屉 AI 工具会话入口可见；进入页显示工具会话标题和“暂未接入”说明，并提供设计稿位置的返回操作。
- 不显示伪造的 Codex/Claude 消息、工具运行状态或只读会话内容；不显示输入框、发送按钮或工具操作按钮。当前 UI 测试对入口的断言与 MIF-10 TODO 的完成记录存在冲突，按 3.9 的核对规则处理。

### 3.13 设置页（`data-view="settings"`）

- 从抽屉底部设置入口进入；页头为返回按钮和“设置”标题。
- 按设计稿分组及顺序显示：账号、连接器、设备、安全凭证；权限、审批规则、急停全部任务；通知、外观、关于。不得增添设计稿没有的入口行或页头按钮。
- 现有真实设置项继续使用原数据和权限逻辑。全局急停必须保留确认及真实服务端结果；不能仅显示原型中的 Toast。无实际功能的项目不得伪装成已完成设置。

### 3.14 Workspace 浏览页（`data-view="ws"`）

- 从资源中的 Workspace 行进入。页头左侧为返回资源按钮和 Workspace 名称，右侧只放设计稿的分享按钮。正文按设计稿显示 Workspace 描述、路径面包屑和文件/目录行。
- 文件浏览和权限遵循现有 Morde Workspace 合同；只读、未挂载、权限不足、加载失败均显示实际状态。
- 分享弹层按设计稿包含查看/编辑权限选择及复制链接按钮。当前客户端是否具备真实分享链接能力须先从代码和接口确认；无真实创建/复制流程时不得提示“链接已复制”。若需增加 API 或服务端权限，先向用户提出范围和影响，等待授权。
- 不加上传、下载、删除、刷新等设计稿没有的可见按钮；如果现有功能需要这些入口，询问用户是否保留。

### 3.15 云电脑页（`data-view="pc"`）

- 按设计稿全屏布局逐项核对：顶部截图按钮、云电脑/当前控制状态标题、关闭按钮；桌面区浏览器/终端/文件入口；底部键盘辅助键；AI 控制态的停止任务/接管控制权；用户接管态的停止任务、键盘、触控、截图和打开 Workspace 文件。
- 所有控制权状态与操作由现有 Host 控制租约、任务状态和权限决定。停止任务、接管和交还不得由本地 UI 状态冒充。
- 当前 iOS 有受短期票据与同源约束保护的 Host WebView；HTML 原型中的终端执行、浏览器输入、截图和控件反馈包含本地模拟行为。先核实 Morde Host 是否提供对应真实能力；没有接口的控件不得显示假结果或注入不安全的本机控制桥。
- 若某个设计稿控件不能接入真实能力，暂停该页并向用户报告具体控件及选项（隐藏该设计稿控件、保留不可用状态，或授权扩展 Host 能力）。不得替换成设计稿没有的新按钮。

## 4. 当前需重点核实的功能缺口

以下项目不能仅通过调整 SwiftUI 外观解决。实现者必须检查当前代码/API，再把结果归入“已接入”“按已确认规则占位”或“需要用户决策”，不可沿用 HTML 的本地演示结果：

- 审批的灰度发布和调整授权天数：现有审批决策是否仅支持批准/拒绝。
- 工作项待验收状态：现有状态合同是否仍没有 review/验收决策。
- 云手机列表与 AI 工具全局运行状态：是否存在当前账号可用的真实数据接口。
- Workspace 分享链接及查看/编辑权限：是否有真实授权、链接生成和撤销流程。
- PC 页截图、终端命令、浏览器操作和触控辅助：Host 是否提供真实、受权限保护的对应能力。
- 好友与工具会话：按已确认的占位规则，不实现真实数据和操作。

如果缺口仅影响某一页，其余已具备真实能力的页面可继续；但有缺口的页面不能标记为全部完成。需要用户决策时，只暂停该项，并给出可理解的选项与影响。

## 5. 验收标准

1. 每个 HTML 页面和弹层都有逐页记录；每页的可见按钮/输入/筛选项与本需求要求一致，位置、顺序和去向能在 iOS 上对照核验。
2. 不存在未批准的额外可见按钮。若发现现有按钮不在设计稿中，逐项列明；没有用户确认前不保留为新增视觉入口，也不擅自丢弃其底层数据或 API 能力。
3. 四个底部入口、抽屉入口顺序和页面间返回路径符合第 3 节；侧边抽屉和主导航没有重复或遗漏设计稿入口。
4. 所有可操作功能使用真实 Morde 能力并正确呈现加载、成功、失败、无权限和不可用状态；任何页面不以静态样例、前端改字或 Toast 冒充业务完成。
5. 好友和 AI 工具会话只显示已确认的占位入口与说明；预算/费用不出现在应用生成的任务界面；已删除入口不恢复；用户可见品牌为 Morde。
6. 每完成一页后，用该页对应的 iOS 页面实际检查按钮数量、相对位置、返回路径和代表性状态，再继续下一页。最终检查浅色/深色、窄屏、键盘遮挡、Dynamic Type、VoiceOver 和减少动态效果；不因辅助功能额外增加可见按钮。
