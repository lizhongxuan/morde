Hermes 可参考的流程 行为参考

参考 Hermes 固定源码版本中的持久会话、有限上下文投影、压缩和恢复机制。这里保留通用思路，不要求 Morde 复制 Hermes 的 Python Agent Loop、Gateway 或 SQLite 存储。

1 · 持久会话原始消息保存在会话记录中，客户端和后台任务围绕稳定会话身份工作。
2 · 选择上下文按模型窗口拼装系统信息、当前请求、近期消息和必要的历史召回。
3 · 执行与检查点模型与工具轮持续运行，状态按边界持久化，故障后可恢复。
4 · 压缩与找回保留近期上下文和恢复线索；摘要不取代原始历史。

上游 DSH compaction 插件也支持自动摘要和上下文溢出恢复，但明确存在边界：不能压缩系统提示、工具定义或单条不可拆分的超长内容。

Morde 当前对话链路 按代码核对

新消息先持久化，再进入有界路由上下文。路由决定直接回复或处理 Task；执行工作由 DSH Runtime 完成并写入检查点。

跨 Task 会话摘要

服务端维护摘要版本和来源证明，供新消息使用；摘要不覆盖的历史会标记不完整，细节需按权限检索原文。

DSH Session 内压缩

执行上下文由 DSH 插件压缩、修剪工具结果并写检查点；不更换产品会话，也不删除原始消息。

优化后的 Morde Harness 目标流程 目标设计

以下顺序把 Hermes 的迭代准备、恢复、工具轮、活动检测与收尾补回设计。已有基础和待补部分见后面的 19 步对照。

  1. 01 · 受理与上下文

    PC/iOS 消息先鉴权、幂等保存；按模型窗口读取当前请求、会话摘要和近期历史，必要时按权限查原文。

  2. 02 · 路由与冲突处理

    DSH Coordinator 区分普通回复、澄清和任务动作；无效输出的有界修正与安全澄清仍需补齐或验证。已受理消息在冲突时保持可见。

  3. 03 · 任务与 Session 恢复

    TaskWorker 认领并续租；DSH 恢复检查点、授权工具和待处理消息。轻量补充可在安全边界使用 steer。

  4. 04 · 每轮准备

    领取新消息，检查取消、预算、角色和工具调用配对；按实际模型容量预检并保留最新用户输入。完整等价性待验证。

  5. 05 · 调模型与处理错误

    模型网关预订用量并调用模型；校验输出。对可安全对账的暂时错误进行有界重试，保留已展示的部分输出；恢复策略待补或验证。

  6. 06 · 工具轮

    核对调用 ID、参数、授权、审批和预算，持久化操作记录后派发；结果未知时对账或等待，不能自动重放副作用。

  7. 07 · 压缩与继续

    任务内按需修剪工具结果并经 DSH 压缩、保存检查点；回到每轮准备。跨 Task 会话摘要独立维护。

  8. 08 · 结束前检查

    候选答案按需核对要求、工具结果和证据；不足时可在预算内继续，不能验证时如实说明。DSH 钩子和现有验证 Worker 的衔接仍需验证。

  9. 09 · 结算与交付

    持久化结果、状态、用量与消息关联；重连时按已保存状态恢复。等待、失败或结果未知不得显示成功。

横切环节：活动检测需要区分真实进展、等待审批和等待外部工作；疑似卡死时重新核对租约代次与最后活动后安全取消。该机制尚需设计和验证。

可行性与适配决策

参考 Hermes 的完整处理行为，优先通过现有 DSH 扩展点和 Morde 服务端适配；按测试结果确认能力和边界。

能力判断Morde 采用方式
长历史后继续追问已有基础用跨 Task 摘要、有限近期历史和授权历史搜索；原文继续保留。
多轮超过模型窗口已有两层处理服务端维护会话摘要，DSH 维护执行 Session 压缩和检查点。
长时间 Task需实机验收用 Task 租约续期和检查点跨多次有界模型调用继续；当前单次模型请求上限为 45 秒。
运行中追问与修改需端到端验收沿用消息投递、任务版本和授权检查；检查实际 PC/iOS 的进度、恢复和幂等。
无效路由输出残留失败面当前可能失败；目标是有限修正并验证动作，不确定时澄清或明确失败。
Hermes 专属架构不照搬保留 DSH Agent Loop。活动检测需要阶段信号与代次保护；引入 OTel 须先完成仓库要求的架构决策，审批继续受 Morde 授权约束。

输入边界：长历史可摘要和检索；单条当前输入若自身超过模型预算，必须给出明确限制，不能静默截断。DSH 压缩无法缩短系统提示、工具定义或单条不可拆内容。

怎么验证长对话与长时间任务

先跑确定性服务端和 Runtime 用例，再跑 PostgreSQL 重启 E2E，最后在实际 PC、iOS 和明确配置的测试 Provider 上验收。

  1. LC-01 · 大历史后短追问：前文含约 18 KB 消息，追加短消息；验证不再因旧正文体积失败，当前输入未被截断，完整原文仍可查。
  2. LC-02 · 多轮压缩：合成 4K 窗口连续 40 轮并触发至少两次压缩；最早约束和最新消息仍能回答，原始消息各保存一次。
  3. LC-03 · 恢复与幂等：工具任务执行中投递追问、重启 Runtime；检查点恢复后不重复已确认工具操作，独立任务状态不串线。
  4. LC-04 · 故障注入：摘要为空/截断、Provider 溢出、取消和租约丢失；不得提交半成品摘要或误报完成。
  5. LC-05 · 会话隔离：两个用户/会话写入不同早期要求，多轮压缩后交叉追问；不能读取对方的摘要、历史或检查点。
  6. LC-06 · PC/iOS 重连：实际客户端继续同一会话，中途关闭再连接；消息、进度和结果保持一致且不重复建任务。

完整步骤与本地命令见 Morde AI 对话长会话测试方案。PC 验收从 morde-pc 客户端入口操作，不以普通网页或构建代替。
