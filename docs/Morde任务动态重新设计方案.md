# Morde 任务动态重新设计方案

> 设计建议，面向 PC 助手页；iOS 沿用相同的信息和状态，用适合手机的列表与详情页呈现。本文描述目标，不代表已经实现。
>
> 2026-11-13：任务动态已补充 [重设计需求](Morde任务动态需求文档.md)，其中的主 Agent、子 Agent 和工具详情规则优先于本文较早的示意。

## 判断

任务动态应回答三个问题：**哪些事需要我处理、助手正在做什么、结果在哪里**。现在的卡片直接显示整段任务原文、服务端状态和修订号，文件取回查询出错也会出现“PC 文件取回”模块，让用户误以为每个任务都在操作自己的电脑。

“PC 文件取回”本身有用途：任务确实需要读取用户授权的本机目录中的单个文件时，系统可将该文件的副本传到云端供任务使用；它**不是下载文件到 PC，也不是文件夹同步**。建议保留这项底层能力，但不要作为所有任务的固定模块；对用户改称“读取本机文件”，仅在与当前任务实际相关时显示。

现有页面会为当前会话任务或已展开任务查询取回状态，查询失败就显示该模块。截图中的报错只能说明状态查询失败，不能据此认定真的读取了 PC 文件。参见[现有页面](../web/portal/src/routes/Assistant.tsx)和[文件取回规则](<实施/Morde个人Muse三会话并行实施/01-共享接口与联调合同.md>)。

## 界面

会话侧边栏通过顶部“任务动态”标签打开，只显示当前会话的任务和待处理标记，不提供账号全部任务与当前会话的切换。切换会话时切换任务内容，其他会话的任务不会丢失。侧栏内容区不重复标签标题、说明或“返回对话”按钮，关闭和切换由顶栏完成。任务列表或数量读取不完整时，提示“任务状态暂不可用”并提供重试，不把部分数量当成全部或显示为零。

```text
3 项任务 · 1 项待处理             刷新

待你处理  1
┌─────────────────────────────────┐
│ 操作云端浏览器          待审批  │
│ 需要你确认操作                  │
│ 查看并处理  ›                   │
└─────────────────────────────────┘

进行中  1
┌─────────────────────────────────┐
│ 整理项目需求            进行中  │
│ 正在整理资料                    │
│ 更新于 10:32     查看详情  ›    │
└─────────────────────────────────┘

▸ 最近结束
```

点击“查看详情”后的样子：

```text
‹ 任务动态                         更多
整理项目需求                 进行中
更新于 10:32

当前进展
正在整理资料

工作过程
✓ 已阅读需求
● 正在整理资料

暂停    停止    补充任务
```

- 列表按“待你处理、进行中、已暂停、最近结束”分组，空分组不显示；同组按更新时间倒序。等待执行、正在暂停和正在停止归入“进行中”，卡片仍显示各自的准确状态；失败和已停止归入“最近结束”，不显示为完成。最近结束默认折叠，展开后可继续查看和翻页。
- 卡片只放任务名、文字状态、最近一条真实进展和更新时间，不重复显示所属会话。标题直接截取任务需求原文，最多显示两行；详情可看全文。没有进展时显示实际状态，不编造进度或百分比。
- 点击卡片进入同一侧栏的详情：顶部显示任务与状态，其下依次是需要用户处理的事项、当前进展、可展开的工作过程、实际子任务和结果；有可用成果时提供查看入口。返回后保留列表位置。子任务归属不明时保留可见，不猜测挂到某个主任务。
- 待审批时说明操作对象、内容和影响，提供批准与拒绝；待澄清时显示问题和回答入口。任务操作放在详情中：按实际状态提供暂停、继续、停止和补充任务。所有操作只作用于该任务，提交中、失败或结果未知时如实显示，确认后才更新状态。
- 任务状态为已完成但最终回复尚在整理时，显示“任务已完成，回复整理中”；失败或停止则显示实际结果及可用的下一步。任务 ID、修订号、原始结果和诊断信息收在“更多信息”，不占卡片首屏。
- 桌面宽屏使用约 320–360px 的右侧栏；空间不足时面板覆盖聊天历史，面板独立滚动并避开底部输入框和发送按钮，不让输入框压住面板内容。关闭后回到原对话。沿用白底、浅灰分隔线和蓝色强调，减少嵌套边框；正文不小于 14px，次要信息不小于 12px，状态用文字配合颜色，键盘可操作。iOS 使用同样的排序与详情内容。

## 读取本机文件与同步

- 只有任务明确需要本机文件且设备、目录已授权时，才按现有规则读取。已同步的项目文件通常直接使用任务指定的云端电脑中的文件；用户需要本机最新内容时，说明云端可能不是最新，并引导其手动同步或按授权读取指定文件，不静默切换目标。
- 确有读取记录时，在对应任务的工作过程中显示“读取本机文件”，列出设备、文件名或授权范围内相对路径、传输状态和必要的失败原因。读取详情说明会产生云端临时副本；现有规则为完成后保留 7 天，也可提前删除，实际期限以服务端记录为准。删除副本不删除 PC 原文件，也不能撤回任务已经读取的内容。
- 区分传输和内容读取：副本传输完成不等于任务已读懂文件。当前单文件上限为 16 MiB，PDF 只保留原始副本、不能据此声称已提取正文；格式或大小不支持时说明原因。
- 列表不逐项查询本机文件读取状态；用户打开任务详情，或已知该任务涉及读取时再按需查询。没有读取记录的任务不显示此模块。记录查询失败但是否发生读取未知时，只在用户查看详情时提示“部分任务记录暂不可用”及重试，不宣称有记录或无记录；已知有读取时，明确提示该文件的状态暂不可用。
- 项目文件夹同步仍由用户在 PC 端选择目标电脑和目录、点击按钮后单向同步；本机之后的修改和删除须再次点击才应用，云端修改不反向同步。读取单个文件不改变这项规则。

## 验收

1. 普通问答和未读取 PC 文件的任务没有“读取本机文件”模块；文件状态接口失败时不误报曾读取或未读取，并可重试。
2. 多会话任务可区分，待审批和澄清能找到并处理；停止一个任务不影响其他任务。任务及子任务的状态、进展和结果与服务端一致，断线或读取失败不显示虚假完成。
3. 实际读取本机文件时能看懂来源、状态和临时副本；传输成功但内容不可读取、设备离线或授权失效时，分别显示真实情况。
4. 宽窄窗口和键盘操作下，任务内容、处理按钮和聊天输入均可触达；结果及关联会话可找到。
