# Morde iOS 与 nanoMuse 视觉融合设计方案

以 `docs/Morde iOS设计稿.html` 的功能流程作为目标，以 nanoMuse iOS 已有的视觉系统和交互组件作为外观基线。建议由一个 nanoMuse 外壳承载 Morde 的四个主要入口：聊天、任务、审批、资源。按现有 iOS 清单移除动态、点子、目标及目标页内例程入口，不放入侧边抽屉；具体清理范围遵循 MI-08/MI-09，保留现有数据，普通例程的独立设置入口按 MI-08 处理。好友和 AI 工具会话记录先保留 iOS 入口及占位页面，真实数据和操作暂不接入；任务与审批界面不展示预算或费用金额。

## 设计目标

- 按 Morde 设计稿呈现聊天、任务进度、事件链、待审批操作、工作项、云端电脑、Workspace 和文件。
- 沿用 nanoMuse iOS 的聊天外壳、头像状态、浮动导航、浅色与深色主题、字体缩放和系统交互。
- 复用现有 Morde 客户端和服务接口。页面只展示服务端已返回、权限已确认的能力和状态。
- 让“任务执行审批”“其他设备发来的权限请求”“已记住的长期授权”在视觉上相似、在含义上明确区分。
- 好友和 AI 工具会话记录仅提供 iOS 占位入口，不显示虚构数据，也不触发尚未接入的操作。
- 任务、任务详情和审批页面不显示预算、额度或费用金额。

## 信息架构

| 入口 | 页面内容 | 设计稿功能的归属 |
| --- | --- | --- |
| 聊天 | 主会话、最近会话、任务提交、执行摘要和产物卡片；AI 工具会话记录保留占位入口 | 聊天、旁聊、AI 工具会话入口 |
| 任务 | “执行任务”和“工作项”两个分段；执行任务详情含步骤和事件链 | 任务、事件链、工作项 |
| 审批 | 待处理和已处理审批，未处理数量显示在导航图标上 | 审批队列 |
| 资源 | 电脑、Workspace、文件与 AI 产物；电脑详情显示在线状态和控制状态 | 资源、文件库、云端电脑、Workspace |
| 侧边抽屉 | 会话搜索与新建、全部会话、AI 工具会话记录占位入口、好友占位入口、智能体资料、账号和设置 | 好友、工具会话入口、会话抽屉、设置 |
| 智能体资料 | 头像、名称、记忆等现有资料入口 | 保留未列入移除范围的智能体资料能力 |

任务页内用分段切换区分“执行任务”和“工作项”。执行任务表示 Agent 正在处理的一次工作；工作项表示项目中的缺陷或需求，两者共享入口但不混用状态、操作和详情。事件链放在任务详情中，按时间展示步骤和结果，避免再增加一个一级标签。

资源页先列出可访问的电脑和 Workspace，再进入文件。默认工作环境仅在默认选择可被可靠保存和恢复后提供。文件页区分本地产物、会话文件和 Morde 账号文件，并标明来源及是否可下载。好友和 AI 工具会话记录的入口进入占位页面，页面说明功能暂未接入；好友列表、申请处理、分享与撤销，以及工具状态和对话记录都不使用静态样例模拟。

## 视觉和交互规范

### 延续 nanoMuse iOS

- 复用 `NanoMuseBottomBar` 的半透明材质胶囊、图标选中态和轻量动效，显示四个无文字图标：聊天、任务、审批、资源。审批有未处理项目时显示数量提示。抽屉和房间使用 nanoMuse 现有的圆形按钮、列表行和页面标题。
- 复用 nanoMuse 的头像、名称和状态行。聊天头部继续展示头像、智能体名称和当前状态；点击头像进入智能体资料页。任务运行、等待审批、出错等状态可复用现有状态视觉，但状态内容取自 Morde 当前任务。
- 使用现有 `NanoMuseTones`、`ChatColors` 和系统明暗模式颜色。保留黑白聊天主色、低对比的智能体气泡、蓝色链接与操作色；不沿用设计稿演示页的灰色浏览器画布、手机外框或固定状态栏。
- 保留 nanoMuse 聊天中的消息排版、输入胶囊、附件入口和滚动渐隐。任务进度、审批、文件只在需要操作或预览时使用卡片，列表维持轻量行样式，不把每项内容都做成大圆角卡片。
- 使用系统字体和 Dynamic Type；图标有 VoiceOver 标签。遵循减少动态效果设置，状态变化以轻量过渡为主。

### Morde 页面交互

- 聊天提交任务后，在对应会话中显示任务状态摘要。点摘要进入任务详情，返回后保留当前会话和输入内容。
- 任务详情依次显示目标、当前步骤、已完成步骤、待处理事项和结果。事件链默认按时间顺序展示，可展开单步查看结果。暂停、继续、取消、重试等操作只在服务端状态允许时出现。
- 审批卡片说明请求来源、操作对象、风险、影响、授权范围和当前状态，再显示服务端支持的决定选项。Morde 云端任务审批当前使用批准或拒绝流程；不要直接套用 nanoMuse 跨设备权限的“本次、会话内、总是”授权选项。收件箱以待处理请求为主；已处理项从任务事件或通知中读取，服务端没有可查询记录时不补造历史。
- 电脑详情明确区分 AI 控制、用户接管、只读共享和控制状态未知。接管、交还、续租等动作必须与当前控制人、租约和服务端状态一致；停止任务放在任务详情中。状态未知或权限不足时禁用操作并说明原因。
- 文件和 Workspace 的空态、加载失败、无权限、只读和下载状态使用真实数据。远程电脑查看沿用现有短期票据和来源限制，不向网页注入本机控制桥。
- 好友和 AI 工具会话记录暂以说明型占位页呈现。添加好友、通过或忽略申请、查看与撤销共享、打开工具对话等操作不执行，也不显示成功反馈。
- 任务列表、任务详情和审批卡片不展示预算上限、预算进度、已花费金额或额度数字。

## 现有实现与页面映射

| 能力 | iOS 当前实现 | 融合方案 |
| --- | --- | --- |
| nanoMuse 主壳与聊天 | `NanoMuseShell.swift`、`NanoMuseHeader.swift`、`NanoMuseComposer.swift` | 作为统一根壳和聊天视觉基线，吸收 Morde 会话与任务提交能力 |
| Morde 对话与任务 | `MordeApp.swift` 已有对话、任务状态、任务操作和审批响应 | 将现有状态与操作接入独立任务页和聊天摘要，不再嵌套另一套根级 `TabView` |
| 待审批 | 当前 Morde 待处理请求在所选任务详情内；nanoMuse 另有跨设备权限请求和已记住授权列表 | 从可读取的 Morde 任务或审批记录汇总待办；跨设备请求仍走 nanoMuse 权限流程，长期授权仍在智能体资料页管理 |
| 电脑、Workspace、文件 | Morde 客户端已有电脑、控制租约、Workspace 和工作区文件页面；nanoMuse 资源库已有文件列表 | 收拢到资源一级入口，保留各自的数据来源、权限和状态 |
| 项目工作项 | `MordeApp.swift` 已有项目和工作项能力 | 放入任务页的“工作项”分段，项目上下文和工作项操作保持完整 |
| 动态、点子、目标及目标页内例程 | `NanoMuseRooms.swift`、`NanoMuseFeed.swift`、`NanoMuseGoals.swift` | 不迁入侧边抽屉，按 MI-08/MI-09 处理入口和具体清理范围；保留本地及云端数据，普通例程独立设置入口按 MI-08 处理 |
| 智能体资料与记忆 | `NanoMuseAgentPage.swift` 等 | 保留未列入移除范围的资料入口，不恢复待移除板块的入口 |
| 好友 | 当前 iOS 有项目成员邀请，但不是好友关系功能 | 先实现抽屉入口和说明型占位页；添加好友、好友申请和共享操作暂不接入 |
| AI 工具会话记录 | nanoMuse 编程助手通过 Hub 访问其他设备会话，与 Morde 任务的工具执行记录不同 | 先实现入口和说明型占位页；不显示实时状态或虚构的工具对话，不触发工具操作 |

当前 Morde 独立页面的根级入口是对话、电脑、项目、通知；Morde 设计稿提出聊天、任务、审批、资源。融合时应把既有页面和数据能力映射进新的四个入口，而不是保留两套导航并让用户在 nanoMuse 与 Morde 页面之间切换。Morde 的任务状态、审批响应、控制权和资源授权仍由原 Morde 客户端负责；改动范围是页面组合与导航，不重做接口协议。

## 落地顺序与验收

1. **统一导航与外壳。** 在 nanoMuse 根壳接入聊天、任务、审批、资源四个目的地；移除嵌套根级标签栏；保留智能体资料与记忆入口，动态、点子、目标及目标页内例程按 MI-08/MI-09 处理。
2. **整理任务和审批。** 增加任务列表、任务详情和事件链入口；增加待审批列表，并在任务事件或通知提供记录时展示已处理历史；从聊天任务摘要和导航提示进入同一条任务或审批记录。
3. **收拢资源与次级入口。** 组合电脑、Workspace、文件和产物入口；把工作项放入任务分段；新增好友和 AI 工具会话记录的说明型占位页，待后续接入数据和操作。
4. **完成视觉适配。** 覆盖浅色、深色、窄屏、键盘、VoiceOver 和减少动态效果；长标题、空列表、网络错误、权限不足、状态过期都需有可理解的页面状态。

验收时应能从聊天查看执行进度，从任务详情追溯事件链，从审批入口处理待办，再回到对应任务；也应能从资源入口找到电脑、Workspace 和文件。动态、点子、目标及目标页内例程不出现在新侧边抽屉，旧入口按 MI-08/MI-09 处理并保留数据。好友和 AI 工具会话记录入口应进入明确标注“暂未接入”的占位页，不发送请求、不伪造列表或成功状态。任务和审批页面不出现预算或费用数字。所有一级页面使用同一套 nanoMuse 外壳，应用中只出现一条主导航；任何危险或授权相关操作都显示真实范围和结果状态。
