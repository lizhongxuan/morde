# Morde AI 助手对话与任务执行体验需求

> 2026-11-07 补充：本次新增 iOS 消息发送、电脑与 Workspace 工具解耦，以及同一对话中多条消息的处理规则。与旧方案或现有实现冲突时，以本次规则为准；本文描述目标，不代表已经实现。
>
> 2026-11-13 补充：细化主 Agent 对连续重复消息、追问、修改和独立任务的判断，以及状态变化时的处理。与旧的同类规则冲突时，以本次补充和仓库根目录 `AGENTS.md` 为准。

## 目标与范围

把 PC 和 iOS 用户端的 AI 助手做成直接的自然语言对话入口。用户描述要做的事后，系统自动使用开源 Agent 执行；执行期间在同一对话中用易懂的话说明进展，完成后给出结果。用户不需要理解或手动启动 Agent Runtime。

原有 PC 对话要求继续有效。本次新增的发送按钮交互针对 iOS；消息接收、任务分流和工具解耦涉及支持该对话的服务端与 Agent。会话级实例、引擎选型和个人记忆沿用本文已有要求；继续使用 Morde 的模型连接、电脑与 Workspace 授权机制。

## 截图现象与现有实现

- 截图中，用户在同一个旁路会话连续发送相同的项目分析请求，随后看到多次“任务状态已变化，请确认要继续原任务还是开始新任务”，以及一条无法使用工具分析项目的回复。重复请求的关联、实际状态与答复没有形成清晰的闭环。仅凭截图不能确定后台是否创建了多个任务、工具是否被调用或当时使用的部署版本。
- 当前工作区的[消息路由](../server/internal/store/postgres/conversation_route_actions.go)在模型判断前后发现上下文快照不一致时，通常直接改成上述通用确认；同一段代码会为需要展示的路由回复单独写入助手消息。因此，连续消息处理时的状态变化可能造成多条确认，并不必然代表用户的意图真的不明确。该校验也防止过期判断错误操作任务，优化时不能去掉这一保护。
- 当前[路由决策](../server/internal/app/conversation_route_decision.go)区分新任务、修改、状态、停止、澄清和直接回答，但没有单独表达“重复请求关联到已有任务”的动作；[消息受理](../server/internal/store/postgres/conversation_message_routing.go)按消息身份处理重试，不能把多次主动发送天然视为同一条消息。
- 当前[主协调器](../server/internal/worker/cloud_dsh_coordinator.go)的分流调用不带工具；[DSH 执行入口](../runtime/morde-cloud-runtime/src/engine.mjs)在任务没有可用工具时也会要求模型如实说明。截图中的“没有可用工具”可能来自误分流，也可能是执行时工具确实不可用；需要结合当时的任务、分流和工具记录才能确定，不能据截图断定原因。

## 功能与规则

1. **只采用一种开源引擎。** DSH 是 Morde 唯一的 Agent Runtime，主 Agent、任务和子 Agent 均使用 DSH；模型继续通过 Morde 模型网关接入。Morde 负责与现有账号、工具授权、会话和任务记录对接，不另建 Agent 循环或并行引入第二套 Runtime。
2. **会话独立运行并支持并发。** 此处的会话指用户的一条助手对话。每条对话按需自动启动或恢复一个独立 Runtime 实例，同一对话同时最多一个活动实例；该实例须支持同一对话中不相关的多个任务并行。同一用户的不同对话以及不同用户的对话也可以并发执行。每个任务的执行上下文、工具状态、进度、结果与停止操作互不混淆；同一任务同一时刻只有一个有效执行者。刷新页面、重试或从另一端打开同一对话不得重复执行同一任务。
3. **共享本用户的个人信息和历史。** 每条个人对话中的 AI 都能使用当前用户的个人资料、记忆和该用户有权访问的过往个人对话，按当前问题提取相关内容；历史较长时可检索或摘要，但原始记录仍可查。不同用户的数据、凭据和会话不得相互读取或混入。已删除或已撤销访问的内容不得再供新任务使用；同一用户其他对话的内容作为历史参考，不得误当成本次对话的指令或执行结果。
4. **像对话一样开始任务。** 用户发送消息后，系统自动准备并调用所选开源引擎；页面不要求用户进入 Runtime 页面、手动启用任务接收或创建单独的任务。消息发送、服务端受理与 Agent 开始处理分别显示真实状态：只有服务端确认持久受理后才显示“已发送”，只有确认执行开始后才显示“正在处理”。暂时无法发送或启动时保留消息，并说明等待或失败原因与恢复方式。
5. **模型与工具按需使用。** 对话使用用户配置的个人或平台云端模型。云端电脑和 Workspace 是 Agent 按需使用的工具，不是会话、Agent 启动或普通问答的前置条件；未选择、不可用、无权限或状态未知都不能阻断文本发送或无需这些工具的对话。只有用户明确要求使用某台电脑，或完成用户请求确实需要该电脑且调用失败时，才在对话中说明电脑异常或不可用；Workspace 仅在实际需要使用且失败时说明其问题。不得静默改用其他电脑或在未授权的环境执行。
6. **在对话中持续反馈。** 开始处理后，助手应尽快回复“收到，开始处理”等确认，无需等工具执行结束；任务阶段变化、取得关键结果或需要用户参与时，继续给出简短、自然且与真实执行情况一致的进度说明。进度进入当前对话并随任务持久保存；关闭页面或短暂断网不取消已开始的任务，用户回来后可继续查看。用户无需阅读原始日志或 Runtime 状态，进度也不应重复刷屏。
7. **需要用户参与时留在对话里。** 缺少关键信息时直接提问；需要审批时说明操作对象和影响，并提供批准或拒绝操作。用户回答澄清或作出审批决定后，继续原任务，不能因此悄悄另起重复任务；用户修改正在执行的任务目标时，按第 11 条在安全边界更新任务。用户可以暂停、继续或停止正在执行的任务，界面如实显示操作结果。
8. **明确交付结果。** 任务结束时，助手在同一对话中总结完成内容、结果和产物；未完成时说明已完成部分、阻塞原因及下一步。只有结果或文件已由服务端确认，才能宣称完成或已保存；错误、超时和执行状态未知时不得伪报成功。
9. **隐藏实现术语，不隐藏真实状态。** 助手聊天页面不展示“云端 Agent Runtime”“任务接收已停用”等要求用户理解的运维术语，也不提供手动启动 Runtime 的用户操作。若系统暂时无法开始或继续任务，用简洁文案说明影响，并保留可恢复的消息或任务状态；管理员仍可在管理界面查看必要的诊断信息。
10. **iOS 发送按钮与消息保留。** 输入框有非空白文字时，发送按钮始终可点击，包括 Agent 正在处理、上一条发送结果未确认、模型列表加载失败、网络断开、附件上传中或电脑/Workspace 不可用时。点击时按系统输入法规则确认正在组合的文字，不吞字或无提示卡住。唯一允许在发送前阻止实际提交的业务条件，是服务端已明确确认当前账号没有配置任何个人或平台云端模型；此时提示配置入口并保留输入。模型状态尚未读取、已配置模型暂时不可用或不支持工具，不能等同于未配置。

    除上述明确未配置模型的情况外，点击发送后先将每条文字与其所属账号、对话安全地保存在本机并显示在对话中，再按实际状态发送；本机保存失败时保留输入并说明未发送。网络、服务、登录或权限异常可以导致消息暂未送达或处理失败，但不能禁用有文字的发送按钮、丢弃内容或显示虚假成功；恢复后可继续发送或重试。身份过期时须在原账号重新登录后才能提交到服务端，不得绕过授权或发到其他账号。带附件的消息不得静默丢失附件，附件未就绪或失败时显示真实状态。

    每次明确发送产生独立消息；上一条请求未返回或结果未知时仍可提交下一条。对同一条消息的网络重试先核对结果并去重，不能重复创建消息、任务或已确认的工具操作。Agent 处理失败与消息是否送达分别显示，允许恢复处理而不重复发送原消息。
11. **执行中继续对话。** 主 Agent 结合新消息、已授权的会话上下文和相关任务的目标、状态判断用户意图；用户无需预先选择任务。明确指向某任务或明确要求重新执行、新建任务时，优先遵从该要求。同一话题不代表一定是同一任务，判断时还须考虑目标、范围、附件、指定电脑或项目等条件：

    - **重复请求：** 同一会话中连续主动发送的消息，如果目标及关键条件相同、没有要求重新执行，即使换了一种说法，也自动关联到同一个未完成的请求或任务，不因重复而新建任务、中断或修订原任务。原消息都保留；只给出必要的实际状态和一份最终结果，不为每条重复消息反复追问或刷屏。等待前一条消息完成判断时显示真实的待处理状态，不能显示为等待用户确认。
    - **追问或状态查询：** 能确定对象时回答对应任务的问题或当前进度，不把追问当成修改，也不停止任务；任务尚未产生结果时如实说明。
    - **补充或修改：** 能确定对象时，把新要求并入对应任务；只有需要改变正在执行的工作时，才在安全边界中断、更新并继续，不影响其他任务。连续修改按其因果顺序生效，保留每条消息、已完成结果和最新进度；较旧版本的迟到结果不能覆盖新要求。
    - **独立任务：** 目标或关键条件不同，且上下文表明用户要另做一件事时，作为独立工作处理。资源不冲突时可与已有任务并行，进度、结果和停止操作各自对应。不能仅因内容相似或同属一个会话就合并。
    - **确实无法判断：** 先保留消息，仅在缺少的信息会影响目标任务或必要操作、且无法从上下文确定时，简短询问具体缺少的对象或条件。在用户说明前，不擅自中断或修改可能涉及的任务。系统状态变化、模型输出异常或暂时无法取得上下文不等于用户意图含糊，不能一律询问“继续原任务还是开始新任务”；应自动基于最新状态重新判断，无法恢复时显示真实等待或失败原因。

    多条重复消息在首次请求尚未完成分流时到达，也须最终关联到同一请求；分流期间原任务完成后，按该任务的实际结果处理，不能因为状态变化重复创建任务或伪报中断。用户在任务完成后再次发送相同请求且没有要求重新执行时，可返回仍满足请求的已有结果；需要新数据、条件发生变化或用户明确要求重做时，按新要求处理。原请求失败、被停止或等待授权时，说明真实状态；重试或恢复须尊重用户的停止意图和现有授权。未完成的回复不能冒充任务结果。

    已确认完成的操作和产物不得丢失或重复执行。正在进行且不能安全中断的操作须先到可确认的安全状态；结果未知时先核实或提示用户，不能盲目重做。资源暂时不足时消息仍可发送并显示真实等待或失败状态。同一条消息的网络重试仍按消息身份去重；多次主动发送是多条消息，即使关联同一任务也不得删除或隐藏。不同会话和不同账号的任务不因内容相同自动合并。
12. **需要工具的请求进入实际处理。** 用户要求查看、搜索或分析项目等需要外部信息的工作时，主 Agent 应在授权范围内使用可用的项目、文件或搜索能力，或交由具备相应能力的任务处理；不因分流环节本身没有工具，就直接回答“无法分析”。未选择云端电脑不等于其他工具不可用。确实没有所需权限、工具、项目位置或访问条件时，说明实际原因和需要用户提供的具体信息，不编造已查看或已完成。

## 对话示例

用户：帮我搜索一下最近有什么 AI 新闻。

助手：收到，我开始搜索近期的 AI 新闻。

助手调用搜索工具，处理结果，并在需要时继续说明进展。

助手：最近的 AI 新闻有……（依据工具返回的结果作答，提供可用的来源）。搜索失败时说明原因，不编造搜索结果。

## 验收条件

- iOS 输入非空文字时发送按钮可点击；上一条正在处理、模型列表或任务状态加载失败、电脑/Workspace 不可用及临时断网均不使其变灰。输入法组合文字按系统规则确认后可发送；空白输入不可发送。
- 服务端明确确认账号没有配置任何云端模型时，点击发送提示配置并保留输入。模型已配置但连接失败、列表尚未读取或模型暂时不可用时，仍可点击并保留消息，界面说明实际失败或等待状态；已配置的模型不支持工具时，普通文字对话仍可发送。
- 断网、服务不可达或登录过期时可连续提交多条文字；消息按原账号和对话保留并显示待发送或失败，恢复后可重试。服务端未受理时不显示已发送，重试和结果未知的恢复不产生重复消息或任务。
- 云端电脑或 Workspace 未创建、离线、准备中或无权限时，纯文字问答仍可发送并正常使用已配置模型；用户明确要求操作不可用电脑时，助手说明该电脑不可用，不伪称已执行或暗中切换目标。Workspace 仅在确需使用且失败时提示。
- 在工具和授权可用时，同一会话连续四次发送截图中的相同项目分析请求，包括首次请求仍在分流和任务已开始两种情况：四条消息均保留并关联同一个请求或任务，只启动一次实际分析，不因重复消息中断、修订或新建任务；不出现“继续原任务还是开始新任务”，进度和最终结果各自真实且不重复刷屏。换一种说法但目标和条件相同的请求也能关联。
- 两条重复消息在分流判断期间遇到任务状态或上下文变化：系统基于最新状态重新判断，仍须核对授权和实际目标；原任务在重复消息提交后、处理前完成时，关联并展示已有结果，不再执行一次。PC 和 iOS 在同一账号、同一会话近同时发送相同请求，以及刷新或重新打开会话后，消息、关联、状态和结果一致；同一消息重试不新增消息、任务或重复已确认操作。
- 原任务失败、已停止、等待授权或操作结果未知时，重复消息展示真实状态；不把未完成回复当成分析结果，不擅自重启已停止任务或重复结果未知的操作。用户明确要求重新执行时，在可确认安全且授权允许后执行。
- 任务 A 运行时发送“进展怎么样”：回答 A 的实际进度，A 不被中断；发送明确的补充或修改时只影响 A。发送“重新分析一次”按明确要求执行，发送针对其他项目或范围不同的独立请求则不因文字相似而合并。
- 同一会话有两个可能的目标任务，用户只说“修改那个”且上下文无法确定对象时，助手具体询问要修改哪项任务，两个任务都不被擅自中断。另一会话或另一账号发送相同内容时，不自动关联或复用本会话的任务。
- 在已授权且所需能力可用的环境中，请求查看并分析指定项目时，实际读取或搜索后给出有依据的结果；未选择云端电脑不阻止可用的其他能力。工具、权限或项目位置确实不可用时，说明具体原因，不声称已完成。
- 同一对话中任务 A 正在处理时，发送“把前面任务的范围改成上周”：系统按新要求在安全边界更新并继续 A，保留已完成结果；同一会话其他任务不受影响，已确认的有副作用操作不重复执行。
- 修订任务尚未完成时再发送一条相关修改：两条修改按发送顺序进入最新版，较早执行的迟到结果不能覆盖最新版；每条用户消息均可在对话中查看。
- 任务 A 仍在执行时发送明显无关的任务 B：B 在 A 结束前开始处理，两者进度和结果各自可辨；停止 B 不停止 A。关联对象不明确时，新消息保留并请求确认，已有任务不被擅自中断。
- 对执行中不可安全中断的操作发送关联修改时，新消息可立即发送；操作结果确认后再继续修订任务。结果未知时不重复执行该操作，并向用户显示实际状态。
- 实际接入 DSH，用户发送消息后自动启动对应会话实例；用户能先看到开始处理的回复，随后看到工具执行进展和最终答复。
- 同一用户的两个对话和另一用户的对话可同时执行，各使用所属会话的实例；消息、工具结果和任务控制不串到其他对话。重复打开或刷新同一对话不会并发创建两个活动实例或重复执行任务。
- 用户在一个对话中提供个人偏好并讨论某件事后，在新对话或实例恢复后询问时，助手能根据该用户的资料和历史正确回答；另一用户不能读取这些信息。历史被删除或撤销访问后，新的任务不再使用它。
- 用户只配置了一个通过检查的个人模型时，也能用它对话；已配置的平台模型同样可选，模型预算与授权仍生效。
- 纯问答在没有选择电脑时仍可完成；需要电脑或 Workspace 的任务只使用已授权且可用的目标，缺失时会先向用户说明并询问。
- 任务执行期间，用户能在消息流中看到有实际进展的自然语言更新；关闭页面、刷新或重新打开对话后，任务仍继续运行，用户能看到已产生的进度，且不会重复执行任务。
- 需要澄清或审批时，用户能直接在当前对话处理并继续原任务；用户暂停、继续或停止后，看到与服务端确认状态一致的结果。
- 任务结束后，用户收到包含处理结果的最终答复；文件等产物只有确认保存后才显示为已交付。任务失败或无法确认结果时，页面明确告知且不声称已完成。
- 普通用户在助手页面无需看到或操作 Runtime 开关；服务异常时看到可理解的说明，而不是内部运行时术语或虚假的“正在执行”。

## 边界

本需求沿用 Morde 的工具授权、审批、审计、模型预算及 Workspace 写入规则。项目或共享会话继续遵循其数据授权范围，不因共享电脑或项目自动暴露个人历史。管理端仍可保留运维与故障诊断信息。
