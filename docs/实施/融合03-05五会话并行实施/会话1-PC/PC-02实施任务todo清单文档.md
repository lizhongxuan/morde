## 本轮审查与实现（2026-11-02，续）

- 修复桌面退出门禁：停止未确认或恢复点无法安全保存时，Morde 保持打开并保留恢复点；仅在子进程不再持有目录且恢复点保存成功后退出。定向主进程用例覆盖“仍持锁拒绝退出、锁释放后可退出”。
- 桌面已将固定版 Syncthing 节点接入主进程与 Workspace UI：账号登录后恢复加密的节点绑定；本机登记用节点证书与私钥签名；节点只使用受控 relay peer；每个 Workspace 独立开关；节点占用目录时禁止选择、登出和副本操作。服务端能力关闭时，客户端在发送账号凭证前按 capability 拒绝启用。
- 节点配置写入后读回并核验 relay 地址、peer 列表、folder 路径/暂停状态和安全选项；不匹配或部分写入时停节点，未确认退出仍保留目录保护。UI 不再提供旧 helper 的上传/下载/双向按钮；遗留运行中的旧 helper 仍可停止，待恢复点未解决时禁用目录与节点开关。
- 固定 Syncthing 构建脚本与上游 commit/补丁哈希、MPL 许可证和第三方声明已随桌面打包配置存在；本轮按锁定 commit 构建了 macOS arm64 节点。
- 本轮用实际二进制启动两个本机私有节点，配置 relay-only Workspace，并通过 folder/peer/options 读回、空 HTTP 200 resume 和正常停机 smoke；该项仅验证私有配置，不连接 peer。随后另以 loopback-only 地址完成实际 peer 数据测试。
- 新增 loopback-only 双节点 E2E：临时节点仅监听 `127.0.0.1`，关闭 global/local discovery、relay 和 NAT；验证基线同步、远端更新覆盖、目标旧版 sidecar 归档、helper 列表、非空目标拒绝恢复、清空后恢复旧版以及逐条删除，全流程通过。
- 实际二进制 smoke 揭示并修复两处 API 行为差异：resume 可返回空 HTTP 200；Syncthing 的 folder devices 读回会包含本机设备 ID。客户端现在接受空成功响应，并在写入/读回校验中显式包含本机设备，避免真实节点配置被误判失败。
- F02 保全目录为 Workspace 父目录 `.morde-preserved/<sha256(folderID)>/<random20>/<relativePath>`；固定版 Syncthing 补丁现随每条副本写入版本化 `.morde.json` sidecar（entry ID、folder ID、原相对路径、创建时间），helper 按 sidecar 验证条目并提供列表、占用统计、空目标恢复和逐条删除。loopback 双节点测试已验证真实覆盖冲突触发保全和本机恢复；无 sidecar 的既有 F02 目录不会按树结构猜测恢复对象，继续保留供人工恢复。
- 服务端本地 `capabilities` 当前未公布 `workspace_sync`，设备 API 在服务未配置节点时也会拒绝；上一轮给定测试 Portal 的 `/admin/login` 与 `/api/capabilities` 均返回 404。未再次登录、SSH 或向远端发送文件，未做实际 peer 联通验收。
- 当前 Task 创建只提交 `workspace_id` 与不可变 `input_revision`，没有选定路径、范围摘要或已确认文件检查点字段。此公共 Task 合同/服务端执行范围由会话 5 维护；本任务在本文件交接合同缺口，合同和节点就绪前不允许把 UI 选择伪装成 Task 文件授权，也不开放文件 Task 提交。
- Go helper 和桌面 IPC/UI 现合并提供旧格式与带 sidecar 的 F02 副本列表、占用统计、空目标恢复和二次确认删除；folder ID 随本地请求限定 F02 范围，mapping/保全根重叠及节点占用门禁均保留。尚未验证真实节点联通与跨设备保全恢复。
