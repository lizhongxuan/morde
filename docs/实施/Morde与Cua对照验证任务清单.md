# Morde 与 Cua 对照验证任务清单

> 整理日期：2026-10-21。用途：后续逐项交给 AI 验证；本轮没有执行以下实验，也没有实现功能。
>
> 对应研究：[Morde 与 Cua 源码对比及超越路线](../Morde与Cua源码对比及超越路线.md)。本清单补充验证方法，不替代 T09–T19 的实施任务，不因实验写完而勾选功能完成。

## 1. 执行规则与已有结论

### 1.1 先核对前提，再执行一项

- **只在本地修改和保存。** 不上传代码、镜像、文件、日志、截图或实验结果；不发送真实消息。使用隔离测试实例与本地合成资料。远程模型可能传出文件内容或截图，本清单不授权这种传输；需要真实 Agent 时使用符合限制的本地模型服务，缺少该条件则标记阻塞。mock 可验证协议及故障分支，不能替代真实 Agent 成功证据。
- **状态与结论分开。** 执行状态：未开始／进行中／待验证／完成／阻塞。结论：通过／不通过／证据不足／不适用。发现缺陷并保存可复现证据，可以结束该次验证，但不能把对应功能勾为完成。源码可行、编译成功和运行通过分别记录。
- **“现在可查”仍需本地实验条件。** 先读当前源码、版本与既有记录。标记“实现后”的项目只核对缺失前提，未实现就列阻塞项，不制造假接口、不循环运行必然失败的测试，也不擅自扩大为功能开发。
- **保护已有工作。** 为本次实验单独命名资源；故障注入只针对测试 Worker、数据库、电脑与本地假服务。清理仅删除本次创建且能确认归属的资源，不执行全局 prune、清空库或覆盖个人资料。
- **沿用已有合同。** 首个模型协议为 OpenAI Responses API，模型 ID 由管理员或用户显式配置；首个外部 MCP 客户端为 Codex Desktop。当前默认上限：活动执行 30 分钟、100 次工具调用、50,000 tokens。执行时先核对 T10.01 是否有后续正式变更，不另选默认模型或静默降级。
- **每次证据保存在本地。** 建议路径：docs/验证记录/cua对照/Vxx-简述.md，附件置于同名子目录；这些是拟新增路径，本轮不创建结果文件。每份记录包含环境/版本或哈希、前提、实际命令与输入、预期、实测、结论、限制、清理结果；敏感信息脱敏。无需上传到外部报告服务。

### 1.2 不需要重新发现的事实

[T09 运行记录](../验证记录/09-运行能力验证.md)已经在固定版本上发现：Shell 脱离子进程和 REPL 超时不能证明停止；当前 Gateway 缺少完整控制权隔离；原始 OpenSandbox 创建路径的普通用户工作目录写入及浏览器 profile 持久化有缺口。

这些是已知缺陷证据。V06–V10 的目的分别是区分完整 Morde 链路、补齐覆盖或验收修复，不能把原记录的“调查完成”写成“能力通过”。T10.01/T10.02 已在开发中，已有任务类型及存储代码；执行 V12 前重新检查实际完成范围，不能沿用早期“完全没有任务模型”的判断。

### 1.3 建议执行顺序

| 批次 | 项目 | 要回答的问题 |
|---|---|---|
| 第一轮：近期选型与上手基线 | V01 → V02 → V03 → V04；V06、V07、V26 | Driver 值不值得接；完整 Morde 链路的保存问题在哪里；新用户究竟卡在哪一步 |
| 条件调查 | V05、V11 | 需要改 AIO 源码时是否有可复现基线；Cua 实际接管范围有多大 |
| 基础控制修复后 | V08–V10、V12、V18 | 停止、接管、持久任务和撤权是否可信 |
| M1/P0 接通后 | V13–V17、V19–V22、V27–V31 | 真实任务能否持续完成，用户能否轻松开始并处理异常 |
| P1/P2 及正式对照 | V23、V24、V32 | 副本、交付、迁移及相对收益是否成立 |
| 外部条件待满足 | V25；V31 的真人部分 | 独立云环境与真实试用者不能由本地 AI 模拟替代 |

先跑与当前选择有关的项目；V32 可先比较已完成的共同子集，不必等全部 P1/P2。不要把 32 项当成一次全部执行的命令。

## 2. 选型与电脑操作

### V01｜固定双方基线与能力边界（未开始）

- **时机/归属：** 现在可查；所有对照实验的公共前提，沿用 T09 记录。
- **动作：** 记录 Morde、Cua、AIO、OSB、runsc、OS/架构、浏览器与模型/harness 版本；无 Git 来源的副本记录文件哈希及来源限制。逐项区分当前实现、计划、当前版本不支持与本机未具备实验条件。
- **通过标准：** 后续结果能定位到实际源码、镜像与配置；没有拿历史 Fleets 代码代替当前产品服务、拿文档承诺代替运行结果。缺少发布来源要写明，不编造 commit。
- **特有证据：** 版本表、能力表、哈希与待确认来源；不采集真实密钥。

### V02｜最小 Driver 集成的许可证与依赖边界（未开始）

- **时机/归属：** V01 后，现在可查；对应研究第 8 节路线 B。
- **动作：** 固定拟使用的 Driver/SDK 版本与具体功能，检查子目录许可、直接/传递依赖、默认与可选构建开关、下载的二进制和模型。尝试最小本地构建，列出真正随产品分发或运行的组件。
- **通过标准：** 技术上能说明该候选路线是否依赖 FSL 服务或额外模型授权，保留要求的声明。无法确认许可、构建来源或实际分发范围的组件列为选型阻塞；构建通过不等于商业授权确认，不能用根 MIT 覆盖全部目录。
- **特有证据：** 功能→组件→依赖→许可证→产物清单，构建日志；需要商业授权的事项单列，未经确认不宣称可自由商用。

### V03｜Cua Driver 能否在 Morde 的隔离电脑中工作（未开始）

- **时机/归属：** V01/V02 后；具备本地 Linux 测试环境时可做，关联 T12.01 的运行能力定稿。
- **动作：** 在与 Morde 匹配的固定 AIO/派生镜像、runsc、普通用户条件下检查显示服务、D-Bus、AT-SPI 和浏览器；运行窗口枚举、截图、原生控件读写与浏览器操作。记录缺包、架构和权限要求。
- **通过标准：** 关键动作在声明隔离边界内工作；不能通过取消 runsc、提权或直连宿主桌面后声称兼容。需要额外权限时精确记录，其可接受性单独决定。
- **特有证据：** 镜像差异、启动配置、窗口/控件输出、操作前后画面与结构化结果；本次只决定候选可行性，不直接替换运行栈。

### V04｜定位、过期引用与动作效果是否可靠（未开始）

- **时机/归属：** V03 后；可独立验证 Driver，再在 T12.05 后验证 Morde 接入。
- **动作：** 测同应用多窗口、多标签、窗口移动/缩放、元素刷新失效、原生文件选择框、DOM 不可用的 GUI 回退。刻意点击无效控件、使用旧引用，对比动作返回与页面/文件实际变化。
- **通过标准：** 不误操作别的窗口；过期目标明确拒绝或重新观察；无效动作不报已确认。独立核验业务结果，区分动作投递、效果确认和整项任务成功。支持不到的操作明确报不支持。
- **特有证据：** 目标 ID 与生命周期、动作/后置条件、预期和实际结果；同一合成场景的 AIO 基线与 Driver 结果。

### V05｜AIO 缺口是否必须修改上游，能否独立构建（未开始）

- **时机/归属：** 条件项；仅当 T12 的派生镜像/自有运行控制无法满足已确定需求时调查。
- **动作：** 对一个具体缺口追踪到服务接口和实现，先区分配置、派生镜像、Morde runtime 修改与上游核心修改。若必须上游二开，核对用户准备的独立项目、版本来源、完整构建与替换/回退路径。
- **通过标准：** 有证据说明最小修改层；需要二开却缺完整源码/构建链时明确阻塞，不把现有 AIO 镜像当作完整服务源码。遵守已有“用户单独准备第三方项目”的约定。
- **特有证据：** 缺口→源码/接口→最小修改范围→独立构建→回退的记录；无二开必要则结论“不适用”，说明依据。

## 3. 保存、停止与人机接管

### V06｜工作目录的普通用户权限与重挂（未开始）

- **时机/归属：** 现在可查；关联 T12.04/T12.07，优先补全 Morde 创建链证据。
- **动作：** 分别通过完整 HostService/派生镜像和原始 OSB 创建测试电脑；以实际普通用户写入、读取、重建、重挂同一工作目录，核对 UID/GID、权限及内容；确认第二用户不能挂载该目录。
- **通过标准：** 声明支持的完整链路正常可写且内容与归属保持；两条路径分开结论，不能用 root 写成功覆盖普通用户失败，也不能用原始 OSB 的失败推定整个平台失败。
- **特有证据：** 创建路径、实际运行用户、挂载与权限、恢复前后文件哈希、越权拒绝结果。

### V07｜浏览器资料、应用与“同一台电脑”的恢复范围（未开始）

- **时机/归属：** 现在可查基线；T12.07 后验收恢复保证。
- **动作：** 用本地合成站点设置 cookie/localStorage/登录占位状态，保存浏览器资料、受支持应用配置及文件；依次重启、释放计算后恢复、重建镜像，检查稳定电脑身份和内容。分别记录应用二进制、配置、未保存内容和运行进程。
- **通过标准：** 每种生命周期操作都与声明范围相符；未保存进程不冒充可恢复，过期登录要求重新登录。保留 profile 不能推导任意第三方站点都接受原 session。
- **特有证据：** 数据路径/恢复清单、身份、哈希与实际登录状态；真实第三方账号不纳入本次合成实验。

### V08｜取消和超时是否真的终止执行（未开始）

- **时机/归属：** 已有失败基线；T12.03/T12.05 的受管执行完成后复验。
- **动作：** 分别启动延迟写文件的前台命令、后台子进程、脱离 session 的子进程、REPL 和排队 GUI 动作；执行超时、暂停、取消、全部停止；再检查文件是否继续变化、进程存活和队列投递。只操作隔离测试资源。
- **通过标准：** 已确认停止后没有不允许的继续执行；无法取消的通道不得声称已停止，应按合同隔离/回收并标记结果未知。客户端 timeout、退出码或按钮变灰都不算停止证据。
- **特有证据：** operation ID、确认时间线、进程/队列状态及确认后的观察窗口；对照 T09 已有失效例。

### V09｜只读、撤权与旧连接是否统一生效（未开始）

- **时机/归属：** T10.04/T12.08/T13.05 完成后；旧基线只作证据引用。
- **动作：** 建立 VNC、终端、文件、GUI/CDP、MCP、预览与事件流连接；降为只读、撤销 Key/用户权限，再通过已有连接和新请求尝试读写。单独验证同源 Cookie 不能让只读入口成为写入后门。
- **通过标准：** 每条通道遵守最新授权；只读拒绝写入、撤销后拒绝相应访问，不能仅靠前端禁用输入。旧票据、旧 WebSocket、缓存授权无持续越权。
- **特有证据：** 角色/授权变化时间、每通道请求与服务端拒绝、旧连接关闭或重鉴权记录。

### V10｜隐私接管、晚到结果与交回（未开始）

- **时机/归属：** V08/V09 及 T12.06/T12.09 完成后；这是 Morde 潜在差异点的关键验收。
- **动作：** Agent 同时排队输入、截图/录屏、读文件、CDP、Shell；用户接管，在服务端确认后输入合成私密标记；人为延迟旧请求结果，尝试旧控制版本执行。交回后要求重新观察，检查任务是否继续原工作。
- **通过标准：** 确认接管后无未经允许的 Agent 读写；私密标记不进入模型上下文、普通日志和晚到结果。无法排空时显示接管中/失败，不能先报成功。交回不重放过期动作，多客户端只有明确获权者能输入。
- **特有证据：** 控制版本、请求/排空/确认时间线、上下文及日志检查结果、交回后的新观察与动作。

### V11｜Cua 的接管与撤权实际覆盖到哪一层（未开始）

- **时机/归属：** 现在可调查；运行需要本地 Cua 完整相关组件与合适权限，缺失则阻塞对应子项。
- **动作：** 在 Cua 原生受支持流程下逐项复现 V08–V10，分别测窗口 lease、viewer、Agent 授权撤销、角色变化和连接切断。列清 GUI、进程、文件、截图、录屏与晚到输出覆盖范围。
- **通过标准：** 形成可复现的支持/不支持/未测矩阵；有窗口锁不等于整机隐私接管，未找到接口也不等于证明产品没有能力。只比较双方共同范围，额外支持单列。
- **特有证据：** 使用组件/配置、原生操作步骤及逐通道时间线；不基于推测宣称 Cua 全部安全或全部不支持。

## 4. 持续任务、权限与成果

### V12｜任务持久化、幂等和失效执行器隔离（未开始）

- **时机/归属：** T10.02 的存储可测后先验，T10.03/T10.05 接线后补 API；当前正在开发，先核对前提。
- **动作：** 用独立 PostgreSQL 验证任务/首事件/消息/幂等原子提交；相同请求重发、同键改内容、两个 Worker 争抢、租约过期后旧 Worker 提交；刷新/重连续读事件，切换受限 Host 访问会话。
- **通过标准：** 无半条记录、重复任务或乱序事件；只有当前 lease_version 能提交/继续受控操作；会话固定 Host，消息关联任务；范围过滤和过期游标行为符合合同。
- **特有证据：** 事务前后记录、竞争时序、租约拒绝、事件序号与 API 返回；单元 mock 与真实 PostgreSQL 分开报告。

### V13｜网页/MCP 委派后客户端退出，任务是否继续（未开始）

- **时机/归属：** T11/T13.07 接通后；需要可按本地限制运行的真实模型。
- **动作：** 网页和 MCP 分别委派同一合成任务，等待服务端持久接收后关闭客户端；保持本地服务器运行，稍后查看进度与产物。另测“外部客户端逐次调用工具”断开后的表现，以及任务活动对空闲回收的影响。
- **通过标准：** 已接收的云端委派由 Morde 继续执行，电脑不被误回收；直接工具循环不被宣传为客户端退出仍自动推进。返回的任务、电脑、文件身份一致，结果独立核验。
- **特有证据：** 接收与断开时间、后台事件、回收判定、最终产物；这里只证明客户端断开，不证明本机关机。

### V14｜重启、模型限流和服务中断后的恢复（未开始）

- **时机/归属：** V12/V13 与 T11 恢复逻辑完成后。
- **动作：** 在准备动作、调用中、写进度前后分别重启测试 Worker；注入模型 429、超时、暂时断连和不可用模型配置；恢复后核对已完成步骤、重试次数、等待提示与授权状态。
- **通过标准：** 在约定策略内有界重试；不可恢复错误给下一步；不静默换模型或重复已知完成动作，失效执行器不能继续写。协议故障可用本地假服务，真实模型闭环另测。
- **特有证据：** 故障点/重启时间、操作状态、调用计数与恢复轨迹；明确哪些步骤需要用户确认。

### V15｜批量 100 项能否准确续跑和只重试失败项（未开始）

- **时机/归属：** T11 批量持久化与 T13 逐项结果完成后。
- **动作：** 固定 100 份合成输入，在部分成功、部分失败时中断；重启续跑，再请求仅重试失败项，并改变一份输入测试旧结果失效。
- **通过标准：** 每项有输入版本、结果和原因；已完成项不被无故重做，变化输入不复用旧结果；全部、部分成功、失败数量与实际文件相符，不把部分成功报成全部完成。
- **特有证据：** 输入清单/哈希、每项调用计数、前后状态和产物核验结果。

### V16｜外部提交成功但响应丢失，是否避免重复副作用（未开始）

- **时机/归属：** T11 的 unknown/恢复语义和 T12 操作记录可用后。
- **动作：** 使用仅在本地的假提交服务模拟提交前断线、提交成功后响应丢失、状态查询失败、进度入库前崩溃。分别测试有幂等键/可查回执和无法自动查证的路径；计数真实落地记录。
- **通过标准：** 可查证时核实再继续；不可查证时标 unknown 并等待处理，不盲目重发或把超时报成未执行。不得承诺对任意外部系统实现 exactly-once。
- **特有证据：** 请求键、服务端落地计数、回执查询、操作状态及用户提示；不测试真实发送/付款/删除。

### V17｜预算、用量不明与停止边界（未开始）

- **时机/归属：** T11 预算与停止逻辑完成后。
- **动作：** 核对 30 分钟/100 次/50,000 tokens 默认合同及用户可降低限制；测试临界值、等待/暂停计时、模型未返回 usage、客户端伪造更高预算、恢复后继续累计与全部停止。
- **通过标准：** 按合同扣减活动执行预算，等待/暂停不误计；不得通过重连/恢复绕过上限。用量未知如实展示并停止后续模型调用，已有调用的最终用量与并发在途边界单列，不用估计值冒充精确计费。
- **特有证据：** 配置和计数时间线、临界请求是否发出、未知用量及超预算 UI。

### V18｜跨用户、限定 Key 与不可信任务内容（未开始）

- **时机/归属：** T10.04/T13.05 以及所测资源实现后。
- **动作：** 两用户、两 Host 和空权限/限权/过期/撤销 Key 覆盖任务、会话、事件、文件、预览及电脑；尝试通过网页文案、工具输出诱导切换 Host、读取另一用户数据或扩大权限。
- **通过标准：** 空集合零权限、无隐式通配符；每次动作按当前授权与批准范围交集执行；外部内容不能授予权限。撤销后在途及后续动作按明确边界处理，无密钥通过工具输出、日志或结果卡泄露。
- **特有证据：** 主体×资源×操作矩阵、实际拒绝与审计记录；有限用例不等于完整安全审计。

### V19｜定时任务的时区、错过、重叠与停用（未开始）

- **时机/归属：** T14 完成后。
- **动作：** 固定时区，覆盖跨日及有夏令时地区的时间变化；重启服务、错过触发时间、上一轮未结束、重复触发、等待登录、停用和恢复；检查上次/下次时间与逻辑运行标识。
- **通过标准：** 符合已选的重叠与错过策略；同一逻辑运行不重复；停用后不产生新运行，已运行任务处理方式明确；“错过/跳过”不能显示成功。
- **特有证据：** 时钟/时区配置、触发/跳过记录、运行 ID、用户可见时间。

### V20｜记忆与笔记能否撤销、隔离并追溯（未开始）

- **时机/归属：** T15 对应功能完成后。
- **动作：** 两用户/两项目创建合成笔记与明确记忆，跨任务引用；修改、删除、关闭记忆、撤销项目授权，再发起新请求；删除关联文件并查看引用。
- **通过标准：** 只检索获授权内容，来源可追溯；后续请求遵守最新修改与撤销，不把全部笔记自动作为记忆；缺失文件如实提示，缓存不复活已撤销资料。
- **特有证据：** 授权和版本变化、检索输入/结果、引用落点与拒绝记录。

### V21｜预览和交付结果是否对应真实版本（未开始）

- **时机/归属：** T15 预览及 T13 结果卡完成后。
- **动作：** 在本地项目生成版本标记 X，启动受保护预览，再改为 Y；模拟旧进程未重载、启动失败、进程结束、错误端口和第二用户访问。独立打开产物核验内容。
- **通过标准：** 页面内容与宣称的文件/进程版本相符；有 URL 或 HTTP 200 不单独代表任务成功；失败可定位、旧版本有提示、越权被拒绝，结果卡能找到真实文件和所属电脑。
- **特有证据：** 文件哈希、版本标记、进程/端口关联、访问画面和 evaluator 结果。

### V22｜备份、升级与失败回退是否保留正确状态（未开始）

- **时机/归属：** T16.02 及所需 T12/T14/T15 完成后。
- **动作：** 在隔离数据集取得一致保存点，升级/恢复到独立本地目标；覆盖缺恢复密钥、损坏备份、镜像/schema 不匹配和目标已有较新数据。恢复前冻结旧执行端、撤销旧连接，核对计划初始停用。
- **通过标准：** 数据、归属、版本和权限一致；只恢复声明范围，普通用户不能整库恢复。失败不覆盖有效数据；旧控制版本不能因回退重新有效；核对单写与归属后才恢复任务/计划。
- **特有证据：** 保存清单、哈希、兼容性检查、前后数据对照与旧端拒绝；同机备份不宣称具备异机容灾。

### V23｜模板、独立副本与团队交付复现（未开始）

- **时机/归属：** T17 完成后，当前只核对前提。
- **动作：** 从固定版本 X 创建两个独立环境，分别修改/删除一个；发布 Y 检查旧实例；另一获授权成员按 X 复现成果，未授权成员尝试创建；检查模板文件及镜像旧层中的合成秘密标记。
- **通过标准：** 副本独立、旧版本不漂移、删除不影响其他环境；交付版本含足够的环境和数据说明，复现结果可关联原版本；私有内容不进入共享模板或旧层。
- **特有证据：** 镜像/代码/配置/数据版本、卷身份、两环境差异、复现记录与模板扫描结果。

### V24｜迁移与回退是否避免双端执行和数据覆盖（未开始）

- **时机/归属：** T18 完成后；仅使用本机内两个隔离测试节点，不传文件到外部机器。
- **动作：** 测兼容/不兼容节点、暂停、保存、恢复、核验、切换；在每个阶段注入失败；目标产生新成果后尝试回退，检查旧端执行与计划是否停用。
- **通过标准：** 只有获权端继续执行；不兼容时拒绝并保留原环境；失败可恢复且不静默覆盖较新数据。仅证明本地协议与流程，不宣称真实跨云网络/存储性能通过。
- **特有证据：** 兼容清单、迁移/控制代次、双端状态、数据差异和回退结果。

### V25｜真正独立云端的连续性（阻塞）

- **时机/归属：** T16.05；当前只有本地修改授权，缺独立目标环境及对应操作条件。
- **动作：** 用户另行准备独立远端副本、运行产物、模型与网络，并另行允许相应远端验证后，才验证正式 DNS/TLS、远程客户端和笔记本断网/关机后任务持续；不能由本 AI 从本机上传材料来补齐前提。
- **通过标准：** 以远端持久事件和重新连接后的成果证明执行跨越本机关机时段；正式访问与隔离可用。没有独立环境时保持阻塞，本地 VM、关闭网页、mock 都不能替代。
- **特有证据：** 由允许的验证过程取得并保存的时间线、远端运行标识和结果；当前不执行远端修改或传输。

## 5. 易用性与公平比较

### V26｜管理员能否按一条路径部署并开始体验（未开始）

- **时机/归属：** 现在可检查现有部署说明；T16.01 后再验收简化后的完整路径。
- **动作：** 从声明支持的干净本地 Linux 环境，仅按快速开始操作；统计必填信息、手工命令、文档跳转、总耗时。分别记录构建/下载、部署、模型检查和首个任务；注入缺配置、磁盘不足、版本不匹配；重复运行并重启机器。
- **通过标准：** 不依赖作者口头补步骤，只有一条清晰默认路径，失败可定位并从适当阶段继续；已有数据和密钥不因重跑重置。不能以关闭隔离或暴露底层服务换取易安装。现有多步骤安装如实形成基线，不冒充一键安装已实现。
- **特有证据：** 操作清单/时间、卡点、必填字段和修复步骤；快速开始缺失或仍需大量手工装配时给出具体删减建议，不捏造通过。

### V27｜模型配置是否一次完成、普通用户直接可用（未开始）

- **时机/归属：** T11 模型配置与 T13.03 完成后。
- **动作：** 分别测试管理员已有可用且授权的默认模型、未配置模型、凭证/地址错误、无图片或工具能力、限流/额度不足。首个协议遵守 T10.01；用真实能力探测，不能只检查模型名称。
- **通过标准：** 有默认模型时普通用户不再填 Key；缺模型时能联系管理员或配置自己有权使用的模型；能力不符不假装支持桌面。不自动选择更贵模型或把测试 Key 暴露给浏览器，诊断不外发本地内容。
- **特有证据：** 各状态的页面与能力探测、授权范围、配置到可用的步骤；受本地模型条件限制的项明确阻塞。

### V28｜普通用户能否快速获得第一个真实结果（未开始）

- **时机/归属：** V27、T12.07、T13.03/T13.07 完成后；使用已部署且模型就绪的环境。
- **动作：** 新账号登录，跳过名称/偏好，直接交办并分别体验三个无需外部账号的合成示例：资料整理、本地表格处理、合成网页/桌面操作。查看结果、原文件和电脑；多次点击/刷新，另测已有多台电脑。
- **通过标准：** 无需安装客户端、配置 MCP、填写 Host ID/端口/底层密钥；目标明确，重复点击不重复创建/提交。首次提交目标 ≤5 分钟，首次可用成果另记实际用时；三个示例走真实执行与核验，至少一个实际使用浏览器/桌面，不能用预录动画或预置结果顶替。
- **特有证据：** 登录→提交→首动作→首成果时间、步骤/填写数、任务与电脑数量、实际产物；“快”与“完成”分开记录。

### V29｜等待、错误、接管与桌面交互是否容易理解（未开始）

- **时机/归属：** T13/T16.06 的相关页面完成后。
- **动作：** 覆盖冷启动、排队、限流、容量不足、创建失败、断网重连、暂停、接管、交回和失败重试；在 1280×720、1920×1080 用真实浏览器检查键盘操作、焦点、按钮名称、缩放与输入坐标。
- **通过标准：** 点击 ≤1 秒显示接收或错误；真实完成/停止/接管必须等服务端确认；等待有阶段与下一步，不要求普通用户读日志才能决定。已就绪电脑且 RTT≤100ms 时首帧目标 ≤5 秒，冷启动另计；不黑屏、不遮挡主操作、不页面级横向溢出，不因重试重复创建资源。
- **特有证据：** 页面录屏/截图、事件和首帧时间、各异常下一步、键盘与坐标操作结果；全部证据仅留本地。

### V30｜外部 Agent 接入是否简单且不会误导（未开始）

- **时机/归属：** T13.06；与 V13 的持续执行验证不同，本项验证实际配置体验。
- **动作：** 从网页“连接”入口按指南配置 Codex Desktop，使用最小范围 Key；完成直接操作与整项委派各一次，回到同一电脑；测试配错地址、权限不足、撤销 Key 和退出客户端。
- **通过标准：** 入口为可选进阶流程，网页首个任务不依赖它；配置格式按客户端实际版本可用，不要求用户猜参数；清楚说明直接工具与委派的差异，错误能定位。客户端会外发文件/截图时遵守本地限制，无法满足则阻塞真实 Agent 部分。
- **特有证据：** 脱敏配置、操作步数、错误恢复、任务/电脑对应关系；不复制真实 Key 到文档。

### V31｜非开发者是否真的能独立用起来（待验证）

- **时机/归属：** V28/V29 和 T16.06 就绪后，还需 5 名未参与开发的真人试用者；当前未安排参与者。
- **动作：** 在部署/模型就绪条件下，只给产品内说明，让每人独立完成首个交办、找到结果、接管再交回；观察者不口头指导，记录求助和放弃位置。AI 可准备任务卡和汇总匿名结果，不能替代参与者。
- **通过标准：** 目标至少 4/5 人无需指导完成；记录每人的登录到提交时间（目标 ≤5 分钟）、首次成果用时、求助次数与误解。未达到就调整流程后复验；五人是早期可用性筛查，不代表市场验证。
- **特有证据：** 匿名逐人操作记录、结果与卡点，必要画面仅本地保存；没有真人数据时不得标通过。

### V32｜在同等条件下，Morde 哪些方面真的更有价值（未开始）

- **时机/归属：** V01 与双方待比较能力就绪后；按已完成的共同子集分阶段执行，对应研究第 10 节。
- **动作：** 分开比较执行层（同模型、预算、环境、任务）与完整产品流程（双方合理原生配置）；让 Cua 使用其相应持久 Agent/Volume 能力。复用第 10.2 节 24 个核心场景，并加入 V26–V31 上手体验；固定合成输入和独立 evaluator，每项先少量重复筛查，重要差异再扩大样本。
- **通过标准：** 报告首次/无人介入通过率、恢复正确率、接管越界、状态保留、耗时中位数/P95、每成功任务总成本、人工分钟、配置步骤和首次成果时间。失败与重试计入成本；无价格依据不报节省比例；小样本不宣称统计领先。无法公平对齐的能力/隔离级别/版本单列。
- **特有证据：** 逐次原始结果、分母、失败归因、比较条件和可复算汇总。结论可以是 Morde 某场景更好、某场景更差或证据不足，不预设超越。

## 6. 每次交给 AI 的任务模板

> 只执行《Morde与Cua对照验证任务清单》的 Vxx。先读当前源码、对应 T 编号和已有验证记录，确认依赖；缺实现或环境就写清阻塞，不擅自实现功能。仅使用本地隔离资源和合成资料，不外发文件、截图或日志。记录实际版本、步骤、预期/实测、结论和限制，将结果保存到本地 docs/验证记录/cua对照/。清理只限本次创建的资源。最后给出结论、证据路径、发现的问题及下一步；“验证完成”和“功能通过”分别报告。

结果记录的最小格式：

| 字段 | 要填写的内容 |
|---|---|
| 项目/时间/状态 | Vxx、实际执行时间、执行状态、通过/不通过/证据不足/不适用 |
| 前提与版本 | 已实现依赖、实际软件/镜像/模型/架构、隔离方式、缺失条件 |
| 方法与结果 | 可复现步骤、预期、实测、局部通过/失败范围、证据文件路径 |
| 影响与后续 | 影响的用户承诺、对应实施 T 编号、最小修复或补证方向 |
| 清理与限制 | 删除了哪些自建资源，哪些保留；mock/本地/真人/远端边界 |

本轮仅建立清单和体验要求。V25 保留外部阻塞，V31 保留真人待验证，其余未因写文档获得通过状态。
