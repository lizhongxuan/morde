# 融合后续任务执行与提问规则

适用融合 03、04、05。这里约定如何推进和提问，不改变既定需求、数据保护、安全门禁或阶段验收。各清单中的父任务保留原编号和完整要求；只有子任务全部完成并满足父任务验收，父任务才能勾选。问题和证据记在所属清单，本文不另做进度总表。

## 选择任务和控制耗时

1. 开工前只检查当前子任务的代码、合同、修改位置和直接依赖。先做可独立验收的纵向切片；相邻功能、另一平台或另一验收场景不应成为无关前置。涉及真实数据、权限、发布或文件权威的既有硬门禁不能跳过。
2. 子任务以一轮内形成可验证结果为目标，约 **30–90 分钟**只是拆分参考，不是最低耗时或完成期限；能直接复用同版本证据的检查应及时完成，不为凑时间重复执行。预计明显超过时，沿平台、接口、功能或验收场景再拆；若一个事务或安全约束必须一起实现，就保持原子性，在阶段记录写明原因。长命令/构建正常运行时按可观察进度判断，不为了凑时间中断有效工作。
3. 遇到疑点先查关联需求、已有约定和代码。**首次确认会改变业务、权限或数据而资料没有答案时就提问**；不要等全部实现后再问。排查超过约 20 分钟仍无新证据，或连续两次有区别的尝试都没有缩小问题范围时，停止重复尝试，记录已做事项并切到其他无依赖子任务。仍在取得新证据时可以继续，说明下一个检查和预期结果。
4. 某一依赖未完成、目标环境不可用或验证失败时，只将直接受影响的子任务标记为“阻塞”或“待验证”，写清缺少什么、影响什么和恢复条件。已经完成的其他子任务及时勾选并记录最短证据；父项和总体交接仍保持未完成。依赖条件满足或用户回答后先复核旧假设，再恢复该子任务。
5. 阶段顺序是**交接和总体验收顺序**，不是禁止准备工作的全局锁：03、04、05 可以提前推进不依赖上游最终结果的本地工作。生产接口、真实跨端联调和阶段交接仍需各子任务列出的真实依赖。mock/fixture 只能证明本子任务的局部行为，不能代替真实接口、真实数据库、目标平台或端到端验收；未交付的能力不得对用户显示为可用。

例如，可先分别推进 F03-T01.01 的 PC 原工程、F03-T01.02 的 iOS 原工程、F04-T01.02 的个人数据合同及 F05-T01.01 的本地基线；iOS 工程缺失不阻止 PC 或服务端工作。F02-T10 未通过时，F03 的真实文件传输与同步联验仍等待，其他无文件子项照常推进。具体先后以工作区实时状态和子项直接依赖为准。

## 哪些情况自己决定，哪些需要问

- 沿用已有合同、数据与权限边界的局部实现、测试方法、任务顺序及可逆的本地验证，由实施者自行选择并简短记录，不为常规技术细节反复提问。
- 会改变用户可见行为、资料归属或删除范围、授权和隐私、运行安全、正式安装身份、已确认的产品范围，且现有资料无法确定时，先停住受影响的具体操作并问用户。先完成可审阅的影响分析、可选方案和无风险的独立工作；不要通过默认值、假成功或扩大权限绕过问题。
- 已确认的事项不再重问：Android 不纳入本期；不迁移原 nanoMuse Cloud 的线上账号及历史云端记录；保留已有 Morde 与客户端本机数据；新注册账号首次经管理员批准时按管理员当前配置发放默认模型额度；未配置保持待审，重复批准/disabled 恢复不重发，既有预算/账本保留；邀请与贡献奖励仍不自动发放（覆盖 2026-11-01 的新用户无默认额度决定）；普通个人同步数据默认每账号 5 GiB、单附件 300 MiB，管理员可调整，普通聊天、Workspace 和额外记录不计入；本期保留目标 PC 授权的截图、文件查看和命令，分别验收且不启动本机 Agent；PC 文件写入仅限目标已选择的 Workspace，沿用同步限额及覆盖前安全副本，F02-T10 后开放；用户已确认的旧模型 API key 定向清理范围、Workspace 本机安全副本及离线规则继续有效。现有 Schedule 的错过策略、时区和夏令时规则见[公共约定](00-总览与公共约定.md)第 9 节，沿用已有合同。旧 Web 持久卷、iCloud 远端独有数据与正式安装身份分别判断，不混同为旧 Cloud 线上账号。
- 所有源码、数据、截图、日志、安装包及验证文件仅留在本地；不得向远端发送文件、上传或部署。旧记录中的其他授权不覆盖本轮限制。缺少本地等效环境时如实记待验证，不以远端代替。

## 提问格式

优先使用当前环境提供的用户输入工具；工具不可用时，在完成其他独立工作后以简短问题直接询问。一次只问能解锁当前工作的关键问题；最多合并 2–3 个互相独立的小问题。每个问题写清：

1. **具体场景和影响**：现在遇到什么，涉及哪些用户行为或数据；只列已有证据。
2. **2–3 个可执行选项**：说明各自结果与代价，明确推荐项及理由；已有约定能解决的选项不再提问。
3. **等待期间的安排**：哪一个子任务会等待回答，其他哪些子任务继续；有无可逆的本地预备工作。

示例（仅在本地可行性核对已完成并掌握具体证据后使用；目前用户已选择先做本地核对）：

> 正式安装身份尚未确定。A. 在原签名和身份可用且本地演练通过时沿用原身份（推荐，可延续访问旧安装数据）；B. 使用新身份并安排本地受控导入（需要验证旧数据读取及恢复）。请选 A 或 B；正式安装身份的变更等待回答，隔离安装和其他独立开发可继续。

这是提问模板，不是替用户决定安装身份；实际提问前须先查明两种方案在当前设备上的可行性和数据影响。等待多久都不等于同意，不能自动执行需要用户选择的方案。收到回复后在对应问题记录写明决定和日期，并只恢复受影响的子任务；同一问题没有新信息时不重复追问。

## 状态与证据

- 子任务开始标“进行中”；实现后缺实际验收标“待验证”；真实依赖、用户决定或环境缺失标“阻塞”；实现和该项验收通过才勾选 `[x]`。每项保留版本/环境、操作、结果和未覆盖范围，证据只保存在本地。
- 可拆解的失败只退回失败子项；共享接口或实现变化导致既有结果失效时，重新标记受影响子项并重验。父任务保留原有完整验收，全部相关子项与真实集成证据满足后才可完成。
- 安全、数据完整性、同意和隔离不是可用样例、临时开关或时间预算替代的检查。环境不可达、测试失败、结果未知、未运行均不能写成通过。
