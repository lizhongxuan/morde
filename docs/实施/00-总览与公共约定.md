## 4. ID、状态和模板

ID 使用 crypto/rand，唯一键冲突最多重试 5 次：Host 为 h、Workspace 为 w、Workspace binding 为 g、Client installation 为 i、Device 为 d、Sync transfer 为 p、User 为 u、Token 为 t、Conversation 为 c、Task 为 q、Message 为 m、Step 为 s、Operation 为 o、Batch item 为 b、Artifact 为 a、Schedule 为 j、Notification 为 n、Schedule run 为 y，后接 7 位小写字母/数字。任务事件不另发 ID，以 task_id 和单调递增 seq 唯一标识。模板 ID 只含小写字母、数字、连字符，最长 32 字符。

Host 状态为 creating、running、stopping、stopped、failed、deleting、deleted；Workspace 状态为 ready、deleting、deleted，不再用 attached 表示文件数据生命周期。Host 是稳定电脑身份，释放计算资源只将其推进到 stopped，保留 Workspace、配置和 Host ID；恢复复用 creating → running 路径。Host 与 Workspace 的关联只由 `workspace_bindings` 表表达：一台 Host 可绑定多个 Workspace，一个 Workspace 同时至多有一个活动可写 Host；绑定有独立 ID、目录名、状态、绑定版本及期望 / 已应用 revision。禁止继续读写 Host.WorkspaceID 或 Workspace.AttachedHostID 作为另一事实源。状态由 domain/app 校验并由 PostgreSQL CAS 更新；handler、worker、gateway 不另建状态机。Host 的 runtime_generation 在每次运行时创建尝试前递增，sandbox_id 在无运行时为空；control_version 在控制权变更时递增。

任务状态为 queued、running、waiting_user、pausing、paused、cancelling、completed、failed、cancelled。pausing/cancelling 表示停止请求尚未确认；只有执行器报告安全边界已停下后才能进入 paused/cancelled。操作状态为 prepared、dispatched、succeeded、failed、unknown。请求超时或执行器在派发后丢失时为 unknown，须先查运行端结果或等待人工核实，不得盲目重放非幂等动作。每任务一个有效执行租约，lease_version 单调递增并用于拒绝旧执行器写入。

Owner 执行门禁是任务执行与计划触发共用的持久控制面，与 Host 的运行状态、人工/AI 控制权和活动租约分离。每个 Owner 有 `enabled`、`stopping`、`disabled` 状态和严格递增的 `epoch`；状态行缺失、读取失败或 epoch 不匹配均 fail-closed。计划触发/任务入队、任务认领、Agent 租约续期以及 operation 从 `prepared` 持久切换到 `dispatched`，都在同一事务中锁定并核对 Owner gate 与相关 schedule/task/operation fence。启用 bounded TaskWorker 时，任务认领会锁定该 Owner gate 并在同一事务复核账号没有超过 `cloud_dsh.max_concurrent_tasks_per_owner`；达到配额的任务留在队列，限制在数据库事务内跨 Portal 实例生效。全局工作上限由 `cloud_dsh.max_concurrent_tasks` 控制。每个计划时点至多创建一个运行，且同一计划不并发运行。`POST /api/execution/stop-all` 需要当前 `expected_epoch` 和幂等键：它先推进 epoch 并关闭门禁、取消排队任务、停用该 Owner 的所有计划，再持久停止/核验在途操作；在所有停止确认到齐前为 `stopping`，由专用 stop worker 继续排空。停用计划不自动取消已创建的当前运行；全停仍按任务停止合同处理在途运行。`POST /api/execution/enable` 只允许从已排空的 `disabled` 开启下一 epoch，不会复活已取消任务，也不会重新启用计划。Owner 范围控制只允许 Portal Session，不能由 Host-scoped API Key 推导。该门禁不关闭 Host、不撤销人工接管，也不替代 Host 活动租约。

首发继续使用 std-2c4g 一个模板和 container runtime。模板固定 lifecycle.onIdle=disabled；在跨实例活动租约和预览追踪可用前不执行自动空闲释放。用户可显式释放计算资源，保留 Host 与其绑定及 Host 专属 runtime 卷；删除 Host 会解绑全部 Workspace，永不删除独立 Workspace 正文。删除 Workspace 只能从 Workspace 管理接口显式发起。模板不可经用户界面或 API 修改。

主机地址为 <hostId>.<host_suffix>，私有预览地址为 <port>-<hostId>.<host_suffix>；端口必须在允许范围内且不能为 8080。以上域名均由 Gateway 接收。OpenSandbox metadata 固定含 ch-env、ch-host、ch-owner、ch-workspace；对账只管理本实例拥有且状态匹配的 Sandbox。

## 5. 凭证与安全

| 类型 | 格式/存储 | 用途 |
|---|---|---|
| 门户会话 | chs_<tokenId>_<secret>；数据库仅存 secret 的 SHA-256 | ch_portal Cookie，默认有效 12 小时 |
| Portal API Key | chk_<tokenId>_<secret>；数据库仅存哈希，可撤销 | Portal API/MCP 的 Bearer 凭证；按账号当前授权动态访问电脑，不继承管理员权限 |
| 原生客户端 | chc_<tokenId>_<secret>；数据库仅存哈希，关联 client installation | 桌面、Android、iOS 的固定日常用户 API 白名单；账号密码登录时签发 30 天，续期仍须账号密码；桌面和 iOS 可凭有效 Client 换短期用户 Web Session |
| 桌面同步凭证 | chd_<tokenId>_<secret>；数据库仅存哈希，关联同一 client installation | 仅限 Workspace Sync；桌面账号登录时与 Client 凭证原子签发，不包含冻结的 Workspace grants；每次操作实时校验 owner、安装与 Workspace 状态 |
| 桌面用户 Web 会话 | chs_<tokenId>_<secret>；数据库仅存哈希，Session 关联 client installation | PC 独立内存分区的 HttpOnly、Secure、SameSite `ch_portal` Cookie；可访问当前账号全部用户 Web API，但服务端拒绝 Admin；有效 Client 可续取，退出或撤销安装时整组失效 |
| 一次性 ticket | chx_<tokenId>_<secret>；存哈希并绑定用户、Host 和用途，有效 60 秒且只能消费一次 | 进入 Host 或私有预览时换取 Cookie |
| Host Cookie | ch_host；短期 HMAC-SHA256 签名，绑定用户、Host 和过期时间；客户端版还绑定安装 ID | Gateway 唯一的主机访问凭证；每次请求复核 Host 授权和客户端安装状态，不入库、不交给 AI 工具 |

桌面、iOS 与支持新合同的客户端必须先从 `/api/capabilities` 确认 `ordered_client_login`，再调用 `POST /api/auth/client-login` 提交账号、密码、平台、安装名、非秘密 `client_instance_id`、严格递增的 `attempt_generation` 与一次性 `Idempotency-Key`。客户端在每次网络尝试前持久化代次；每个请求使用新幂等键，响应未知时用更高代次和新键重试。服务端按账号与客户端实例串行比较代次，并在同一 PostgreSQL 事务轮换凭证；一个客户端实例只绑定一个安装，较旧或重复代次不能轮换，撤销安装不能被原登录流复活。升级旧客户端时可用服务、账号匹配的现存安装 ID 绑定首次有序登录流；已绑定或已撤销的安装拒绝再次绑定。为保持本期 Android 源码不变，服务端暂时接受省略两个有序字段的旧 Android 请求，按服务端到达顺序记录安装流，并保留同键重试在同一安装轮换凭证的旧行为；该路径不宣传 `ordered_client_login`，不提供迟到请求的客户端意图顺序围栏。Android 源码变更后可迁移到有序合同。桌面/iOS 缺少新字段或不支持该能力时返回 `unsupported`。沿用普通 Portal 的密码校验、限流、审核及强制改密规则；失败不得留下安装或凭证。成功在同一事务登记或续期安装、签发 Client；桌面额外签发独立 Sync 和安装绑定的短期用户 Web Session，手机只签发 Client。客户端只在系统安全存储保存长期凭证；密码与令牌不保存在登录围栏表中。

桌面有效 Client 可调用 `POST /api/auth/client-web-session` 续取短期用户 Web 会话，不延长 Client 到期；手机 Client 无权续取。`POST /api/auth/client-logout`、客户端安装绑定 Web 的 `POST /api/auth/logout`、以及 `DELETE /api/clients/{id}` 均撤销该安装的 Client、Sync、Web Session 和关联 Host/Gateway 凭证；普通浏览器的 `/api/auth/logout` 只撤销自己的 Session。`GET /api/clients` 只列本账号安装与撤销状态，不返回秘密或静态 Workspace grants。`KindClient` 仍只访问固定日常 API 白名单；完整 PC 用户功能由安装绑定 Web Session 调现有用户 API，Admin 必须使用独立普通浏览器 Session。`KindDevice` 只准 Workspace Sync，每次核对安装有效、owner 和 ready Workspace；撤权后活动传输停在最后已确认检查点。手机 Web `/app/*` 继续用普通 Portal Cookie。

登录、续期和撤销审计与对应凭证变更同事务提交，审计失败整体回滚；记录安装 ID、平台和动作，不含密码、设备码或凭证明文。迁移 `00047` 清空旧待批准码、撤销此前所有安装及其令牌，增加登录幂等记录，并允许 Session token 关联安装；迁移 `00089` 持久保存账号范围内的登录实例、最新代次和安装绑定，不保存密码或令牌。旧 `client_authorizations` 表和 `client_installations.workspace_ids` 列本次停止使用，遵照扩展/收缩原则待后续版本物理删除；迁移 `00044` 对旧未关联 `KindDevice` 的撤销仍有效，已发布迁移不回改。

secret 为 32 字节随机数的无填充 base64url；比较时使用常量时间算法。Token kind 为 session、api_key、ticket、device、client。新 API Key 创建只提交名称与可选有效期，不选 Host 或 scope；每次使用重验 Key、账号状态与电脑所有权/共享授权。API Key 只访问普通用户可用的电脑与运行端能力，不继承管理员权限，也不能管理 Key。迁移时撤销全部旧静态授权 Key，避免双逻辑。任务、计划及其 MCP 工具对所有凭证都不可用。

Host Cookie 绑定用户、Host 和过期时间；客户端票据换得的 v2 Cookie 还签名绑定安装 ID，每次请求复核安装状态。Gateway 转发前清除 ch_host Cookie、Authorization 及客户端自带的 AIO Key，再注入服务端 X-AIO-API-Key。Cookie 写请求和 WebSocket 均校验 Origin；登录、ticket、请求体、命令执行、MCP 输出和 Host 资源均受限。

错误响应、访问日志、审计和指标不得包含密码、secret、API Key、ticket、Cookie、Authorization、AIO Key、请求体或文件内容。鉴权失败统一返回 404，不泄露 Host 是否存在。

## 6. 配置合同

唯一配置样例为 `deploy/single/portal.yaml`，环境变量见同目录 `.env.example`；不在多份文档复制 YAML。配置支持环境变量展开，必填值缺失或无效时启动失败。单机仅配置 container 档位，统一使用 `CH_OSB_URL` 和 `CH_OSB_API_KEY`。样例 API/MCP/Gateway body 上限分别 1 MiB/4 MiB/100 MiB，控制面读写超时 60s；只有完成鉴权的长连接代理清除连接读写 deadline。
模板必须声明 idleTimeout；当前唯一可用的 onIdle 值为 disabled，显式释放由 Host API 发起。新 Host 必须绑定一个 Workspace，并挂载以 Workspace ID 注册的 `workspace-<workspace_id>` Docker named volume 到模板的 `Workspace.MountPath`（当前发布模板均为 `/home/gem/workspace`）；创建和恢复都校验 volume 的实例、所有者和 Workspace 标签，已登记卷缺失或身份不符时失败关闭。旧 `workspace-root` 卷仅允许经唯一旧 Host/Workspace 注册映射访问，迁移完成前不能自动选择冲突卷。新 Host 不挂载持久 `host-apps` 卷；Runtime apps 使用 `/run/morde-runtime/apps` 临时目录。AIO 首次创建的 Desktop/Downloads 等 XDG 目录与浏览器下载默认指向 Workspace，非空用户 profile 保留既有设置。新增绑定不得重启运行中的 Host。私网隔离统一由宿主固定规则执行，不提供模板 network 字段。pids_limit=4096 由 OpenSandbox 服务配置，不由模板覆盖。Docker 命名卷的 `storage` 字段不代表实际容量限制；当前备份 bundle 不包含 Sandbox named volumes，不能据此声称 Workspace 卷已备份。条件允许时，应将 Docker 数据和 PostgreSQL 数据放在不同数据分区。Metrics 只监听 loopback。Portal 执行 `portal migrate up` 后启动；空库首次启动时自动初始化 `admin/admin` 超级管理员，首次改密前只能通过本机回环地址或受信任的 SSH 本地隧道登录。普通用户统一从 Web 注册并等待审核，不提供管理员凭据文件同步或 CLI 直接建号入口。单机部署流程以 deploy/single/README.md 为准。

`cloud_dsh.enabled` 默认关闭。启用时，`cloud_dsh.max_concurrent_tasks` 必须为 1–64，`cloud_dsh.max_concurrent_tasks_per_owner` 必须为 1 到 min(全局上限, 16)；16 与账号 Runtime IPC 的硬上限一致；样例为全局 4、每账号 2。数据库认领事务跨 Portal 实例实施每账号 Task 数配额，达到上限的任务留在队列。该配置是 Task 并发数量限制，不代表账号常驻 Runtime 的 CPU/内存隔离或账号 Runtime 生命周期已经交付。

配置中的 Docker 数据根目录必须匹配 Engine `/info`，Host 创建前检查其文件系统剩余字节；默认保留 10 GiB，低于阈值拒绝新建。Workspace 配置为 `workspace_storage.root_dir`、`max_workspace_bytes`、`max_owner_bytes`、`min_free_bytes` 与 `workspace_sync_node.data_root`；这些值必须在启动时校验。用户已选定共享硬上限：所有 Workspace 块、当前文件、同步节点和 relay 状态共用一个固定容量、非 thin-provisioned 的专用文件系统；`data_root` 是该挂载点，`workspace_storage.root_dir` 与 `workspace_sync_node.workspace_root`（启用同步时还包括 `state_root`、`relay_state_root`）必须是其下彼此不同的直接子目录。该卷必须与 `/`、Docker、PostgreSQL、Site、Workbench 和 Portal 静态资源分离；安装器及 Portal 启动检查 mount、路径、设备号和 systemd 绑定关系。若使用不同挂载或嵌套目录、符号链接、路径复用，启动失败关闭。
`max_workspace_bytes` 限制单个 Workspace revision 的文件逻辑字节；`max_owner_bytes` 是该用户所有 Workspace 不可变块的账号级块账本额度，以块文件系统已分配字节（Linux 为 `st_blocks × 512`）核算，并把未落盘的新块预留纳入并发核算。它不代表整块数据卷的物理上限；目录、当前文件副本、staging、节点索引和 relay 状态均由共享文件系统的硬容量限制。`min_free_bytes` 既用于新建 Workspace 前检查，也用于 upsert 接收前检查：容量服务按当前可用空间减去该阈值和本次文件大小，空间不足则拒绝新接收 reservation；删除仍可尝试释放空间。这个检查不是持久的全卷容量 reservation，并发请求可能竞争余量；最终物理边界由文件系统负责。遇到 ENOSPC 时不得提交 revision；恢复基线失败或结果未知时保留未决 reservation 并阻止相关同步继续，不能把写入报告为成功。容量与额度分别核算，不得混用逻辑文件长度和已分配块字节。
单机只支持本地文件系统 adapter；固定数据块为 4 MiB，单端最多 4 个数据块并行传输，缓冲上限 16 MiB，不把整个文件或 Workspace 一次载入内存。物理块账本必须能够从实际文件目录对账，账本未核验时拒绝新写入；所有仍被历史 revision 或活动 / 未过期 session 引用的块都保留，不自动清理已提交旧版本或结果未确认的块。既有 Docker Workspace volume 是迁移源：迁移前冻结写入，按实际 volume 名称导入并比较文件数、字节数和 SHA-256；新目录与恢复校验通过前不得删除旧卷。容量默认值和性能目标以单机基准测量为准，不凭文档宣称达标。
`workspace_sync_node.enabled` 默认关闭。Portal 即使关闭同步节点，也将块库和当前文件根放在 `data_root` 下的共享硬容量卷；当前目录是由 PostgreSQL revision 和不可变块重建的投影，私有 `.morde-revisions` marker 用于发现缺失、revision 不一致或内容漂移。Portal 以 root 运行时会把发布树属主设为同步容器 UID/GID 65532。Revision 清单覆盖文件和空目录，目录新增 / 删除也会形成持久变更。启用同步时，固定 Syncthing 与 Morde relay 镜像的源码 revision、补丁摘要及 Go 版本；每账号节点只挂载自己的状态和 Workspace 当前文件目录，并通过只读配额 UDS 在改动当前目录前申请 reservation，文件读回核验与 revision 落账后才确认接收。节点启动前 nftables 必须已生效并默认拒绝，只允许已获授权账号普通 bridge 经 host-bind 私网 IPv4 连接 Morde 专用 relay TCP 22067；桌面客户端使用公告公网地址。Relay 不加入公共 relay pool、关闭状态接口，专用端口仅开放 TCP 22067。账号授权变更与 relay gate 共用授权围栏；Host 绑定、applied revision、heartbeat、解绑和任务完成均需复核账号、Host generation、Workspace revision 与 binding 状态。当前 `workspace-sync` capability 保持关闭，须完成专用卷、数据库迁移、Syncthing peer/session、撤权、Host 重启/离线和容量边界验收后才可启用。

Site 发布物使用独立必填配置 `site_storage.root_dir`、`max_release_bytes`、`max_owner_bytes`、`min_free_bytes`；启动时由 `sitefs` 打开仅 Portal 服务账号可访问的绝对非根目录，并拒绝与 Workspace 块存储、Docker 数据根、Workbench 或 Portal 静态目录重叠。当前完成单 release 字节上限、每 owner 总额度与 PostgreSQL 候选 reservation、文件系统空闲预留，以及固定 revision 物化文件数 / 字节记录与晋升门禁；`backup.py` 格式 v2 已备份、校验和原路径恢复 PostgreSQL、Workspace 与 Site 三个目录，但尚无真实 Linux 恢复演练；sitefs 通过共享发布锁 / 排他容量锁串行跨进程写入，并在启动时回收已中断的私有 staging；真实 Linux 部署演练仍待完成，发布 API 未开放。

## 7. 数据库合同

数据库保留 users、workspaces、hosts、tokens、audit_logs，并新增 conversations、account_main_conversations、conversation_messages、tasks、task_steps、task_operations、task_agent_instances、task_agent_sessions、account_agent_runtimes、task_batch_items、task_artifacts、task_events、idempotency_keys、迁移回滚用的 `retired_instant_chat_conversations` / `retired_instant_chat_exchanges`，以及 `devices`、`host_members`、`workspace_bindings`、`workspace_revisions`、`workspace_files`、`workspace_revision_empty_directories`、`sync_sessions`、`sync_blocks`、`workspace_changes`、`workspace_current_materializations`、`workspace_sync_commit_receipts`、`workspace_sync_device_identities`、`workspace_sync_device_bindings`、`workspace_sync_device_challenges`、`workspace_sync_device_registration_requests`、`workspace_sync_folders`、`workspace_sync_node_revisions`、`workspace_sync_receive_reservations`、`workspace_sync_receive_blocks`、`workspace_sync_receive_quota_rejections`、`host_runtime_heartbeats`、`task_workspace_view_deletions`、`orphan_host_volume_cleanups`、`sites`、`site_releases`、`host_site_drains`、`mcp_connectors`、`task_mcp_connector_grants`、`task_mcp_connector_operations`。没有单独的内存任务队列；执行租约放在 tasks 行，事件游标由每任务 seq 表示。正文和数据块只写专用文件存储，PostgreSQL 只存元数据、哈希、版本、会话及确认回执。

Host 用量由 `host_usage_samples` 和 `host_usage_intervals` 按 Host/runtime generation 持久记录；项目读接口只返回 project-attributed 聚合，且在同一事务内复验当前项目成员。原始采样与容器身份不通过 Portal 回执公开。该账本当前无保留/汇总策略，费率与扣费规则未定义。

- users：用户身份、密码哈希、`user|admin|super_admin` 角色、`pending|rejected|approved|disabled` 单一账号状态、超级管理员首次改密标记、每用户 Host/CPU/内存配额和时间戳。旧用户迁移保留数据，原禁用状态保持禁用，其余普通账号置为待审核并撤销旧会话；用户名 `admin` 且原为管理员时迁为超级管理员并保留密码。冲突不得暗中提权。
- workspaces：owner、name、状态、最新 revision、实际字节数、配额 / 计量信息、创建和更新时间；不含 Host 外键或卷名。独立持久化且无 Host 时也可上传、下载、备份和恢复。
- workspace_bindings：`id`、owner、host、workspace、Host 目录名、state、`binding_version`、期望 / 已应用 revision、时间戳；按 Host/workspace 有效约束，同一 workspace 至多一个活动可写绑定。Host 的目录名由服务端从 binding identity 生成，不接受任意路径输入。
- hosts：owner、template_id、state、state_reason、加密的 aio_key、可空的加密 `runtime_credential`、可空的 sandbox_id、runtime_generation、可空的 `runtime_instance_id`、control_version、control_state、created_by_token_id、create_attempted_at、expires_at、last_active_at 和时间戳。`runtime_credential` 是逐 Host 的 256-bit 运行端凭证，不复用 AIO/API Key；新 runtime_generation 轮换凭证，删除 Host 时清除。`runtime_instance_id` 在运行端重启后重新握手并持久更新。state CHECK 仅允许第 4 节规定的状态；Host/Workspace 绑定只从 `workspace_bindings` 查询。
- host_usage_samples / host_usage_intervals：记录 Host runtime generation、Sandbox/container 样本、CPU counter、memory snapshot、unknown 原因及采样时的 Workspace binding/project attribution；区间保存 CPU 秒与估算内存 MiB 秒，价格与 actor 当前保持 unknown。项目读取按 `(project_id, host_id)` 过滤并在同一事务持有当前成员行共享锁；project viewer 只获得汇总，不获得原始样本、容器 ID 或 Workspace attribution。`00122` 为项目读取增加部分索引。未决定保留期/roll-up 前不可将 4 秒持续采样当作已具备长期运行容量。
- sites / site_releases：Site 绑定 owner、Host、Workspace 与 active / draining / stopped 状态，保存当前 / 回滚 Release 指针；Release 固定 Workspace revision、规范 manifest SHA-256、服务端口及 candidate / healthy / failed / cancelled 状态，并保存物化文件数、字节数、完成时间与 owner 配额 reservation。候选创建时按 revision 字节数在 owner advisory lock 内原子预留额度；失败 / 取消会释放未物化候选的 reservation。候选创建时重算并核验 revision 清单摘要、文件数与字节数；物化完成值必须与固定 revision 元数据一致，未物化或缺少 `health_checked_at` 的候选不能晋升为 healthy，数据库 CHECK 同步拒绝该状态。健康检查时间仅由完成有界探针后的受信任内部调用方记录；生产探针尚未接入。不匹配或损坏的清单拒绝。外部服务端口只允许 `1024–65535`，并拒绝 AIO、VNC、Runtime / sandbox 控制等 Host 保留端口；应用层复用 `ValidPreviewTargetPort`，数据库约束同步拒绝 `8080, 5900, 6080, 8090, 8091, 8100, 9222`。Host release / delete 使用 `host_site_drains` 持久屏障，与状态转换事务化；仅运行资源清理完成后才停止 Site、取消候选并解除屏障。当前仅有持久化与生命周期门槛，没有网站构建、运行或 Gateway 发布路由。
- orphan_host_volume_cleanups：`instance_id`、`host_id`、`runtime_profile`、`sandbox_id`、`runtime_generation` 组成无 Host 外键的清理身份，另有创建与完成时间。孤儿 Sandbox 删除前先持久记录；Host 已删除 / 不存在、无活动 Sandbox 后才重试删除 Runtime、profile 及仍存在的旧 apps 卷，成功后保留完成墓碑。待清理期间禁止复用 Host ID；此孤儿路径不删除 Workspace named volume。
- devices：owner、配对设备公钥指纹、名称 / 平台、撤销时间和最近访问；只保存设备凭证摘要，密钥由 PC App 的系统安全存储保护。

- task_batch_items：原始输入快照、唯一 item_key、状态、结果和失败原因；重试只对已确认可重试的单项进行。task_artifacts：经过运行端核验的任务 Workspace 相对路径、媒体类型、来源 step 和时间戳；所属 Host 与 Workspace 由 task_id 关联，不复制文件内容到元数据表。Task 完成时检查全部已持久化产物均有当前 Workspace revision 的相同摘要证明，最终完成事件可复用此前分步写入的产物记录。
- task_events：task_id 与单调递增 seq 为主键，事件与对应状态变化同一事务提交。idempotency_keys：owner、operation、key、规范请求摘要及关联资源；(owner, operation, key) 唯一，相同摘要返回原资源，不同摘要为冲突。

Host 创建事务可同时建立唯一 workspace_binding；Host 私有运行数据与 Workspace named volume 分开。显式释放成功后进入 stopped 并保留 Workspace volume；恢复推进新代次并重新核验期望 revision。删除 Host 只解绑并回收 Host 专属运行数据，不能删除 Workspace volume 或正文；正常删除保留 deleting 状态直至专属资源清理成功。若 Host 记录已不存在，孤儿 Sandbox 路径先记录持久清理身份，再在 Host / 活动 Sandbox 核验通过后回收 Runtime、profile 及仍存在的旧 apps 卷，失败记录由后续 reconcile 重试；待清理期间禁止复用 Host ID，该路径不删除 Workspace volume。Runtime 持久操作账本保存在服务端 PostgreSQL，按 Host、generation 与 namespace 校验哈希链及幂等重放；账本不可达、链分叉或副作用结果未知时 Runtime 必须失败关闭。删除 Workspace 是独立、显式操作且要求无活动绑定 / 传输 / 恢复引用。一次性迁移只导入现有 Host/workspace 指针一致且状态允许的数据；不一致记录使迁移预检失败并列出原因，不静默择一覆盖。旧 Docker 卷保留到导入、校验和恢复实测完成。自动空闲释放暂禁用，后续启用前须补齐跨实例任务、人工控制和预览活动租约。

主动释放 Host 在同一 Host 行锁事务中检查未结算的 Task 电脑操作、当前代次 Host replica 尚未提交的 Workspace 上传会话、绑定同步冲突，以及每个 binding 的 `applied_revision == desired_revision == workspace.revision`；空目录新增/删除也算未完成上传。发现任一项则返回 409，以固定 `reason`（`host_release_unsettled_operation`、`host_release_uncommitted_sync`、`host_release_sync_conflict`、`host_release_workspace_checkpoint_pending`）和经过校验的 `task_id` / `workspace_id` 标明范围，不推进 `stopping`。Host 上传会话的创建与提交也锁定 Host 行，避免释放检查后再写入。该新屏障的源码与集成用例已补充但未运行；它只覆盖已登记的变更，Host 本地尚未扫描的文件仍需运行端报告和原生生命周期验收。

共享 Host 成员由 `host_members` 持久化；邀请、列举、撤权仅允许 Host Owner 的 Portal Session。普通 Host/Gateway API、预览和 Host 管理仍拒绝成员直接访问。`desktop:view` 只允许读取 VNC 并连接只读桌面流，RFB 过滤器丢弃输入消息且不申请桌面输入许可；成员的 `desktop:control` 只准许显式绑定此 Host、由该成员发起且 Agent 固定了当前授权快照的 Task 执行桌面输入，不扩大普通 Gateway 权限。任务领取在 Host 行锁下核验 Host owner 与 Task actor 的当前授权；Agent start/renew、操作创建 / 准备重试 / 派发还核验 Agent 固定的 Host runtime 和 grant fence。撤权或撤权后重授都会阻断旧 Task Agent 的后续操作。只有显式 `workspace:file:read` 才可进入 Workspace-only Workbench、读取有效 Host binding 的已应用文件，并下载经块和整文件摘要校验的内容。Workspace 授权不推导桌面、终端或 MCP 权限；终端 / MCP 按各自独立权限控制，且 MCP 客户端另需自有有效 API Key。桌面观察流每 5 秒重新查成员授权；Workspace API 每个请求及下载流每块重新核验，撤权或授权查询失败后阻断后续内容。桌面共享会暴露 Host 当前画面可见内容。Morde Agent 模型仍归 Host Owner 的连接和额度；第三方 MCP 客户端自行承担模型费用。审计记录邀请、撤权及共享桌面进入的实际操作者。

## 8. 错误码

domain 定义稳定错误码；HTTP 状态映射由 httpserver 负责。details 为空时序列化为 {}。响应不返回内部错误文本。

| Code | HTTP | Meaning |
|---|---:|---|
| invalid_argument | 400 | 参数无效；details.field 标明字段 |
| unauthenticated | 401 | 登录态或 API Key 无效、过期或已撤销 |
| forbidden | 403 | 已登录用户缺少管理员权限 |
| account_pending / account_rejected / account_disabled | 403 | 用户密码正确但账号处于待审核、已拒绝或已禁用；响应只在密码验证成功后返回 |
| not_found | 404 | 资源不存在或用户无权访问 |
| quota_exceeded / capacity_exceeded | 409 | 达到用户或单机资源限制 |
| workspace_busy | 409 | Workspace 被绑定、传输或恢复材料引用，无法删除或变更绑定 |
| workspace_conflict | 409 | Workspace revision 或目标文件基线已变化；返回可定位冲突，不覆盖任一方 |
| workspace_unavailable | 503 | Workspace 元数据或文件块暂不可用；不发送未完成或未校验的文件内容 |
| transfer_expired | 409 | 断点续传会话已过期；需重新比较并创建新传输，不重用旧块确认 |
| invalid_state | 409 | 当前状态不允许此操作 |
| idempotency_conflict | 409 | 相同 owner/operation/key 被用于不同请求内容 |
| event_cursor_expired | 409 | 事件保留范围已越过游标；客户端需重取任务快照 |
| unsupported | 422 | 请求的运行端 capability 未声明；不得降级到其他工具路径 |
| result_too_large | 413 | 运行端读取结果超过单次返回上限；不截断为成功 |
| host_not_ready | 503 | Host 正在创建或尚未就绪；可带 Retry-After |
| request_too_large | 413 | 请求体或代理数据超过配置上限 |
| rate_limited | 429 | 触发限流；带 Retry-After |
| internal / upstream_error / upstream_timeout | 500 / 502 / 504 | 返回安全的通用说明，内部原因只写日志 |

paused 是任务状态，不是 Host 状态；Host 不使用 host_token。能力 scope 不匹配返回 forbidden；Host/Task 不存在或当前用户无权访问时统一返回 not_found。

## 9. App 与适配器合同

HostService 是唯一的电脑生命周期 API，提供 Create、List、Get、Delete、Renew、IssueTicket、Stop、Start；Stop 只释放运行时，Start 保持同一 Host ID 并恢复 Host 级工作副本及全部有效绑定。控制权切换由同一 HostService/ControlService 合同负责；不提供 Host Bearer Token 或公开预览。

HostRuntime 提供 Lookup、Resolve、InvalidateUpstream、MarkActive 和 Start；运行代次随每次新运行分配递增。Verifier 提供 VerifySession、VerifyAPIKey、VerifyDevice、VerifyClient、ConsumeTicket；Principal 中的 API Key scopes/Host allow-list 与 Host Cookie 的 HostScope 分开存放。Gateway、REST 与 MCP 通过同一 app 授权服务校验所有权、scope、控制版本和运行代次。

Create/Start 立即返回 creating；worker 按 Host 串行推进，获得 sandbox_id 后立即持久化。Host 状态转换使用 compare-and-swap。Reconciler 负责续期、显式释放中的 Sandbox 清理、修复可确认的状态并安全重试清理；不会因本地时间戳单独自动释放。运行端 Create 结果不确定时绝不重发，Workspace 归属不确定时绝不删卷。

TaskService 是 Portal、MCP 与后台执行器共用的任务用例入口。TaskStore 提供原子提交（必要时创建 Conversation，并写会话消息、Task、首事件和幂等记录）、ClaimNext、RenewLease、CommitProgress、RecordOperation、AppendEvent 与按游标读取；Task 和事件状态变化必须同事务。省略 conversation_id 时，创建会话与提交 Task 同成同败。Conversation 保存历史，同一会话可并行活动 Task：消息先持久接收，模型结合活动任务和对话上下文判断修改、新任务、查询、停止或澄清；程序校验任务发起人、授权、状态和修订，不根据活动任务数量推断目标。缺失或损坏的固定历史快照使任务进入带可见原因的安全停止流程，不得阻塞其他任务或猜测历史。Agent 执行位置统一为服务端。旧 `/api/instant-chat/*` 路由已退役，请求返回 404；历史旧请求键仅作为迁移保留数据，不通过旧路由回放。MCP Connector grants 通过独立 `TaskMCPConnectorGrantStore` 端口读取、CAS 固定工具 schema 和 CAS 撤权，不扩张 TaskStore；Task 创建与初始 grants 在 PostgreSQL 同一事务提交。接口为 `ListTaskMCPConnectorGrants(ctx, ownerID, taskID) ([]TaskMCPConnectorGrant, error)`、`SetTaskMCPConnectorToolSchema(ctx, ownerID, taskID, connectorID string, expectedGrantVersion int64, schema, sha256 []byte) (TaskMCPConnectorGrant, error)`、`RevokeTaskMCPConnectorGrant(ctx, ownerID, taskID, connectorID string, expectedGrantVersion int64) (TaskMCPConnectorGrant, error)`。租约使用 lease_version fencing 旧执行器写库；外部动作另以 operation_key 去重并保存运行端版本。批次项状态通过 `task.batch_item` 事件更新；运行端核验过的产物元数据通过 `task.artifact` 事件通知 Portal。文件内容保留在 Host/Workspace，不复制进数据库。数据库 fencing 不能撤回已经发出的操作，因此 unknown 结果先对账，不宣称 exactly-once。

Hostless Task 沙箱调用使用独立 `TaskSandboxCallStore` 和 `task_sandbox_call_receipts`（迁移 00166），不复用要求 Host Runtime fence 的 `task.Operation`。当前合同只接受个人账号拥有的 Workspace：回执固定 Task/Owner/Initiator、Context digest、授权版本、输入与 checkpoint revision、Task lease、DSH call ID 和请求摘要；同一 Task 一次最多有一个 prepared/dispatched/unknown 调用。prepared 可在副作用前由新租约接管；派发事务先绑定 sandbox ID/generation，重复派发被拒；成功/失败结果仅保存最多 64 KiB 的 UTF-8 输出及摘要。派发结果不确定则保存稳定错误码为 unknown，禁止重放并阻塞该 Task 后续沙箱调用。Workspace、当前 Task 授权、账号执行开关与 lease 每次准入都重新核验。该账本只提供持久化和围栏，不等于沙箱 supervisor、Guardian、OpenSandbox Execd 控制通道、拒绝外连网络策略、Task 文件隔离或 DSH Shell 已接通；上述隔离验收前仍不得开放 Shell。项目 Workspace 暂不接受 Task Sandbox 调用。

每个事件序号在 task 行锁定的短事务内递增，并与状态变更一起提交；全局 sequence 不可用于断线游标。执行器认领使用数据库事务和行锁，外部网络调用不放在事务内。暂停、取消和接管都是请求状态，直到执行器/运行层确认停止才进入最终状态。

AIO 使用 X-AIO-API-Key。JSON 调用要求 success=true 并解析 data；流和二进制响应保持有界转发。只有 Gateway 在服务端注入解密后的 AIO Key；平台 MCP 不再调用 AIO API。所有适配器复用现有 typed app 接口和 typed OpenAPI client，不另建客户端体系。

Gateway 终端会话是 Host/用户级单一登记：`PUT /__ch/api/terminal-session` 在所有者 Cookie、同源请求、运行中 Host、用户控制状态与活动租约下幂等创建或返回现有 AIO 签发的 session ID；只接受 AIO 返回的 `/terminal?session_id=...`，严格校验后持久化。`creating` 在 60 秒内只能等待，过期转 `unknown`；请求结果不明时不自动重试。Host 运行代次变化返回 `interrupted`。若 Gateway 收到精确 `/v1/shell/ws` WebSocket 请求对当前登记 session ID 的 404，则以 Host 代次、控制版本和 ID 做 CAS 标记 `interrupted`；普通 HTTP、网络错误及 5xx 不推断会话丢失。AIO 没有主动查询 PTY 清单的接口，故该判断发生在下一次终端连接尝试时。只有用户显式确认 `POST` 且 `confirm_new=true` 才可替换已知/未知旧登记；新建不会终止旧 PTY 中的命令。session ID 不写日志。终端 iframe 只建立一条活动 WebSocket，切换工作台标签会断开前端连接，再用原 ID 顺序恢复；同一 ID 并发连接会被 AIO 拒绝。真实 AIO 重启行为仍待 Host 验收。

#### 9.1 运行端协议与控制围栏

T12 的 `morde-runtime` 是唯一受管操作执行与停止服务；它不是现有 AIO API。完整冻结协议见[独立项目方案 4.4.1](../开源依赖二开与独立项目方案.md)。协议为 `/runtime/v1`，每个请求携带 `X-Morde-Runtime-Protocol: major.minor`，JSON 请求/响应也带 `protocol_version`；主版本不匹配即关闭执行。首版能力为 `operation.execute/query/cancel`、`control.fence/quiesce`、`task_lease.fence`、`desktop.observe/input`、`window.list/activate`、`browser.observe/actions`、`shell.exec`、`file.read/write/list/find`。Morde 按独立方案中的逐工具能力表开放工具；浏览器操作只允许 task 自有隔离 context/tab 和受限可访问性定位，不复用默认 profile 或接管用户标签；能力未声明即返回 `unsupported`，不回退 AIO 直连。

运行请求绑定 `host_id`、`runtime_generation`、`control_version` 和运行端进程 `runtime_instance_id`；仅 capabilities 首次握手可不带 instance ID。进程重启生成新 instance ID，Morde 重新核对后再发控制或操作请求。每 Host 使用独立随机 256-bit runtime credential；经受信 Sandbox 通道注入 root-only 文件，Morde 以 `Authorization: Bearer` 在私网 TLS 上发送，不复用 AIO/API Key。运行协议 request/response body 上限为 1/8 MiB，单请求超时 60 秒；错误体只含协议版本与稳定代码。任务操作另带 `task_id`、Host-wide 唯一且不复用的 `operation_id`、`lease_version`、capability/action/arguments；操作查询同样绑定原任务和租约。generation、instance、control 或 lease 围栏过期时，在副作用前拒绝。

运行端启动默认 blocked；运行态存储未就绪时不得执行新操作、放行 AI/human 或把查询失败当成 operation_not_found。Morde 可请求进入 blocked，也可尝试 quiesce/cancel，但没有停止证据时只能返回 draining/unknown；登记库不可用时不得确认 cancelled/drained 或签发 human receipt。操作先持久登记，再进入 running 后才产生副作用。登记库跨进程重启和 Sandbox generation 持续存在；崩溃后只有能证明未启动的 accepted 操作可用相同 ID 继续，running 只核验原受管进程及持久结果，无法证明结果时转 unknown 且不重放；cancelling 恢复后只继续停止并核验。operation_not_found 仅由 Host-wide 完整健康登记库证明从未接受时返回。file.read 内容必须经授权响应返回，仅 UTF-8 文本单次最多 64 KiB；为原 ID 查询而临时持久的正文只保存在 root-only operation store，绝不写普通日志/指标。

同一 app `RuntimeControl` 提供 `Capabilities`、`SetControl`、`SetTaskLease`、`Execute`、`GetOperation`、`CancelOperation`、`Quiesce`。请求/结果显式携带 Host fences 和 operation/task 标识；`Agent.ToolExecutor` 与 MCP 电脑工具共用该端口，用户授权和 API Key scope 仍只由 Morde 校验。MCP 持久上下文按 API Key ID、协议 session 和 Host 隔离，MCP operation 保存请求摘要、runtime task/operation ID、Host fence、租约和结果；接管快照包含活动 MCP runtime task ID，Owner stop-all 通过同一 RuntimeControl 取消并保持 stopping 直到终态证据到达。租约 `lease_version` 标识一次任务认领，相同版本相同过期时间是幂等重放；续租同一认领只可单调延长，过期后不能续租。接管先设 blocked，再携完整活跃 `task_ids` 与目标 `control_version` 调用 quiesce；receipt 绑定唯一目标 human control_version，由运行端原子验证、消费并保证操作队列/受管进程已排空后开放 human。Morde Host `user` 对应 runtime `human`。`cancelled/drained` 必须核实队列和全部派生进程已停止，否则保持 draining/unknown。`internal/runtimeclient` 是唯一协议适配器；T12.05/T13.05 已将 MCP 直接电脑读写迁入它，不保留直连 AIO 写路径。运行端已为桌面截图、窗口列表/激活和按目标窗口校验的点击/文本/按键注册受管 handlers；截图原图仅保存在 root-only runtime operation journal，Morde operation 结果只留引用。真实 Host framebuffer、X display 和 Codex Desktop 联调仍待验收。AIO typed client 仅可用于 Gateway 转发及非 AI 管理/探测调用。

**桌面截图尺寸与点击证明（T07，新合同）：** Host Runtime 截图结果的 `width`、`height` 是缩放后图像尺寸，`screen_width`、`screen_height` 是实际显示器尺寸。点击使用截图像素点，并携带 Host 签发的 `screenshot_token`；模型不能提供截图或显示器尺寸。Host 按 Task 保存最新 token 的哈希、截图尺寸及显示器尺寸，token 90 秒有效，并绑定 Task、完整 Host fence 与 lease version，只能消费一次；重拍会使该 Task 的旧 token 失效，任何 Task 的桌面输入或窗口激活都会清除该 Host 上全部待用截图 token，重启也不会恢复 token。点击时 Host 根据绑定尺寸映射实际坐标，并复核显示器几何、目标窗口位置及焦点；图像/尺寸无效、token 不匹配、过期、重放或几何变化均拒绝输入。审批只展示截图点位和窗口，不展示未经验证的屏幕坐标。Portal 与 Host Runtime 必须配套升级；原图仍仅保存在 root-only Runtime operation journal，服务端工具输出仅传受限图片和一次性 token，不把图片内容写入步骤日志。尺寸及窗口检查之后到输入派发之间仍有短暂非原子窗口；真实 Host 用户流程待 T07/T15 验收。

**个人记忆开关（T09，新合同）：** 使用个人对象 `skill_setting/builtin_memory`，正文为 `{"enabled":true|false}`；缺省或已删除视为开启，仅显式 `false` 才关闭。开启后仅该账号的个人会话可读取、更新个人记忆，项目会话不读取；个人资料及 SOUL 不受此开关影响。历史按需检索且有严格条数/文本长度上限，不会注入完整会话记录。个人 DSH 初始提示包含 `MORDE_MEMORY_STATE_V1:` 与 base64url 编码的 `{enabled, revision, items:[{id, revision}]}` 标记，仅保存授权开关及实际注入的记忆 ID/版本，不含记忆正文。恢复检查点和发起模型调用前复核当前授权及版本，失效时停止并提示重新发送；含子 Agent 的个人任务检查点暂不恢复。跨会话历史检索及删除后不可召回仍需完成验证。

T21.12 的原生应用生命周期只覆盖由 Morde 固定应用清单启动并登记的实例；登记需绑定 Host、generation、Runtime instance、app ID、launch ID 和专属 cgroup。Runtime 重启后先用持久记录与 cgroup 身份核对进程，未知或不匹配时不得报告已停止；排空先关闭新启动，再逐实例停止并核验 cgroup 为空。该登记不包含 AIO Supervisor 服务、AIO PTY 或绕过 Morde 启动器的 GUI 程序：PTY 沿用 AIO `session_id`，其它 GUI 进程不能按进程名或可复用 PID 猜测并强杀。Host 释放是经用户确认后的整个 Sandbox 销毁，不等同于逐应用优雅退出；只有 Sandbox 删除完成后才能确认其进程整体终止，不能把它描述为已完成应用级 drain。

T21.11 应用安装只允许 Owner 从 Morde 固定应用清单选择；清单固定 app ID、版本、Host 架构、官方 URL 与 SHA-256。Runtime 在下载暂存区核验哈希后安装，并把已核验的原始包与安装状态保存到 Host 专属持久应用卷，以便 Sandbox 重建后恢复。安装 / 更新 / 卸载是独立的可查询操作，不开放任意 URL 或 root 命令；共享成员的桌面 / 终端 / MCP 权限不包含应用安装权限。

#### 9.2 定时任务与站内通知

ScheduleService 将计划管理和触发接入 TaskService，不另建执行循环。触发在同一数据库事务内锁定 Schedule、Owner gate 与 Host/授权 fence，幂等创建普通持久 Task 和 ScheduleRun，并推进 `next_run_at`；`(schedule_id, occurrence_key)` 唯一。同一计划同一时点至多一个运行，且同一计划不并发。运行快照固定 `schedule_version`、Host、model、目标和预算；编辑仅影响尚未触发的未来运行。计划状态为 `enabled`、`disabled` 或一次性计划执行后的 `completed`。

所有计划要求 IANA tz database `time_zone`。一次性 `run_at` 是带 UTC offset 的 RFC3339 instant，时区只用于展示；`daily`/`weekly` 按 `local_time`（本地 `HH:mm`）触发，weekly 另要求 ISO weekday 1–7，`starts_on` 为本地日历日期。`every_n_hours` 要求 `interval_hours` 为 1–168 的整数；未提供 `anchor_at` 时首次触发在创建或启用后 1 分钟，此后每隔 N 个实际经过小时触发。可选 `anchor_at` 是带显式 UTC offset、最多 6 位小数秒的 RFC3339 instant，用作间隔相位原点；周期槽为 `anchor_at + k * interval_hours`（整数 `k >= 0`）。创建或重新启用时选取严格晚于当前时刻的最早槽；未来锚点本身可作为首次运行，已过槽跳过。间隔不受夏令时变化影响。Daily/weekly 的 DST 不存在墙钟时刻跳过并记 `skipped/dst_gap`，不平移；重复墙钟时刻只选较早 instant（第一次）。`next_run_at` 以 UTC RFC3339 返回并按计划时区展示。时区编辑不重新解释已记录的 occurrence。

Schedule 有独立展示字段 `title` 和执行字段 `objective`。创建时 `title` 可省略，省略后取 `objective` 去除首尾空白后的值；服务端会去除两字段首尾空白后校验为 1–32768 UTF-8 字节并保存。执行始终使用独立的 `objective` 字段，不拼接标题。读取和 Personal Snapshot 均返回 `title`；更新可单独修改标题，省略时保留现值。迁移 `00129` 为既有计划回填 `title = objective`；若存在自定义标题，迁移回滚会拒绝丢弃数据。

`misfire_policy` 仅允许 `skip` 或 `run_once`，默认 `skip`。为吸收正常轮询和短暂调度延迟，逾期不超过 1 分钟的 occurrence 仍按时触发；超过 1 分钟才算错过。`skip` 不补任务，将错过时点记为 `missed` 并推进到下一个未来时点；`run_once` 将所有错过时点合并到最新一个，最多补跑一个任务，绝不逐条追赶。计划永不重叠：上一运行非终态（包括 `waiting_user`、`paused`、`pausing`、`cancelling`）时，新到时点记 `skipped/overlap`，不排队。等待用户处理只可显式恢复原 Task，计划不会重复提交调用。停用只阻止新触发，当前运行默认继续；只有明确请求 `current_run_action=cancel` 才发起 Task 取消，未取得安全停止确认前保持 stopping/cancelling。

计划创建和启用要求 Owner gate 为 `enabled`，写操作带 `Idempotency-Key`；编辑必须带 `expected_version`，版本不匹配返回 409。例程执行使用服务端保存的独立、可撤销授权，不把登录 token 长期用作例程凭证；原生客户端的 schedule grant 绑定单个安装，可单独续期或撤销。撤销某安装的 grant 不影响其他安装授权的计划，也不取消已被调度器接纳的 Task；授权失效或账号停用时跳过后续触发。Owner `stop-all` 先推进 epoch、取消未开始任务并停用所有计划，再停止/核验在途操作；只有确认全部安全停止才成为 `disabled`。之后启用 Owner gate 不复活任务或计划，用户须另行启用计划。缺少 gate、读取失败、epoch 或 fence 不符均拒绝触发。每次任务执行都按 TaskService 规则重新核验用户、模型、API Key、Host scope、授权和预算；撤销或过期授权后不允许新动作。

通知仅为 Portal 站内 inbox，不发邮件、推送或 MCP 通知。可订阅 `completed`、`failed`、`waiting_user`；成功且无变化的检查安静完成，不建完成通知。同一持久 TaskEvent 最多建一条通知，以 `(owner_id, task_id, event_sequence)` 去重。Goal 与项目工作项使用持久 source outbox，按来源、版本、事件种类和收件人去重，只保存固定摘要与不透明来源引用，不复制私人正文；项目通知在消费时复验成员关系，读取与标记已读也按当前项目成员资格过滤。读取和展示关联内容时重验当前权限；授权失效后隐藏任务摘要和敏感内容。标记已读不批准、不执行动作；登录、审批或澄清入口仍须对当前请求 ID/version 做有效性校验，过期时只显示已处理。

## 10. 外部接口合同

### 10.1 Portal API

JSON 使用 UTF-8，时间使用 UTC RFC3339。列表统一返回 items 数组，不返回 null。Cookie 鉴权的写请求必须带同源 Origin 和 JSON Content-Type。会话 Cookie 名为 ch_portal；平台 MCP 使用 Authorization: Bearer chk_… 。Portal Session 依照用户角色/所有权授权；Bearer API Key 依据账号当前权限与资源授权访问，不继承用户管理员角色。创建 Host、提交 Task 和写 Conversation 消息必须带 Idempotency-Key；同一 owner、同一 operation 和相同规范请求返回原结果，不同请求体返回 idempotency_conflict。

Host 用量回执只给 Host 所有者、管理员或当前拥有 `host:read` 的 API Key；项目用量回执只给当前项目 viewer，读取时在存储事务内再次校验成员关系，并且只按项目归因返回 CPU/估算内存汇总。两个接口都不公开原始快照、容器 ID 或 Workspace 归属，且返回 `price_status=unknown`；没有费率和预算规则时不估价、不扣款。

固定超级管理员 `admin` 在空库首次初始化时建立，初始密码为 `admin` 并强制首次修改；后续启动不覆写密码。默认密码只允许 loopback 登录并得到限权改密会话。注册只需用户名和密码，账号先进入待审核且不签发会话或 Client 凭证；只有已通过的账号可登录。普通管理员可审核账号、禁用/恢复账号及调整其他已通过用户的管理员角色，但不能操作 `admin` 或自身角色/状态。账号列表、状态筛选和状态/角色更新仅通过 Portal API；状态更新携带 `expected_status`，过期或非法状态转换返回 409。密码变更只允许用户自行验证当前密码后修改。

管理员设置 `GET /api/admin/settings` 返回 `automatic_new_user_model_budget=true` 和 `default_model_budget: {configured, token_limit, max_concurrent, version}`；未配置时为 `false/0/0/0`。管理员 Portal Session 可用 `PUT /api/admin/settings/model-budget-default` 设定正数 token 限额及 1–100 并发数，携带 `expected_version`（初次配置为 0），成功后版本递增；版本过期返回 409 `conflict`。首次将新账号从 pending 或 rejected 批准为 approved 时，服务端在同一事务内写入状态、默认预算和审计。默认值缺失时照常批准但不发放平台额度，配置损坏时返回 409 `invalid_state` 并回滚审批；已有人工预算保留，重试、重复审批及 disabled 恢复均不重发、不重置预算或账本。邀请与贡献奖励不自动发放。

同一管理员设置 `GET /api/admin/settings` 另返回 `default_model: {configured, model_id, version}`；`PUT /api/admin/settings/model-default` 接收 `{expected_version, model_id}`，空字符串清除，成功后版本递增，过期返回 409。仅管理员 Portal Session 可写；未知连接返回 404，个人连接或未验证/text 能力不足返回 422；是否支持工具另行检查。只有当前已配置可用的默认模型会出现在 `GET /api/available-models` 的 `default_model_id`；该响应同时包含 `default_model_configured`，并按当前账号只枚举共享和个人模型。模型连接 CRUD/check 接受 Portal Session 或安装绑定 Client credential；普通 API Key 拒绝，Client 只可访问自己的个人连接，共享连接的写操作仍只接受管理员 Portal Session。

### 10.2 Host Gateway and private preview

- GET /__ch/auth?t=… 消费一次性 ticket，设置 host-only ch_host Cookie 并跳到 /__ch/wb/；无效 ticket 统一返回 404。共享成员可凭独立 `workspace:file:read` ticket 精确进入 `/__ch/wb/?tab=workspace`，该入口只提供只读 Workspace 页面。
- /__ch/wb/* 托管 Workbench；/__ch/api/host 和 /__ch/api/renew 提供当前 Host 信息与续期，/__ch/api/control 查询控制状态，/__ch/api/control/actions 通过唯一 app.ControlService 发起接管或交回。Host 信息仅对所有者 Workbench 可见；每个 Workspace binding 返回配额 `quota_bytes`、同步状态 `sync_state` 和始终为数组的 `sync_conflicts`（无冲突时为空数组），以供页面 fail-closed 展示状态。仅 Host 所有者或明确获授 `workspace:file:read` 的成员可调用 `GET /__ch/api/workspaces` 查看该 Host 的绑定状态、`GET /__ch/api/workspaces/{id}/manifest` 分页读取当前健康且已应用 revision 的文件清单，并经 `GET /__ch/api/workspaces/{id}/files/{relative_path}` 下载该 revision 中按块和整文件摘要校验的文件。共享成员的文件读取权限在每个请求及下载流的每块前动态复核；桌面查看权限不包含文件读取。该 API 不读取 Host AIO 实时目录，不接受 Portal cookie、Bearer 或同步设备凭据。控制响应只包含安全的转换摘要，不返回任务快照或运行端回执；写操作要求同 Host Cookie 与精确 Origin。
- `PUT /__ch/api/terminal-session` 按 Host/所有者幂等复用终端，`POST` 仅在 `confirm_new=true` 时显式新建；两者要求所有者 Cookie、同源、运行中 Host、用户控制状态与 Host 活动租约，不返回 AIO 原始 URL，只返回 Gateway 同源 `/terminal` 地址。
- 未认证预览请求重定向到 Portal 的 `/api/hosts/{id}/preview-auth?port=…&next=…`；Portal Session 只为 Host 所有者签发绑定 Host、目标预览端口的短期 ticket 并重定向到对应私有预览域。预览域消费时同时核对 Host 与端口，设置仅限当前预览域的 host-only Cookie；普通 Host 进入 ticket 不得用于预览，预览 ticket 不得进入 Workbench 或其他端口。ticket 跳转响应设置 `Cache-Control: no-store` 与 `Referrer-Policy: no-referrer`。端口不可设为公开。
- Host/preview 请求认证后才可转发，且 Host 必须为 running 并通过控制/运行版本校验。creating/stopping/stopped 返回 host_not_ready；failed/deleting/deleted 返回统一 404。代理移除 ch_host、Authorization 和客户端提供的 AIO Key，再注入服务端密钥。AIO 主接口固定使用 8080，预览只代理允许的非 8080 端口。
- WebSocket Origin 必须精确匹配当前 Host 或预览域。保持流式代理和请求体上限；日志不记 query string 和凭证。

### 10.3 Platform MCP

MCP 保留 Host 与受控运行端电脑工具，使用动态 API Key 权限；每次调用仍核验当前电脑所有权或共享授权及运行端控制条件。`task_*` 与 `schedule_*` 工具不注册、不分发；旧名称请求不可执行。历史任务的安全停止由服务端收尾流程负责。

上述 `/mcp` 是外部客户端调用 Morde 的入站服务。云端任务需要连接第三方 MCP 时，走独立 owner-scoped `mcp_connectors` 资源和 F01-T16 出站 broker；每个 Task 必须显式授予具体 connector 并固定 revision/tool schema。凭据只在 Go 服务端按 grant 解密并注入经过目标地址校验的 MCP HTTP 请求，绝不交给 dsh 子进程；每次调用先持久化 hostless operation，重新验证 Task lease/grant/connector 版本后才可派发。撤权阻止新派发，但不丢弃已派发调用的结果记录；Task stop 屏障等待本地出站请求结束，传输无法确认时记 unknown 且禁止重放。

## 16. 架构变更与网络合同

2026-11-06：根据用户最新要求，同一会话允许多个活动任务，消息接口必须显式选择 `new` 或 `append`；迁移仅移除活动任务唯一索引，不删除历史。此决定覆盖本节历史记录中的单活动任务约束；OpenAPI、服务端和调用方使用同一合同，不保留旧路由行为。

2026-11-07：用户要求按最新逻辑统一实现，消息接口和所有调用方改为先受理、再自动分流，移除显式 `new` / `append` 路径；历史数据保留。配置状态独立于模型健康、预算及工具能力，已验证的纯文字模型可用于普通对话。该决定覆盖上述发送模式。

自动分流待发送记录按服务实例、原发送账号和会话隔离。消息受理、客户端 ID 对账、文本分片及附件写入携带 `X-Morde-Actor-ID` 与 `X-Morde-Service-Instance-ID`；服务端逐请求核对认证账号，写入事务中锁定并核对服务实例。由待发送记录触发的会话创建使用同样围栏和稳定幂等键；一般手动创建会话不强制携带上述可选围栏。个人附件使用 `pa_`，项目附件使用独立的 `pca_` 和项目作用域上传、分片及提交接口，不能通过个人路径共享；项目附件的上传及恢复由原发送人执行，消息只展示已提交文件，查看还须通过当前项目成员权限检查。单条消息的附件占位未全部关联时暂不认领该消息，其他消息可独立认领。PDF 提取文本与预览等派生内容的项目作用域关联正在联调，完整客户端链路通过前不能视为已验收。

项目附件以 `/api/projects/{project_id}/conversations/{conversation_id}/messages/{message_id}/attachments/{client_attachment_id}` 为占位，`PUT` 初始化、`GET` 查询，`PUT .../chunks/{sequence}` 发送最多 4 MiB 的原始分片并携带 `Content-Length` 和 `X-Chunk-SHA256`，`POST .../commit` 核对全文大小及 SHA-256 后关联。单文件最多 300 MiB，项目总预留上限 5 GiB；过期的未完成上传可用原占位恢复。项目成员可通过同一消息下的 `attachments-by-id/{attachment_id}` 获取元数据或读取 `.../content`，服务端核对当前成员、账号、实例和消息归属；返回内容禁用缓存并限制并发。附件不可被当前模型读取时，消息仍会受理，任务应明确提示模型能力不足，不能声称已读取。

支持 `project_attachment_derivatives_v1` 的服务允许原件初始化时固定 `derivative_mode=none|pdf|image`；客户端在原件提交前持久化该模式，旧服务不支持时保留本机记录并提示升级。原件提交后，原发送人以 `PUT .../derivatives` 原子提交完整有序派生集或明确跳过；请求 JSON 不超过 8 MiB，PDF 派生集最多含 48 KiB UTF-8 文本与 10 张各不超过 512 KiB 的 JPEG，图片转换为一张 JPEG。服务端核对内容摘要、项目成员、原发送人及实例，相同集合重试返回原结果，不同集合冲突。`GET` 状态区分 `none`、`awaiting`、`completed`、`skipped`；单条消息等待派生内容完成或明确跳过时，其他消息仍可认领。派生文件计入项目配额，仅可由该任务的授权执行读取，并标明所属原件；文本和预览上限不能伪称完整 PDF 均已解析。

自动分流的模型判断使用 `route` 用量来源，绑定消息、发起人、服务实例、授权和路由租约；不得伪造 Task 或借用不含项目预算的 chat 来源。实际派发前重新核对，项目平台模型须原子保留账号与项目预算；已派发且结果未知时等待核对，不盲目重试。关联修改在安全停止与重启完成前显示 `waiting_adjustment`，不表示新版已开始。

已受理消息因分流失败且尚未创建 Task 时，可通过带账号、服务实例和稳定幂等键的 `retry-processing` 重新处理；同一键重放不得重复执行。`message_too_long` 表示内容及上下文超过模型输入上限，服务端保留原文，客户端提示缩短后重新发送，不为不可修改的原消息提供无效重试。

Task 已开始后，实际模型请求因输入过长被网关或服务商拒绝时使用 `model_context_limit` 等待状态，保留原消息并说明缩短后重新发送；不得将该情况表述为电脑异常或假称任务成功。模型派发是否发生仍按用量和操作账本核对。

DSH 个人上下文证明需记录实际注入的 profile、SOUL、goal 和已授权 memory 的对象标识及版本；恢复与模型派发前核对当前账号和版本。不能证明包含这些版本的旧检查点须安全等待，不可继续发送其中的旧资料；本任务的后续改动只有具备持久成功回执时才能更新证明。

Task 的 `current_revision`、`desired_revision` 表示执行修订，不是 Workspace 版本。最终结果等待组合消息时，`result_message_pending=true`；发布后 `result_message_published=true`，客户端应等待/使用带精确 `sources` 的统一会话消息，不能先把 Task.result 重复显示为独立回复。已展示的流式前缀保留原消息身份，只有同 Task、同修订、同结果事件才能去重。

TaskStep 新增 `progress` 类型：根 Agent 的本次修订真正进入执行并持久化首个回合后，写入一条“开始处理”步骤和带修订及事件序号的 `task.step`。它的 `succeeded` 只表示开始这一事实已确认，不表示整个 Task 已完成；按任务和修订幂等，排队或领取租约不生成该提示。Task 详情的可选 `current_revision_started` 表示当前修订已有该记录；客户端须同时确认 `current_revision == desired_revision`，才能提示本次要求已开始。客户端按持久状态和事件恢复，不展示内部工具名。

模型网关内部合同：`ModelRequest.DisableThinking` 仅用于能力探测；`ModelContentPart` / `ModelResponse` 可在模型网关与 DSH 间传递模型的私有推理，供多轮工具调用恢复使用。私有推理仅进入经加密的任务检查点，不投影到用户消息、事件或公开 HTTP 合同。`capabilities.text_stream` 只在当前模型连接版本通过显式的流式探测后为真；该探测单独调用模型并记录用量，`all` 不额外触发。探测未知、失败或连接版本变化时不得推定流式可用，普通文字对话仍走已验证的非流式路径；当前先用于无工具的单任务。

内置搜索由 `cloud_dsh.builtin_search` 配置 `enabled`、`node_path`、`script_path`、`searxng_url`（仅固定 loopback）及 `max_concurrent`。来源标识固定为 `builtin:searxng-v2.10.0`，复用任务 MCP 操作账本并校验任务 read/submit 权限。外部网页的访问校验不因内部搜索服务使用 loopback 而放宽；镜像 digest 和 npm 锁文件须随交付核对。

`network-policy.sh apply` 由 root 设置规则并保存保护的规则指纹；`check` 核对规则、网桥与运行时安全条件。`orchestrator.profiles.container.network_guard_path` 是必填绝对路径。Portal 启动、readiness 和每次 OSB Create 前执行同一 check，失败不发创建请求。本机Linux真实隔离、资源和主流程已验证；每个部署目标仍须安装并检查同一规则。

### 16.2 DNS 与检查绑定

runsc 使用专网时不依赖 Docker 内嵌 127.0.0.11 的 NAT 路径。宿主 root 安装 `/etc/cloudhost/resolv.conf`（仅 1.1.1.1、8.8.8.8），固定 OSB sandbox_binds 将其只读挂载到 `/etc/resolv.conf`。guard 同时检查文件/父目录保护、实际 OSB CLI 参数、运行中的 Docker runtimeArgs，并把实际 profile URL 与受保护 TOML 的 loopback host/port 绑定；不允许远端编排绕过本机规则。

### 16.3 网站发布隔离门槛

当前 Host 沙箱内的应用共享 `gem` 用户空间；Runtime 固定应用的 cgroup 限制资源和进程身份，但不构成文件系统或网络隔离。Host nftables 可阻止 Sandbox 访问宿主、私网、其他 Sandbox 与 IPv6，但允许公网 IPv4；同一 Sandbox 内的 localhost 服务也不能按 release 隔离。因此 T21.13 必须使用独立 release 沙箱，挂载已核验的不可变发布输入为只读、可变数据单独限额、移除 Host/Runtime 凭证，并通过专用网络规则只允许 Gateway 入站、默认拒绝主动出站。构建也要使用限时独立沙箱；依赖只来自预装缓存，或经过 lockfile 校验的受控包代理 / allowlist，不能直接开放任意公网下载。不能移除 Shell 的 `--unshare-net` 来凑通构建，也不能把同 Host cgroup 误认为文件 / 网络隔离。网站 Gateway 只接受持久登记且健康的 release / 端口；一般 Host 预览永久拒绝 Runtime TLS 控制端口 `8090`。

2026-10-25 Docker Desktop 隔离烟测证实：`--internal` 网络能阻断出站，但其 loopback 发布端口不能由宿主 Gateway 到达；另一个可被宿主访问的 bridge 则没有出站过滤。两种网络都不满足站点要求。本机没有 Linux nftables / runsc，因此这只是淘汰错误拓扑的证据，不是隔离功能验收。部署前必须在一次性 Linux 环境验证独立 bridge、nftables 与 OpenSandbox profile；未验证前不要启用站点发布。

### 16.4 融合任务目标合同

本节定义目标边界，接口的具体字段、版本和实施状态随对应任务登记；不预告未实现能力。

Workspace 条目目前按融合 01 已实现的旧 revision 合同记录；融合 02 完成后，文件权威改为服务端持久目录，PC/Host 使用 Syncthing 传输，Task 使用 Morde 已确认的不可变检查点。旧端点仅可作迁移期兼容或历史快照读取，不能维持两套可写当前文件树。

- 云端 Task、消息、授权、事件与持久执行租约由 Morde/PostgreSQL 统一管理。用户消息按幂等键与内容摘要先和待分流记录原子落库，Task 与执行事件随后按分流结果建立；同一会话可在新任务中切换获准模型和 Host 目标，查看任务不会重复执行。
- 云端 Runtime 以 `(server_instance_id, conversation_id)` 确定归属，每个会话按需获得唯一活动逻辑实例；同一会话内任务可并行但执行上下文与权限独立，共享项目对话逐任务校验发起人。不同会话、账号的记忆、检查点、凭据和授权隔离；同一 Task 同时只有一个有效执行者，单任务停止与 Runtime 停止分别核验。
- worker 管理服务端 dsh 实例、代次、执行许可、预算和受保护检查点；Agent 身份与目标 Host/Workspace 身份分离。电脑工具通过 RuntimeControl 校验目标、权限、代次、操作 ID 和围栏；用户 shell/文件不在 Agent 管理环境执行。无 Host 时允许获准的非电脑步骤。
- dsh 可将受限子 Agent 作为持久后台 job 启动。父/子共享同一 Task 预算、Host/MCP operation ledger、审批及输出核验；子工具只允许父任务授权集合的子集。状态、取消请求和每个子 Session 的检查点落 PostgreSQL；取消先持久记录再通知运行端。重启时由当前根 Session 恢复未结束 child，未知停止状态保持 unknown，不能报告成功。
- Host 工具的 `computer:observe` / `computer:operate` 是资源权限，不等于对某次操作的批准。按 nanoMuse Sentinel 默认风险策略，safe/moderate 操作可在相应 scope 允许时继续；sensitive 操作逐次请求批准，且批准绑定原工具名、调用 ID、参数摘要和当前 Host fence。权限、参数或 fence 任一变化都要求重新核验；未知风险按 sensitive 处理。持久审批不记录完整工具参数。
- Agent 运行许可独立于 Task 执行租约；模型调用与检查点写入必须同时匹配 Task 当前租约、Agent 实例/代次/session、引擎与 profile 版本、授权版本、检查点序号和未过期的活动 Agent 租约。Agent 租约最多 30 秒；租约过期不证明进程树已停止，下一代启动须等可信监督器签名的完整停止回执。
- Task 模型响应恢复使用 app 端口 `TaskModelResponseStore.RecoverTaskModelResponse(context.Context, ModelCallReservation) (TaskModelResponseRecord, bool, error)`；有效 Task 输出通过 `ModelCallSettlement.TaskCall` 或 `SettleProjectModelCallCommand.TaskCall` 与密文、digest 一起提交。`task_model_call_responses` 只保存响应正文密文及原调用身份，`model_call_ledger` 仍是唯一模型用量账本。个人模型的响应与 usage settlement、项目模型的响应与账号/项目账本 settlement 必须在各自现有 PostgreSQL 事务中原子提交；prompt 不持久化。
- 响应恢复须匹配 owner/initiator、Task、稳定 call ID、request digest、模型及 provider 连接版本、session/root session、checkpoint 序号、授权版本与项目 scope，并重新验证当前租约和授权。相同 Agent generation 还须匹配原 Agent instance；后继 generation 只有在当前 Agent 租约有效、前代实例已有停止回执，且 session/checkpoint/request/auth/连接围栏相同后才可读取前代响应。没有响应正文的旧 ledger 仍走未知/对账路径，禁止再次派发同一调用；密文使用现有 AES-GCM data key，响应摘要同时校验。
- dsh 内部接口最少覆盖启动/恢复、输入、审批、取消与状态；事件按序持久化后确认，重放去重，未知副作用先对账。执行许可与客户端观察凭证分离，不保存用户密码或完整 bearer token。授权撤销分别停止并核验 Agent 执行树与 Host 工具树，不能确认则阻断并显示未知。
- Host 运行端拒绝已过期或剩余有效期超过 30 秒的任务许可；服务端发送时取任务实际到期时间与当前时间加 25 秒中较早者，留出少量时钟误差余量。Agent 执行许可和两侧停止确认仍须分别落实，运行端许可截止不代表工具已确认停止。
- 现行 F01 文件合同的 Workspace 输入使用已提交 revision；融合 02 目标改为服务端已确认的不可变文件检查点。两者均要求有文件产物时先在服务端持久读回核验再完成。无文件产物的任务不强制文件写入；存在未确认写入或未知副作用时不得绕过核验。完整模型请求/附件记录默认关闭并需单独同意，恢复检查点不是管理员全文查看的旁路。
- Host 主动释放先围栏活动任务，再检查未结算的 Task 电脑操作、当前代次 Host 未确认的文件写入及 Workspace 同步冲突；拒绝时以固定原因和经过校验的 Task/Workspace ID 返回 409。现行 F01 由 Host 同步会话、提交和释放共用 Host 行锁；融合 02 须让新文件检查点、Host 待同步写入与释放共用围栏，防止释放检查后产生新写入。未扫描的 Host 本地文件仍需运行端报告和原生生命周期验收。
- 文件交付意图由 Morde 服务端根据不可变 Task 目标及批次输入自动分类，保存为 `required`、`none` 或 `unclear`；客户端不得用开关或预期路径覆盖分类。当前固定规则无法确定时必须等待用户确认，不能按“无需文件”完成；明确交付要求仍须通过真实 `file_write`、服务端文件检查点和读回核验。现行 F01 的 commit 是旧合同，融合 02 完成后切换到新检查点。
- 第三方 MCP 走账号私有 Connector、显式 Task grant 与独立 hostless operation ledger；不是 Host 电脑工具，也不要求伪造 Host fence。每次派发都重验 Task lease、grant 与 Connector 当前启用/版本。Task stop 取消未派发操作并等待派发中的本地请求 settle；unknown 表示本地调用已结束、远端影响待审查且不得重试，不会永远阻塞本机停止。OAuth 服务端发现、PKCE、一次性 state、issuer 校验、密文保管和令牌刷新在 Morde 服务端闭环。

- 配置和依赖保持单一权威：现有 `portal.yaml`、本文件第 6/11 节及锁定 dsh 依赖；新增配置、执行协议和版本在实现时登记于本文件，HTTP 同步 `server/openapi/portal.yaml` 与调用方/测试。不得启动时隐式迁移或新建第二业务数据库。

### 16.5 Workspace named volume 与 Runtime 操作账本

新 Host 的 Workspace 持久化边界是每个 Workspace 一个 Docker named volume，而不是每台 Host 一份 Workspace root。volume 名称为 `workspace-<workspace_id>`；服务端注册状态与 Docker labels 必须同时匹配 service instance、当前 owner 和 Workspace ID。新建只在注册状态为 pending 时创建；ready volume 缺失、身份不符或旧 Host/Workspace 归属存在歧义时拒绝启动，不自动生成空卷。旧 `workspace-root`、`runtime-data`、`host-apps` 只保留作迁移和回滚来源，按唯一显式映射过渡；在逐台数据验证、备份和回退证据齐全前不得清理。

新 Host 的 AIO profile 首次创建时把 Desktop、Downloads、Documents、Music、Pictures、Videos 与 Chromium 下载默认指向 `/home/gem/workspace`；已有非空 profile 路径不覆盖。Host Apps 使用镜像内容或 `/run/morde-runtime/apps` 临时目录。Runtime 端操作恢复记录保存在服务端 PostgreSQL，以 `(host_id, generation, namespace, sequence)` 和前序摘要围栏；相同 operation ID 的不同内容、分叉链、账本缺失或未知副作用均拒绝继续。Docker volume 的 `storage` 声明不等于硬容量限制，Sandbox named volumes 当前不进入单机备份 bundle；上述本机实现不代表 Linux 固定镜像、Ubuntu 卷重建、硬限额或可恢复备份已通过。

`server/migrations/preflight/legacy_host_volume_inventory.sql` 只读列出数据库可推导的 Host/Workspace 与旧 named-volume 候选，并将 Compose 单卷名保留为 owner/Host/Workspace 未知；它不是 Docker 实际卷清单，也不会自动关联、复制或切换数据。迁移前须与本机 Docker 卷及标签清单核对，并为每个源卷显式确认归属、目标、凭据处理和回退；未知项保持未解决。

2026-11-03 本机 `desktop-linux` Docker 只读清单显示 `workspaces-<host>`、`profile-<host>`、`runtime-<host>`、`apps-<host>` 各两卷，driver 为 `local`，可见标签只有 `opensandbox.io/volume-managed-by=server`，未发现 Compose 单卷候选。卷内容、本机数据库 owner/Workspace 关联与容器挂载状态均未读取；名称和管理标签不作为迁移映射依据。

Workspace revision 从迁移 `00126_workspace_hardlink_files.sql` 起用 `hardlink_to` 保存卷内硬链接的规范锚点；含硬链接的 manifest 使用 v3 摘要，旧无硬链接摘要保持兼容。同步、复制、旧 Workspace 导入、Runtime Task 私有视图与 current materialization 都保留链接身份，并在提交前校验锚点和同一文件元数据。ACL 与扩展属性当前不能完整表示，Workspace 同步、复制和旧卷导入遇到这些元数据时必须拒绝；目标 Ubuntu/Linux ACL、xattr 和真实 named-volume 恢复仍需部署环境验收。

F01-T17 的 Node 账号 Runtime 协议原型以私有 stdin/stdout 运行：首帧 `runtime_start` 精确绑定 `version: 1`、`server_instance_id`、`owner_id`、`runtime_id`、`runtime_generation` 与 `max_concurrent_tasks`，并回 `runtime_ready`；每个顶层 `start` 另携这组服务/账号 Runtime 围栏、Task/owner/Agent/session/授权围栏及正整数 `runtime_sequence`。Runtime 只保存最近接受的序号高水位，旧序号拒绝，避免常驻进程为重放防护无限积累 Task 历史；序号只在任务完整校验并被接纳后推进。每个 Task 由账号父进程 spawn 独立 `bin.mjs` 子进程，单 Task 停止按该进程组发送信号并等待 child `close`；Node 测试证明停止一个 Task 后另一个仍能推进，`npm test` 46/46 通过。这里的 close 只确认直接 child 退出，不证明全部后代退出，也不构成 Guardian/cgroup 停止证明。本机已用该原型重建并 smoke `linux/amd64` 模拟镜像，digest 为 `sha256:0933979aa13fcc33728fda38cd888fce61c9d330cf8b43d9882d09149f7de267`，构建时 46/46，smoke 运行 Node v24.22.0；smoke 检查 `bin-account.mjs` 的身份围栏及 `runtime_ready/runtime_stopped`，并检查既有 `bin.mjs` fail-closed 行为，但没有执行多 Task 容器场景。以上是早期原型证据，不代表原生 Ubuntu 或 Guardian/cgroup 销毁。随后 Portal/Go、数据库租约、Guardian Task/Runtime stop-proof ACK outbox 与部署接线已进入本地实现；最新 Node 47/47 和多 Task 模拟容器 smoke 证明停止 Task A 后 Task B 继续推进。原生 Linux cgroup、systemd 重启和真实 Docker 故障竞态仍未验收，执行开关默认关闭。

### 16.6 Workspace 单人领取副本分享

Morde 生成 256-bit 随机 Workspace 分享 token，只在创建响应中返回一次，数据库只保存 SHA-256；分享链接要求接收者先登录，未领取 7 天失效，每个链接只允许一位账号领取，领取成功后 token 立即失效。领取期间失败只允许同一接收者恢复；服务端复制已确认 Workspace revision，并在 reservation 事务中直接创建归接收者所有的目标副本、写入 ownership history 和目标卷归属、原子绑定 share target；`view` 副本初始即 `is_read_only=true`，`edit` 副本初始为可编辑。copy reservation 显式保存 `source_owner_id`、`target_owner_id`、`share_id` 和 `read_only`；保留的旧 `owner_id` 只表示源 owner，配额 reservation/settlement 始终计入 target owner。普通 Workspace copy 继续要求 source owner 与 target owner 相同。处于 `reserved` 状态且能证明目标卷仍为 `pending`、物料化尚未开始时，可原子释放接收者配额、删除 reservation/idempotency、保留目标 tombstone 并清空当前领取链接的 target，让同一接收者重试并创建新目标；进入 `copying`、`unknown` 或可能已发生卷/物料化副作用后，必须保留原 target 和 reservation fence，由同一接收者在原目标上恢复。分享领取和任何恢复路径都不得创建或接受 ownership transfer，也不得转移原 Workspace/Host binding。原 Workspace 不向接收者开放；接受后的副本永久独立，源后续修改、删除及分享方权限变更都不影响副本。token 不放在请求 URL 中，预览/领取响应设置 `Cache-Control: no-store`。链接过期或源 revision 已变化时不得以更晚版本冒充分享时快照。

### 16.8 AI 对话摘要与长期记忆边界

摘要只作为每个 Conversation 的有损派生上下文；原始消息、主会话指针、Task 结果和长期记忆对象仍由原有记录负责。主会话和旁聊各自按服务实例、owner、actor、Conversation 与 scope 保存摘要。个人 scope 要求 actor 等于 owner；项目 scope 要求 Conversation 所属项目匹配，且 actor 仍是当前 owner/member，项目成员版本变化后旧摘要不可读。摘要不自动写入长期记忆。

迁移 `00174_conversation_summaries.sql` 新增四张表：`conversation_summary_heads` 保存当前摘要版本/摘要 digest、授权版本和单写者租约；`conversation_compaction_operations` 以稳定 operation ID 和输入 digest 支持幂等认领，记录 baseline、状态、租约版本、检查点身份及 model call ID；`conversation_summary_versions` 保存 AES-GCM 密文、摘要 digest、来源 digest、前驱和授权/scope 版本；`conversation_summary_sources` 按顺序保存 message、已发布 task result 或 memory revision 的来源身份、版本、序号和 digest。迁移 `00175_conversation_compaction_model_calls.sql` 将 `compaction` 加入现有账号/项目模型账本来源，并在操作记录中绑定模型、连接版本、请求 digest 及加密后的已结算结果；不创建 Task 或复用路由结果表。源证明必须仍满足当前会话和授权，消息还必须严格早于当前处理的用户消息。摘要提交须同时通过来源检查、检查点身份、有效租约和 head version CAS；冲突不推进 head。摘要密封和解封还会校验加密文档内的身份、摘要 hash 与完整来源清单。

源删除、抑制、记忆更新或 scope 撤权时，后续变更路径必须调用来源失效端口（各调用方由 T10 接入）；失效按版本前驱链递归传播，head 回退到相同授权/scope 版本下较早的有效摘要，若无则回到版本 0。此过程只使派生摘要不可用，不删除或改写原始消息。T02 保存 DSH checkpoint 的 session ID、覆盖序号与 digest 身份；T03 已接通压缩模型网关、账号/项目账本和加密结果恢复，真实 IPC checkpoint 正文持久化及 Worker 调用桥接由 T04 接通。当前压缩引擎 `auto: false`，不代表自动压缩已上线。
