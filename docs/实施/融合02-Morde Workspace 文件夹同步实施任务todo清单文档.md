## 1. 修改边界和门禁

本清单采用**完整 Syncthing 节点 + Morde 控制面**。Syncthing 承担所选 PC 目录、服务端持久目录、必要时的 Host 目录之间的扫描与传输；Morde 承担设备授权、目录映射、300 MiB/5 GiB 准入、状态、稳定检查点、Task 文件证明和撤权。不移植 Syncthing 核心。PC 开关、进程与界面由融合 03 接入；本阶段用隔离测试节点验证服务端和 Host，服务端文件持续保留。iOS 仍只做显式文件上传/下载，不运行常驻目录同步。

**门禁一：** F02-T01～T03 必须证明原版 Syncthing 的缺口能通过可维护的准入扩展解决，还要证明直接目录变化不会绕过 Task 输入版本和 Host 操作屏障。若旧副本、并发 5 GiB 准入或任务围栏无法可靠实现，停止 F02-T04～T10，记录失败序列，并按设计方案改评 `morde-sync` 备选；不能把 `.stignore` 或 Syncthing `completion=100` 当作通过。

**门禁二：** 服务端持久目录切换为当前文件权威前，旧 Workspace 必须可恢复为该目录并核对摘要；旧 revision/块只作为不可变历史与任务证据，不形成两套可写当前文件树。F01-T09/T11/T13 已有验证只证明旧协议，新文件合同要重新验收。修改 OpenAPI、公共约定、代码及测试须在同一变更完成，遵循 `server/AGENTS.md`。

300 MiB = 314,572,800 字节，5 GiB = 5,368,709,120 字节，边界值允许；5 GiB 只计算实际参与同步的文件逻辑大小。超额保留已接纳内容，暂停新增/扩容，允许删除/缩小恢复；超过 300 MiB 的本机原件保留且不上传。路径只相对用户明确选定的目录；符号链接不越界，空目录保留。

**2026-10-29 用户确认的离线规则：** PC 断网或同步停止期间，本机未上报的修改对云端不可见；云端任务继续使用提交时已确认的云端版本，不能把该版本说成已知与离线 PC 的最新内容一致。PC 恢复同步后，服务端确认存在外部变化时，相关任务安全暂停并要求用户按新版本重新提交；任务自身已证明的写入按原有规则处理。

**2026-10-29 首次确认、2026-10-30 再确认的本机保全规则：** 同步覆盖或删除本机已有文件前保留可恢复的本机安全副本；副本不自动上传、不计入 5 GiB，但额外占用磁盘，原路径可能显示新版本。提示用户查看和恢复；删除副本需另行明确确认。副本须隔离于所有同步目录，保全失败或无法确保仍打开的旧句柄后续写入可恢复时，暂停该覆盖/删除。Syncthing 独立原型已完成本地保全、跨卷失败和 ENOSPC 失败关闭验收；数据块完全耗尽未单独模拟。恢复列表、查看和恢复入口归 F03-T06。
