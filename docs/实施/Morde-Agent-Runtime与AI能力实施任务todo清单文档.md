## 修改边界

修改服务端会话、DSH 任务与工具接入、用户隔离环境、PC 对话页面及受接口影响的 iOS 客户端。沿用 DSH、现有模型网关、授权和账本；不恢复已删除的 nanoMuse 旧数据导入组件。旧的“每对话一个活动任务”约束由本方案替换，现有对话、任务、密钥、Workspace 和个人数据必须保留。

优先复用 [DSH 官方插件清单](../Morde-Agent-Runtime与AI能力设计方案.md#331-优先复用-dsh-插件)，每项落在现有任务中。Runtime 上游 DSH 包已升级并锁定到 `0.2.2-rc.1`；Morde 持久化检查点与服务端围栏继续使用兼容标识 `0.2.0-rc.2`，二者语义不同。后续插件接入仍须完成各自任务中的授权、隔离及恢复验收，不把调研结论标成已实现。

本次及后续当前指令有效期间只在本地操作，不外发或发送文件；真实文件传输、邮件附件和截图外发不作为本轮验收。外部服务使用本地替身与合成数据，公共新闻查询仅发送合成的搜索词。涉及产品外发消息或文件的能力，实际执行仍需单独满足用户授权与当时的工作限制。

## 关键接口变化

| 接口 / 模块 | 目标合同与调用方 |
| --- | --- |
| `POST /api/conversations/{id}/messages`；项目对话对应消息接口（现有） | 唯一使用自动受理与分流：客户端提交稳定消息 ID、正文、可选附件/模型/电脑/Workspace 与明确任务引用；不暴露 `new` / `append` 模式。服务端先在事务内持久化消息、顺序、幂等记录和待分流记录，返回 `202` 与消息回执，Task 可暂不存在；分流 Worker 再按规则和模型判断是新任务、更新指定任务、查询、停止或澄清。重复 ID 与相同请求返回原回执，内容不同则冲突；账号、服务实例及会话不匹配时拒绝。模型、电脑或 Workspace 状态未知不阻止受理。PC、iOS、项目调用方及 OpenAPI 同步使用此合同，不保留旧发送分支。 |
| `GET /api/conversations/{id}/tasks` 和项目对话对应任务列表（拟新增） | 返回当前会话内调用者可查看的活动任务及其状态/版本、事件游标，支持分页；跨用户或无项目权限返回无权/不存在。页面刷新后可发现所有活动任务，不依赖最后一条消息。 |
| `GET /api/tasks/{id}/events`、`GET /api/tasks/{id}`（现有） | 保持任务级事件序号及游标；补足可安全展示的消息、工具开始/结果和产物摘要。事件缺口或游标过期后回读该任务快照；UI 按 `task_id + sequence` 去重。 |
| `POST /api/tasks/{id}/actions`、`/inputs`、`/approvals/{approval_id}/responses`（现有） | 按指定任务执行停止、澄清或审批：停止使用预期任务状态；澄清和审批使用对应请求 ID、版本。失败和结果不明确如实返回。多任务页面不能复用另一任务的状态或审批。 |
| `CloudDSHToolBroker.Definitions/Execute`、MCP 客户端（现有，需调整） | 在现有授权前提下加入管理员固定的内置 MCP 连接及任务授权；工具目录固定，取消/结果走现有操作账本。公共用户自定义连接器的 HTTPS 与 SSRF 规则不变；新增的媒体结果必须验证类型、大小、归属。 |
| 个人数据/记忆及计划服务（现有，按任务扩展） | 个人 SOUL、资料、记忆与目标按用户授权读取/更新；新增受限的历史检索及计划工具入口。删除或撤权后不再召回；项目场景单独按项目权限过滤。 |

数据库迁移仅新增版本：解除同一对话的单活动任务唯一索引，并保留查询索引、历史记录和既有活动任务。按用户最新要求直接切换为唯一的新合同，同步更新所有调用方，不保留旧逻辑或兼容开关。回滚前若存在同会话多个活动任务，须先安全处理至可满足旧约束，不能删任务或静默合并。

**问题记录（T01/T02）：** 旧版运行时清单曾记录必填 `mode` 和明确追加任务，与 2026-11-07 的《Morde AI 助手对话与任务执行体验设计方案》冲突；以较新的方案为准，消息统一先受理再自动分流，客户端不选择新建或追加模式。会话可有多个并行任务；任务创建时固定经授权的历史快照，避免其他任务完成后改变快照或污染新任务上下文。

**问题记录（T02 项目会话）：** 项目成员可以在其权限范围内读取共享历史和提交新消息；已有任务的补充消息、澄清、审批及停止仍只允许该 Task initiator 操作，不能借消息自动分流扩大权限。项目活动 Task 分页、撤权后列表、终态幂等重试及跨设备恢复均须在本轮合同下继续验收。

**问题记录（T03）：** 共享 Runtime 的任务事件队列满时会阻塞其他任务；模型同次返回文字与工具调用时，原有 DSH 内容块索引冲突会丢失工具调用。已分别添加复现用例并修复，仍需完成并发和端到端集成验收。

独立 PostgreSQL 与真实本机 DSH 子进程的重启恢复回归发现失败状态的 Runtime 会拒绝已签名的任务停止证明；已修复并通过该重启恢复和停止证明校验用例，重启恢复的串行 race 复测通过。其余并发及浏览器整体验收仍需完成。

真实 DSH 父子取消回归又发现间歇卡住：`lockTaskInitiatorInTx` 先持有 Task `FOR SHARE`，调用方随后升级为写锁，与 Task lease 续租竞争时可能形成 PostgreSQL 死锁。现改为读取不可变的 Task actor 字段而不锁 Task 行，项目授权仍由项目成员锁串行化；新增 `TestPostgresTaskInitiatorReadDoesNotHoldTaskRowLock`。真实 Node 子进程父子取消/兄弟隔离 race 与重启恢复 race 均通过，父子取消测试连续 5 次通过。浏览器整体验收仍待完成。

**问题记录（T07）：** 现有 Host 截图成功判定与 Worker 的图片限制不一致；运行中续租还需检查 Host 控制权限是否撤销。截图缩放坐标与实际桌面坐标不同，点击还需验证屏幕分辨率未变化。正在复用现有授权和任务围栏修复，不假报操作成功。绑定 Workspace 的任务按现有策略不能执行桌面输入，安全隔离未完成前不视为支持同一任务同时修改 Workspace 文件并操控桌面。共享 Host 场景另需保留 Host owner 与 Task initiator 分离，并使成员撤权后的 Agent lease、任务领取与桌面操作准入失效；撤权后立刻重授相同权限也不能复活旧 Agent。

**问题记录（T10）：** 定时任务使用专属 `schedule.ValidRunID`；任务执行凭据已区分计划运行授权与普通 Session/Client Token，并覆盖撤权、Hostless/Host-bound scope 的回归用例。
