## 2. 登录、换账号和内嵌工作台

当前 OpenAPI 的 `/api/auth/client-login`：桌面返回安装绑定的 Client、Sync 和用户 Web 凭证，iOS 返回 Client；安装绑定的 `/api/auth/client-web-session` 可给桌面或 iOS 换取短期用户 Web 会话，不能访问管理员路由。桌面/iOS 使用有序登录合同：先要求客户端支持 `ordered_client_login`，每次网络尝试使用持久递增的 `attempt_generation` 与新的 `Idempotency-Key`，并在事务中按 `client_instance_id` 围栏。由于本期 Android 源码必须保持不变，服务端为旧 Android 保留仅按服务端到达顺序递增的兼容入口，不在能力列表中声明；它保留同键同请求在同一安装上轮换凭证的旧行为，但不能阻止客户端意图较旧的请求迟到后覆盖新凭证。

例如客户端先发 A、超时后发 B，但 B 先到服务端并提交、A 随后才提交：即使客户端按发出顺序丢弃迟到的 A 响应，A 仍可能在服务端把 B 的凭证撤销，造成界面显示登录成功却无法使用。单纯串行发送或取消 HTTP 也不能证明超时的旧请求未在服务端执行。

`client_login_attempts` 仅保存账号、UUID 实例、最新代次和安装绑定，不存密码或令牌；同一实例只能绑定一个安装。有序客户端的代次必须严格大于服务端已提交的代次，重复 key 或过时代次返回冲突；响应未知时客户端推进代次并换新 key。撤销会保留 stream 与安装绑定，迟到请求不能恢复撤销安装。能力列表不再发布旧登录 feature；桌面/iOS 缺字段返回 `unsupported`，Android 旧版缺少两个有序字段时服务端在隔离的 legacy stream 中分配代次。PC 与 iOS 端的实现和验收证据分别记录在 F03-T02.06/.07。

按 F03-T02.01～.07、T07.02～.03 分端落地：基础登录及账号隔离可先分别实现；可靠重试需同时完成服务端围栏与对应平台接入。真实验收覆盖 A/B 反序到达、响应反序、响应丢失、应用重启、同安装不同登录键竞争以及登录与退出/撤销竞争。T07.02～.03 各自接入工作台：

1. 原生可信层先读取 `/api/capabilities`，再登录并将凭证写入各平台安全存储；缓存/outbox 按 `(server_instance_id, user_id, installation_id)` 隔离。离线退出先隔离业务数据并清除可用凭证，保留仅用于待撤销提示的非秘密标识，不假称服务端已撤销。
2. PC 参考现有 `harness/desktop/src/morde-main.ts`：主进程换取受安装约束的短期 Web 会话，注入独立内存分区的 HttpOnly Cookie；renderer 不得到 Client/Sync 凭证。iOS 由原生可信层取得短期会话并配置独立 WebView 数据容器，具体 Cookie/会话接线需实测；旧精简壳不证明原工程已接好。
3. 对 Portal/Host 分别限制可信来源、导航与票据作用域；远程网页不可调用任意文件、凭证或本机执行 IPC。换账号、撤安装或会话过期时销毁对应 Web 内容并清除分区；续期失败显示真实状态。Host 查看和人工操作仍分别鉴权，接管必须等待 AI 工具停止确认。
4. PC 和 iOS 先分别验证登录、换账号和过期处理；工作台真机/模拟器及内置浏览器验收各记证据，缺少一个平台不替代另一个平台通过。

## 3. 会话提交与事件恢复

**已有合同：**`POST /api/conversations/{id}/messages` 返回持久消息和 Task；`GET /api/tasks/{id}/events` 支持 `after`/`Last-Event-ID`，过期时发 `task.snapshot_required`。提交前客户端持久化本次请求的幂等键和完整确认内容；超时继续用相同键和相同内容查询/重试，不能换键重复执行。界面只有收到持久回执才提示可以关闭；关闭应用不发取消。

**原发现及当前进展：**PostgreSQL 的 Task 快照已有同一读取快照中的 `EventSequence`，最初 `GET /api/tasks/{id}` 响应和 OpenAPI `Task` 未返回该序号。服务端现在已返回非负 `event_sequence`，OpenAPI 已要求该字段，Portal/Workbench TypeScript schema 已生成。API 路由单测与 PostgreSQL 快照并发测试通过；Morde Swift DTO 与快照游标处理现已随共享视图并入原 Minis target，helper 测试、独立 target 与原 Minis target 通用 iOS 构建通过。真实服务 SSE 与可交互设备上的恢复验收仍待完成。若流先提示序号 7，而客户端随后取得的快照实际已包含到序号 9，再从 7 重放，8、9 可能把较新界面状态倒回去；只使用通知中的序号不能证明它与快照一致。

**后续修正，归 F03-T04.06：**服务端 Task 详情现返回与 Task/steps/待审批状态同一数据库读取快照的非负 `event_sequence`；OpenAPI、Portal/Workbench TS schema、API 单测和 PostgreSQL 并发测试已同步。Morde Swift DTO 和从 `task.snapshot_required` 获取 Task/消息快照、用快照序号续读的路径已并入 Minis 共享视图，并通过 helper 测试及原 target 通用 iOS 构建。该合同项已完成；真实服务中的完整恢复路径与并发回归仍待 F03-T04.02 / F03-T10 验收。不能把通知中的序号持久化为确认，也不能通过客户端时间或独立查询猜测序号。最终回归须覆盖“发 snapshot_required → 快照读取期间新事件提交 → 恢复 SSE”，不能漏事件、倒退状态或重复处理审批。

**流式正文另有缺口，归 F03-T04.07：**现有 `AppendAssistantTextDelta` 把增量写入 Task 事件，完整 assistant 消息在后续完成时才写入会话；当前 Task 详情不带消息正文。如果历史事件已清理，只返回快照序号会跳过之前的增量，而客户端拿不到当时的完整前缀。先核对云端 dsh 的真实输出路径；对实际向客户端提供的流式正文，拟在既有会话消息的唯一写路径维护有大小上限的未完成正文及完成状态，并与相应事件原子持久化。快照提供同一序号下本 Task 所需的消息内容和状态，完成后仍使用同一消息 ID；独立读取的会话分页按消息 ID 和版本合并，不能把同一段正文重复追加。若该路径尚无流式正文，先展示真实进度并在完成后读取持久消息，不伪造中间文本；核对原客户端适用能力，需保留流式正文时补齐云端路径，核心能力冲突按规则提交审核。实现前需检查现有消息序列、恢复与授权，控制写入频率但不能确认尚未持久化的片段。该项未完成不阻塞独立的状态查看和纯文本提交，但不能将流式功能标为已完成。

验证需覆盖事件历史过期、输出尚未完成时的新快照、快照与新 delta 并发、完成消息恰在重连期间提交；恢复后正文不能漏前缀、重复或把未完成内容显示为已完成。Task 快照和会话消息读取的权限也须分别校验。

T04.01 的无文件提交可独立推进；文件提交、显式上传、下载和检查点只接 F02-T10 已交付且真实可用的合同。待文件门禁期间不显示文件同步已就绪，也不以测试替身完成端到端验收。
