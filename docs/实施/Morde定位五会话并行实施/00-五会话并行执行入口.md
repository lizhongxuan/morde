阶段是依赖顺序，不是五个会话必须同时停下等待的全局栅栏。具体任务只等待文中列出的前置；已有组件先核对并复用，有实现但缺验收时写“待验证”。各会话只在自己的清单更新 `未开始 / 进行中 / 阻塞 / 待验证 / 已完成`，记录改动范围、检查结果和缺口；只有本职责实现及必要验收通过才勾选完成。前置任务已有稳定的本地合同但仍有环境验收缺口时，后续会话可注明依赖状态并继续不受影响的开发或替身验证，不能据此宣称完整链路通过。

新增约束以设计 10.7–10.10 为准，可行性与验证以 11 节为准：创建和运行电脑必须恰好绑定一个 Workspace；一个 Workspace 同时只能被一台电脑使用；多人可观察但同一时间只有一个人操作；Workspace 可完整复制和经接收确认移交，移交等待期冻结；AIO 的工作/下载统一使用 Workspace 根目录，Workspace 是用户工作的唯一持久化边界。纯云端对话不因这些约束而必须创建电脑。

### 本机验收口径

当前 Mac 已有 Docker Desktop、本地 PostgreSQL 16 镜像和 iOS 模拟器；这些可以在不发文件时检查元数据事务与页面。Portal/Workbench 要求 Node 24，当前默认 Node 为 26，本机另有 Node v24.19.0，路径和使用前提见设计 11.2；缺失依赖不自动安装。Mac 本地 Go 单测只证明对应代码分支，不能替代 Linux `renameat2`、Ubuntu 固定镜像及真实卷。

W18a 提前核对命名卷、可访问性、运行账本、镜像启动及容量隔离；其本机代码核对和替身结果可先交接，即使目标 Ubuntu 仍待验证，W18/W20/W21 仍可实现不依赖目标环境的部分，但相关能力及最终验收标阻塞/待验证，其他会话继续不受影响的工作。不要把单盘的备用方案、COW 或同步联通写成已验证。

## 4. 跨会话交接与完成标准

1. 发起方只在**自己的清单**末尾“交接记录”追加：任务 ID、目标会话、具体文件/接口、前后合同、权限/幂等/错误条件和必要验收。不要把代码修改直接写入他人的范围。
2. 文件所有者在**自己的清单**记录接收、实现、结果和阻塞；发起方读取该记录后继续。每完成一项或进入阻塞前主动检查其他清单的交接记录，会话 5 持续承接公共请求。共享路由、数据库迁移/查询与 `sqlcgen`、OpenAPI 由会话 5 负责，Portal API 类型由会话 2 负责。
3. 每项按其写入边界完成实现和验收；W02/W08 只是迁移与合同基线，不代表服务可用。HTTP、表结构、状态机及跨文档签名必须按 `server/AGENTS.md` 在同一交付变更内同步公共约定、OpenAPI、实现与测试；中间进度不得单独作为完整交付或发布。公共接口的装配分别由 W02b/W08b 完成，客户端对应项及 W14 对应阶段集成通过后，才能宣称跨端功能完成；未集成或未验收不得伪报。W14 先记录 P0 集成结果，后续已排期的 P1/P2 合并后再补最终汇总。
4. `make generate`、共享迁移编号和全仓会改变生成文件的命令由会话 5 串行执行；会话 2 生成前端 schema 前与会话 5 的 OpenAPI 结果对齐。开发中优先跑自身定向检查，全链路检查在共享变更稳定后执行。
5. 本地页面用内置浏览器和内存模拟数据验收；文件相关测试只允许进程内模拟或本机读写，不发送真实或合成业务文件。不得连接远端服务、上传/外发/发送文件、部署或改远端状态。多人、多端用两个逻辑账号和请求/浏览器状态；iOS 用本机模拟器，不要求真机；多 AI 用两个替身，不要求真实外部服务；COW 不支持就只测普通复制。目标 Ubuntu 本机验证只在该机已有同版本代码、固定镜像及依赖且得到用户授权的本地会话中进行，不通过传送文件或远程修改补齐条件。未实测记录“待验证”，不得绕过安全门禁。
6. F02-T10 已按此前用户要求豁免运行验收并关闭实施项；Ubuntu peer 连接超时仍未解决，`workspace-sync` capability 继续关闭。旧阶段结项、mock、构建成功都不等于真实同步链路通过。
7. `server/AGENTS.md` 和各端适用约定继续有效。新旧文档/代码冲突先按原有规则记录归属并同步合同；原 01～05、原 29 份并行文档保留编号、状态和证据，本次任务只实现新定位的增量，不重新宣称它们未做过或已验收。
8. 后端最终检查按 `server/AGENTS.md` 执行 `make lint`、`make test race cover`、`make generate`，涉及 Store/迁移还需用本机临时 PostgreSQL 执行 `make it`。这几个命令含 `go run` 或全量测试：先确认依赖已缓存、禁止自动下载，逐项核对不会发送文件、连接远端或改其他会话文件；日常优先执行已检查的定向测试。不能安全运行或环境不足时记录具体阻塞和待验证，不以局部测试替代全部检查通过，也不把未配置数据库时的跳过记成通过。
