## 接口与调用方

以下路径均为现有接口，新增接口在合同定稿前标为拟新增。接口、迁移和调用方需同时更新 `server/openapi/portal.yaml`、`docs/实施/00-总览与公共约定.md` 及对应客户端类型。

| 接口 / 所在模块 | 本次变化 |
| --- | --- |
| `POST /api/hosts`、`/api/hosts/{id}/workspace-bindings`、`/api/workspaces` 及其转移、分享、删除操作 | 创建电脑自动确定专属持久目录；普通调用方不能再选旧目录或通过绑定、解绑、转移等旧操作改变电脑归属。核对现有管理端及任务调用方，迁移必需的内部操作，阻止旧接口绕过绑定规则。 |
| `DELETE /api/hosts/{id}` | 现有合同仅解绑并保留独立工作区；改为在用户明确确认同时删除电脑与其 `~/workspace/` 后提交删除。缺少新确认的旧请求须拒绝；`202` 只表示受理，删除完成须包含该电脑的目录清理，失败或结果未知可查询并安全重试。 |
| `POST/GET /api/hosts/{id}/sync-folders`、`/api/workspaces/{id}/sync-sessions` 及分块/提交接口 | 复用项目上传协议，由目标电脑确定内部存储和 `project/<项目名>`；用户界面不传或选择独立工作区。保留项目基线、幂等、目录边界和冲突保护。 |
| `morde:portal-project-upload-targets`、`morde:portal-project-select-directory`、`morde:portal-project-upload`，Electron main/preload | 将项目选择、上传与恢复从旧 `/workspaces` 页面迁到新入口；调用方使用目标电脑和本机选择结果，内部解析存储身份。仅信任指定同源页面、主 frame 和当前账号，页面切换及账号变化时继续校验。 |
| `POST /api/codex/connections`、`DELETE /api/codex/connections/{profile_key}`，服务端及 PC | 绑定当前账号、PC installation 与 Codex profile 的非敏感标识；一次确认授权整个配置的会话读取和实时同步，发送、中断、审批按已确认权限执行。服务端存储 profile 级范围并兼容旧逐会话授权；旧授权不能静默扩权。 |
| `POST /api/codex/sessions/discover`、`GET /api/codex/sessions` | 从逐条授权登记调整为依据有效工具连接自动登记全部可访问线程；返回来源、分页与同步状态。确保首轮分页期间新增会话也能在对账后出现。 |
| `GET/POST /api/codex/sessions/{id}/events`、`GET .../events/stream` | 持久保存并按顺序读取完整可见消息、推理、工具输入/输出及其他事件；保留原生轮次和条目顺序，用于合并晚到的历史与实时事件。在工具和授权允许时支持会话图片、附件的安全读取。大内容分段、续传和去重，不能因当前白名单或大小上限静默丢弃。服务端提交后才确认，iOS 用游标补缺。 |
| `POST /api/codex/sessions/{id}/commands`、`POST /api/codex/commands/claim`、`POST /api/codex/commands/{id}/result` | 沿用持久命令链路并校验工具连接、目标 PC 与原生会话；消息幂等，运行中追加和审批仅在工具实际支持时执行，结果未知不得盲目重发。 |

## 顺序与并行文件边界

先由 A0 验证真实 Codex 会话能力，同时由 H1 核对电脑数据归属。电脑与项目主线为 H1 → H2、H1 → H3 → H4，以及 H1 → H5；本机 AI 会话主线为 A0 → A1 → A2 → A3 → A4/A5。A1 定稿连接和事件合同后客户端可按各自边界接入，最后执行 Z1。

如使用多个 agent，按下列唯一写入边界分配，同一行中的任务顺序执行；合同确定后其他 agent 才据此接入：

| 写入责任 | 文件边界 |
| --- | --- |
| 服务端 | `server/`、`server/openapi/portal.yaml`、后端迁移及对应测试；跨端合同由该责任人统一提交。 |
| PC 页面 | `web/portal/src/` 及其页面测试，包含生成的 Portal API 类型；等待服务端合同后更新。 |
| PC 桌面 | `clients/desktop/harness/desktop/` 的 main、preload、Codex、同步模块、资源和测试；H4、A2、A3 及 A4 的桌面部分由同一责任人顺序实施，避免同时修改共享文件。 |
| iOS | `clients/nanoMuse/android/src/ios/` 中 Morde 工程、导航、文案和测试；H5 与 A5 顺序实施。 |
| 集成与文档 | 本清单、需求文档和 `docs/实施/00-总览与公共约定.md` 由集成责任人统一维护；`project/T3code/` 只作参考。 |
