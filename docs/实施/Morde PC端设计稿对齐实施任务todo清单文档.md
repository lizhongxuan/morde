## 修改边界与现状

- 以 `web/portal` 为 PC 用户网页与桌面客户端共用的业务界面，改造导航、对话、任务、电脑、设置、个人数据和目标计划；`web/workbench` 负责真实电脑画面和控制。桌面安装包入口是 `clients/desktop/harness/desktop/src/morde-main.ts`。管理后台和 iOS 页面布局不改，个人数据的 iOS 刷新需配合。
- 云端电脑及其默认 Workspace 应开通后自动配置；用户在对话、任务和电脑工作区中无需重复配置，默认电脑可在设置页修改，默认 Workspace 随所选电脑显示并从设置页进入管理。某项能力不可用时，在用户触发该操作的位置给出可关闭、可恢复的提示；保留同页其他功能，不因局部接口失败跳入全页错误页。
- 设计稿是本地示例，不把示例数据、预览状态或伪窗口按钮搬进产品；保留真实授权、任务、模型、文件、电脑和账户功能。会话相关侧栏只展示当前会话，非对话页不显示会话内容或右侧工作区。

## 接口与状态变化

以下新增名称为拟定合同，实施时与代码、调用方、`server/openapi/portal.yaml`、`docs/实施/00-总览与公共约定.md` 和测试在同一变更中更新；由集成负责人统一生成 Portal 与 Workbench 的 API 类型。

| --- | --- | --- |
| `GET /api/conversations`（已有） | 拟增加可选会话名称搜索参数 `q`，沿用 `cursor`／`limit` 并返回 `items`、`next_cursor`；在服务端限定当前用户，稳定排序，不只搜索已加载页。省略搜索时保留现有行为。 | P03、P04 |
| `GET /api/conversations/{id}/tasks`（已有） | 拟增加 `view=active\|recent`，省略时保留活动任务语义；返回对应 `items`、`next_cursor` 和当前会话待处理数量。继续校验账号、会话、项目和 Host 权限。`/api/tasks` 当前没有会话筛选，不以当前页前端过滤冒充完整结果。 | P03、P05 |
| `POST /api/me/main-conversation/ensure`（已有） | 实际调用为此路径；修正 OpenAPI 中将 POST 放在 `/api/me/main-conversation` 的不一致，保留已初始化、需用户选择和失败行为。 | P03 |
| `POST /api/conversations/{id}/messages` 与项目会话对应接口、长消息上传初始化（已有） | 需要时增加可选 IANA `time_zone`，个人及项目会话的普通消息和分片路径合同一致；旧请求可省略。原客户端消息 ID、实例／账号围栏和幂等规则不变，重试使用原始参数，旧 outbox 不补写而改变已有请求指纹。时间由服务端采样并固定到分流快照；无效或缺失时区不编造用户本地时间。 | P06 |
| `POST /api/hosts/{id}/embed-tickets`（P07 已实现基础单视图合同；P10 扩展） | 增加 `conversation_id`、初始 `target` 和期望 `targets`；服务端按 Host owner／当前共享授权计算可用目标集合，只签发授权范围内的交集并确保初始目标在集合内。服务端生成随机 `embed_nonce`，返回 `exchange_url`、短期单次 `ticket`、同一个 nonce、实际目标权限集合和 `expires_at`，响应禁止缓存。票据／后续 Cookie 绑定服务实例、会话、目标权限上限集合、Host、访问者、Portal 凭据、来源及运行代次；客户端不得自填身份或扩大授权。旧 `/enter` 与 `/observation-ticket` 保持原语义。 | P07 基础、P10 扩展 |
| `POST /__ch/embed-auth`（P08 已实现；P10 扩展浏览器嵌入交换） | 通过 iframe 定向的表单 POST 提交单次 `ticket` 和 `embed_nonce`，避免跨源 JSON fetch 的 CORS 预检依赖；主机只接受受限 `application/x-www-form-urlencoded` 正文，不接受 query ticket。原子消费后建立独立 Host-only、HttpOnly 嵌入 Cookie，303 到不含票据的 Workbench URL，并在 URL 中放入已与票据比对的 nonce／初始视图；响应只向受信 Portal 提供 `strict-origin-when-cross-origin`，不泄露路径或票据。每个请求及长连接持续复核票据权限集合、实时凭据、Host 代次和当前授权。 | P08、P10 |
| Workbench 与 Portal 的嵌入消息（P09 已实现基础协议，P10 接入） | Workbench 通过 `?embed=1&embed_nonce=...` 建立上下文；父源只取受信交换后留下的 `document.referrer` origin。双方校验精确 `origin`、`source`、协议版本、channel 与票据绑定 nonce。消息类型为 `init`、`visibility`、`ready`、`state`，只同步界面状态，不授予控制权；`iframe load` 不代表桌面连接成功。P10 在 ready 后发送 init，之后才可更新可见状态。 | P09、P10 |
| Portal 桌面桥接（拟新增受限 preload） | 仅暴露目标列表、`selectProjectDirectory(hostId, workspaceId)`、用户显式触发的 `uploadProject(selectionId, projectName)` 和最小同步状态／进度；不得通过 Portal 桥透传桌面通用 `publicState()`、账户、安装、映射或其他同步配置。主进程验证可信 Portal 顶层 frame、账号、Host／Workspace 与本次选择授权。浏览器无该能力时提示使用桌面客户端，不开放通用文件／IPC 权限。 | P11、P13 |
| 个人数据 `/api/sync/snapshot`、`/api/sync/changes` 及写入接口（已有） | 复用快照、增量、版本、幂等和附件机制；保存自动提交，回执前保持待提交；PC/iOS 连接、重连及在线时自动获取已确认版本。无需仅为去掉按钮新增同步 API。 | P15、P16 |

## 执行与并行约定

### 推荐执行顺序

已标记完成的任务不重复实现；继续执行未完成任务时，按以下批次和任务依赖推进：

1. **统一布局：P01 → P02。** 先统一顶栏、可折叠侧栏、各页左侧子菜单和标题层级，再将长列表接入屏内分页，避免各页面自行调整造成错位。
2. **对话与任务：P03 → P04 → P05；P06 依赖 P03。** 先定稿会话搜索／任务查询合同，再接入会话、草稿和当前会话工作区，最后验证普通问答与任务分流。
3. **云端电脑：P07 → P08 → P09 → P10 → P11。** 按票据、Gateway 授权、Workbench 嵌入、Portal 面板和桌面窗口／本机桥的顺序联调；已完成的安全与嵌入基础保留证据，只补剩余集成和平台验收。
4. **业务页面与跨端数据：P12、P13、P14、P15、P17；P16 依赖 P15。** 设置、电脑、客户端、个人数据和目标页面复用现有接口；个人数据 PC 保存流程确认后再完成 iOS 自动刷新。P17 可在 P01、P02 后独立验收。
5. **恢复与总验收：P18 → P19 → G1～G3。** 先覆盖错误恢复、剪贴板和输入，再按本地安全边界完成逐页集成；真实服务、平台或跨端条件不可用时保留待验证状态。

可按独占文件并行准备；任务依赖完成后再接入并验证。`web/portal/src/App.tsx`、`components/PortalLayout.tsx`、全局 `styles.css`、`routes/Assistant.tsx`、`app/api.ts`、`server/openapi/portal.yaml`、`00-总览与公共约定.md`、生成的 API 类型，以及 Electron `morde-main.ts` 由各自唯一集成负责人持有。其他负责人只改各任务列出的独立文件或新增专属组件／样式；确需改共享文件时交给负责人串行合并，不并行编辑。

后端 P03、P06、P07、P08 存在共享接口或接线文件；可先分别准备互不重叠的实现，但涉及同一文件、OpenAPI 和公共约定时按任务顺序集成。契约与实现必须在同一变更中一致，生成文件由命令生成，不手改。P04、P05、P10 对 `Assistant.tsx` 的接线串行；P11 统一负责桌面窗口和本机桥，避免多个人同时改 `morde-main.ts`。不覆盖当前工作区已有改动。
