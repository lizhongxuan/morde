## 修改边界与现状

- 以 `web/portal` 为 PC 用户网页与桌面客户端共用的业务界面，改造导航、对话、任务、电脑、设置、个人数据和目标计划；`web/workbench` 负责真实电脑画面和控制。桌面安装包入口是 `clients/desktop/harness/desktop/src/morde-main.ts`。管理后台和 iOS 页面布局不改，个人数据的 iOS 刷新需配合。
- 设计稿是本地示例，不把示例数据、预览状态或伪窗口按钮搬进产品；保留真实授权、任务、模型、文件、电脑和账户功能。会话相关侧栏只展示当前会话，非对话页不显示会话内容或右侧工作区。
- 根目录约定要求**只在本地位置修改，不外发或发送文件**。不向服务、设备或他人发送项目文件、附件、日志、截图及合成测试文件，也不修改远端环境。验证使用本地界面、模拟接口、空目录和元数据；不能将替身结果写成真实文件内容传输通过。项目上传门禁与真实数据面未完成事项沿用 [CFS-11](<Morde云端电脑与项目文件同步实施任务todo清单文档.md>)，本清单不擅自打开门禁。
- 执行任何现有测试或验收脚本前先核对副作用；涉及文件发送或远端修改的用例不运行，并记录未验证，不能把其余测试通过写成整套测试通过。
- 对照工作区现状：PC 的个人数据保存先写本地队列；切换会话会清空未发送输入；Workbench 本地嵌入模式已完成，Portal／Gateway 授权链仍待接入。上一轮 PortalLayout／分页定向测试 8 项及 Portal 类型检查通过；本轮新增的窄主导航、上下文侧栏折叠和默认分类选择尚未复验。P01 的多尺寸浏览器对照、深链回归和 P02 在真实页面中的列表接入仍未验收，因此相关任务保持进行中。

## 接口与状态变化

以下新增名称为拟定合同，实施时与代码、调用方、`server/openapi/portal.yaml`、`docs/实施/00-总览与公共约定.md` 和测试在同一变更中更新；由集成负责人统一生成 Portal 与 Workbench 的 API 类型。

| 接口或模块 | 计划变化与约束 | 归属 |
| --- | --- | --- |
| `GET /api/conversations`（已有） | 拟增加可选会话名称搜索参数 `q`，沿用 `cursor`／`limit` 并返回 `items`、`next_cursor`；在服务端限定当前用户，稳定排序，不只搜索已加载页。省略搜索时保留现有行为。 | P03、P04 |
| `GET /api/conversations/{id}/tasks`（已有） | 拟增加 `view=active\|recent`，省略时保留活动任务语义；返回对应 `items`、`next_cursor` 和当前会话待处理数量。继续校验账号、会话、项目和 Host 权限。`/api/tasks` 当前没有会话筛选，不以当前页前端过滤冒充完整结果。 | P03、P05 |
| `POST /api/me/main-conversation/ensure`（已有） | 实际调用为此路径；修正 OpenAPI 中将 POST 放在 `/api/me/main-conversation` 的不一致，保留已初始化、需用户选择和失败行为。 | P03 |
| `POST /api/conversations/{id}/messages` 与项目会话对应接口、长消息上传初始化（已有） | 需要时增加可选 IANA `time_zone`，个人及项目会话的普通消息和分片路径合同一致；旧请求可省略。原客户端消息 ID、实例／账号围栏和幂等规则不变，重试使用原始参数，旧 outbox 不补写而改变已有请求指纹。时间由服务端采样并固定到分流快照；无效或缺失时区不编造用户本地时间。 | P06 |
| `POST /api/hosts/{id}/embed-tickets`（拟新增） | 请求体包含当前 `conversation_id` 与 `target` 目标视图，返回 `exchange_url`、短期单次 `ticket` 和 `expires_at`，签发响应禁止缓存。服务端校验会话访问及目标权限，并将服务实例、会话、目标、Host、访问者、Portal 会话、来源、权限上限及运行代次绑定票据；客户端会话有安装身份时绑定并持续校验，普通网页使用自身账号与会话授权，不能由客户端自填身份。切换到权限上限之外的视图须重新授权，不能扩张已有共享权限。无权、错 Host、过期和重放拒绝。现有 `/enter` 与 `/observation-ticket` 保持原语义。 | P07 |
| `POST /__ch/embed-auth`（拟新增） | Host 以受限 POST 原子消费票据，建立 Host-only、HttpOnly 的独立嵌入会话并以 303 跳转到无票据地址；每次请求复核实时权限、原 Portal 会话和租约。不得直接把现有 `ch_host` 或任务只读 `ch_task_read` 当作嵌入授权。 | P07、P08 |
| Workbench 与 Portal 的嵌入消息（P09 已实现，P10 接入） | Workbench 通过 `?embed=1&embed_nonce=...` 建立上下文，从 `document.referrer` 限定父源；双方校验精确 `origin`、`source`、协议版本、channel 与 nonce。消息类型为 `init`、`visibility`、`ready`、`state`，只同步界面状态，不授予控制权；`iframe load` 不代表桌面连接成功。P10 在 ready 后发送 init，之后才可更新可见状态。 | P09、P10 |
| Portal 桌面桥接（拟新增受限 preload） | 仅暴露目标列表、`selectProjectDirectory(hostId, workspaceId)`、`uploadProject(selectionId, projectName)` 和状态／进度订阅；主进程验证可信 Portal 顶层 frame、账号、Host／Workspace 与本次选择授权。浏览器无该能力时提示使用桌面客户端，不开放通用文件／IPC 权限。 | P11、P13 |
| 个人数据 `/api/sync/snapshot`、`/api/sync/changes` 及写入接口（已有） | 复用快照、增量、版本、幂等和附件机制；保存自动提交，回执前保持待提交；PC/iOS 连接、重连及在线时自动获取已确认版本。无需仅为去掉按钮新增同步 API。 | P15、P16 |

## 执行与并行约定

可按独占文件并行准备；任务依赖完成后再接入并验证。`web/portal/src/App.tsx`、`components/PortalLayout.tsx`、全局 `styles.css`、`routes/Assistant.tsx`、`app/api.ts`、`server/openapi/portal.yaml`、`00-总览与公共约定.md`、生成的 API 类型，以及 Electron `morde-main.ts` 由各自唯一集成负责人持有。其他负责人只改各任务列出的独立文件或新增专属组件／样式；确需改共享文件时交给负责人串行合并，不并行编辑。

后端 P03、P06、P07、P08 存在共享接口或接线文件；可先分别准备互不重叠的实现，但涉及同一文件、OpenAPI 和公共约定时按任务顺序集成。契约与实现必须在同一变更中一致，生成文件由命令生成，不手改。P04、P05、P10 对 `Assistant.tsx` 的接线串行；P11 统一负责桌面窗口和本机桥，避免多个人同时改 `morde-main.ts`。不覆盖当前工作区已有改动。
