## 1. 怎么使用

固定三个会话：**A 服务端与云端 DSH、B PC、C iOS**。A 同时负责公共合同和集成，不增加第四个主控会话。每份 TODO 只有 3–4 项任务；同一会话按顺序领取自己的下一份，不同时打开该会话名下的两份文件开发。

先完成 [A00](A00-公共合同与隔离基线实施任务todo清单文档.md)，再并发推进 A10/B10/C10。接口、文件和环境分别隔离；最终联调和公共合同变更需要串行关口，不能承诺三个会话从头到尾完全没有依赖或始终同时忙碌。

## 4. 公共合同与交接

公共接口目录见 [01-共享接口与联调合同](01-共享接口与联调合同.md)。它是目标合同，不冒充已经实现的 OpenAPI。A00 冻结目标与合成样例；A 在对应实现变更中同步正式 OpenAPI、实现和测试，B/C 使用该版本。

发现合同问题时，B/C 在自己的任务记录中写明“调用、预期、实际、需要的字段/行为”，交 A 处理。A 更新公共合同并公布新本地基线后，相关消费者再同步；不得自己改服务端、扩大权限或私加备用 API。合同变更期间仅暂停受影响任务，其他独立任务继续。

每份清单交付只报告：

1. 完成的任务编号及未完成项。
2. 本地 worktree/分支、可合入的本地提交或变更位置。
3. 依赖的合同版本和基础代码版本。
4. 已执行验证、使用替身的范围及结果。
5. 必须由其他会话处理的交接项。

A 只在自己的集成分支顺序合入，核对文件范围、合同和验证；通过后发布新的本地基线。B/C 自行同步基线，不让 A 操作正在开发的工作区。没有代码提交时，先由所属会话整理可复现的本地交付，不复制整个目录覆盖他人文件。

## 5. 隔离工作区与测试环境

正式开发获得授权后，再建立三个独立本地 worktree，建议分支名为 codex/muse-a-server、codex/muse-b-pc、codex/muse-c-ios。本轮不创建它们。

- 基础代码必须包含已接受的必要改动；不得从缺少前置成果的旧 HEAD 开始，不自动暂存或提交用户的无关文件。
- 当前 /docs/ 被已有 Git 规则忽略，worktree 不会自动带入本文档。各会话直接读取主目录 /Users/zhongxuan_li/Desktop/morde/docs/实施/Morde个人Muse三会话并行实施/；只更新自己名下的清单。公共状态由 A 更新，不修改忽略规则或强制加入 Git。
- A/B/C 各自使用临时数据目录、数据库、模型替身、端口、容器/卷、桌面用户资料、构建输出和测试缓存。名称加入会话字母与本次运行标识；启动前检查端口空闲，清理只针对自己创建的资源。
- 三个会话都可以启动自己版本的服务端进行验证，但 B/C 只能运行冻结的服务端代码，不能改它，也不能借用 A 正在运行的服务或数据库。
- B/C 的跨端边界检查可使用冻结的另一端版本或注明范围的协议替身，不等待彼此的最终验收记录。两端同时操作同一消息、Task 和审批的真实验证，由 A 在关口使用同一独立集成环境执行。
- C 使用独立 iOS Simulator 与 DerivedData；B 使用独立 Electron 用户资料；A 的集成 fixture 另建，不复用任一开发 fixture。
- 本机前台鼠标/键盘、内置浏览器和同一模拟器是共享资源。可视化操作预约串行时间段；其他会话继续代码或无界面测试，不争抢焦点。
- 全部验证用本地合成资料和隔离环境；禁止连接真实在线应用、外发文件、push、远程 PR、公开发布。所谓 PC 到云的传输，在本轮验证中只发生于本机隔离端点。

## 6. 通用完成条件

只有实现及本任务要求的验证完成才勾选。状态使用未开始、进行中、待验证、完成、阻塞；缺条件写明具体缺什么，不能把未启动任务写成阻塞。

- A 的服务端改动遵守 server/AGENTS.md：make lint、make test race cover、make generate；涉及数据库时用独立临时 PostgreSQL 执行集成检查。云端 DSH 改动运行其 npm test，并按根 AGENTS.md 先核对已有 DSH 插件，不自建第二套循环。
- B 运行改动包的现有 typecheck/test；Web 类型由 B 根据 A 发布的正式 OpenAPI 生成。PC 页面用内置浏览器验证，文件 helper 同时验证真实文件边界；模拟结果不能代替 Electron/文件链路。
- C 遵守 iOS AGENTS.md，使用既有工程与 scheme，新增文案同步 Localizable.xcstrings。Swift 单测、模拟器 UI 和最终真机验证分开记录。
- 所有版本升级、生成物、迁移和构建脚本仍按第 2 节独占；没有必要不新增依赖。每个关口只重跑受影响验证和必须检查，最终由 A 汇总完整链路证据。
