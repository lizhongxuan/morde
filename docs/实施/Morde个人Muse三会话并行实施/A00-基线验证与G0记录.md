## 本地隔离服务资源与限制

当前可复核的 Portal fixture 由独立 linux_fixture 会话创建并持有，配置说明位于仓库根 `.local/morde-a00-linux-fixture-20261109/README.md`。A00 只读该说明，并对运行端点做只读请求；没有启动、停止、改写或清理该 fixture。容器为 `morde-a00-linux-fixture-20261109-portal-final` 与 `morde-a00-linux-fixture-20261109-postgres`，数据库卷为 `morde-a00-linux-fixture-20261109-pgdata`。Portal API 经 `fixture-helper` 从容器 loopback 转到宿主 `127.0.0.1:7080`；Docker inspect 确认宿主绑定为 loopback。数据库和应用数据均为合成数据；本地 OpenSandbox list 为 stub。

本机只读复验命令与结果：

```bash
curl -fsS -o /dev/null -w 'healthz HTTP %{http_code}\n' http://127.0.0.1:7080/healthz
curl -fsS -o /dev/null -w 'readyz HTTP %{http_code}\n' http://127.0.0.1:7080/readyz
docker exec morde-a00-linux-fixture-20261109-portal-final \
  /fixture/portal migrate status --config /fixture/portal.yaml
curl -sS -o /dev/null -w 'synthetic admin login API HTTP %{http_code}\n' \
  -H 'Content-Type: application/json' --data '{"name":"admin","password":"admin"}' \
  http://127.0.0.1:7080/api/auth/login
docker inspect morde-a00-linux-fixture-20261109-portal-final \
  --format 'state={{.State.Status}} portbindings={{json .HostConfig.PortBindings}}'
```

回执依次为 `200`、`200`、`current=170 latest=170`、`200`、容器运行中且仅映射宿主 `127.0.0.1:7080`。Fixture README 和脱敏证据记录合成管理员密码变更、重登，以及 `/api/me` 和管理员 overview API 的 2xx；这不证明 `/admin/login` UI。模型能力检查返回 HTTP 200、`text=true`；Portal `POST /api/model/v1/chat/completions` 返回 HTTP 200、`A00 synthetic model response.` 及 usage input=1/output=5；stub receipt 共两条（探测、完成），见 `model-completion-response.json`、`model-stub-receipts.jsonl`、`model-portal-requests.log`、`model-stub-logs.txt`、`post-model-request-evidence.txt`。这是 Portal→本地 model stub 的动态验证，不证明 DSH Task/Agent 或真实模型。readyz 由空列表 OpenSandbox stub 满足，不代表真实 sandbox 可执行能力。Fixture agent 对隔离数据库的只读检查发现预置合成默认 Host `hdssbyzu`（13:43 创建）为 stopped、`sandbox_id` 为空，并有空的 Default Workspace；两项均非该 agent 创建/启动/修改，A00 也未触碰，不证明 Host/Workspace 可执行或同步能力。PC Electron UI、iOS UI、Host runtime、Workspace Sync 与真实模型未验收。

## A00-T1 最终可复现 Portal 与模型替身验证

G0 的动态 Portal/model 证据采用独立 linux_fixture 会话的本地 Docker Portal/PG 与模型 stub，README 和脱敏证据保存在仓库根 `.local/morde-a00-linux-fixture-20261109/`。A00 只读取 README/evidence，并从宿主 loopback 对服务端点做只读验证，没有启动、停止、改写或清理该 fixture。README 记载 Portal 和 PostgreSQL 容器、独立数据卷、loopback 7080 host binding、restart/stop 命令和本地模型请求重放方式；删除容器/卷的清理命令未授权、未执行。

实际 Portal 模型请求（使用 fixture 本机 mode-0600 session cookie jar；凭据本身不写入本记录）：

```bash
FIXTURE_DIR=.local/morde-a00-linux-fixture-20261109
curl -sS -o "$FIXTURE_DIR/model-completion-response.json" \
  -w 'Portal chat completion HTTP %{http_code}\n' \
  -b "$FIXTURE_DIR/session-cookies.txt" \
  -H 'Origin: http://127.0.0.1:7080' \
  -H 'Idempotency-Key: a00-fixture-completion-001' \
  -H 'Content-Type: application/json' \
  --data '{"model":"ppyhbswv","messages":[{"role":"user","content":"Reply with a short local fixture confirmation."}],"max_tokens":32}' \
  http://127.0.0.1:7080/api/model/v1/chat/completions
```

回执为 HTTP 200，助手内容为 `A00 synthetic model response.`，usage 为 1 输入 / 5 输出 token；同一 stub 另收到 Portal 的文本能力探测请求，合计两条 Portal receipt。README 说明合成管理员初始口令通过 Portal API 修改，替换值只存在本机 mode-0600 文件；脱敏日志还确认重登、`GET /api/me` 与管理员 overview API 成功。模型 connection ID、response、probe、request hit 与 Portal HTTP 记录分别在同目录 `model-connection.json`、`model-completion-response.json`、`model-capability-check.json`、`model-stub-receipts.jsonl`、`model-stub-logs.txt`、`model-portal-requests.log` 和 `post-model-request-evidence.txt`。这些日志不含模型 key/cookie；A00 未读取保存合成密码的文件。

这个测试只证明 Portal model API 经本地 CONNECT proxy 到合成 Responses stub；`cloud_dsh` 关闭，未验证 DSH Task/Agent、Host runtime/电脑工具、Workspace Sync、真实 OpenSandbox、`/admin/login` UI 或 PC Electron/iOS UI。README 表明 network guard/DNS/hosts 未改动，proxy 只接受规定 CONNECT target 并固定拨到 loopback stub，没有外网请求。当前 Docker fixture 由其所有者持有；需重启或停止时仅按 README 的命令且由所有者在父会话安排；A00 没有清理其容器、网络或卷。
