# Morde 个人 Muse：共享接口与联调合同

日期：2026-11-09。合同版本：`muse-a00-v1`。状态：目标合同；除 K1 指向的既有接口外，K2–K4 均未实现，也不等于正式 OpenAPI。

来源：[需求与架构](../../Morde个人Muse需求与架构设计方案.md)、[公共约定](../../00-总览与公共约定.md)第 16.7 节和本地合成样例[文件](.local/muse-a00-contract-v1.json)。当前正式字段仍以 `server/openapi/portal.yaml` 为准。A/B/C 本轮统一使用 `muse-a00-v1`，实现变更需由 A 同步 OpenAPI、服务端、测试和本合同，再通知客户端。

## 版本和通用规则

- 所有新字段和端点为拟新增目标。客户端不得因 fixture 可解码而假定服务端已经实现。
- 继续使用 Morde 的账号、Conversation、Task、消息、审批、设备安装、目录授权和文件存储；不新增客户端 Agent、本机执行循环、第二个会话 API 或另一套 Task 状态机。
- 未经服务端鉴权、对象归属、当前授权版本和任务修订校验，不处理事件、审批或 PC 文件请求。对象不存在和调用方无权访问时可统一返回 `not_found`，避免泄露对象存在性。
- 空集合使用 `[]`，可选对象缺省或 `null` 的含义按正式 OpenAPI 统一。绝对路径、模型/设备凭据、访问令牌、PC 根目录和未验证的文件内容不得进入客户端 DTO、日志或事件载荷。
- 现有错误码沿用 `server/internal/domain/error.go` 与 OpenAPI：`unauthenticated`、`forbidden`、`not_found`、`conflict`、`idempotency_conflict`、`invalid_state`、`quota_exceeded`、`request_too_large`、`transfer_expired`、`workspace_unavailable` 等。设备离线是可恢复状态，不是同步请求失败。新增错误码只有在对应实现同步更新错误注册、HTTP 映射、OpenAPI 和测试时才可引入。

## K1：先持久受理用户消息

继续调用现有 `POST /api/conversations/{id}/messages`；不创建替代聊天路由。

- 请求中的 `client_message_id` 必须等于 `Idempotency-Key`。`previous_client_message_id` 只表示该客户端连续发送的前序引用；它不替代服务端顺序和归属校验。显式 `reference_task_id` 是目标提示，仍须由服务端核验调用方有权访问且目标状态允许。
- 服务端持久化消息及路由收据后返回现有 `AcceptedConversationMessageResponse`。接受表示消息已保存，不表示已创建 Task、模型已响应或执行已开始。
- 同一 owner、Conversation、幂等键及规范化请求摘要重试，返回原消息/收据且 `replayed=true`；同键不同内容返回 `idempotency_conflict`。断连或超时后客户端先按原 ID 对账，不生成新 ID 盲目重发。
- 原消息是否存在、路由状态和 Task 状态各自使用正式 DTO；不新增客户端对账数据库或状态别名。

## K2：Task 依赖、子任务与结果审阅投影

沿用 `GET /api/tasks/{id}`、任务列表和现有 Task 事件。目标版本在 Task 投影中增加：

| 字段 | 类型和规则 |
| --- | --- |
| `dependencies` | 数组；每项为 `{task_id, required_revision, task_status, satisfied}`。`task_status` 复用既有 `TaskStatus`；仅目标 Task 的指定修订完成后 `satisfied=true`，失败、取消和迟到的旧修订不能满足依赖。 |
| `child_jobs` | 数组；每项为 `{job_id, task_step_id, title, task_revision, status}`。`job_id` 是不透明 DSH 子会话 ID，不是可单独授权的 Task；`status` 复用既有 `TaskStepStatus`（`queued / running / waiting_user / succeeded / failed / unknown`）。 |
| `result_review` | 可空对象 `{state, source_task_id, source_task_revision, source_event_sequence, reply_message_id}`；`state` 为 `pending / processing / published / failed`。它只表达主协调会话对结果事件的处理进度，不改变来源 Task 状态；无待审阅结果时为 `null`。 |

所有数组必须非 null。`Task.status` 仍只使用既有 `queued / running / waiting_user / pausing / paused / cancelling / completed / failed / cancelled`；`TaskStepStatus` 仅描述 Task 内的步骤/子会话，不新增 Task 状态机。文件取回状态单独描述传输，不反向推导 Task 状态。

## K3：主协调事件消费与去重

内部事件消费复用 Morde 持久消息、Task 和审批记录；它是服务端合同，不要求 iOS/PC 自行 ACK 或直连 DSH。每个待消费事件提供以下公共字段；事件身份由下表中的现有来源字段构成，不另生成随机 `event_id`：

```text
service_instance_id, owner_id, conversation_id, source,
payload_sha256, authorization_version, occurred_at
```

稳定消费键按来源构成，并共同限定在 `(service_instance_id, owner_id, conversation_id)` 下：

| `source` | 来源身份字段 | 完整去重身份 |
| --- | --- | --- |
| `message` | `message_id` | `service_instance_id + owner_id + conversation_id + source + message_id` |
| `task_result` | `task_id + task_revision + result_event_sequence` | `service_instance_id + owner_id + conversation_id + source + task_id + task_revision + result_event_sequence` |
| `approval_reply` | `task_id + request_id + revision` | `service_instance_id + owner_id + conversation_id + source + task_id + request_id + revision` |

来源身份字段取自已持久化的 Morde 记录；不存在的来源字段省略，不能造 ID。若结果来自 DSH 子会话，`job_id` 可作为来源元数据记录，但不替代 Task 结果身份。

- 上述完整去重身份在同一事务中只能产生一条处理收据。调用方身份、事件来源和当前授权需由 Go 应用层重新校验；快照中的 `authorization_version` 用于拒绝过期授权，不授予权限。DSH 是唯一 Agent Runtime，不直接接受客户端权限声明。
- 消费结果与业务动作或“已持久延期”收据原子提交后才确认。精确重复返回已保存处理结果；相同身份键而 `payload_sha256` 不同返回 `idempotency_conflict` 并写安全审计，不能第二次执行。
- 模型/工具结果未知时保存可见的 `unknown`/待审阅信息并先对账，不确认成功、不重新派发副作用。暂停或失败不得丢弃原始 Task 结果。

## K4：PC 按需文件取回、撤权与副本清理

K4 参数版本为 `muse-k4-v1`。文件请求由 DSH `file.fetch` 工具经 Go 应用层授权，不新增模型或客户端直连的第二套 Task 入口。现有 PC Hub 授权每个安装只有一个当前选中目录根；本版用 `source_installation_id + target_grant_version` 绑定该目录授权，路径只能是相对此根的相对路径，不接受绝对路径或模型输入的目录名。将来若一个安装支持多个目录，须另发 K4 版本并引入显式目录 grant ID。PC 继续经现有认证 Hub 主动连接，不开放 PC 入站公网端口。

首批文件与解析器固定如下：

| 文件类型 | K4 v1 规则 |
| --- | --- |
| `.txt`、`.md`、`.csv`、`.json` | 仅接受有效 UTF-8（拒绝 NUL）；由 `utf8-text-v1` 作为不可信纯文本读取，JSON 先校验语法，CSV 不执行、不导入。 |
| `.docx`、`.xlsx`、`.pptx` | 复用现有有界安全 OOXML 提取器 `morde-ooxml-v1`；拒绝宏、外部关系、解压越界或格式不符，只将提取的文本和有界 PPTX 图片作为不可信输入。 |
| `.pdf` | 允许取回原始 PDF；当前没有 PDF 原件解析器，解析状态明确为 `raw_only`，不把 PDF 原始字节直接放入模型输入。 |
| 其他格式 | v1 拒绝，不根据扩展名猜测类型。 |

服务端给 DSH 的文件工具输出最多 64 KiB；OOXML 文本提取最多 48 KiB。PPTX 最多附带 4 张内嵌图片，单张最多 512 KiB、合计最多 2 MiB，图片解码尺寸最多 1280×720。超出安全输出上限时保留传输成功状态并记 `parse_status=failed, parse_error=result_too_large`；格式/编码无效记 `invalid_document`/`invalid_encoding`。文本解析结果必须以不可信数据提示开头，模型不得将文件内容当指令执行。

| 限额/寿命 | K4 v1 参数 |
| --- | ---: |
| 单文件最大尺寸 | 16 MiB |
| 单块最大尺寸 | 512 KiB；块号从 0 开始，末块可更短；最多 32 块 |
| 每账号 staging 上限 | 64 MiB，按 manifest 声明的大小原子预留 |
| 每账号未过期副本上限 | 300 MiB，按已提交文件尺寸计费 |
| 每 Task 取回数 | 最多 16 条，含等待、失败及未过期完成记录 |
| PC 传输 ticket | 256-bit 随机不透明值；只存 SHA-256；有效 5 分钟；不放 URL、模型输入或 Portal/iOS 响应 |
| 未完成 staging | 最长 1 小时 |
| 已完成云端副本 | 完成后保留 7 天；Task 所有者可提前删除 |
| 清理 worker | 每 15 分钟调度，每轮至多处理 500 条；清理失败留待后续轮次重试 |

状态与副本管理仅允许 Task 所有者 Portal Session 调用；服务端不得在客户端凭证或 iOS 响应中暴露 PC 传输票据。A30-T1 实现持久取回记录、授权工具和单条状态查询；A30-T2 实现以下数据面及副本管理路由：

| 方法与路径（拟新增） | 用途 |
| --- | --- |
| `GET /api/tasks/{id}/file-fetches/{fetch_id}` | Task 所有者 Portal Session 查询该 Task 下取回的持久状态和进度；响应 `Cache-Control: no-store`。 |
| `GET /api/tasks/{id}/file-fetches` | Task 所有者 Portal Session 查询最近 16 条记录；返回 `{items: TaskFileFetch[]}`，包括内容状态和删除时间；响应 `Cache-Control: no-store`。 |
| `POST /api/tasks/{id}/file-fetches/{fetch_id}/manifest` | 目标 PC 提交 `{source_version, source_sha256, size_bytes, media_type}`；服务端固定快照清单并原子预留账号 staging 额度，返回已确认块序号。 |
| `PUT /api/tasks/{id}/file-fetches/{fetch_id}/chunks/{sequence}` | 目标 PC 上传 `application/octet-stream` 原始分块，以 `Authorization: Bearer <ticket>` 鉴权并带 `X-Chunk-SHA256`；块体不超过 512 KiB。 |
| `POST /api/tasks/{id}/file-fetches/{fetch_id}/commit` | 请求体为 `{source_version, source_sha256, size_bytes}`；完整核验大小、摘要、Task 修订与授权后原子发布云端副本；不得发布部分内容。 |
| `POST /api/tasks/{id}/file-fetches/{fetch_id}/cancel` | Task 所有者 Portal Session 请求停止；服务端串行化后撤销票据并清理 staging，再显示 `cancelled`。不能用取消接口删除已完成副本。 |
| `GET /api/tasks/{id}/file-fetches/{fetch_id}/content` | Task 所有者读取已提交副本；继续校验当前 Task 归属、内容状态和整文件摘要。 |
| `DELETE /api/tasks/{id}/file-fetches/{fetch_id}/content` | 显式删除已完成的云端副本。要求 Task 所有者身份；目录被撤权或源 PC 离线不妨碍删除。成功后保留 `content_state=deleted` 和 `deleted_at`，阻止后续读取；不更改 PC 原文件、不删除 Task 历史文字或伪称擦除了模型已读内容。重复删除返回 204。 |

PC 的 manifest/chunk/commit 接口仅接受短期 file-fetch ticket。`fetch_id` 是服务端生成的不透明 ID，正则 `^o[a-z0-9]{7}$`（8 字符）；在该 Hub `file.fetch` call 中，`args.fetch_id` 必须与 `from.operation_id` 完全相同。服务端 Task 操作账本继续用 provider call 的稳定幂等键关联同一条 fetch 记录。ticket 为 32 随机字节的 canonical unpadded base64url（43 字符），绑定 `fetch_id`、目标 `source_installation_id`、Task/修订、`target_grant_version` 和有效期；只通过已认证 Hub 的 `file.fetch` call args 交给目标 PC。`ticket_expires_at` 是服务端生成的 RFC3339 UTC 时间；客户端可校验格式，但不得依据本机时钟将票据判作过期或未来，服务端时钟是唯一有效性权威。Hub 的 server-generated caller context 将 `task_id`、`task_revision`、`authorization_version`、`target_grant_version`、`operation_id` 平铺在 `from`；`task_revision` 只在 `file.fetch` 中提供，旧动作可以缺省。`file.fetch` 模型工具只接受 `{path}`，服务端派生其余字段。在线时 PC 对这次同步调用最终返回安全提交收据 `{fetch_id, task_revision, target_grant_version, status:"completed", source_version, source_sha256, size_bytes, content_id, expires_at}`；Go 仅在服务端记录已由 commit 路由提交且所有回执字段一致时确认完成。离线时服务端持久记录 `waiting_device`，不伪报完成。ticket 绝不进入 Task 结果、事件、Portal 状态或 DSH 模型输入；服务端只保存 ticket 的 SHA-256。允许解析的文件会以明确标记的“不可信数据”作为 DSH 工具结果输入；PDF 原始字节不进模型。Task 事件和 Portal 状态仅暴露安全状态字段及 `fetch_id`。每个数据请求都重新校验绑定、当前 Task 授权和修订、安装状态与票据有效期。用户侧查询、取回内容、取消和删除只接受 Task 所有者 Portal Session；无权访问和不存在统一隐藏为 `404 not_found`。PC 不获得 Portal Session、API key 或目录外路径能力。

`manifest` 请求体为 `{source_version, source_sha256, size_bytes, media_type}`，响应为 `{fetch_id, source_version, status, confirmed_sequences}`；`status` 只允许 `transferring`、`verifying` 或精确重放已提交记录时的 `completed`，`confirmed_sequences` 必须是非 null 的 0 起始已确认块序号数组。`manifest` 必须声明 PC helper 固定的 `source_version`、完整源 SHA-256、字节数及媒体类型；文件大小须大于 0 且不超过 16 MiB。`PUT chunks/{sequence}` 成功响应为 `{fetch_id, sequence, confirmed_bytes, replayed}`。分块请求原样传字节，`sequence` 唯一绑定该块，精确重复只返回原确认，摘要或内容不一致返回 `conflict`。块可断点续传，但只能复用同一 `fetch_id + source_version + source_sha256`。Hub 调用结果未知或断线时，服务端先对账原 fetch；仍在进行的 fetch 使用同一 `fetch_id` 和新票据重放，manifest 返回已确认序号，不新建记录或重复发布。若 fetch 已完成，服务端根据已提交记录恢复安全回执而不重放 Hub 调用。`commit` 请求体为 `{source_version, source_sha256, size_bytes}`，完成后返回安全提交收据 `{fetch_id, task_revision, target_grant_version, status:"completed", source_version, source_sha256, size_bytes, content_id, expires_at}`；只有全部块齐全、整文件哈希吻合、Task/安装/目录授权仍有效时才发布；缺块不得提交。PC 调用结果必须等到 commit 完成才上报 `status:"completed"`。

取回状态单独表达传输生命周期，不是 Task 状态：`queued / waiting_device / transferring / verifying / completed / cancelling / cancelled / failed`。文件副本使用独立 `content_state=none / retained / deleted / expired`；删除时写 `deleted_at`，到期清理后显示 `expired`。解析状态与传输状态分离：`parse_status=pending / extracted / raw_only / failed / unavailable`，`parse_error` 仅可为 `invalid_encoding / invalid_document / result_too_large / content_unavailable / integrity_failed`。transfer 已完成但解析失败时，`status` 仍为 `completed`，通过 `parse_status/parse_error` 显示内容未能安全交付。查询投影至少包含 `fetch_id`、`task_id`、`source_installation_id`、显示用 `source_device_name`、`relative_path`、`task_revision`、经 PC manifest 确认后固定的 `source_version`、`source_sha256`、`media_type` 和 `size_bytes`、`confirmed_bytes`、`status`、可空 `waiting_reason`、可空 `content_id`/`expires_at`/`deleted_at`、`content_state`、`parse_status` 和 `parse_error`。`GET /api/tasks/{id}/file-fetches` 以 `{items: [...]}` 返回最近 16 条安全投影。K4 v1 尚无服务端目录 grant 标识或目录显示名，因此查询不返回 `source_directory_name`；目录身份由 `source_installation_id + target_grant_version` 绑定。`waiting_reason` 最小集合是 `device_offline`；云端文件取回接口返回原始字节，Task 仅接收安全解析的文本或受限图片；PDF 始终 raw-only。

真实本地 HTTP 联调使用测试专用 Go fixture（只在 `go test` 测试二进制中注册，绑定 `127.0.0.1`）：在 `server/` 运行 `CH_K4_FIXTURE=1 go test ./internal/store/postgres -run '^TestK4NodeHTTPFixture$' -count=1 -v`，并设置指向本机 PostgreSQL 的 `CH_TEST_DATABASE_URL`。Fixture 创建独立临时数据库、真实迁移/store/API 路由及合成 Task/fetch/ticket，打印 `K4_FIXTURE_READY {"base_url":"http://127.0.0.1:<port>","task_id":"<task>","fetch_id":"o.......","ticket":"<base64url>","task_revision":1,"target_grant_version":5,"chunk_bytes":524288,"max_file_bytes":16777216}`。客户端完成请求后 POST `{base_url}/__test/k4-fixture/shutdown`；测试清理数据库并退出。该 shutdown 路由不进入生产 API。

- 用户级 Portal Session 或既有 client credential 负责身份；服务端仍逐次核验 Task 所有权、目录授权版本、安装身份及当前任务修订。Hub 每条消息与每块数据都核验同一绑定；凭据只在既有受信服务端路径使用。
- PC 离线时持久返回 `waiting_device` 状态，不报告文件传输成功；该状态查询为 `200`，文件传输端点不得伪造已完成回执。源文件在读取期间变化、摘要不一致、授权撤销或修订变更时停止接收后续数据并丢弃未完成 staging；通过现有错误码安全表达失败原因，不能发布部分文件。精确重试返回原收据/状态，改变 manifest 或已确认块内容返回现有 `conflict`/`idempotency_conflict`。
- 撤权阻止新的请求和在途后续数据接收；取消、撤权、失败和过期时清理未完成 staging。撤权前已完成副本不因撤权立即删除，按上表保留 7 天或由用户显式删除；目录撤权不自动回写/删除 PC 源文件。账号额度由 manifest 原子预留、commit 结算或取消/过期释放，不能依赖单进程计数。
- 错误映射：未登录用 `unauthenticated`；无权用 `forbidden` 或隐藏资源时用 `not_found`；幂等冲突用 `idempotency_conflict`；状态不允许用 `invalid_state`；源版本/校验冲突用 `conflict`；请求或单文件限制用 `request_too_large`/`quota_exceeded`；过期续传用 `transfer_expired`；暂时无法写入文件存储用 `workspace_unavailable`。映射在正式 OpenAPI 中固定后才可实现。

## 兼容、验收与交接

K1 的现有 API 是 A10/B10/C10 的唯一消息入口。G0 的本地样例验证成功/重试、并发 Task 与修订、子会话结果、审批稳定身份，以及文件离线、源变化、撤权、取消和副本删除均可表达；不验证未实现的新路由。A20/A21/A30 分别在实现时落 K2/K3/K4，维护迁移前兼容数据并更新正式 OpenAPI。B/C 可以先依此目标映射自己的类型/界面，不得为 fixture 改写客户端之外的服务端契约或加入备用 API。
