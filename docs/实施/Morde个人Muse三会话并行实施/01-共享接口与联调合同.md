# Morde 个人 Muse：共享接口与联调合同

日期：2026-11-09。合同版本：`muse-a00-v1`。状态：目标合同；除 K1 指向的既有接口外，K2–K4 均未实现，也不等于正式 OpenAPI。

来源：[需求与架构](../../Morde个人Muse需求与架构设计方案.md)、[公共约定](../../00-总览与公共约定.md)第 16.7 节和本地合成样例[文件](.local/muse-a00-contract-v1.json)。当前正式字段仍以 `server/openapi/portal.yaml` 为准。A/B/C 本轮统一使用 `muse-a00-v1`，实现变更需由 A 同步 OpenAPI、服务端、测试和本合同，再通知客户端。

## 版本和通用规则

- 所有新字段和端点为拟新增目标。客户端不得因 fixture 可解码而假定服务端已经实现。
- 继续使用 Morde 的账号、Conversation、Task、消息、审批、设备安装、目录授权和文件存储；不新增客户端 Agent、本机执行循环、第二个会话 API 或另一套 Task 状态机。
- 未经服务端鉴权、对象归属、当前授权版本和任务修订校验，不处理事件、审批或 PC 文件请求。对象不存在和调用方无权访问时可统一返回 `not_found`，避免泄露对象存在性。
- 空集合使用 `[]`，可选对象缺省或 `null` 的含义按正式 OpenAPI 统一。绝对路径、模型/设备凭据、访问令牌、PC 根目录和未验证的文件内容不得进入客户端 DTO、日志或事件载荷。
- 现有错误码沿用 `server/internal/domain/error.go` 与 OpenAPI：`unauthenticated`、`forbidden`、`not_found`、`conflict`、`idempotency_conflict`、`invalid_state`、`quota_exceeded`、`request_too_large`、`transfer_expired`、`workspace_unavailable` 等。设备离线是可恢复状态，不是同步请求失败。新增错误码只有在对应实现同步更新错误注册、HTTP 映射、OpenAPI 和测试时才可引入。

## K1：先持久受理用户消息

继续调用现有 `POST /api/conversations/{id}/messages`；不创建替代聊天路由。

- 请求中的 `client_message_id` 必须等于 `Idempotency-Key`。`previous_client_message_id` 只表示该客户端连续发送的前序引用；它不替代服务端顺序和归属校验。显式 `reference_task_id` 是目标提示，仍须由服务端核验调用方有权访问且目标状态允许。
- 服务端持久化消息及路由收据后返回现有 `AcceptedConversationMessageResponse`。接受表示消息已保存，不表示已创建 Task、模型已响应或执行已开始。
- 同一 owner、Conversation、幂等键及规范化请求摘要重试，返回原消息/收据且 `replayed=true`；同键不同内容返回 `idempotency_conflict`。断连或超时后客户端先按原 ID 对账，不生成新 ID 盲目重发。
- 原消息是否存在、路由状态和 Task 状态各自使用正式 DTO；不新增客户端对账数据库或状态别名。

## K2：Task 依赖、子任务与结果审阅投影

沿用 `GET /api/tasks/{id}`、任务列表和现有 Task 事件。目标版本在 Task 投影中增加：

| 字段 | 类型和规则 |
| --- | --- |
| `dependencies` | 数组；每项为 `{task_id, required_revision, task_status, satisfied}`。`task_status` 复用既有 `TaskStatus`；仅目标 Task 的指定修订完成后 `satisfied=true`，失败、取消和迟到的旧修订不能满足依赖。 |
| `child_jobs` | 数组；每项为 `{job_id, task_step_id, title, task_revision, status}`。`job_id` 是不透明 DSH 子会话 ID，不是可单独授权的 Task；`status` 复用既有 `TaskStepStatus`（`queued / running / waiting_user / succeeded / failed / unknown`）。 |
| `result_review` | 可空对象 `{state, source_task_id, source_task_revision, source_event_sequence, reply_message_id}`；`state` 为 `pending / processing / published / failed`。它只表达主协调会话对结果事件的处理进度，不改变来源 Task 状态；无待审阅结果时为 `null`。 |

所有数组必须非 null。`Task.status` 仍只使用既有 `queued / running / waiting_user / pausing / paused / cancelling / completed / failed / cancelled`；`TaskStepStatus` 仅描述 Task 内的步骤/子会话，不新增 Task 状态机。文件取回状态单独描述传输，不反向推导 Task 状态。

## K3：主协调事件消费与去重

内部事件消费复用 Morde 持久消息、Task 和审批记录；它是服务端合同，不要求 iOS/PC 自行 ACK 或直连 DSH。每个待消费事件提供以下公共字段；事件身份由下表中的现有来源字段构成，不另生成随机 `event_id`：

```text
service_instance_id, owner_id, conversation_id, source,
payload_sha256, authorization_version, occurred_at
```

稳定消费键按来源构成，并共同限定在 `(service_instance_id, owner_id, conversation_id)` 下：

| `source` | 来源身份字段 | 完整去重身份 |
| --- | --- | --- |
| `message` | `message_id` | `service_instance_id + owner_id + conversation_id + source + message_id` |
| `task_result` | `task_id + task_revision + result_event_sequence` | `service_instance_id + owner_id + conversation_id + source + task_id + task_revision + result_event_sequence` |
| `approval_reply` | `task_id + request_id + revision` | `service_instance_id + owner_id + conversation_id + source + task_id + request_id + revision` |

来源身份字段取自已持久化的 Morde 记录；不存在的来源字段省略，不能造 ID。若结果来自 DSH 子会话，`job_id` 可作为来源元数据记录，但不替代 Task 结果身份。

- 上述完整去重身份在同一事务中只能产生一条处理收据。调用方身份、事件来源和当前授权需由 Go 应用层重新校验；快照中的 `authorization_version` 用于拒绝过期授权，不授予权限。DSH 是唯一 Agent Runtime，不直接接受客户端权限声明。
- 消费结果与业务动作或“已持久延期”收据原子提交后才确认。精确重复返回已保存处理结果；相同身份键而 `payload_sha256` 不同返回 `idempotency_conflict` 并写安全审计，不能第二次执行。
- 模型/工具结果未知时保存可见的 `unknown`/待审阅信息并先对账，不确认成功、不重新派发副作用。暂停或失败不得丢弃原始 Task 结果。

## K4：PC 按需文件取回、撤权与副本清理

文件请求通过用户选择的 PC 安装、已授权目录 ID、相对路径及当前 Task 授权建立；创建由 DSH `file.fetch` 工具经 Go 应用层授权，不新增模型或客户端直连的第二套任务入口。PC 继续经现有认证 Hub 主动连接，不开放 PC 入站公网端口，也不接受模型给出的本机绝对路径。目标路由为：

| 方法与路径（拟新增） | 用途 |
| --- | --- |
| `GET /api/tasks/{task_id}/file-fetches/{fetch_id}` | 查询该 Task 下取回的持久状态和进度。 |
| `POST /api/tasks/{task_id}/file-fetches/{fetch_id}/manifest` | 目标 PC 固定并提交获准相对文件的版本清单；服务端绑定当前安装、目录授权版本及 Task 修订。 |
| `PUT /api/tasks/{task_id}/file-fetches/{fetch_id}/chunks/{sequence}` | 目标 PC 按序上传原始分块及 `X-Chunk-SHA256`；具体块大小由 A30-T1 冻结。 |
| `POST /api/tasks/{task_id}/file-fetches/{fetch_id}/commit` | 完整核验大小、摘要、Task 修订与授权后发布云端副本；失败或重复提交不得发布部分内容。 |
| `POST /api/tasks/{task_id}/file-fetches/{fetch_id}/cancel` | Task 所有者请求停止；仅在确认数据流停止且未完成块已清理后显示 `cancelled`。不能用取消接口删除已完成副本。 |
| `GET /api/tasks/{task_id}/file-fetches/{fetch_id}/content` | Task 所有者读取已提交副本；继续校验当前 Task 归属与内容状态。 |
| `DELETE /api/tasks/{task_id}/file-fetches/{fetch_id}/content` | 显式删除已完成的云端副本。要求 Task 所有者身份；目录被撤权或源 PC 离线不妨碍删除。成功后保留最小审计/tombstone，阻止后续读取；不更改 PC 原文件、不删除 Task 历史文字或伪称擦除了模型已读内容。重复删除返回 204。 |

PC 的 manifest/chunk/commit 接口仅接受短期 file-fetch ticket，ticket 绑定 `fetch_id`、目标 `source_installation_id`、Task/修订、目录授权版本和有效期，只通过已认证 Hub 交给目标 PC；每个请求重新核验绑定。用户侧查询、取回内容、取消和删除只接受 Task 所有者 Portal Session；无权访问和不存在统一隐藏为 `404 not_found`。PC 不获得 Portal Session、API key 或目录外路径能力。

取回状态单独表达传输生命周期，不是 Task 状态：`queued / waiting_device / transferring / verifying / completed / cancelling / cancelled / failed`。查询投影至少包含 `fetch_id`、`task_id`、`source_installation_id`、显示用 `source_device_name`/`source_directory_name`、`relative_path`、`task_revision`、经 PC 首片确认后固定的 `source_sha256` 和 `size_bytes`、`confirmed_bytes`、`status`、可空 `waiting_reason`、可空 `content_id`/`expires_at`。`waiting_reason` 最小集合是 `device_offline`；固定版本文件只在整文件大小/摘要复核成功后才对任务可读。

- 用户级 Portal Session 或既有 client credential 负责身份；服务端仍逐次核验 Task 所有权、目录授权版本、安装身份及当前任务修订。Hub 每条消息与每块数据都核验同一绑定；凭据只在既有受信服务端路径使用。
- PC 离线时持久返回 `202` 与 `waiting_device`，不报告失败或成功。源文件在读取期间变化、摘要不一致、授权撤销或修订变更时停止接收后续数据并丢弃未完成 staging；通过现有错误码安全表达失败原因，不能发布部分文件。精确重试返回原收据/状态，改变 manifest 或已确认块内容返回现有 `conflict`/`idempotency_conflict`。
- 撤权阻止新的请求和在途后续数据接收；取消、撤权、失败和过期时清理未完成 staging。撤权前已完成副本不因撤权立即删除，可按 A30-T1 冻结的期限保留或由用户显式删除；目录撤权不自动回写/删除 PC 源文件。文件格式、文件/账号额度、分块限制及保留期限都由 A30-T1 定稿，本项冻结删除语义，不预设数值。
- 错误映射：未登录用 `unauthenticated`；无权用 `forbidden` 或隐藏资源时用 `not_found`；幂等冲突用 `idempotency_conflict`；状态不允许用 `invalid_state`；源版本/校验冲突用 `conflict`；请求或单文件限制用 `request_too_large`/`quota_exceeded`；过期续传用 `transfer_expired`；暂时无法写入文件存储用 `workspace_unavailable`。映射在正式 OpenAPI 中固定后才可实现。

## 兼容、验收与交接

K1 的现有 API 是 A10/B10/C10 的唯一消息入口。G0 的本地样例验证成功/重试、并发 Task 与修订、子会话结果、审批稳定身份，以及文件离线、源变化、撤权、取消和副本删除均可表达；不验证未实现的新路由。A20/A21/A30 分别在实现时落 K2/K3/K4，维护迁移前兼容数据并更新正式 OpenAPI。B/C 可以先依此目标映射自己的类型/界面，不得为 fixture 改写客户端之外的服务端契约或加入备用 API。
