# Morde iOS 融合界面并行实施入口

本入口把[融合设计总清单](<../Morde iOS与nanoMuse融合设计实施任务todo清单文档.md>)的 MIF-01～MIF-12 拆为一个集成组和三个页面组。各编号的执行状态只在对应子清单维护；原总清单保留任务内容的初始快照。页面实施时逐项参考 [Morde iOS 设计稿](<../../Morde iOS设计稿.html>) 和[融合设计方案](<../../Morde iOS与nanoMuse融合设计方案.md>)，使用 nanoMuse iOS 风格。

## 当前边界

- 原会话 3 曾独占 `project/nanoMuse/android/src/ios/**`。2026-11-04，用户明确指定当前会话为本组唯一集成者；原会话 3 已暂停共享源码写入，并在其 iOS TODO 记录释放该源码树写入权。当前会话已核对原会话进入 idle，持有本轮集成写入权。会话 1 的云端 Runtime 工作仍按原边界进行。
- MI-07 已完成本地原工程和模拟器验收；MI-01～04 等状态以会话 3 最新记录为准。MI-05/06、MI-08/09 的清理确认和原工程迁移由原清单继续处理，不在本入口重复执行或更改其状态。
- iOS 正式目标为原 `Minis.xcodeproj` 的 `morde` scheme，保留原身份、扩展和用户数据。好友与 AI 工具会话只做“暂未实现”占位；任务、审批及工作项不展示预算；不恢复已关闭的旧云服务或本机 Agent。用户已授权扩展聊天附件 API，首期类型确定为图片与 PDF：图片规范化为 JPEG，PDF 用 PDFKit 提取文本并渲染页图；实现/验收使用本地 fixture 与合成文件，不传输真实文件。
- 只在本地修改及验收，不外发、上传、下载、分享或发送文件，不访问真实 Portal 或 Host。验证使用进程内替身、合成账号及元数据；不覆盖、重置已有用户数据模拟器。

## 执行顺序

1. **交接。** 会话 3 或交接负责人确认可写范围，并记录当前实际源码、未提交及未跟踪工程文件的基线。普通 `git worktree` 只含已提交内容，不能假定带有正在执行会话的改动；不重置、覆盖或清理工作树。
2. **冻结共享接口。** 组 1 先完成 MIF-B01：以当前 Morde 客户端为准，确定并提供页面所需的状态、ID 和回调，保留 SSE、版本、权限、账号范围和幂等语义；记录可编译的签名及各组所需文案。接口未冻结前，页面组只做只读分析。
3. **并行准备页面。** 组 2、3、4 在各自暂存区并行实施并记录独立检查结果。组 3 按 03 子清单已完成的类别/认领合同实现和验收；如后续需要改共享合同，先记录变更请求并交给对应接口所有者。任何需要共享文件的改动交组 1，不越界写入。
4. **串行集成。** 组 1 按子清单接收完成的暂存文件，逐组纳入原 target、接真实状态与操作，并统一更新所有既有语言、本地化、共享测试及根导航。普通 `Morde/` 组的新文件如需工程登记，也只由组 1 改 `project.pbxproj`。
5. **验收。** 先分别验收可用页面，再由组 1 以原 `morde` scheme 在专用干净 Simulator 完整走查。MIF-07 的实现与本机验收按 03 子清单记录为完成；其他缺少交接、能力或验证的任务保持未完成，不能把演示数据当作实际结果。

每个工作者只更新自己子清单的状态与交接记录；组 1 汇总本入口。MIF-03～10 涉及的共享客户端或工程接线由组 1 交付，页面组在自己的界面、接线及本项验收均完成后才勾选。不得把互相依赖的半成品标为完成。
