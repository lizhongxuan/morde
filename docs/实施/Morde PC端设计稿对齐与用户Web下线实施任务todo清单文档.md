## 接口与交接

| --- | --- | --- |
| **拟新增** `GET /api/me/task-approvals` | 当前 `GET /api/tasks` 返回任务摘要，审批详情在任务详情中；已批准、拒绝或取消的审批会从 `pending_request` 隐藏。查询当前账号有权处理的待审项及有权查看的已处理项，支持 `cursor`、`limit` 和按会话读取；返回来源会话/项目、任务和审批 ID、版本、状态、时间线所需定位及必要展示字段、`next_cursor` 和完整待审核数量，并支持按权限恢复已处理卡片的结果。待审核数量只统计当前账号可处理的事项；服务端校验账号、项目成员及任务审批权限，排序和游标稳定；撤权不泄露内容，查询失败不显示为零。若盘点发现已有查询已完整满足此合同，可复用并删除本拟新增项。 | U07、U08 |
| **拟扩展** `GET /api/conversations/{id}/tasks`，以及项目会话对应任务接口 | 保留现有默认/`active`/`recent` 行为；若现有分页无法完整提供混排列表，增加 `view=panel`：合并有权访问的活动及最近结束任务，`running` 优先、各组按更新时间倒序并以 ID 稳定打破同时间排序；返回 `items`、`next_cursor` 和既有会话待处理信息。权限变化及排序字段变化时正确刷新，不将一页结果当全量。若复用完整现有分页即可满足，则不新增参数。 | U07、U08 |
| `POST /api/tasks/{id}/approvals/{approval_id}/responses`（已有） | 对话卡片与审核页复用同一 `version`、`decision` 和 `Idempotency-Key`；`202` 表示决定已受理，任务状态仍须查询。过期、版本冲突、跨端已处理或结果未知时对账，不重复提交新动作。 | U07、U08 |
| `POST /api/schedules`、`PUT /api/schedules/{id}`（已有） | 创建时省略或传空 `host_id` 当前表示无电脑；更新时省略表示保留，`null` 表示移除。移除表单下拉时不得把原目标改成 `null`。新计划在何时绑定默认电脑须先核实并确定；如需调整合同，保留旧客户端语义并同步 OpenAPI、调用方和测试。 | U09 |
| 桌面 Portal 桥（已有） | 复用 `morde:portal-project-upload-targets`、`morde:portal-project-select-directory(hostId, workspaceId)` 和 `morde:portal-project-upload(selectionId, projectName)`。展示账号固定的默认目标以及项目名和范围供确认；同步 UI 不提供目标切换。主进程继续校验顶层可信页面、账号、安装、默认目标及本次目录授权，不给 Host iframe 任意本机文件权限。 | U13 |
| 客户端本地页面与网关连接 | 用户/工作台资源由本地包加载；回环服务或受控桥只访问已授权服务和指定 Host，按需支持业务 API、SSE、WebSocket 和票据交换。若需修改网关或消息合同，在 U10 定稿并同时更新服务端、客户端及测试，禁止扩大 Cookie、CSP 或通用代理权限。 | U03、U10、U11 |

消息历史继续复用现有 `GET /api/conversations/{id}/messages` 的 `cursor` 和 `next_cursor`；`POST` 返回的 `202` 表示消息持久受理，不表示任务已经执行。消息已收到及思考状态优先复用受理回执、消息路由/输出状态和任务事件；若现有状态不足以准确区分排队、思考与未知，在 U06 核实并最小扩展服务端合同及调用方，不以定时器伪造。默认电脑继续复用现有 `/api/me/default-host`。接口变更同步 `server/openapi/portal.yaml`、生成类型和实际调用方，不手改生成文件。

- 工作台界面继续使用 Gateway `/__ch/wb/`；noVNC、终端、Workspace、主机文件及 VS Code 页面/流按指定 Host 和 Gateway 现有授权提供。PC 嵌入使用同一 BrowserWindow 内的顶层 WebContentsView，以 Host 自己作为严格 Cookie 的顶层站点；Portal 的 Web iframe 路径仍要求部署后的 Portal 与 Host 满足既有同站及 CSP 条件。

- 真实文件传输验收受当前“不发送文件”限制阻塞；其他本地实现和不发送文件的验收继续进行。
