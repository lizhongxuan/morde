## 1. 本阶段目标与修改边界

把原 nanoMuse Cloud 的关键服务、接口和管理页面迁入 Morde，补齐原客户端的个人数据、目标例程、自有设备互连和记录设置。**本文同时负责这些功能的服务端与 PC/iOS 接入**，无需回到 03 另开未完成任务。Agent 执行统一走 01 的账号级云端 Runtime 与 Task/dsh；客户端不运行本机 Agent 或工具循环。

| 来源/目标（相对仓库根目录） | 迁移边界 |
|---|---|
| `project/nanoMuse/cloud/nanomuse_cloud/` | 读取 `api.py`、`service.py`、`sync.py`、`hub.py`、`record.py`、模型/统计/规则等行为；移入 `server/internal/{api,app,domain,store/postgres}` 的相应层，不部署第二套 Cloud 或复制第二账号库 |
| `project/nanoMuse/cloud/console/src/` | 按第 3 节页面清单迁入 `web/portal/src/routes/admin/`；统一 API client、身份、导航和权限，不用旧 console iframe |
| `project/nanoMuse/harness/dsh-nanomuse/src/` | 改造 `cloud.ts`、`hub.ts`、`task.ts`、`profile.ts`、`rooms*.ts` 及原个人页面；服务端 dsh 接入账号业务用例。客户端保留界面、受限数据适配及目标 PC 获准的单次设备动作，不启动本机 Agent；设备动作可复用源码语义，但不得为调用它启动本机 dsh |
| `project/nanoMuse/android/src/ios/NanoMuse/` 及原同步模块 | 接个人同步、Hub、目标例程、同意设置及原有相关页面；完成 03 留下的全部 iCloud 替代与停用验证 |
| `server/internal/domain/schedule`、`app/schedule_store.go`、`store/postgres/schedule.go` | 在已有计划定义上恢复调度；Routine 使用 Schedule，不创建平行的云端 routines 系统 |
| 原 Python App Server 与 `demo/showcase/gateway/` | 将原服务端 Agent/持久 Web 环境能力映射到现有 Morde 执行、Host、Workspace 和个人数据；01～03 已交付的能力直接复用，旧 Web 卷仅在实际存在且涉及应保护数据时由 05 单独核对 |

不迁移验证码登录，不默认启用旧 Cloud 的采集和奖励规则；用户已确认本期默认不自动发放邀请奖励、贡献奖励或新用户免费额度，保留计量、预算与管理能力。“独立 Cloud 退出融合构建”不等于删除原源码、历史数据或参考测试。训练贡献与完整记录是不同目的，不能合并同意。

03 交接时应已按设计稿搭建 iOS 导航和会话、资源主流程。本阶段在同一套页面上完成真实功能接入：动态中的内容和待处理审批、点子带入会话及目标/例程、助手个人数据、同步与记录设置、技能/连接器及设备入口，分别接对应的 Morde 服务和授权。页面示例替换为当前账号可访问的数据；没有数据、未启用、无权限和失败时显示对应状态，不把设计稿里的示例按钮当作功能完成。

## 2. 接口变化与数据归属

除现有管理、模型与任务接口外，下列为**拟新增或恢复并改造**；F04-T01 按能力分别准备方法、schema、错误码、权限和调用方，实际接口须与 OpenAPI、公共约定、实现及受影响调用方在同一变更落实。复用 01 的版本、幂等、Installation 撤权和统一错误体。

| 目标入口 | 读写范围、鉴权与关键行为 | 任务 |
|---|---|---|
| `GET/PATCH /api/me/profile` | 账号资料、头像引用、预期版本；保留本机专用资源；不接收任意本机路径 | F04-T02、F04-T05 |
| `GET/PUT/DELETE /api/personal-data/{type}/{id}`，`GET /api/sync/snapshot`，`GET/POST /api/sync/changes` | 类型白名单、mutation ID、base revision、账号 cursor、tombstone。已有会话/Goal/Schedule 写入其唯一用例，变更流只作投递索引，不另存一套业务正文 | F04-T02 |
| `POST /api/personal-data/uploads`、`PUT /api/personal-data/uploads/{id}/chunks/{index}`、`POST /api/personal-data/uploads/{id}/commit`、`DELETE /api/personal-data/uploads/{id}`、`GET /api/personal-data/attachments/{id}` | 创建受限上传会话；分片按序号/摘要幂等，有限请求体和断线续传；校验账号、大小/类型/完整摘要后原子引用。取消不删除已引用数据；附件读取校验 owner，不以摘要当授权 | F04-T02 |
| **拟新增** `GET /api/me/personal-data/quota`；`GET/PATCH /api/admin/users/{id}/personal-data-quota` | 用户查询当前个人数据已用量、预留及生效上限；管理员按账号查询和调整总量、单附件上限，版本冲突/无权拒绝并审计。默认 5 GiB/账号、300 MiB/附件，与普通聊天及其他额度分开 | F04-T02.14、F04-T08.13、F04-T09.12 |
| `POST /api/conversations/import` | 用户选择的本机历史显式导入，按来源 ID/批次去重，校验所有者与附件；只保存历史，绝不创建执行 Task | F04-T02、F04-T05 |
| `GET/POST /api/goals`、`GET/PATCH/DELETE /api/goals/{id}`；`/api/schedules` 及详情/启停操作 | Goal、进展、关联资料及计划唯一来源；IANA 时区、规则版本、云端模型、可选 Host 与授权。每个 occurrence 最多创建一个 01 Task；旧计划不自动启用 | F04-T03 |
| `WS /api/hub`、`GET /api/devices`、`PATCH/DELETE /api/devices/{id}` | 保留 hello/welcome、ping 及适用非 Agent 设备调用语义；设备连接绑定安装，云端 Task 来源使用服务端真实身份和授权，不伪造设备。PC 写文件仅允许已选 Workspace：请求标识目标安装、Workspace、相对路径和操作，实际传输沿用 F02-T10 最终合同。双端鉴权、限额/超时/取消，不能委派客户端 Agent；Device 与 Client 关联，不复制安装身份 | F04-T04 |
| `GET/PUT /api/me/data-consents`、`GET /api/records`、`GET/DELETE /api/records/{id}`、`GET /api/records/{id}/attachments/{attachment_id}` | 用途、类别、版本及撤回范围；记录采集为受认证内部路径；默认关闭，当前同意决定写入与内容访问，删除历史需另行明确选择 | F04-T07 |
| **扩展已有** `/api/admin/users`、`hosts`、`workspaces`、`capacity`、`audit` | 使用同一业务来源；普通管理权限不自动获得正文、附件、导出或删除权限 | F04-T08、F04-T09 |
| **拟新增** `/api/admin/overview`、`live`、`health`、`models`、`usage`、`stats`、`activity`、`quality`、`records`、`controls`、`settings`、`invites`、`site` | 第 3 节各类管理查询与操作；优先在同一用例聚合。F04-T01 展开实际用到的方法、分页/过滤、版本及审计 schema，不能交付只有路径无数据合同的空接口 | F04-T08、F04-T09 |

个人同步包含：选择上传的会话/消息、资料头像、SOUL/记忆/日记、目标/例程、Feed/Ideas/Library、兼容平台的模型分组和技能/连接器/MCP 非秘密配置。原设备私有 API key、OAuth token、Vault、环境密钥、绝对路径、设备系统授权和未选本机内容不自动上传；用户授权的云端 MCP OAuth 凭据由 01 按 D9 加密保存在 Morde。用户自带模型 key 的设置与使用已决定移除，PC/iOS 本应用旧模型 API key（含 iOS 同步项）由 F03-T08 清理；Morde 平台模型凭据和云端 MCP OAuth 不属于该移除范围。Workspace 使用 02 建立的文件目录、限额与不可变检查点，PC/iOS 文件入口由 03 接入；个人同步仍使用独立合同。

下列各行由 **F04-T08 提供 API/权限，F04-T09 提供页面及交互验收**。同类页面可以合并导航，但每行功能都必须有明确去向与真实数据证据；尚无数据展示正确空态。

|---|---|

| people、AccountDrawer、事件/账本 | 既有用户详情扩展审核、安装、用量、授权与事件；同一用户表和账本，正文另行授权 |

| usage、stats、platforms、cohorts | 用量与平台/版本/留存统计；明确时间、分母、去重与数据来源，不复制另一账本 |
| hands、quality、abuse | 工具质量与风险统计；必要元数据可管理，内容抽查遵守独立同意和权限 |
| activity、places、AddressDrawer | 活动及既有聚合维度；限制原始标识可见范围，不新增设备定位授权 |

| controls、rules、evaluate、audit、notify-test | 规则、评估、审计与通知检查；不绕过审核/同意/资源权限，测试使用本地接收端 |

| invites | 关系、历史与反滥用；邀请不能替代密码登录/管理员审核，本期默认不自动发放奖励 |
| site、demo、GitHub/展示统计、nudges | 迁移原有展示和运营提示；外部集成显式配置，内容不自动公开，验证仅使用本地数据 |
