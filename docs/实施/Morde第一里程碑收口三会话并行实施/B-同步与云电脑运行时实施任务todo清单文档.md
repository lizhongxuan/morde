## 接口变化

1. **已实现** `POST /api/workspaces/{id}/sync-sessions` 项目上传：要求 `source_binding_id`；服务端绑定已验证的安装、owner、folder 和 Host 目标，不接受客户端自报安装身份或删除列表。换本机目录、安装或目标需显式新绑定；旧数据不授予删除权。未决 Host 应用会阻止新破坏性上传，原幂等键仍可重查/恢复。
2. **已实现** `GET /api/workspaces/{id}/sync-sessions/{session_id}` 的 session 级 Host 应用投影，区分 `pending_apply`、`applied`、`conflict`、`unknown`。回执事务核对 owner、Host、Workspace、binding version、当前 Runtime generation、source、目标 revision、manifest 及影响路径；`SyncSession.state=completed` 仍只表示服务端提交。
3. **已实现** Desktop bridge 既有入口的 session 回执消费：确认框来自主进程权威 Host 名称，显示目标、完整扫描范围与失联整次失败语义；云端 session 完成后保留恢复点，只有本次 receipt 验证为 `applied` 才清除。renderer 不依据 legacy 聚合 `hostStatus` 宣称完成。
4. **已实现** Host 副本回执路由复用现有 Host 身份、binding version、generation 与 `sync_state`。高于本次目标的 `applied_revision` 仅在服务端验证连续 revision lineage 和项目影响路径后接受；单独的 desired/applied 相等不作为证据。
