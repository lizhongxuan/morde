## 修改边界

- 清理独立普通用户 Portal 和手机 Web 的入口及其专属遗留物。`web/portal` 同时服务后台和 PC，`web/workbench`、Gateway 工作台及其资源仍被 PC、iOS 使用；按实际调用关系保留，不按目录名称整批删除。普通用户已有功能以 PC 承载，iOS 保留自己的现有能力。
- 删除前逐项核对源码引用、构建依赖、实际打包产物、动态资源与客户端调用；分为“继续使用”“已确认仅供独立 Web 且可移除”“待确认”三类，待确认的保留。旧 PC 过渡依赖、用户数据及共享资源不得清理；不覆盖工作区已有改动。
- 只在本机或本机隔离环境实施和验证，不修改远端；不向服务、设备或他人发送真实或合成的文件、附件、安装包、日志或截图。运行构建和测试前检查副作用，使用隔离输出与合成数据，避免清空现有构建产物或用户数据。无法验证的真实服务、旧版升级及文件传输如实标记待验证。

## 接口与行为边界

| 现有接口或模块 | 本次目标与约束 |
| --- | --- |
| Portal 静态路由与 `CH_PORTAL_LEGACY_PC_ENABLED` | 过渡期继续支持旧 PC；完成过渡后，外部普通用户页面及 `/app/*` 返回 404，不回退用户 SPA。PC 的本机页面路由不受影响。当前变量未设置时默认为启用；不得提前修改部署默认值。 |
| `/admin/*` 及后台实际引用的资源 | 维持登录、权限和深链，所有资源在真实构建 URL 下可访问。当前本地后台构建引用 `/assets/`，而关闭旧 PC 兼容后现有静态路由不会提供该路径；不能只测后台 HTML 或整段放开包含用户资源的目录。 |
| `/downloads/manifest.json`、`/downloads/files/<安装包>` | 保留清单与符合现有规则的安装包路径，以及 GET、HEAD、Range、文件名限制和原有校验；不开放目录或任意文件。文件传输受当前限制，未实测的部分记为待验证。 |
| `/__ch/wb/*`、Host 票据及客户端 API | 保留 PC/iOS 实际使用的工作台页面、授权网关和连接，维持 Host、账号、权限及租约隔离；认证（包括 `/api/auth/client-web-session`）、业务 API、事件流与 `/mcp` 不因用户页面清理而删除或改变合同。本次不预设新增业务 API。 |

  - 验收：每个拟删除项均记录调用方及处置，确认没有后台、PC、iOS、服务端、构建或旧 PC 过渡所需引用；专属旧测试随之调整或删除，仍有价值的测试保留。仅凭名称或搜索无结果不足以证明可删；未知依赖列为待确认并保留。

- [ ] **W02（未开始，依赖 W01）保障后台与 PC 构建资源**

  - 验收：在隔离目录生成真实构建产物，核对后台 HTML 和动态加载所需资源及其 URL、产物位置；PC 安装包仍包含用户界面和工作台所需资源。关闭兼容后的实际服务端资源加载及对外范围由 W03 验证；不得仅凭构建成功认定客户端可用。

- [ ] **W03（未开始，依赖 W01、W02）收口服务端静态路由**

  - 验收：兼容启用时旧 PC 所需页面和资源仍可取；关闭时用浏览器 HTML 请求验证 `/`、`/assistant`、`/login`、`/register`、`/download`、旧深链及 `/app/*` 返回 404。后台深链、实际 JS/CSS/图片、下载路径规则、业务 API 和工作台授权不受影响；只供独立用户 Web 使用的资源不对外发布，无权限及非法路径仍被拒绝。
