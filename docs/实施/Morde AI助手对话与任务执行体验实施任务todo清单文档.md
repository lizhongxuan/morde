## 修改边界与现状

- 本次新增的发送交互面向 iOS；消息持久接收、自动分流、任务修订、Runtime、工具按需使用及结果展示由服务端支持，PC 与 iOS 读取同一份对话和任务记录。项目会话继续执行原有成员权限和 Task 发起人限制。
- 当前个人及项目对话的 `POST .../messages` 已切换到自动受理合同：服务端先持久接收消息，再异步判断关联并创建或更新任务，受理时不要求返回 Task。iOS 与 Portal 发送队列不再通过 `new` / `append` 选择处理方式；真实服务链路及多任务跨端表现仍待验收。当前账号 Runtime 以服务实例和账号为键，而目标是每条对话最多一个活动的**逻辑** Runtime。
- 唯一 Agent Runtime 确定使用 DSH，当前 harness 与锁文件接入版本为 `0.2.2-rc.1`。已验证的取消、恢复和并发能力作为实现基础；当前缺口由 T06、T07 及相关任务修改并验收。新增官方插件若需升级 DSH，按[运行时实施清单](./Morde-Agent-Runtime与AI能力实施任务todo清单文档.md) T17 验证后再决定，升级后须重跑本清单涉及的并发、取消与恢复验收。Morde 负责消息分流、任务修订、授权、持久化和工具对接，GPT、DeepSeek 等模型继续通过现有模型网关接入。
- 按用户最新要求统一执行路径：个人及项目对话都切换到自动分流，更新现有调用方，移除旧 `new` / `append` 发送分支及旧客户端消息视图，不另建兼容实现。已有会话、任务、结果、操作账本和待处理消息必须保留；切换 Runtime 时先确认旧执行已停止，避免新旧执行者同时工作。
- 现有 [Agent Runtime 实施清单](<Morde-Agent-Runtime与AI能力实施任务todo清单文档.md>) 中相关任务继续记录其实现和验收；涉及消息自动分流、任务修订和会话级 Runtime 的冲突，以本次需求及设计为准。以下“未开始”表示本次改造尚未完成验收，不表示既有基础能力全部缺失。

## 接口与数据合同

以下为本次计划的合同，实施 T01 时同步 `server/openapi/portal.yaml`、`docs/实施/00-总览与公共约定.md`、服务端及调用方；新增名称均为拟定，落地后以同步的 OpenAPI 为准。

| 接口或模块 | 计划变化与关键约束 |
|---|---|
| `GET /api/capabilities` | 增加拟定的 `conversation_auto_routing_v1` 能力；只有接收、分流、任务隔离及客户端必需的长消息恢复链路均已装配时才声明。旧服务未声明时，新 iOS 保留待发送消息并提示升级。 |
| `GET /api/model-connections`；`GET /api/available-models` | 认证后的连接信息增加与健康检查分开的模型配置状态。读取失败或状态过期在客户端视为未知；仅明确无个人及平台模型才阻止本地提交。为普通对话提供已检查的文字模型列表，保留现有调用方对工具模型列表的合同；不返回密钥。 |
| `POST /api/conversations/{id}/messages` | 使用唯一的自动分流路径：携带客户端消息 ID、原文、稳定附件引用、可选模型和明确引用；客户端消息 ID 与幂等键一致。`X-Morde-Service-Instance-ID` 和 `X-Morde-Actor-ID` 必填，逐请求核对鉴权账号并在数据库事务中核对实例；不匹配时保留本地消息。鉴权后原子写入消息、顺序、幂等记录及待分流记录，返回 `202`、消息 ID、序号与待分流状态，Task ID 可为空。相同键与相同内容返回原结果，内容不同返回冲突；移除手工选择 `new` / `append` 的分支。 |
| `GET /api/conversations/{id}/messages` | 增加按 `client_message_id` 对账的查询；返回该用户有权读取的消息、分流状态与组合回复来源。使用统一消息视图，分页、快照和重连不能导致重复或漏项。 |
| `POST /api/conversations/{id}/messages/{message_id}/retry-processing`（拟新增） | 对已受理但分流失败、尚无 Task 的消息请求重新处理；校验发送账号和会话权限，以请求幂等键去重，不重新写入用户消息。Task 已创建时通过该任务的安全重试操作处理。 |
| 文本分片接口（拟新增） | `PUT /api/conversations/{id}/message-uploads/{client_message_id}` 创建或恢复上传，`PUT .../chunks/{sequence}` 幂等上传分片，`GET .../{client_message_id}` 查询进度，`POST .../{client_message_id}/commit` 校验完整内容并进入统一自动分流路径。UTF-8 原始字节每片最多 16 KiB，序号从 0 起，初始化携带总字节数、片数和全文 SHA-256，分片携带 base64 内容及该片 SHA-256；GET 返回已收片序及提交状态，commit 返回普通消息回执。单条初始上限 8 MiB，超过时本地保留并提示限制。项目会话使用项目作用域下的对应路径；所有请求携带并核对服务实例 ID。分片本身不是多条消息；未完整提交不显示服务端已发送。 |
| 附件关联接口（拟新增） | 扩展现有 `/api/personal-data/uploads` 流程，并通过 `PUT /api/conversations/{id}/messages/{message_id}/attachments/{client_attachment_id}` 幂等关联上传结果，请求体为 `{attachment_id}`；服务端校验实例、消息、上传和附件归属。该对话附件上传的初始化、分片和提交均携带并验证同一服务实例 ID。消息身份只包含稳定附件标识，上传进度变化不改变原请求指纹。项目附件遵守现有项目权限，不通过个人路径绕过。 |
| `GET /api/tasks/{id}`、`GET /api/tasks/{id}/events` 及现有任务控制接口 | 任务快照、进度和结果增加任务修订及来源信息；事件按任务 ID、修订与事件序号恢复和去重。任务控制扩展对失败任务的安全重试；继续使用现有审批、澄清、暂停、继续及停止接口，不以选中卡片代替服务端确认。 |
| 服务端分流与模型网关（拟新增内部合同） | 以受理消息的发送账号、会话授权和消息 ID 建立路由调用身份；返回 `update` / `new` / `status` / `stop` / `clarify` 及必要目标。路由发生在 Task 创建前，需为无 Task 的模型调用补齐授权、模型预算、账本和恢复约束，不能伪造 Task ID 或绕过配额。 |
| 会话 Runtime 与工具派发（内部合同） | 以服务实例和对话 ID 为唯一键获取 Runtime，并校验会话授权；任务执行、停止、模型/工具调用和结果提交都携带任务 ID、修订、租约及代次。项目对话虽共享会话实例，仍逐任务按发起人校验数据、模型和工具权限。 |
