# 开源依赖二开与独立项目方案

> 日期：2026-10-21。配套 [精简设计方案](AI与用户共用云端主机设计方案.md) 与 [需求文档](AI与用户共用云端主机需求文档.md)。上游构建尚未运行；本地固定镜像隔离实测见 [09 验证记录](验证记录/09-运行能力验证.md)，没有连接远端主机或外发文件。运行端协议见 4.4.1；其代码与镜像尚未实现。

## 1. 先说明要单独准备什么

**当前没有证据要求 fork OpenSandbox 或 noVNC。** T12.04 已确认固定 AIO 镜像的启动脚本会覆盖用户 profile 配置；此项需要一个单独维护的 AIO 派生镜像来实现幂等初始化，不能把补丁混进 Morde。镜像内的服务脚本尚未对应到公开源码文件，所以这是独立的镜像兼容项目，不代表已确认能从公开仓库重建 AIO 服务。强接管、后台任务停止仍由 `morde-runtime` 实现；AIO 核心二开只在取得实际源码且运行扩展无法满足时再评估。Morde 的任务基础可与能力验证并行开发，具体先后与集成门槛见 [设计方案第 6 节](AI与用户共用云端主机设计方案.md#6-交付顺序与验收重点)。

| 类型 | 含义 | 本项目对应情况 |
|---|---|---|
| Morde 自身开发 | 在平台实现业务和上游适配 | Agent、任务、计划、笔记、授权、预览、团队模板与交付记录。 |
| 派生镜像 / 自有扩展 | 以固定上游镜像为基础，增加受控服务、数据目录或经过审阅的启动兼容补丁 | `morde-runtime` 与待用户单独准备的 `morde-aio-profile`；后者不是 AIO 源码 fork。 |
| 上游源码二开 | 修改第三方服务内部行为并自行构建发布 | AIO 核心二开仍是条件项；OpenSandbox 暂无确认的必改项。 |

执行规则：发现源码二开需求时，先提供“对应需求、上游仓库与精确版本、现有能力证据、为何接入或配置不能解决、修改边界、接口、验证与回退”并告知用户，再在用户单独准备的项目实施。不得把补丁藏进运行容器或 Morde 的依赖目录。

对应任务见 [09 运行能力验证与二开判定](实施/09-运行能力验证与二开判定实施任务todo清单文档.md) 和 [12 运行扩展与电脑接管](实施/12-运行扩展与电脑接管实施任务todo清单文档.md)；按验证结果选择分支，不要求提前克隆所有上游。

**T09 判定（2026-10-21）**：AIO 的 Shell kill/超时不覆盖后台子进程；Gateway handler 的隔离 HTTP 探测确认有效 Host Cookie + 同源 GUI 写请求会转发到 AIO；workspace 卷数据可跨 sandbox 重建，但 `gem` 写入失败，`/v1/file/write` 也返回 `success=false`；Chrome profile `/home/gem/.config/browser` 不在 workspace 卷，重建后合成标记消失。T09.05 将这些缺口判定为 Morde 控制/存储和独立运行扩展工作；目前不启动 AIO、OpenSandbox 或 noVNC fork。Gateway 完整进程和真实剪贴板/旧连接路径仍需 T12 集成验收。

## 2. 已核对的基线与限制

### 2.1 AIO：能使用镜像，不代表已拿到完整服务源码

Morde 当前固定 `ghcr.io/agent-infra/sandbox:1.11.0`，digest 为 `sha256:6328d7fd2f0ff0b4c147c3d05b3df1ce331f4a482eb6e550ecd64ed1fcf906e7`，见 [现有镜像定义](../images/host/Dockerfile)。

固定镜像的公开版本基线为 [AIO Sandbox v1.11.0](https://github.com/agent-infra/sandbox/releases/tag/v1.11.0)，标签解析到提交 `6bd4b52bbfcbc629040aac1f72abfb7989de970b`；镜像 digest 为 `sha256:6328d7fd2f0ff0b4c147c3d05b3df1ce331f4a482eb6e550ecd64ed1fcf906e7`。只读检查该版本的公开仓库树，未发现 `gem.sh`、`gem_init.sh`、`run.sh` 或 Dockerfile；固定镜像内实际存在 `/opt/gem/gem.sh`，但该运行文件目前无法映射到公开仓库中的源文件。公开仓库有 SDK、CLI、示例和文档，不能据此承诺仅克隆该仓库就能重建镜像内所有服务。

公开 [OpenAPI 文件](https://github.com/agent-infra/sandbox/blob/7f1afaf8d82bd30531a19caeb1a24dfebbc97d8c/website/docs/public/v1/openapi.json)包含 Shell kill、会话清理和停止观察等接口，但其 `info.version` 为 `1.9.4`，不能直接当作固定 `1.11.0` 镜像的能力证明。尤其“结束某个 Shell 会话”不自动等于“停止所有派生进程、浏览器自动化和截图采集”。

### 2.2 OpenSandbox：先验证已有能力

Morde 固定 Server/execd `release-1.1.1`；上游同名标签本次解析到 `531700ca18a7fa5fab6a2f25d6dc68a76eddab12`，镜像 digest 仍以 [公共约定](实施/00-总览与公共约定.md)为准。后续构建还需核对源码与实际镜像的来源对应。

该版本 [生命周期协议](https://github.com/opensandbox-group/OpenSandbox/blob/531700ca18a7fa5fab6a2f25d6dc68a76eddab12/specs/sandbox-lifecycle.yml)已有 pause/resume、snapshot；[Docker 实现](https://github.com/opensandbox-group/OpenSandbox/blob/531700ca18a7fa5fab6a2f25d6dc68a76eddab12/server/opensandbox_server/services/docker/snapshot_runtime.py)通过容器 commit 创建快照，[卷实现](https://github.com/opensandbox-group/OpenSandbox/blob/531700ca18a7fa5fab6a2f25d6dc68a76eddab12/server/opensandbox_server/services/docker/volumes.py)支持 named volume。Morde 已使用卷，当前适配器尚未接入暂停和快照，不能据此判断上游没有这些能力。

当前方案仍以“固定镜像 + 独立数据 + 重建恢复”为基础。整容器暂停会连同桌面一起暂停，不能解决保留 GUI 的人工接管；运行快照也不能代替干净的团队交付镜像、独立数据备份或进程迁移。是否在固定 runsc 环境可用，需要实测。

### 2.3 noVNC：接入客户端，权限在服务端落实

[noVNC API](https://novnc.com/noVNC/docs/API.html)已有 `scaleViewport`、`resizeSession`、`viewOnly` 与连接事件。可在 Morde 工作台使用这些接口实现布局、缩放和交互，当前无需修改 noVNC 核心。`viewOnly` 是客户端设置；授权观察者是否可以发送输入，必须由服务端限制。

### 3.1 T09.05 固定版本判定

| 能力/缺口 | 实测与代码证据 | 当前分支、精确边界与后续任务 | P0 影响 |
|---|---|---|---|

## 4. 独立 `morde-runtime` 项目方案

### 4.1 仓库边界

建议由用户单独准备以下工作目录，名称可调整。`morde-runtime` 是建议新建的自有项目名称，不是一个已经存在、可直接克隆的上游仓库；本次没有创建这些项目。

```text
morde/                  平台业务、页面、Gateway、运行层客户端
morde-runtime/          自有运行扩展、派生镜像、持久化配置、协议与验收
OpenSandbox/            仅在确认需要源码修改后单独准备
aio-runtime-source/     仅在取得实际服务源码后准备；不是默认指公开 SDK 仓库
```

`morde-runtime` 负责 `image/`、`runtime/`、`profiles/`、`contract/`、`tests/` 五个范围。以固定 AIO digest 为底座，保留其正常启动链，添加独立受控服务；原有 AIO 启动、GUI、终端与 MCP 必须可用。实现时统一迁入目前 `images/host` 的运行镜像构建职责，Morde 只引用产物 digest，避免长期维护两份 Dockerfile 和补丁。

### 4.2 必须先完成的能力验证

1. 读取固定镜像自身的接口与工具清单，记录版本、架构和实际响应；区分已有 GUI 工具与需要新增的能力。
2. 核对 Shell 会话、浏览器动作、截图/录制、持久 REPL 和预览进程能否登记、查询和可靠停止；验证普通子进程、后台进程及脱离终端进程。
3. 验证能否在保留桌面和用户应用的同时停止 AI 自动化；整容器 pause 或删除不算通过。
4. 验证浏览器资料、应用配置的真实位置与启动覆盖行为，以及服务端只读 VNC 是否可配置。

结果按“原样接入 / 配置或扩展 / 必须改源码 / 尚不可交付”逐项记录。未通过的能力不宣称支持，不能在接管失败时静默降级成只停鼠标。

### 4.3 受控执行与接管

所有 AI 工具经平台授权后进入统一受控入口，带电脑、任务、操作标识和控制版本。服务登记操作及所属会话/进程域，拒绝旧版本、重复的非幂等提交及未授权工具；客户端不能自行指定可信身份。

接管流程：Morde 进入“接管中”并提高控制版本 → 运行层拒绝旧操作 → 取消队列、停止采集和受管后台任务 → 确认无在途动作 → 开放人工控制。运行层重启默认禁止新操作，重新向平台确认控制版本后才启用；不能自行恢复旧任务。

进程管理必须覆盖派生进程，不能只保存一个 PID 或杀死 Shell 父进程。选用的进程域隔离与停止机制必须在 runsc 下实测，不能假设容器内可使用宿主 cgroup。AI 执行默认非特权，安装软件走受控安装或镜像构建；任务进程不能读取控制凭证、终止控制服务或通过本地 AIO 接口绕过管控。

**若仍允许 AI 任意取得 root/sudo，或能把自动化移交给不可追踪的常驻服务，就不能承诺强接管。** 若独立扩展无法实现所需边界，明确列出缺口，转入第 5 节源码方案；未获解决前，该验收项保持未通过。用户正常网页脚本与应用进程不因接管被无差别杀死。

### 4.4 运行端接口（非规范摘要）

以下接口由独立扩展提供，**不是 AIO 现有 API**。本节仅作接口索引；与本节或示例有冲突时，以 4.4.1 及 T12.02 产出的 schema 为唯一规范。只允许 Morde 服务端访问，公开 MCP 不直接暴露控制凭证或内部地址。

| 接口 | 请求与响应合同 |
|---|---|
| `GET /runtime/v1/capabilities` | 握手查询传入期望 `host_id/runtime_generation/control_version`；返回实际 `runtime_instance_id`、模式、operation store 健康状态与能力清单。 |
| `PUT /runtime/v1/control` | 请求携带 Host/generation/instance/control fences。`blocked/ai` 按控制版本幂等更新；切换到 `human` 必须带运行端签发、绑定目标控制版本的 drained receipt，运行端原子验证并消费。 |
| `PUT /runtime/v1/tasks/{task_id}/lease` | 请求携带 Host/generation/instance/control fences、lease 版本与到期时间；相同版本同一到期时间为幂等重放，相同版本只能单调延长，禁止缩短或在租约过期后续租。lease_version 是认领世代围栏，不是每次续租的序号。 |
| `POST /runtime/v1/operations` | 请求字段见下方 schema；先持久登记再执行。响应含 operation ID、状态和受限结果。 |
| `GET /runtime/v1/operations/{operation_id}` | 按 Host-wide 持久登记查询；返回原 generation、instance、control/lease 版本、状态和受限结果，不恢复执行。 |
| `POST /runtime/v1/operations/{operation_id}/cancel` | 请求携带当前 Host/generation/instance/control fences；仅确认该操作的全部受管进程和排队动作均停止后才返回 `cancelled`。 |
| `POST /runtime/v1/quiesce` | 请求携带 Host/generation/instance/blocked control fences 与待排空任务；返回 `draining/drained/failed`、待处理操作及绑定当前围栏的 receipt。 |
| `GET /runtime/v1/windows`、`POST /runtime/v1/windows/{id}/activate` | 使用 `window.list`/`window.activate` 能力并携带 Host/generation/instance/control fences；激活作为受管 operation 登记，目标消失或围栏过期即报错，不按旧坐标操作其他窗口。 |

每个请求带 `X-Morde-Runtime-Protocol: major.minor`；JSON 请求和响应还包含相同的 `protocol_version`。运行端操作请求的 v1 schema 为：

```json
{
  "protocol_version": "1.0",
  "host_id": "h1234567",
  "runtime_generation": 6,
  "runtime_instance_id": "ri_01J...",
  "control_version": 11,
  "task_id": "q1234567",
  "operation_id": "o1234567",
  "lease_version": 3,
  "capability": "browser.actions",
  "action": "click",
  "arguments": {"target_id": "element-1"}
}
```

初次 `GET /runtime/v1/capabilities` 是唯一不带 `runtime_instance_id` 的请求；它返回实例 ID，Morde 校验 Host/generation/control 后，后续所有请求都必须带回该 ID。运行端进程每次启动生成新 instance ID；缓存的旧 ID 一律拒绝，Morde 必须重新握手后才能发送控制或操作请求。

长连接与后台操作同样受控制版本约束。旧请求即使在接管之后才到达，也必须被拒绝；无法确认执行结果时要求核对，不默认重放。请求体、截图和凭证不进入普通日志。

#### 4.4.1 T12.01 冻结的运行协议

协议路径主版本为 `/runtime/v1`；每个请求都带 `X-Morde-Runtime-Protocol: major.minor`，JSON 请求和响应还带同值 `protocol_version`。同一主版本内只允许新增可选字段/能力；主版本不一致即拒绝执行。首版运行能力名固定为 `operation.execute/query/cancel`、`control.fence/quiesce`、`task_lease.fence`、`desktop.observe/input`、`window.list/activate`、`browser.observe/actions`、`shell.exec`、`file.read/write/list/find`。宣称受管 AI 执行必须具备 `operation.execute/query/cancel`、`control.fence/quiesce`、`task_lease.fence` 六项控制能力；具体用户工具另需下表对应能力。Morde 请求未声明的能力必须在副作用前失败，不回退 AIO 直连或猜坐标。

所有请求使用 `Authorization: Bearer <per-host runtime credential>` 认证；凭证由 Morde 客户端注入请求，不进入 URL、业务参数、错误或日志。所有主机级请求带 `host_id`、`runtime_generation`、`control_version`；首次 capabilities 握手可不带 `runtime_instance_id`，运行端返回实例 ID 与其实际接受的 Host/generation/control 值，Morde 必须逐项核对。握手后所有请求（包括 operation、lease、cancel、quiesce、window）都带该实例 ID；实例重启即拒绝旧实例请求，Morde 重新握手并校验后才能继续。GET 使用 query 参数，JSON 请求使用 body；JSON 响应直接返回对象，不另包 `data` envelope，且包含 `protocol_version`。请求 body 上限为 1 MiB、响应 body 上限为 8 MiB，单个运行端请求超时 60 秒；超时后的副作用结果只能按原 `operation_id` 查询，不得盲目重放。错误响应使用 `{protocol_version, code}`，错误码必须与 HTTP 状态对应，客户端不透传或记录内部错误文本。任务操作另带 Morde 创建的 `task_id`、`operation_id`、`lease_version`、所需 `capability`、`action` 和有界 `arguments`。`GET operation` 查询还必须带当前 Host fences、原任务 `task_id` 与 `lease_version`，以便仅在原授权任务和 Host 围栏下返回结果；响应的 `request_fence` 回显本次查询围栏，`operation` 对象保留原执行的 generation、instance、control 与 lease 版本，使 Host-wide 登记库可安全对账跨 Sandbox generation 的操作。quiesce 请求带 Morde 要排空的完整活跃 `task_ids` 集合和唯一的 `target_control_version`；响应含 `status`、`pending_operation_ids` 和可空 `drained_receipt`。receipt 绑定目标版本，运行端只有在操作队列与受管进程确已全部排空时才签发，之后设置 `human` 必须原子验证并消费它。`runtime_generation` 在每次 Sandbox 创建尝试前递增；同一 Sandbox 内运行服务重启不改变 generation，但改变 instance ID。运行端启动默认 `blocked`；Morde 确认 Host/generation/instance 后才可下发控制态。Host `ai` 映射到 runtime `ai`；Morde Host `user` 映射到 runtime `human`；`taking_over/returning` 映射到 `blocked`。

quiesce receipt 含不可猜测 `receipt_id`、Host/generation/runtime_instance_id、排空时的 blocked `control_version`、唯一的目标 human `target_control_version`、排空任务集合及签发时间。Morde 在进入 `taking_over` 时先持久推进 Host 控制版本并命令 runtime blocked/quiesce；receipt 绑定预期的人工作业控制版本。`PUT /control` 设置 `human` 时，运行端必须原子核对 receipt 未消费、目标版本完全匹配、操作队列仍为空且所有受管进程均已验证停止，再消费 receipt 并开放输入。被消费、目标版本变更或 runtime 实例变化后 receipt 失效；不得仅凭 Morde 调用顺序开放 human。

任务租约由 `PUT /runtime/v1/tasks/{task_id}/lease` 更新，字段为 Host/generation/instance/control fences、`lease_version` 和 UTC `expires_at`。`lease_version` 标识一次 Morde 任务认领，在该租约有效期内保持不变。新认领只接受更高版本；相同版本且 fences 与到期时间完全一致的请求为幂等重放，相同版本如要续租只接受严格晚于当前值的 `expires_at`；降低版本、缩短期限、租约过期后续租或控制围栏不符均拒绝。操作必须匹配运行端保存的最新租约且未过期；Morde 数据库续租成功并获运行端确认后才允许继续派发；任一续租失败立即停止派发，运行端到期时取消受管动作，无法证明停止则保持 draining/unknown。

`operation_id` 在 Host 范围跨 generation 唯一且永不复用；Host 级 root-only 登记库跨进程重启与 Sandbox generation 持续存在。运行端原子存规范请求摘要后先记 `accepted`、再记 `running`，随后才允许副作用。同 ID/同摘要返回原记录；同 ID/不同摘要返回 `operation_conflict`。响应状态为 `accepted/running/succeeded/failed/cancelling/cancelled/unknown`。启动恢复时，`accepted` 只有在持久记录证明外部副作用尚未启动时才能以同 ID/同摘要继续一次；`running` 不得重启其命令，只能用持久化的受管进程域标识核对原进程，已完成且结果持久化则收敛到终态，仍运行则继续监视，无法证明则置 `unknown` 且绝不重放。`cancelling` 恢复后只可继续停止并核验；无法证明全体子进程停止则保留 `draining/unknown`。`unknown` 只能由核验结果显式收敛，不自动执行。Morde 超时后查询原 ID；只有 Host-wide 健康完整登记库确认从未接受时的 `operation_not_found` 才允许完全相同请求以同 ID 尝试。登记库不可用、连续性不明或旧 generation 已无法对账时不重派，并要求核实。登记库位于独立 root-only Host runtime 数据卷，不放用户 Workspace、环境变量、命令参数或普通日志。`operation_store_ready=false` 时禁止新操作以及 AI/human 模式放行；`GET operation` 返回 `runtime_state_unavailable` 而非 404。Morde 可以请求进入 `blocked`，也可以尝试 quiesce/cancel，但登记库不可用时不得返回 `cancelled/drained` 或签发 human receipt。

运行服务使用每 Host 独立的随机 256-bit runtime 凭证，与 AIO Key、Portal API Key 分开。Morde 数据库仅保存其应用层加密值；创建/恢复时经受信任的 Sandbox 配置通道注入运行端 root-only 凭证文件，运行端服务仅接受该身份及私网 TLS 请求。凭证不进入 Sandbox metadata、可写 Workspace、浏览器、MCP 输出或日志；新 generation 更换凭证并撤销旧值。Host、Task、Operation 身份均以已认证服务端请求体为准，用户任务不能声明或伪造调用身份。

运行端先持久写入 `accepted`，再持久切换为 `running`，最后才启动任何外部副作用；因此崩溃后 `accepted` 可证明尚未启动，允许以同一 ID/同一摘要继续一次，`running` 必须核对存活进程与最终结果，无法证明时转 `unknown` 并禁止重放。运行端重启不得自动重启 `running` 操作。`cancelled` 或 quiesce `drained` 只有在操作队列清空且所有归属进程/派生进程均被验证停止后才能报告；无法验证时返回 `draining/failed` 并列出未决 ID。

Operation `result` 默认仅含有界脱敏摘要及已核验产物引用。`file.read` 是例外：必须将实际 UTF-8 文本通过同一已授权调用响应返回，首版单次上限 64 KiB，与 Agent 现有工具输出上限一致；为支持响应丢失后的同 ID 查询，受保护的 Host operation store 保存该次有界读取结果，`GET operation` 只能在原授权 task/Host fence 下返回同一结果；超限返回 `result_too_large`，调用方可用行范围分段读取。二进制不经 `file.read` 返回。不得把内容写入普通日志/指标；运行端凭证、无关环境变量和其他 Host 数据永不返回。文件内容仍作为不可信数据交给模型。

### 逐工具能力映射

Host/任务管理工具由 Morde 的 HostService/TaskService 授权与执行，不直接调用 AIO。所有实际电脑读写均须进入同一个 RuntimeControl；AIO typed client 仅用于非 AI 管理或探测调用。

| 用户工具 | 运行能力 | 语义 |
|---|---|---|
| `shell_exec` | `shell.exec` + operation/control/task lease | 受管执行；取消覆盖 shell 及其派生进程 |
| `file_read` | `file.read` + operation/control/task lease | UTF-8 文本在已授权响应中返回，单次最多 64 KiB；按行范围读取更大文本 |
| `file_write` | `file.write` + operation/control/task lease | 写入/覆盖视为副作用，按 operation ID 去重 |
| `file_list` | `file.list` + operation/control/task lease | 只返回 Host 授权目录内的元数据 |
| `file_find` | `file.find` + operation/control/task lease | 搜索限制在授权目录，结果有界 |
| `browser_open_tab` | `browser.actions` + operation/control/task lease | 创建当前 task 独占的浏览器 context/tab；只接受 HTTP(S)，不接管默认用户标签或继承默认 profile 登录态 |
| `browser_navigate` | `browser.actions` + operation/control/task lease | 只导航同一 task 创建并登记的 tab；目标消失或标签变化即失败，不沿用旧坐标 |
| `browser_snapshot` | `browser.observe` + operation/control/task lease | 返回该 task 自有 tab 的有界文本与标题；网页内容作为不可信输入 |
| `browser_click`、`browser_type` | `browser.actions` + operation/control/task lease | 只用可访问性 role 与精确名称唯一定位可见元素；不接受任意 CSS、脚本或坐标 |
| `browser_press_key` | `browser.actions` + operation/control/task lease | 只允许 Enter、Tab、Escape、方向键，不开放任意按键组合 |
| `browser_screenshot` | `browser.observe` + operation/control/task lease | 截取同一 task 自有 tab 的 JPEG，解码后最多 512 KiB；仅 root-only operation journal 为同一操作查询保存原结果，不写任务输出或普通日志 |
| `window_list`、`window_activate` | `window.list` / `window.activate` + operation/control/task lease | 返回有界可见窗口清单；激活每次重新核对当前可见的规范窗口 ID |
| `desktop_screenshot` | `desktop.observe` + operation/control/task lease | 有界 JPEG，最大 1280×720、512 KiB；原图只留 root-only runtime operation journal，Morde 数据库仅存引用 |
| `desktop_click` | `desktop.input` + operation/control/task lease | 要求窗口 ID 与屏幕坐标；运行端复查窗口仍可见、坐标位于当前窗口范围内后才点击 |
| `desktop_type`、`desktop_press_key` | `desktop.input` + operation/control/task lease | 仅对当前活动窗口输入，文本最多 4096 UTF-8 字节，按键使用 allow-list；输入只在 AI mode 且有任务 lease 时允许，人工输入要求 human mode 与当前用户会话 |
| `preview_url` | Morde Gateway 预览授权 | 仅签发/返回受保护预览地址；不作为运行端执行通道 |
| `host_create`、`host_list`、`host_get`、`host_delete`、`host_renew`、`task_submit`、`task_list`、`task_get`、`task_pause`、`task_resume`、`task_cancel`、`task_respond` | HostService/TaskService | 按公共合同做 owner、scope、状态和幂等校验；暂停、恢复、取消必须共用 ControlService 并等待 RuntimeControl 的停止/放行确认 |

未在能力表中匹配的工具不得执行。除 `preview_url` 这类仅签发链接的 Morde 管理动作外，所有 AI 电脑读取和写入都要求 runtime mode=`ai`、当前 control fence 与有效任务 lease；`blocked` 或 `human` 时 AI 不得截图、读网页/文件或执行动作。取消浏览器操作时只销毁该 task 的隔离 browser context 并验证其标签关闭，不关闭共享 Chromium 或用户标签；这只能证明本地自动化停止，不能撤销网站已经收到的点击或请求。AI 自有 context 不复用用户默认 profile 的 Cookie；noVNC 的真实可见效果须在固定 Host 镜像验收。GUI/VNC 人工输入必须经过运行端 human-mode 围栏并绑定当前用户会话，不能只由前端隐藏按钮实现。

运行端错误使用稳定机器码：`invalid_request`（400）、`runtime_authentication_failed`（401）、`fence_rejected`/`operation_conflict`/`protocol_incompatible`（409）、`capability_unavailable`（409）、`operation_not_found`（404）、`result_too_large`（413）、`runtime_state_unavailable`（503）。Morde 将 `capability_unavailable` 映射为现有公共错误 `unsupported`（422），并将 `result_too_large` 映射为公共同名错误；其余错误按失效围栏、未知结果或运行端不可用处理，不向用户透传内部文本。错误、日志及指标不得包含凭证、参数正文或文件内容。

本合同冻结的是 Morde 与未来 `morde-runtime` 的边界，不表示代码、镜像、私有 TLS 或运行端数据卷已经实现。T12.02/.03 必须在单独准备的 `morde-runtime` 中实现并验证上述协议；若固定 OpenSandbox 无法提供受保护的凭证和数据卷挂载，先更新本合同及 T12.01 验收，不得悄悄改用 AIO Key 或用户 Workspace。

### 4.5 桌面权限与持久化

- 观察者使用服务端只读通道；输入者使用绑定电脑、会话和控制版本的写通道。覆盖键盘、鼠标、剪贴板写入等动作，不能只依赖页面禁用按钮；必要时在运行镜像内增加只读入口或可信 RFB 输入代理。
- 工作文件、浏览器 profile、受支持应用配置分别声明路径、权限和备份方式；首次启动初始化空卷，已有卷不覆盖。服务程序与控制凭证不放在用户可写 profile 中。
- 备份先让受支持应用完成写入或停止相关写入，再校验恢复；登录过期按正常登录处理。模板使用干净 profile，个人恢复点保持私有，两者不能混用。
- 预览服务与 AI 自动化进程分别标记用途：可安全保留的应用服务不因接管消失；无法确认是否还在执行 AI 操作时，不提前报告已接管。

| `docs/UPSTREAM.md` | 记录上游版本/提交、基础镜像 digest、补丁原因、镜像内路径证据、开源许可核对、重建命令与回退步骤。 |

验收顺序：在用户单独准备的项目中提取脚本并生成补丁；先跑补丁摘要和 profile 两次启动测试；再在 `linux/amd64` 隔离 Linux/runsc 上确认 AIO 浏览器、终端、文件、MCP 原功能可用且 profile 保留；最后更新 Morde 的唯一 Host 镜像 digest。当前不能因镜像路径检查就宣称二开已完成；需要用户先单独拉取/准备该项目，再继续改 AIO 派生镜像。构建与推送均由用户另行安排，当前不上传文件或镜像。

回退时恢复上一组 AIO 基础 digest、profile schema 版本和 Morde Host 镜像 digest；回退前备份 profile，确认新字段能由旧镜像读取，不能用旧默认配置覆盖用户数据。若之后拿到与镜像匹配的 AIO 源码，再评估是否把该兼容行为贡献到 AIO 上游或改成源码构建；在此之前不把派生镜像方案升级描述成 AIO 核心 fork。

## 6. OpenSandbox 的条件性二开方案

**当前先接入与验证，不开 fork 任务。** 暂停迁移可由备份、原有创建/删除及卷能力组合实现；多主机选择和任务记录归 Morde。仅在复现固定版本缺陷、确认影响目标且配置无法解决后，修改对应上游模块。

若出现此类缺口，从 `release-1.1.1` 的已核对提交开始，在独立项目按以下文件边界处理：

| 上游范围 | 可能修改内容 |
|---|---|
| `server/opensandbox_server/services/docker/docker_service.py` | 经复现的 Docker/runsc 生命周期错误；保留已有创建、暂停、恢复语义。 |
| `server/opensandbox_server/services/docker/snapshot_runtime.py` | 经复现的快照状态、超时结果核对及失败清理；保留可查询的操作结果。 |
| `server/opensandbox_server/services/docker/volumes.py` | 经复现的挂载、目录或卷清理问题；不得删除不属于本次操作的数据。 |
| `specs/sandbox-lifecycle.yml` 与 `server/tests/` | 同步确需变化的协议和对应回归；Morde 仅更新受影响的 typed adapter。 |

每项改动先附最小复现和影响范围，确认镜像与代码版本对应；优先采用能解决问题的上游正式修复，需自维护补丁时记录差异。容量硬配额、数据卷写时复制和进程热迁移若要增加，必须另列存储/运行时方案，不通过给普通 API 加字段来宣称已支持。

## 7. 构建、接入与回退

1. **锁定输入**：记录上游提交、基础镜像 digest、架构、协议版本和构建步骤；先本地完成，未经用户指令不创建远端仓库、不推送源码或镜像。
2. **独立产物**：`morde-runtime` 产出运行镜像、内部协议、能力清单及验证记录；确需 fork 的上游各自产出镜像及变更说明。敏感凭证不进入构建参数、层、日志或测试材料。
3. **平台接入**：Morde 更新唯一运行客户端、Gateway 控制权校验和模板 digest；构建隔离于用户 AIO，不把 Docker socket 交给任务。API/状态变化同步现有权威契约。
4. **能力门槛**：缺少受管停止能力时，接管功能显示不可用或失败原因，不回退成无保护模式；手机端仍在 P3。
5. **回退**：保留前一组匹配的平台、协议与镜像版本；先暂停任务并保存数据，再整体回退。profile/schema 不兼容时从验证过的备份恢复，不能直接覆盖新数据。回退版本缺少强接管时明确禁用该能力。

## 8. 验收门槛与实施顺序

| 验收 | 必须看到的结果 |
|---|---|
| 固定版本与原功能 | 固定 AIO/OSB/runsc 下 GUI、原 MCP、Shell、文件、预览仍正常；记录实际协议与能力。 |
| 接管与停止 | 长命令、后台/派生进程、GUI 排队动作、截图采集分别进入可停止状态；已接管后不再有 AI 读写，未知或无法停止时不报告成功。 |
| 旧连接与绕过 | 过期控制版本、旧 WebSocket、伪造身份、本地绕过接口均被拒绝；正常桌面和用户应用仍可操作。 |
| 观察者权限 | 修改前端只读开关、直接发送键盘/鼠标/剪贴板写入仍被服务端拦截；取得控制权后正常输入可用。 |
| 持久资料 | 重建后恢复文件、声明支持的 profile 与应用配置；已有数据不被覆盖，失败可恢复。 |
| 团队交付 | 干净镜像与独立测试数据可复现；配置、层与产物不含合成测试凭证，成员不能读原电脑私人资料。 |
| 复制与迁移 | 副本写入独立；失败重试不创建重复资源、不删源数据；切换后单端执行，回退保护较新数据。 |
| 升级与回退 | 协议不兼容明确拒绝；运行层重启不自动放行旧操作；成套回退与备份恢复可完成。 |

先做固定版本能力验证，再完成 P0 所需的受控执行、接管和持久化；P1 接入团队交付与副本，P2 完成跨主机迁移，P3 最后实现手机体验。是否启动 AIO 或 OSB 核心二开，以验证结果为依据，届时必须把准确仓库与文件级方案交给用户。
