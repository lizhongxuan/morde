# S09｜H08 评测、可观测性与方案比较

**状态：** 未开始；仅在 S07 完成 P0 验收后启动，可与 S08 并行。

**共同开发门禁：** 评测发现的失败要回到机制根因与文件 owner；复杂方案和模块/函数边界按[并发总控](00-并发实施总控.md)留档。不得用扩大阈值或指标噪声掩盖失败。

## 目标与任务来源

按已归因的失败补最小评测/观测能力，并建立固定任务样例，比较现状、固定版本 Hermes 与 Morde/DSH 方案。不得预先重构 Runtime，也不能把本方案或 Harness 宣称为最优。

具体行为与验收直接引用[最终规格](../Morde_Harness_最终流程与实现规格.md)“方案评价边界”和[主 TODO](../Morde_Harness_实施任务_TODO.md) H08。

## 文件所有权

独占 `server/internal/evaluation/**`、`server/internal/app/evaluation_blind.go`、`server/internal/worker/metrics.go`、`server/internal/worker/metrics_test.go` 及这些文件的必要直接测试。若确需在其他 worker/API/Runtime 产品文件埋点，向其唯一 owner 提出最小变更，不自行跨域编辑；不修改任何 H01–H06 功能源文件、`engine.mjs`、依赖/lockfile 或客户端。

## 实施步骤

1. 先利用 P0 已保留的脱敏阶段、原因码、关联 ID 和耗时判断诊断缺口；无真实缺口不加新平台或依赖。
2. 规则化成功/失败用确定性断言；Judge 仅用于用词/质量。观测数据不得包含原始提示、工具参数、凭据或高基数用户/Task 标签。
3. 固定比较任务、输入、模型/Provider、工具授权、预算和运行环境，比较任务成功与约束满足、安全拒绝/重复副作用、恢复、延迟和用量/成本。环境无法对齐时单列差异。
4. Hermes 行为复用只按总控表 A/B/C 与配对回归记录；不要把 Hermes 默认超时、并发值或压缩阈值设为生产默认。

## 验收

对任一纳入的失败能定位阶段并定点重跑；关键指标标签有界、内容脱敏；前后性能比较可复现。缺乏相同环境或真实 Hermes 对照时结论写“尚不能判断最优”。只在需要且完成依赖/架构登记后才考虑 OTel/Phoenix/Inspect AI。
