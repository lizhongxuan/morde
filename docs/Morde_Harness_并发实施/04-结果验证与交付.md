## 验收

按 H05 覆盖只有模型自述、证据缺失、错误环境、旧修订、重启/重连和晚到结果。必要证据缺失时不能标 PASS；Task completed 和 ResultReview 与 validation 状态分开展示；同一最终回执只发布一次。包括一个工程证据和一个非工程证据场景，实际客户端展示由 S05/S06 完成，端到端证据由 S07 记录。

## 本轮审计、验证与交接（2026-11-22）

### 调用链与当前行为

- `CommitTaskProgress` 在同一 PostgreSQL 事务中写入 `task.result` 事件、结果 SHA-256 和 `task_validation_reviews` 待处理记录；满足自动路由条件时，也在该事务中创建原会话结果源。Worker 不是最终回复的同步前置门禁。
- `TaskValidationReviewWorker` 领取审核后复核当前 Task revision、result event sequence、result SHA-256、任务状态与租约代次；模型报告只提供建议，最终 verdict 由 PostgreSQL 读取的服务端事实计算。旧修订或迟到审核无法更新当前 verdict。
- `ConversationResultReviewWorker` 将到期结果批次交给现有路由链。发布事务再次核对原会话、来源、Task revision、事件、结果摘要、授权版本与依赖，然后原子插入一条 assistant 汇总消息并将 source/batch 标为 `published`。按相同 Task/revision 重放不会再次插入回执。
- `Task.status`、`ResultReview.state` 和 `TaskValidationSummary.state` 是分开的 Task 投影字段；validation 仅在 review verdict 与当前 completed Task、revision、event sequence 和 result SHA 全部匹配时返回非 `pending`。原会话 assistant 回执现包含有界主 Agent 摘要，并分别标注 `Task` completed 与各来源当前修订的服务端 validation 状态；缺少匹配事实时标为 `pending`。这段回执不是独立验收本身，用户端仍需验收这些标签及 Task 投影状态的呈现。

### 未闭合证据接口

- 有工具/操作的 Task 目前将不可逆操作事实设为 `unknown`，所以 validation 不会因模型自述升级为 PASS。Web 内容有独立的内容哈希覆盖检查；Artifact review 输入现包含经校验的 Workspace revision、内容 SHA-256 metadata 和该 Task 修订的持久 `source_call_id`，并要求与当前 Task workspace 匹配，但不提供 Artifact 字节，也未将内容核验绑定进 validation verdict。缺少可信环境身份或可核查内容证据时保持 `pending` 是当前安全行为，不代表该能力已验收。
- 交 S03：从已授权操作/目标运行时持久提供服务端证明的环境身份，以及可用于硬门禁的 Artifact 内容证明和对应操作 Call ID；这些事实必须来自持久操作/产物记录，不能取自模型文字。当前 review packet 已把 Artifact ref 与持久解析的 `source_call_id`、Workspace revision 和 SHA-256 绑定；metadata 不可替代内容核验。
- 交 S02：确保 DSH 结果和工具证据保留当前 Session、Task revision、Call ID 与已验证运行上下文的关联，使 S04 可解析上述 S03 证据；模型不能自报环境或产物版本。
- S04 后续只消费这些已验证引用并在现有 review/verdict 事务中重核，不另建审查或发布管线。未分配新 Schema；接口就绪后如需迁移，由协调会话统一分配编号。
