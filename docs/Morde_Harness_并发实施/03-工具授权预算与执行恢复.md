### H04 合同、实现边界与未覆盖项

活动帧按 Session 顺序发送并携带 Task revision；Go 解码器、执行器和 PostgreSQL 分别校验严格字段、当前 Agent/Task fence 及单调序号。Heartbeat 是运行进程仍能报告状态的证据，不等同于业务进展；服务端只在 heartbeat 超过 60 秒未更新且仍有 `delivery_status='pending'` 的用户消息时提示。当前 root/child `model/started` 另按 45 秒模型请求期限提示；任何阶段出现 `started` 但 Session status 不是 `running` 时快照为 unknown，不产生新提示，也不清除已有提示。其它阶段不按 `activity_progressed_at` 单独判停滞。`applied` 只表示消息已领取，不表示已经回复。提示通过 `task_steps` 和 `task_events` 同事务持久化，带有 Task/message ID 但不包含用户文本、工具参数、结果或凭据；同一消息最多提示一次。未知/陈旧代次、revision、租约或活动状态不产生新提示。等待审批仍由 Task 的 `waiting_user` 状态表达，不参与运行 Task 的停滞监控。

模型请求超过 45 秒可在心跳仍新鲜时提示；工具、子 Agent 和 checkpoint 若 Node Runtime 仍按期发送 heartbeat，则沿用现有规则，不因旧进展时间单独提示。本轮未为这些阶段新增请求级 deadline 或取消策略，避免把长时间合法子任务或未知副作用误判为可安全终止。静态核对发现 `morde-pc` 的本地 Portal Assistant Task 详情订阅服务端 Task SSE 并显示 Task steps，iOS Task Detail/Event Chain 也消费服务端 `task.step`；独立 Rooms `TaskDetail.tsx` 是本机 ActivityRecord 视图，不承载云端 Task。尚未通过实际 PC/iOS 任务入口验证本次持久停滞提示的呈现。真实工具进程、断线恢复和 60 分钟耐久任务仍交 H06/S07，H04 不标整体完成。
