### 根因、实现与接口

| 缺陷 | 根因 | 最小修复与回归 |
|---|---|---|
| coordinator 确认收到 Provider 429 后不能按上限恢复 | 普通分类请求会把 provider-status 429 保持为拒绝；coordinator 路径却先把该响应记为 `unknown`，Worker 随后无法把同一次确认拒绝原子结算为 `rejected` 并释放预留 | `CompleteConversationCoordinatorModel` 对已确认的 provider-status 429 跳过 unknown 结算，让唯一重试拥有方 Worker 调用原子恢复；不确定传输错误仍结算为 `unknown`。新增 app 单测和 Worker+PG 集成用例，验证 3 次总调用、独立调用 ID、账号/项目预留释放及第三次封顶。 |
| 摘要授权或项目成员 scope 版本改变后，路由上下文读取失败且历史来源可能被旧摘要屏蔽 | `ensureConversationSummaryHead` 刷新 head 身份却保留旧版本；输入页随后按新身份读取旧摘要得到冲突。来源排除只按 `summary_version` 判断，没有要求该版本在当前授权/scope 下仍有效 | 身份变化时失效旧身份下的有效摘要及仍在运行的旧 compaction 操作，保留 head 版本号作为全局版本高水位；缺少当前身份摘要时按“无摘要”继续读历史，来源仅在摘要版本对当前授权/scope 有效时才被跳过。新增 PG 回归验证来源重新出现、旧摘要/操作被失效。 |
| 历史工具在额度刚好用尽时不能恢复已确认的工具结果；跨会话搜索无法续页且结果缺来源 ID | 三个 handler 都在检查点重放前检查剩余额度；跨会话查询只读取首批会话/消息，虽然 Store 返回分页 cursor，工具结果只报告 `partial`，模型无法继续 | Task/授权/个人记忆校验之后先重放并校验准确检查点输出，不重新读取或计费；跨会话结果增加会话/消息 ID、签名 continuation cursor 与明确截断原因。cursor 绑定 service、Task/session/current conversation、owner/initiator、授权版本与摘要、memory revision、query 和到期时间；续读仍只读用户自己的个人非项目历史，并复核每条消息。新增同消息页和跨会话页续读、身份/授权/query 变更拒绝、额度耗尽重放测试。 |

内部 DSH history tool schema 增加 nullable `cursor` 输入及 `conversation_id`、`message_id`、`next_cursor`、`truncation_reason` 输出字段；不是 Portal HTTP 或数据库 Schema 变化。结果按页续读，匹配项只在当前已扫描页内按相关度/时间排序，不对尚未扫描的整个历史声称全局排序。未配置签名密钥时结果明确 `partial=true` 和 `continuation_unavailable`，不返回不可验证的游标。没有修改 Runtime 或其他会话 owner 的文件。
