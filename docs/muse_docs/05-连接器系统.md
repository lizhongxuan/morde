# 05 连接器系统（Connectors）

## 5.1 什么是连接器

连接器 = **接某个外部应用/服务/账号/设备的官方通道**。
每个连接器有一份 `CONNECTOR.md`：怎么连接、支持哪些操作、
结果与错误怎么处理、读写权限与默认值、OAuth 流程。

位置：
- 系统连接器：`/opt/hatch/connectors/<名字>/CONNECTOR.md`（只读）
- 自定义连接器：`~/workspace/custom-connectors/custom.<服务>/`
  （含 `connector.yaml`、`CONNECTOR.md`、辅助脚本）

使用规则（系统指令原文大意）：
1. 每次新任务，先读该连接器当前的 `CONNECTOR.md`，再跑它的命令、
   再呈现结果；以前的调用、摘要、记忆不能替代当前文档。
2. 承诺依赖已连接服务的工作前，先读文档、跑状态检查；
   未连接时分享连接链接，不承诺结果，直到连接完成且健康。
3. 标志与参数格式以文档或命令的 `--help` 为准；
   一个接收者/条目上能用的调用，换多个时可能不对。
4. 发现相关技能时用 `muse.connector_search` 找；找不到时，
   先别说没有，再考虑浏览器、公开 API 或自己写代码。

## 5.3 连接方式（按文档类型分三类）

1. **OAuth / Accounts Center**：多数 Google、Meta、Spotify 等服务；
   走服务商自己的授权页，Agent 不碰密码。
2. **API 密钥（Secure Vault 流程）**：没有现成连接器的服务，
   用 `credentials.request_api_access` 拿连接链接，用户在安全页填密钥，
   再按 `custom_connector_setup` 写连接器文档。
3. **网站登录（浏览器任务）**：没有连接器时，让浏览器任务去登录；
   登录 Agent 用已保存的登录信息，没有时向用户弹出安全录入卡，
   不在聊天里要密码。

## 5.4 状态检查与错误处理

- 每个连接器文档都规定了状态检查命令；使用前跑一次，确认已连接且健康。
- 速率限制：收到 429、`provider_rate_limit_stop`、
  `connector_rate_limited`（且 `terminal_for_attempt=true`）时，
  立即停止对该服务商该范围的请求；不 sleep 重试、不换端点、
  不降速继续、不委托、不排替代任务；报告部分进展，提供不继续
  访问该服务商的其他工作。
- 403 或其他屏蔽：若响应归因于速率限制或自动访问，同样停止。
- 浏览器上的机器人检查，走浏览器自身的挑战规则，不与 API 限流混同。
