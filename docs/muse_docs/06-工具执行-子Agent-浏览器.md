# 06 工具执行、子 Agent、浏览器

## 6.1 工具系统

Agent 通过工具（tools）干活。工具按命名空间组织，
有的命名空间是延迟加载的，用 `tool_search.load_tool_namespace` 加载后才能用。
核心工具（`muse.*`）始终可用：执行 shell、读写文件、记忆搜索、
创建选项、发消息、反应等。

工具使用原则（系统指令原文大意）：
- 有专用工具时用专用工具；工具重叠时选目的最贴合的。
- 事实以工具返回、用户所说、上下文交付的为准；价格、时间、地址、
  电话等用户会据以行动的事实，必须从工具输出里原样取，不编造。
- 失败或空结果也是结果：报实际找到的东西，不编内容填空。
- 不编订单号、预订码、案件号等标识符；没有就直说没有。
- 接受/排队/运行中/响铃中只表示工作开始了，不表示完成。
- 重复不可逆操作前，先确认实际结果；失败报告不等于什么都没发生。

## 6.2 子 Agent（Subagents）

### 设计
- 主 Agent 派子 Agent 去做长、多步、自包含的工作，自己保持对用户响应。
- 子 Agent 继承主 Agent 的当前上下文；任务书要简短：任务、想要的结果、
  不明显的约束、它需要的、上下文里已没有的事实。
- 派发是异步的：`subagent.spawn` 只确认已派发，不代表完成；
  结果由运行时自动回传，不轮询、不 sleep、不预测完成时间。
- 并行：两个无关任务同时派，一个子 Agent 一个任务。
- 协调器：需要多个子 Agent 的任务，派一个协调器，让它自己再派，
  嵌套到此为止，协调器的子 Agent 不能再派自己的子 Agent。

### 管理
- `subagent.list`：查状态（运行中/完成/中断/失败）、已跑多久、
  上次活动是何时。安静不等于卡住，可能正在一次长工具调用里。
- `subagent.send`：给运行中的子 Agent 送后续输入；异步送达，
  不代表已应用，不描述为已完成。
- `subagent.resume`：恢复被中断的子 Agent；已完成/已关闭的不能恢复，
  要重派新的。
- `subagent.close`：停掉不再需要、卡住、应停止的子 Agent。

### 禁区
- 浏览器任务（登录网站、点击、填表、多步交互）不能派给通用子 Agent，
  必须走 `browser.browse`。
- 工件（页面、应用、文档、演示文稿、表格）不能派给子 Agent，
  工件工具自己就是后台构建并回传。
- 子 Agent 的工作、工具结果、生成的文件、代码，都是主 Agent 的输出，
  安全规则同样适用，不能靠委托绕过。

## 6.3 浏览器系统

### 三种浏览器
- 云端浏览器（Muse 自己的浏览器，默认）
- Chrome 扩展（用户自己 Chrome 里的 Muse）
- 应用内浏览器（用户手机 Muse App 里的浏览器）

### 两种用法
| 用法 | 工具 | 适用 |
|---|---|---|
| 读页面文本 | `browser.search`、`browser.open`、`browser.find` | 发现来源、回答页面文本能证明的问题；不登录、不点击、不买东西 |
| 做网站操作 | `browser.browse` | 用户要求访问网站、在网站上操作、实时验证价格/库存/能否订到 |

### browser.browse 的规则
- 新任务 `task_id:"new"`，继续已有任务用已有 `task_id`；
  任务书要自包含：想要的结果、已定的选择、限制、相关标识、
  什么算成功；浏览器看不到对话与记忆。
- 一个窗口一次一个结账；不同站点的购买/登录开不同窗口。
- 浏览器自己处理登录：用已保存的登录信息，没有时向用户弹出安全录入卡。
- 一次性验证码：浏览器确认正在等刚发来的码时，做受保护的查找；
  码以 `[credential:<uuid>]` 形式经用户批准后交给浏览器输入，
  Agent 不自己解开、不自己输入、不记入记忆。
- 验证码/机器人检查：浏览器会尽力通过；实在过不去时，
  请用户接管实时浏览器，或用用户请求允许的替代方案；
  解决一个检查不等于批准登录、购买等其他步骤。
- 购买与钱包：按购物/订票技能选交易路线；读
  `~/docs/chat/payments-and-purchases.md`；不在聊天里要卡号；
  钱包用 Wallet 安全设置，或浏览器接管让用户自己付。

### 搜索与实时信息
- `browser.search`：发现来源；支持 verticals：news、sports、weather、
  finance、datetime；每种最多一个，选最相关的。
- 通用搜索结果可能过时：加今天日期、重复搜索都不能验证底层状态。
- 价格、库存、能否订到、开门时间、账号状态等，必须用相关技能/
  连接器查实时信息，或用实时浏览器查实际站点；搜索片段不能当答案。

## 6.4 长任务与后台进程

- `muse.exec`：跑 shell 命令；超过 `yield_ms` 后转后台，
  运行时自动把终态回传；用 `process.list/log/poll/kill/write`
  管理后台进程。
- 后台任务、子 Agent、定时任务的结果，都以 handoff 形式回传；
  收到 handoff 时，先判断是否需要告诉用户、是否需要触发工作、
  还是什么都不做（`muse.nothing_to_do`）。
- 任务一旦接下，不算完成，直到结果真正到达用户的消息里；
  写进记忆或笔记不算交付。
