## 一、执行规则与最终目标

**用户体验目标：**普通问题直接回答，简单任务按需使用工具；复杂任务由主 Agent 协调并在原会话交付可核查结果。执行期间用户仍可追问、修改或停止指定任务，也可以提出独立任务；必要时才问清楚，失败、等待、验证和未完成内容都如实展示，并告诉用户当前可做什么。PC 界面遵守 `docs/design/ice-cream-blue/morde-icecream-blue-ui-spec.html`，状态和操作适配键盘、焦点与屏幕阅读器。实际使用要覆盖会话与任务隔离、长对话、授权电脑、工具、审批、多 Agent、恢复、记忆及 PC 文件夹同步。

1. 一个会话在含本方案和分步改动的同一工作树中检查 `git status`、相关 `AGENTS.md`、最新 TODO 和代码；本方案可能尚未跟踪，独立 worktree 不会自动包含未提交内容，缺失时先核对，保留其他会话的改动；每完成一项就在本文件更新状态、证据和剩余项，同时更新对应分步 TODO、最终流程图及验证记录。依赖指先稳定所需接口与事实合同：若仅实际客户端验收受环境阻塞，可继续合同已稳定的后续开发，但依赖验收未通过前不得关闭相应总项。`[x]` 只用于实现和本项要求的验收都通过；测试跳过、fixture 成功或本地代码存在都不等于端到端通过。
2. 使用 DSH 作为唯一 Agent Runtime，模型经 Morde 网关，副作用经既有 Broker、授权/审批、预算和操作账本。先检查当前依赖与本地 `project/deepseek-harness` 对应插件；可复用时按版本、许可证和用户/会话/任务隔离做适配。不要另建 Agent 循环或绕过 Broker。
3. 涉及普通用户交互、手工及端到端验收时只操作实际  `make pc` 启动的PC端；不得用普通用户 Web 或 iOS 代测。原生 iOS 是独立产品目标，但在当前限制下，其交互和跨端端到端验收保持阻塞，不以 PC 结果冒充通过。
4. 服务端实现遵守 [`server/AGENTS.md`](../../../server/AGENTS.md)：接口、状态、数据库变化必须同步权威契约、实现和测试；不另建平行账本或状态机。冲突先在所属实施文档记录后协调。其禁止本期引入 OpenTelemetry SDK，因此总计划中的 OTel/Phoenix 不作为可直接接入的默认实现；先用现有结构化日志和有界指标，且不记录模型原文、工具参数或凭据。
5. 测试结果分四类记录：**本地自动化**、**实际 PC + 合成服务**、**实际 PC + 真实 DSH/工具链**、**跨端/真实云端**。每条记录版本、环境、操作、实际结果、证据、限制和结论；未跑、跳过、失败分别注明。当前限制不允许的真实云端文件传输和外部连接器写入不得伪装为通过。

### PC 体验补充需求与审核（2026-11-24）

本节依据用户反馈和截图，覆盖旧用例中与下列 PC 展示要求冲突的描述；历史验证记录仍保留为当时的事实。具体实施与防回归见 R19–R24、T45–T54，均尚未实施或验收。

必要截图已保存在本地：[PC 中断提示](参考截图/01-morde-interrupted.png) · [PC 任务侧栏](参考截图/02-morde-task-sidebar.png) · [Muse 工作项列表](参考截图/03-muse-activity-list.jpg) · [Muse 命令详情](参考截图/04-muse-command-detail.jpg)。Muse 截图用于核对交互、信息层次与内容完整性；Morde 视觉样式遵循项目统一规范，实际执行、结果和权限以账本及验收证据为准。

1. **复杂任务与续接：**目标明确时正常创建或继续指定任务；不能把分类异常一律转成“分类暂时不可用，请说明要操作哪个任务”。确有歧义才结合当前会话和候选任务提出可回答的问题；服务不可用时说明实际情况。不能误操作其他任务或重复已执行的动作。
2. **中断与合并：**删除截图中用户消息下“任务已中断……查看任务详情”的状态行。任务确实中断或无法继续时，由主 Agent 在原对话依据已确认事实说明完成了什么、原因/未知之处及下一步；模型不可用或任务预算已用尽时在对话内如实给出服务或预算提示，不能绕过预算。请求并入另一任务本身不算失败；目标后来真正失败时说明其实际原因和未完成事项。用户取消、等待审批和结果未知也须各自表达，不能冒充成功或失败。
3. **长输入：**超过 8K 的输入在现有支持范围、模型能力及预算允许时应正常受理、理解并完成；完整保留原消息，长文分析可分段处理、追溯来源。区分字节、Unicode 字符和 token；超出能力或证据不足时如实说明，不静默截断、编造完整结论或要求重复副作用。
4. **审批与侧栏：**PC 任务动态删除截图中的“任务验证”模块及其证据面板、“停止此任务”按钮、“在 Workbench 只读观察/查看已核验产物”入口，并移除侧栏内所有审批动作。需要审批时，同一审批以 **MCP Apps 交互卡片**出现在发起对话和审核区，两处使用同一后端决定；用户通过对话仍可补充、停止、回答澄清或安全重试指定任务，不打开侧栏也能完成工作。验证事实、成果和现有 Workbench 能力继续保留。
5. **任务动态：**显示简洁的任务标题、状态和按主/子 Agent 归属的真实工作项；让用户看清 AI 搜索了什么、查看了什么、执行了什么及真实结果。可展开查看适用的查询、来源、命令、工作目录、退出码、耗时和输出；失败、取消、等待或未知须可分辨，低价值调度噪音不占主要视图。最终成功、失败原因和未完成事项仍在对话中交付。

**审核依据与待证实问题：**`conversationRouteClassifyFallback` 在分类异常且识别为控制意图时确会返回截图中的固定提示，但这不足以证明所有复杂任务的共同根因；R19 须先复现并核对分类输出和目标匹配。消息上传当前有 16 KiB 分块和 8 MiB 上限，不能据此断定存在统一的 8K 硬上限；R21 须逐层定位。现有 `TaskApprovalCard` 是 React 组件，服务端的 `ui://morde/desktop-observation` 是只读观察资源，均不证明对话区/审核区已接通审批用 MCP Apps。Muse 逆向报告和用户截图显示动作标题、查询、命令和结果的呈现方式；本地 [actions 表结构](../muse-all-materials/skills/muse_db/references/tables/activity.activity_monitor_thread_actions.md)与 [threads 表结构](../muse-all-materials/skills/muse_db/references/tables/activity.activity_monitor_threads.md)支持动作、归属和终态字段，表结构本身不证明每条实际数据或实现算法。

## 二、明确接口与兼容边界

以下是要核对并按需修改的**既有接口**，不是新建第二套接口的指令。若当前接口足够表达行为，保留接口，补调用方和测试；确需增加字段或持久化时，先记录合同、迁移和调用方，并同步 OpenAPI 与服务端权威文档。

| 接口或合同 | 实施要求 |
|---|---|
| 收件、路由与计划：`ConversationRouteWorker`、`conversation_route_decision.go`、`executeTaskPlan` / `task.Plan` | 延续原消息 ID、Task 修订、作用域和幂等。`dependency_task_ids` 是已有 Task 依赖；`PlanStep.depends_on` 是同计划步骤依赖，必须分别验证，计划保存不等于派发已受门控。 |
| DSH 委派与工具：`engine.mjs` 的 `dsh_delegate` / `validTools`，`CloudDSHToolBroker` | 现有每轮工具定义上限为 64；全局已注册工具可以超过 64，但每轮只提供满足模型、Runtime、预算与授权约束的有界集合，保留必需工具和稳定调用身份。工具选择不能授予权限。 |
| 预算：`ModelGatewayService`、`modelRequestInputTokenReservation`、`model_usage.go` | 预留和结算继续在服务端原子执行；只采用模型/提供方可验证的精确计数或有证明的保守上界，否则安全缩减输入或维持原上界。未知用量不释放，不通过降低系数或提额绕过上限。 |
| 工作项/审批：`TaskStepDetail`、`PendingRequest`、`POST /tasks/:id/approvals/:approval_id/responses` | 按现有授权读取详情与审批；缺字段再补充可追溯证据、可用成本与未知态。对话与审核区接入同一审批的 MCP App（资源/宿主适配按 R22 拟新增或复用），继续调用现有审批响应接口并绑定任务修订、调用身份、参数及目标；批准不等于执行成功。 |
| 对话澄清/重试：`POST /api/tasks/:id/inputs`、`POST /api/tasks/:id/steps/:step_id/retries` | 对话回答绑定 `clarification_id`、`clarification_version` 与幂等键；在原会话可持久恢复问题与已确认回答，优先按现有事件及请求记录投影，缺少授权读取合同才扩展接口。显式重试绑定源步骤、`expected_task_revision`、`expected_attempt` 与幂等键；沿用授权、等待期和未知结果对账，不新建平行重试入口或账本。 |
| 验证/交付：`TaskValidationReviewWorker`、`CompleteTaskValidationReview`、`publishConversationResultReviewInTx` | 验证证据与当前 claim、修订、结果事件、来源和权限绑定；完成结果发布前重检 steer 与完成栅栏。现有结果整理只接已完成任务，失败/等待须按 R20 接通事实事件到原会话，不将其伪装为 completed，不放松成功门禁或另造状态源。 |
| 记忆与恢复：`searchCurrentConversationHistory`、`GetMemoryHistory`、`Broker.Reconcile`、`RequestTaskStepRetry` | 历史和规则每次重验授权及来源；未确认遗忘不执行。已派发结果未知先按原身份对账；显式重试、等待期、checkpoint 和审批继续遵循现有精确身份合同。 |
| PC 文件同步：`morde-sync.ts`、`workspace_sync*.go` | 用户点击才单向同步到固定默认电脑，按 applied 回执建立基线；冲突、撤权或未知结果保留受影响内容。不能绕过现有路径、授权与操作账本边界。 |

## 六、总计划增强项：保留任务，不能冒称 Muse 事实

在核心闭环后继续执行以下项目；若 R13 受当前 iOS/外发限制阻塞，不妨碍可以在本地安全进行的独立开发，但整份方案不能标为全部完成。每项先核对既有能力，插件可用则优先适配，避免重复造轮子。

- [ ] **R15（未开始，依赖 R09/R12）受控 Skill 草稿与整理，对应 P2-1。**评估本地 DSH skill provider 和现有只读目录；实现时只允许在用户授权的租户范围形成候选、验证、明确审批、启用及撤销/归档，未批准不能执行，不能访问任意本机文件或把一次批准当未来操作审批。验收 **A01**：本地合成候选未批不可用、审批后可用、撤销立即失效，重启后隔离和来源可追溯。整理周期由 Morde 的可配置策略和证据决定，不把原文数字当 Muse 必然规则。

## 七、完成判定

- **PC 核心闭环完成：**R00、R00A、R01–R14、R19–R24 的 PC 范围实现和适用 T01–T43、T45–T54 通过；真实 PC 与 DSH 链路、正确/错误产物、任务中途接续、恢复去重、长历史及授权隔离均有可追溯证据。任一真实 PC/DSH 场景只有 fixture 通过时，该项保持待验收。T44 与原 M01-02/03 的双端要求独立保留，不随 PC 核心通过而关闭。
