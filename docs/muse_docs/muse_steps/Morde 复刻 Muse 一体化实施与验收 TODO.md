## 一、执行规则与最终目标

**五会话并发时：**按[并发实施总览](<五会话并发实施/00-并发实施总览.md>)分配写入权和分项交接；B–E 只更新各自任务文档，A 统一同步本方案、分步 TODO、总流程及验证记录，避免同时写同一文件。缺失的公共合同优先查找现行来源；现有代码、项目规则与用户目标足以确定时，可新编当前版本并标注依据，不恢复旧文件；无法确定的条款保持阻塞。

**用户体验目标：**普通问题直接回答，简单任务按需使用工具；复杂任务由主 Agent 协调并在原会话交付可核查结果。执行期间用户仍可追问、修改或停止指定任务，也可以提出独立任务；必要时才问清楚，失败、等待、验证和未完成内容都如实展示，并告诉用户当前可做什么。PC 界面遵守 `docs/design/ice-cream-blue/morde-icecream-blue-ui-spec.html`，状态和操作适配键盘、焦点与屏幕阅读器。实际使用要覆盖会话与任务隔离、长对话、授权电脑、工具、审批、多 Agent、恢复、记忆及 PC 文件夹同步。

1. 一个会话在含本方案和分步改动的同一工作树中检查 `git status`、相关 `AGENTS.md`、最新 TODO 和代码；本方案可能尚未跟踪，独立 worktree 不会自动包含未提交内容，缺失时先核对，保留其他会话的改动；每完成一项就在本文件更新状态、证据和剩余项，同时更新对应分步 TODO、最终流程图及验证记录。依赖指先稳定所需接口与事实合同：若仅实际客户端验收受环境阻塞，可继续合同已稳定的后续开发，但依赖验收未通过前不得关闭相应总项。`[x]` 只用于实现和本项要求的验收都通过；测试跳过、fixture 成功或本地代码存在都不等于端到端通过。
2. 使用 DSH 作为唯一 Agent Runtime，模型经 Morde 网关，副作用经既有 Broker、授权/审批、预算和操作账本。先检查当前依赖与本地 `project/deepseek-harness` 对应插件；可复用时按版本、许可证和用户/会话/任务隔离做适配。不要另建 Agent 循环或绕过 Broker。
3. 涉及普通用户交互、手工及端到端验收时只操作实际 `morde-pc`，优先使用 `make pc`；不得用普通用户 Web 或 iOS 代测。Playwright 若无法安全连接 `make pc` 启动的进程，可在执行同等源码构建并核对入口、版本和启动配置后启动同一 Electron 客户端，按第四节先验证可行性，不能使用旧打包版或独立 Portal 页面冒充 PC。原生 iOS 是独立产品目标，但在当前限制下，其交互和跨端端到端验收保持阻塞，不以 PC 结果冒充通过。
4. 服务端实现遵守 [`server/AGENTS.md`](../../../server/AGENTS.md)：接口、状态、数据库变化必须同步权威契约、实现和测试；不另建平行账本或状态机。冲突先在所属实施文档记录后协调。其禁止本期引入 OpenTelemetry SDK，因此总计划中的 OTel/Phoenix 不作为可直接接入的默认实现；先用现有结构化日志和有界指标，且不记录模型原文、工具参数或凭据。
5. 测试结果分四类记录：**本地自动化**、**实际 PC + 合成服务**、**实际 PC + 真实 DSH/工具链**、**跨端/真实云端**。每条记录版本、环境、操作、实际结果、证据、限制和结论；未跑、跳过、失败分别注明。真实云端文件传输按任务与授权目标安排；尚未执行的云端或外部连接器场景不得伪装为通过。

### PC 界面测试与 Trace（可行性待验证）

- 项目已有 Playwright 1.64.1，但 `web/portal/playwright.config.ts` 启动的是独立 Portal 浏览器，不能用于本方案的普通用户交互或 PC 验收。先用当前源码构建的实际 `morde-pc` 做一个本地合成冒烟，验证 Playwright 的 Electron 支持能否定位客户端的 `WebContentsView`、操作界面并保存可回看的 trace；使用独立测试 profile，不关闭沙箱或安全策略。Electron 自动化是实验性能力，此链路目前尚未验证。若不可行，记录原因，继续用能操作实际 PC 的方式验收，不因选用工具阻塞功能开发。
- 冒烟通过后，优先为 **T51–T54 的 PC 界面部分**，以及 T45/T47 的界面故障复现编写 Playwright 测试并录制 trace；T02 跨重启分别保存前后 trace 和任务状态。真实 DSH、审批账本、工作项结果与长文语义仍须按各用例独立核对，不能用截图、Mock 或 trace 回放代替。原生文件选择等 OS 弹窗不由 Playwright 直接操作；替身只算合成测试，真实客户端交互仍须另验。
- Trace 记录操作、页面快照和网络信息，使用合成账号和数据，默认保存在本机，需要传输时按任务授权处理。失败时优先保留 trace；需要成功过程证据时按场景显式保留。无重试配置可选 `retain-on-failure`，不能在 `retries: 0` 时依赖 `on-first-retry` 生成记录。优先用本地已安装的 Playwright `show-trace` 查看；在线查看或分享按任务授权处理。确保测试报告保留断言结果；若对 Electron 的自建 context 使用 `context.tracing`，该 API 本身不记录 `expect` 断言。参考 [Trace Viewer](https://playwright.dev/docs/trace-viewer)、[Electron 支持](https://playwright.dev/docs/api/class-electron)、[Tracing API](https://playwright.dev/docs/api/class-tracing)。
