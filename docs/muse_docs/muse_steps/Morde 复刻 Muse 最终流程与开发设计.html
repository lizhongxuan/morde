01

收件与会话

复用 / 端到端待验收

现状与要修改的地方

代码可见服务端消息受理、幂等和会话序号，PC/iOS 均有本地待发与恢复机制。两端能否在同一会话持续接续消息、任务进度和结果，仍须从实际客户端完整验收。

设计与开发

先验证身份、会话归属和内容，再在同一事务内保存消息、稳定客户端 ID、请求摘要和路由状态；同 ID 同内容返回原记录，不同内容报冲突。按服务端序号显示；客户端重启先用原 ID 查受理结果，再决定重试。

Morde 落点

TaskService.AcceptConversationMessage；Store.AcceptConversationMessage；enqueueOutboxMessage；MordeMessageOutbox。

开源参考

OpenClaw · recordInboundSession：参考收件后的会话归属；LibreChat · createConversationMethods / getConvo：参考会话读取。多租户与幂等继续由 Morde 实现。

验收

同账号 PC/iOS 接续同一会话；重发同 ID 无重复消息和 Task；并发定序、重启恢复、两账号隔离。参考 TC-1.1、TC-1.7。

02

意图路由与任务拆分

需核对 / 补强

现状与要修改的地方

已有分类、非法输出修复/兜底、聚合和 Task 创建链路。Muse 的分类与归并算法未知；现有“Planner 独立文件、60 秒窗口、缺验收标准就必问”的建议不能视作现状或已确认规则。

设计与开发

分类输出应绑定已受理消息、会话和当前任务快照；分成回复、查询、明确修改/停止、简单工具、新 Task 和澄清。新 Task 记录目标、范围、验收、预算与回传会话；只在确有必要且无法推定时追问。先复用已有聚合/计划字段，实测误归并和遗漏后再决定是否增加判定机制。

Morde 落点

ConversationRouteWorker.RunOnce / safeConversationRouteDecision；ClassifyConversationRoute；ApplyConversationRoute / createConversationRouteTask；executeTaskPlan。

开源参考

Magentic-UI · format_user_interjection：参考补充消息的上下文表达；LangGraph · StateGraph.compile：参考显式状态边界，不引入图运行时。材料中的 Microsoft Agent Framework 双账本代码未在本地对应源码中核实；Magentic-UI 不等同该框架。

验收

普通问答不启动云电脑；追问、停止、新任务不串线；指代不清澄清；非法输出有界恢复。参考 TC-2.1–2.12 中适用项。

03

并发派发与主 Agent 协调

明确差距：子 Agent 暂不能再委派

现状与要修改的地方

Muse 资料观察到 root → 子 Agent → 孙 Agent 两层派生。Morde 当前 validDelegateArguments 排除 dsh_delegate，validateChildSession 拒绝子 Session 获得该工具；因此现有运行链无法照此继续派生。存储层有父子关系与祖先校验，需连同运行时和恢复链一起扩展。

设计与开发

目标支持 root → 协调员 → worker，根 Task 保留最终责任。每层持久记录父 Session、深度、派生身份、工具范围、预算和根检查点；权限只可收窄。独立 worker 并行，依赖任务等待前置结果；结果、证据和失败逐层回传。参考 nanoMuse 的 10 并发作为候选值，按负载验证；Muse 实际上限未知。

Morde 落点

validDelegateArguments / validateChildSession / runAgent；createCloudDSHChildSession 与结算/恢复；AgentChildSessionService；CreateAgentChildSession；根检查点授权栅栏。

开源参考

DSH · delegationDepthOf / assertSubagentMaxDepth；SubagentManager.startLocal；maxDepth 配置：本地插件源码默认为 1，目标两层需显式配置并接入；安装或注册本身不等于 Morde 的授权、账本和恢复已接通。Magentic-UI · build_handoff：参考逐层回传。

验收

实际创建 depth 1 与 depth 2；至少两个 worker 真并行并汇总；取消隔离、重启恢复、权限和预算不越过父级。参考 TC-3.1–3.13。

04

工具执行与工作项

明确差距：工作项详情需扩展

现状与要修改的地方

Broker 已有调用接纳、执行和对账。TaskStepDetailDocument 当前保存对象、输入/结果摘要和部分证据；Shell 证据有退出码、输出字节数与截断标记，并非 Muse 报告中的完整命令、执行目录、耗时和输出。

设计与开发

按工具类型补执行位置、原始命令/参数、退出码、耗时、工作目录、输出和结论；不适用或取不到时明确标记。沿用加密详情与按用户授权读取，长输出附截断说明及安全回查方式。调用前持久化操作意图，结果未知先对账，不重复副作用。

Morde 落点

TaskStepDetailDocument / TaskStepShellExecutionEvidence；taskToolCallProgress / taskToolShellExecutionEvidence；GetStepDetail；Execute / Reconcile；对应 API、PC/iOS 详情视图。

开源参考

Magentic-UI · enrich：参考执行结果补充观察；nanoMuse · ToolLoopDetector.check/record：参考防循环，不直接移植其单机内存状态。OpenHands Agent Canvas · groupEvents：参考前端工作项分组，本地目录不是完整 Agent 后端源码。

验收

工具调用可查看适用详情；运行、失败、取消均留痕；结果未知不重放；新 steer 不让旧调用越过栅栏。参考 TC-4.1–4.14。

05

授权、预算与审批

复用 / 披露与真实入口待验收

现状与要修改的地方

代码中已有 Broker 和绑定具体工具调用的 PendingRequest；审批卡披露、动作范围授权、费用来源和端到端生效情况需逐项核对，未知成本不能写成 0。

设计与开发

技术执行范围与审批策略分开判断；审批绑定账号、目标、具体动作/参数、Task 修订和授权版本。待批、拒绝、超时、撤权或预算不足时保存状态且不执行；获批后再次校验身份、预算和 steer。卡片显示已知对象、影响、成本和拒绝后果，缺失明确标未知。

Morde 落点

CloudDSHToolBroker.Execute；ListTaskApprovals；审批持久化；PC 审批卡；iOS 审批视图。

开源参考

Codex · AskForApproval / SandboxPolicy：参考两类决策分离；Hermes · request_tool_approval：参考审批请求表达；Claude Agent SDK · PermissionResultAllow / PermissionResultDeny：参考明确的允许和拒绝接口，不替代 DSH。单机授权、绕过模式和模型代批不引入服务端。

验收

错目标、过期批准、撤权、拒绝和超预算均不派发；PC/iOS 展示真实审批与未知费用。参考 TC-5.1–5.17 中适用项。

06

结果验证

明确差距：产物内容未进入当前复核包

现状与要修改的地方

代码中已有验证 Worker、修订和结果栅栏。reviewInput 对 Artifact 构造 artifact_metadata_only，复核提示也明确不含产物字节；因此当前这条路径不能证明产物内容正确。

设计与开发

为适用任务收集真实检查与读回证据，绑定 Task 修订、尝试、来源调用、产物版本和执行环境。补充按复核任务和当前授权读取产物的本地检查路径，校验版本、来源及摘要后生成可追溯的检查结果；由服务端硬规则区分通过、失败和待验证。模型复核仅作辅助。

Morde 落点

review / reviewInput；EvaluateTaskValidationReview；CompleteTaskValidationReview；conversationTaskResultValidationStateInTx。

开源参考

Magentic-UI · decide_verifier_class / diff_states：参考操作前后状态取证，不视为通用验收系统。独立换模型家族并非 Muse 已证实机制，不能替代硬门禁。

验收

旧修订、错环境、只有模型自述均不通过；区分已执行、待验证和验收通过。参考 TC-6.1–6.9。

07

交付与用户提问

复用 / 客户端展示待补验

现状与要修改的地方

已有原会话结果发布和单次回执方向；任务状态与验收状态的端上展示、跨端恢复及真实入口仍需核对。Muse 回复长度和提问比例是观察值，不设为 Morde 硬指标。

设计与开发

Task 完成前在锁内重检 pending/applied steer 与完成候选 fence；有新输入则恢复同一 Session。确认后先持久化一份回执，再发回原会话；回复包含结果要点、产物、证据和未完成项。PC/iOS 展示执行中、待批、失败、待验证和已通过等真实状态。

Morde 落点

publishConversationResultReviewInTx；PC Assistant；iOS MordeApp。

开源参考

LibreChat · createChannelArtifactService：参考按会话读取产物；artifactByIdSelector / visibleArtifacts：参考展示状态。客户端使用 Morde 统一蓝色样式。

验收

回执只发布一次，断线后可恢复；新 steer 不发布旧结果；两端能区分完成与验收。参考 TC-7.1–7.12 中适用项。

08

记忆与纠正沉淀

需对照完善记忆与经验

现状与要修改的地方

代码可见会话历史检索、摘要及个人记忆历史。Muse 采用可读记忆与索引双轨并保留纠正关系；Morde 是否覆盖全部写入、索引、整理和遗忘链路须逐项核对。Muse 具体写入与去重规则未知。

设计与开发

设计按用户隔离的可读记忆与检索索引，记录来源、范围、版本和纠正的 supersedes 关系；后台整理不阻塞对话。删除需确认范围并同步清理索引。可执行经验先形成候选，经过验证和授权后启用，支持撤销和回退；不复用旧审批。

Morde 落点

searchCurrentConversationHistory；GetMemoryHistory；executeSkillRead；在现有记忆、授权与版本机制内对照补齐候选流程。

开源参考

OpenClaw · recordMemoryArtifactWriteProvenance：参考记忆来源；Agno · MemoryManager.search_user_memories / delete_user_memory：参考按用户查找与删除。不能照搬单机文件权限。

验收

授权撤销后查不到旧记忆；纠正能追溯旧版本；删除覆盖可读内容与索引；候选未批准不生效。参考 TC-8.1–8.12 中适用项。

09

失败、限流与恢复

需补真实故障验收

现状与要修改的地方

代码中可见部分错误分类、明确 429 的有限恢复、操作对账和活动状态；仍须核对真实 Provider、Host、客户端及长时间运行时的表现。Muse 自动重试和降级阈值未知。

设计与开发

统一记录阶段、原因码、调用身份、租户、耗时和结果状态；按错误是否可安全重放决定恢复。明确 Provider 429 沿用当前路由层有限重试；超时、断流、已派发操作或用量未知先对账。连接器只有在显式 terminal 标记及 `retry_after` 被持久到账本后才结束本次 Task 尝试；Task/MCP 重试必须由用户发起，且仅在唯一操作账本、调用/参数摘要、当前 Agent 已有可验证停止凭据、授权、审批、预算和等待期均通过当前状态复核后开放，避免旧 Agent 进程树尚未停止时排入新一代执行。审批或进程恢复只能继续同一预留尝试和调用身份；未知操作仍等待对账，不自动重派。已展示的文本保留并标中断，等待审批不算失败。Agent 未发布最终答复时，原消息下应显示任务已中断、结果未确认及最后确认的工作项；模型结果校验失败与未授权工具分开记录，未授权调用不得执行。工具调用在校验阶段被拒时，日志及任务事件记录白名单阶段、原因码、工具名、有效调用 ID 和是否派发；工具执行异常导致执行状态无法确认时，日志记录工具名、调用 ID、派发状态、稳定失败原因码及底层错误类型。已派发工具的最终结果通过 Task 操作账本按任务及调用身份排查。不得将工具参数、原始模型内容、原始错误文本或凭据复制到通用日志。

Morde 落点

conversationRouteRateLimitDelay / failRoute；cloudDSHModelErrorCategory；MCPConnectorTerminalRetryAfterSeconds / newMCPToolTaskStep；RequestTaskStepRetry / ConsumeTaskStepRetryIntent；listTaskStepsWithActivity；Reconcile。

开源参考

Hermes · classify_api_error；parse_retry_after_seconds / jittered_backoff：参考分类和退避。阈值、账本及重试拥有方按 Morde 设计，不叠加多层自动重试。

验收

429、断流、取消、授权失效和结果未知分别处理；已生效但回执丢失不重复操作。Task/MCP 重试须等到账本推导出的 `retry_after`，同一幂等键只保留一个新尝试；账本不唯一、调用摘要变化或存在 unknown 操作时没有重试入口。Task 恢复未决时，原消息下能看到没有最终答复、最后确认工作及可打开的任务详情。参考 TC-9.1–9.8。

10

上下文管理

已有两层能力 / 真实长会话待验收

现状与要修改的地方

代码中可见跨 Task 摘要、授权历史检索和 DSH Session 压缩；真实模型窗口、长会话和大消息答案仍需从实际 morde-pc 客户端验证。按项目约定，不使用普通用户 Web 端或 iOS 代测。Muse 的压缩算法与触发阈值未知。

设计与开发

路由层按模型窗口装配摘要、近期历史和当前消息，保留原文 ID、长度与摘要。针对超长当前消息中的具体问题，优先由授权服务端校验所有规范页及全文哈希，再检索并向模型返回带页码/页哈希的有限摘录，避免把 1 MiB 全文灌入 Task 预算；只有确需全文时才顺序分段读取并遵守预算，无法完整处理时明确说明。Task 层复用 DSH 修剪和压缩，保留工具调用/结果配对及最新要求。压缩失败保留原文和旧摘要，无进展不得反复压缩；无法取得必要历史时说明。

Morde 落点

fitConversationRouteContext；compactConversationSummary；executeCurrentConversationMessageSearch / executeCurrentConversationMessageRead；MordeCompactionEngine / ToolResultPruner。

开源参考

DSH · BasicCompactionEngine.compactIfNeeded；Hermes · _plan_compaction_window / summary_view：参考保护头尾及完整工具组。Morde 不照搬 Hermes 原地改写或固定阈值。

验收

在实际 morde-pc 客户端验证真实累计历史超过模型单次窗口后早期要求可回查，并验证 1 MiB 消息中的分散锚点、来源页码和恢复行为；压缩失败、撤权和跨账号隔离保持正确。禁止使用普通用户 Web 或 iOS 代测。参考 TC-10.1–10.20 中适用项。

11

Bug 发现与处理

工程方法 / 持续执行

现状与要修改的地方

逆向材料的五步法来自排查案例，没有足够证据证明它是 Muse 的产品机制。Morde 代码中已有自动化测试；是否覆盖实际问题和完整调用链，应以本次复现及执行结果为准。

设计与开发

记录现象和版本 → 本地复现并区分环境 → 验证根因 → 先补能捕获根因的回归再修复 → 记录实际结果、未测项和回退。脱敏记录阶段与原因码；需要扩大观测工具时先核对项目依赖及授权，不让评测自行改代码。

Morde 落点

TestConversationMessageReceiptIsAtomicAndScoped 是现有回归示例；针对实际缺口在对应服务端、DSH 和客户端测试目录补可复现用例。

开源参考

Hermes · test_corrections_are_generation_fenced_and_consumed_by_same_provider_loop：参考围绕消息代次编写回归。五步法为团队方法，不宣称来自某个开源产品。

验收

每个缺陷能追到复现、根因、修改、回归和实际生效状态；未执行项如实记录。参考 TC-11.1–11.10。

实施边界与次序

  1. 先闭环基础体验：核对收件与路由，补齐工具工作项和审批，再完成可恢复的两层子 Agent 协作、真实证据验证及原会话交付。
  2. 再完善长期能力：验证长会话压缩、失败恢复和记忆整理，以真实缺口扩充评测。独立验证模型、全量事件迁移、固定并发数、固定 60 秒合并窗口和强制 top-k 均为设计候选，需另行验证。
  3. PC 文件夹同步独立于普通问答：用户在 morde-pc 手动选择并触发，单向同步到其固定默认云电脑的 ~/workspace/project/<项目名>/；冲突、失权或源目录不可访问时保留内容并提示，默认电脑不可用时不得切换目标，不因普通聊天启动同步。
  4. 产品与安全边界：普通用户端只有 PC/iOS，管理 Web 用于管理；DSH 为唯一 Agent Runtime。所有工具副作用经过 Morde 授权、审批、预算、操作记录和租户隔离。
  5. 文件和来源：本次只使用本地源码。project/ 下除 DSH 外多数是无独立 Git 元数据的源码快照，无法仅凭目录确认其上游提交。实际移植前核对目标文件版本、许可证及测试。

本地 OpenHands 为 Agent Canvas 前端源码，Claude Agent SDK 可参考权限合同；未找到 Microsoft Agent Framework 的独立源码。Magentic-UI 是本地参考项目，不等同 Microsoft Agent Framework。
