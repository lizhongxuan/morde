01

收件与会话

复用 / 端到端待验收

现状与要修改的地方

代码可见服务端消息受理、幂等和会话序号，PC/iOS 均有本地待发与恢复机制。两端能否在同一会话持续接续消息、任务进度和结果，仍须从实际客户端完整验收。

设计与开发

先验证身份、会话归属和内容，再在同一事务内保存消息、稳定客户端 ID、请求摘要和路由状态；同 ID 同内容返回原记录，不同内容报冲突。按服务端序号显示；客户端重启先用原 ID 查受理结果，再决定重试。

Morde 落点

TaskService.AcceptConversationMessage；Store.AcceptConversationMessage；enqueueOutboxMessage；MordeMessageOutbox。

开源参考

OpenClaw · recordInboundSession：参考收件后的会话归属；LibreChat · createConversationMethods / getConvo：参考会话读取。多租户与幂等继续由 Morde 实现。

验收

同账号 PC/iOS 接续同一会话；重发同 ID 无重复消息和 Task；并发定序、重启恢复、两账号隔离。参考 TC-1.1、TC-1.7。

02

意图路由与任务拆分

需核对 / 补强

现状与要修改的地方

已有分类、非法输出修复/兜底、聚合和 Task 创建链路。截断长消息开头明确要求总结、分析或解释文章时，即使分类输出误判为回复、工具或澄清，工作区已补齐新 Task 路由并通过 app/worker 与 PostgreSQL 定向回归；测试机数据库找到与截图文章请求开头相同的消息，但它进入 waiting_user 且没有创建 Task。线上助手回复与截图文字不同，不能断定为同一轮显示。测试机 Portal 仍运行源码提交 5b3dc07，尚未包含该未提交修复；新服务版本仍需实际 PC 复验。Muse 的分类与归并算法未知；现有“Planner 独立文件、60 秒窗口、缺验收标准就必问”的建议不能视作现状或已确认规则。

设计与开发

分类输出应绑定已受理消息、会话和当前任务快照；分成回复、查询、明确修改/停止、简单工具、新 Task 和澄清。新 Task 记录目标、范围、验收、预算与回传会话；只在确有必要且无法推定时追问。PC 任务详情不再提供下一条消息手动绑定入口或当前进展区，消息依靠路由识别目标，含混时澄清；既有未发送消息保留其原始路由字段。长消息的路由层只看有界预览：开头明确要求总结、分析或解释文章/原文时仍创建 Task，再由 Task Agent 通过授权的当前消息搜索或分段读取工具取回来源；有其他任务时只放行清楚独立的内容分析，指代现有 Task 的控制请求或意图不明确时继续澄清，不能把预览当全文。相同请求对应的旧任务等待恢复时先说明状态，用户明确要求重新开始才另建 Task；保留正常重发去重。先复用已有聚合/计划字段，实测误归并和遗漏后再决定是否增加判定机制。

Morde 落点

ConversationRouteWorker.RunOnce / safeConversationRouteDecision；ClassifyConversationRoute；ApplyConversationRoute / createConversationRouteTask；executeTaskPlan。

开源参考

Magentic-UI · format_user_interjection：参考补充消息的上下文表达；LangGraph · StateGraph.compile：参考显式状态边界，不引入图运行时。材料中的 Microsoft Agent Framework 双账本代码未在本地对应源码中核实；Magentic-UI 不等同该框架。

验收

普通问答不启动云电脑；追问、停止、新任务不串线；指代不清澄清；非法输出有界恢复。参考 TC-2.1–2.12 中适用项。

03

并发派发与主 Agent 协调

服务端/Runtime 已验收 · PC 端到端待验

现状与要修改的地方

已在现有 DSH 和持久子 Session 链路接通 root → 协调员 → worker 两层委派；第三层被拒绝。子树身份、工具范围、检查点、预算、取消及恢复由 Morde 持久层和 Broker 栅栏约束。待补的是从实际 morde-pc 发起复杂任务并观察进度、汇总结果及指定取消的端到端验收。

设计与开发

根 Task 保留最终责任，父子 Session、派生调用、允许工具与状态持久化，权限只可收窄。互不冲突的 worker 模型回合可受预算约束地并发；共享电脑/工作区工具 Broker 仍串行，避免副作用冲突。结果、已分类失败与未知状态逐级回传；取消后确认进程停止，已派发副作用按原身份对账，不安全重放。真实 PC 入口验收尚未完成。

Morde 落点

validDelegateArguments / validateChildSession / runAgent；createCloudDSHChildSession 与结算/恢复；cloudDSHChildDelegationTools；AgentChildSessionService；CreateAgentChildSession；根检查点授权栅栏；reserveModelCall。

开源参考

DSH · delegationDepthOf / assertSubagentMaxDepth；SubagentManager.startLocal；maxDepth 配置：插件本地管理器不承担 Morde PostgreSQL、Broker、预算、取消及对账边界，故复用 DSH 帧协议并适配现有会话合同。Magentic-UI · build_handoff：参考逐层任务交接。服务端本地 DSH + PostgreSQL 并发、权限、失败和恢复回归通过；真实 Provider/MCP/Host 与 PC 产品流程仍待验。参考 TC-3.1–3.13。

04

工具执行与工作项

本地实现与自动化回归通过 · 客户端/云端待验

现状与要修改的地方

Broker 已有调用接纳、执行和对账。本轮补齐加密工作项执行详情、取消终态和网页工具状态；未知结果不重放。项目同步亦接入固定默认电脑、云端 applied 回执和本机待处理指纹。服务端及本地自动化回归通过，实际客户端和真实云端仍待验收。

设计与开发

Shell 和文件工具详情保存适用的位置、命令/参数、工作目录、实际派发耗时、退出状态和有界输出；先脱敏，再加密；按现有 owner/Task/Workspace 授权回查。原始 Shell 输出总量仍限制在 64 KiB，Runtime 截断与详情容量截断分别标记；PC/iOS 先显示 2,000 字符预览，再展开显示每路最多 64 KiB 的已记录输出。unknown/cancelled 不展示未确认结果。项目同步仅由用户点击触发，单向进入固定默认电脑的 ~/workspace/project/<项目名>/ 并保留相对目录；目标应用回执后保存本机指纹，后续只读扫描显示待处理而不上传。Linux 创建使用 RENAME_NOREPLACE，替换使用 RENAME_EXCHANGE 后校验，删除/移动先暂存并验证；此举保护目录项冲突，但不能绝对阻止持有旧 inode 文件描述符的非协作 Host 写入。云端应用与基线采集仍有窄竞态。

Morde 落点

TaskStepDetailDocument / TaskStepExecution；taskToolCallProgress 与 taskToolExecutionDetails；GetStepDetail；Execute / 对账；PC Assistant 和 iOS MIFTaskViews；项目同步由桌面 main/IPC、morde-sync helper 与 workspace_sync_project_upload 服务实现。

开源参考

Magentic-UI · enrich：参考执行结果补充观察；nanoMuse · ToolLoopDetector.check/record：参考防循环，不直接移植其单机内存状态。OpenHands Agent Canvas · groupEvents：参考前端工作项分组，本地目录不是完整 Agent 后端源码。

验收

服务端加密详情回读、长输出、授权撤销/未知状态、Portal/iOS展示组件、同步冲突保护及 PostgreSQL/Linux 定向回归通过；Portal 222 项测试、类型检查、两项 Swift 单测及 build 通过。大输出经 HTTP 端点的组合验收、PC/iOS 实际页面操作、真实云端同步与 Agent 读取内容仍待验。非协作 Host 若持有旧 inode 文件描述符并发写入仍无法绝对阻止；云端应用与基线采集仍有窄竞态。参考 TC-4.1–4.14。

05

验收

06

结果验证

产物读回及定向 PostgreSQL 已通过；PC 验收待做

现状与要修改的地方

验证 Worker 已按当前 claim 读取 Task 结果证据所引用的固定 Workspace 产物版本，校验整文件 SHA-256，只把最多 4 KiB 的文本预览交给只读复核；二进制或截断内容不能单独支持通过。服务端会复核来源调用、Task 修订、结果事件、当前授权及 Workspace 文件版本，旧文件不再显示为当前 validation。App/Worker/Store 本地测试和步骤 06 定向 PostgreSQL 16 集成通过，含当前文件变更后 validation 回到 pending；并发撤权回归与 PC 当前 validation 页面合成 Task 验收仍待完成。

设计与开发

为适用任务收集真实检查与读回证据，绑定 Task 修订、尝试、来源调用、产物版本和执行环境。补充按复核任务和当前授权读取产物的本地检查路径，校验版本、来源及摘要后生成可追溯的检查结果；由服务端硬规则区分通过、失败和待验证。模型复核仅作辅助。

Morde 落点

review / reviewInput；EvaluateTaskValidationReview；CompleteTaskValidationReview；conversationTaskResultValidationStateInTx。

开源参考

Magentic-UI · decide_verifier_class / diff_states：参考操作前后状态取证，不视为通用验收系统。独立换模型家族并非 Muse 已证实机制，不能替代硬门禁。

验收

旧修订、变更后的当前文件、错授权、审批覆盖未知、只有模型自述、哈希或不完整预览均不认定通过；实际 morde-pc 区分已执行、待验证和验收通过。步骤 06 定向 PostgreSQL 集成通过；PC 合成 Task 验收待做，审批不匹配或账本缺失必须保持 pending/unknown。参考 TC-6.1–6.9 及步骤 06 TODO。

09

失败、限流与恢复

后端恢复回归补齐；PC/iOS Task/MCP 局部闭环通过；其它故障待验收

现状与要修改的地方

服务端已有 route 429/超限、MCP 终止账本和 Task 精确重试的定向回归。实际 morde-pc 已从失败任务详情发起 MCP 重试，并由本地 PostgreSQL 核对来源失败步骤保留、重试关联与账本单项；完整浏览器夹具尚未通过。iOS 未决状态投影有规则测试；Task 列表的工作项详情提供受服务端资格控制的重试入口。iOS 原生 Task/MCP 限流重试已通过本地合成服务/PostgreSQL 闭环：从原生任务详情点击重试后，数据库确认 Task 恢复运行、来源失败步骤保留、新 retry 步骤正确关联且仅有一条连接器账本；该验证不调用真实 Provider/MCP。iOS 原消息路由入口、未知副作用、审批/中断和跨端故障链路仍待验收。Muse 自动重试和降级阈值未知。

设计与开发

统一记录阶段、原因码、调用身份、租户、耗时和结果状态；按错误是否可安全重放决定恢复。明确 Provider 429 沿用当前路由层有限重试；超时、断流、已派发操作或用量未知先对账。连接器只有在显式 terminal 标记及 `retry_after` 被持久到账本后才结束本次 Task 尝试；Task/MCP 重试必须由用户发起，且仅在唯一操作账本、调用/参数摘要、当前 Agent 已有可验证停止凭据、授权、审批、预算和等待期均通过当前状态复核后开放，避免旧 Agent 进程树尚未停止时排入新一代执行。审批或进程恢复只能继续同一预留尝试和调用身份；未知操作仍等待对账，不自动重派。已展示的文本保留并标中断，等待审批不算失败。Agent 未发布最终答复时，原消息下应显示任务已中断、结果未确认及最后确认的工作项；模型结果校验失败与未授权工具分开记录，未授权调用不得执行。工具调用在校验阶段被拒时，日志及任务事件记录白名单阶段、原因码、工具名、有效调用 ID 和是否派发；工具执行异常导致执行状态无法确认时，日志记录工具名、调用 ID、派发状态、稳定失败原因码及底层错误类型。已派发工具的最终结果通过 Task 操作账本按任务及调用身份排查。不得将工具参数、原始模型内容、原始错误文本或凭据复制到通用日志。

conversationRouteRateLimitDelay / failRoute；cloudDSHModelErrorCategory；MCPConnectorTerminalRetryAfterSeconds / newMCPToolTaskStep；RequestTaskStepRetry / ConsumeTaskStepRetryIntent；listTaskStepsWithActivity；Reconcile。

开源参考

验收

429、断流、取消、授权失效和结果未知分别处理；已生效但回执丢失不重复操作。Task/MCP 重试须等到账本推导出的 `retry_after`，同一幂等键只保留一个新尝试；账本不唯一、调用摘要变化或存在 unknown 操作时没有重试入口。Task 恢复未决时，原消息下能看到没有最终答复、最后确认工作及可打开的任务详情。参考 TC-9.1–9.8。

上下文管理

已有两层能力 / 真实长会话待验收

现状与要修改的地方

代码中可见跨 Task 摘要、授权历史检索和 DSH Session 压缩；1 MiB 搜索现已返回可核验的 rune 范围及摘录覆盖页哈希，检索 checkpoint 和工具定义上限也有服务端回归。测试机当前 Portal 源码版本尚未包含工作区路由修复，最新长任务失败仍未由 PC 与新服务版本复验；本机可见的 PC 连接的是 M09 夹具，且没有 Cloud DSH/Guardian 运行端点。真实模型窗口、长会话和大消息最终答案仍需从实际 morde-pc 客户端验证。按项目约定，不使用普通用户 Web 端或 iOS 代测。Muse 的压缩算法与触发阈值未知。

设计与开发

路由层按模型窗口装配摘要、近期历史和当前消息，保留原文 ID、长度与摘要。针对超长当前消息中的具体问题，优先由授权服务端校验所有规范页及全文哈希，再检索并向模型返回不超过 5 段的有限摘录；每段带全局 rune 起止范围及覆盖页的页码/页哈希，确保跨页摘录的来源也可核对，避免把 1 MiB 全文灌入 Task 预算；只有确需全文时才顺序分段读取并遵守预算，无法完整处理时明确说明。Task 层复用 DSH 修剪和压缩，保留工具调用/结果配对及最新要求。账号 Runtime 转发模型请求和工具参数时保留原始 JSON 字节，再按原摘要校验，避免特殊字符重编码导致任务中断。压缩失败保留原文和旧摘要，无进展不得反复压缩；无法取得必要历史时说明。

验收

在实际 morde-pc 客户端验证真实累计历史超过模型单次窗口后早期要求可回查，并验证 1 MiB 消息中的分散锚点、来源页码和恢复行为；压缩失败、撤权和跨账号隔离保持正确。禁止使用普通用户 Web 或 iOS 代测。参考 TC-10.1–10.20 中适用项。

实施边界与次序

  1. 先闭环基础体验：核对收件与路由，补齐工具工作项和审批，再完成可恢复的两层子 Agent 协作、真实证据验证及原会话交付。
  2. 再完善长期能力：验证长会话压缩、失败恢复和记忆整理，以真实缺口扩充评测。独立验证模型、全量事件迁移、固定并发数、固定 60 秒合并窗口和强制 top-k 均为设计候选，需另行验证。
  3. PC 文件夹同步独立于普通问答：用户在 morde-pc 手动选择并触发，单向同步到其固定默认云电脑的 ~/workspace/project/<项目名>/；冲突、失权或源目录不可访问时保留内容并提示，默认电脑不可用时不得切换目标，不因普通聊天启动同步。
  4. 产品与安全边界：普通用户端只有 PC/iOS，管理 Web 用于管理；DSH 为唯一 Agent Runtime。所有工具副作用经过 Morde 授权、审批、预算、操作记录和租户隔离。
  5. 文件和来源：本次只使用本地源码。project/ 下除 DSH 外多数是无独立 Git 元数据的源码快照，无法仅凭目录确认其上游提交。实际移植前核对目标文件版本、许可证及测试。
