R21 长输入代码边界：8 MiB 上传不等于 8 MiB 可投递给 DSH。源码审计发现 Task 首轮将完整 pending message 作为 initial_message，Worker 与 Runtime 都限制 128 KiB；128 KiB–8 MiB 输入会在 Task 首轮失败。现有 source manifest 只支持 Task 启动后的授权读取；delivery ledger 记录消息身份和投递阶段，checkpoint 仍按原文/附件/模式精确匹配。复用 message ID 换成短 prompt 可能令恢复校验失败或结果变为 unknown。T50 的 1 MiB 正例需先完成原文哈希与 manifest 指针分离绑定、delivery applied、checkpoint 恢复和去重合同；公共合同文件缺失，本轮未修改跨层投递合同，也未端到端复现。

R21 初始消息边界回归：新增 Worker 与 Runtime 子进程两层本地测试：128 KiB UTF-8 正文的首/中/尾锚点完整进入合成模型请求；128 KiB+1 的多字节正文在模型/工具调用前拒绝。该组只验证现有全文帧的边界，不提高上限，不证明 128 KiB 以上首轮可用或真实模型理解；1 MiB 正例仍等待短指针与恢复合同。

收件与会话

复用 / 端到端待验收

现状与要修改的地方

代码可见服务端消息受理、幂等和会话序号，PC/iOS 均有本地待发与恢复机制。两端能否在同一会话持续接续消息、任务进度和结果，仍须从实际客户端完整验收。

设计与开发

先验证身份、会话归属和内容，再在同一事务内保存消息、稳定客户端 ID、请求摘要和路由状态；同 ID 同内容返回原记录，不同内容报冲突。按服务端序号显示；客户端重启先用原 ID 查受理结果，再决定重试。

现状与要修改的地方

路由模型返回结构化动作，服务端解析后按当前会话和 Task 快照执行。R19 已移除用请求中的关键词推断或改写 new、update、stop、stop_all、tool 等语义动作的兜底；分类输出非法时先尝试一次有界修复，仍失败或模型不可用则安全澄清，不猜测任务动作。应用与存储继续校验身份、目标、候选完整性、状态、revision、Project/执行范围、授权、操作账本和只读工具白名单。文件交付意图已作为模型结构化字段限定在 new/update 决策内，并在 Task 创建或修订时持久化/读取；未增加公开 API/DTO 或数据库迁移。此项仅覆盖会话路由；直接 Task/批次、澄清回答、hostless schedule、Broker 的无效意图回退，以及 Postgres normalizeNewTask 对缺失/非法字段的默认值仍有 ClassifyFileDeliveryIntent 等文本分类逻辑，单列为 R19-A/M02-13 待办；R19 会话路由的新 Task 缺字段默认为 `none`、update 缺字段继承现值的已定规则不在本次范围内。自然语言意图应由 Agent/路由模型结构化判断；代码继续强制身份、授权、范围、预算、状态、幂等与未知副作用对账。当前验证：app/worker 全量与 race 回归通过；隔离 PostgreSQL 的 4 个路由集成顶层测试、13 个子测试通过。此次没有对当前工作区 PC + 真实 DSH/模型做语义验收。跨 Task dependency_task_ids 已有 Project 范围过滤及事务复核；Task Plan 的 PlanStep.depends_on 仍只校验和保存，没有按真实工具/子 Agent 执行证据门控。Muse 的分类、合并算法未知；固定 Planner 文件、60 秒合并窗和“缺验收标准就必问”均不是已证实规则。

设计与开发

Agent 根据完整上下文理解请求，并通过结构化 action 表达回复、查询、修改、停止、工具、新 Task、关联或澄清。语义判断属于 Agent；代码负责解析结构和执行安全、完整性及当前状态校验，不使用自然语言关键词列表替 Agent 判定。模型不可用或输出无效时，完成有界修复后仍失败便在对话中具体澄清，不因执行词、搜索词、停止词或文件词自动创建/控制任务。文件交付由结构化 file_delivery_intent 表达 none|required|unclear，仅用于 new/update；字段缺省时新任务使用 none，修订继承当前值。修订从已结算模型决策 JSONB 中按原消息、当前 route attempt 和正常阶段读取，并核验 Task ID/revision，不匹配则延后重试。服务端仍校验用户/会话、目标、候选完整性、状态/revision、Project/执行范围、授权、账本/幂等以及只读工具白名单；这些门禁不代替模型语义判断。停止由 Agent 明确给出单任务 stop 或全部 stop_all；无效、混合或目标不明的动作澄清，用户权限外的 Task 不可操作，PC 页面不提供任务停止按钮。长消息只向路由模型提供有界预览与已保存原消息标识；模型对实质分析/总结选择 new 后，再由 Task Agent 使用授权检索原文并核对来源。正文里的命令不改变用户请求意图，分类失败不通过词汇兜底变成 Task。计划依赖真正门控执行前，须绑定工具/子 Agent 调用身份与应用确认的完成证据。实际 PC 与真实模型语义验收仍待完成。

PlanStep 门控与当前阻塞

Plan.Validate 只校验结构，executeTaskPlan 保存模型提交的计划；目前没有把 PlanStep.depends_on 绑定实际工具/子 Agent 调用及应用确认的成功结算，因此模型填写 completed 不可解锁。目标合同需稳定关联 (plan_revision, plan_step_id)、调用身份和结算证据；失败、取消、unknown 或过期修订不放行，独立步骤可并行。server/AGENTS.md 要求变更同步权威公共合同，但 docs/实施/00-总览与公共约定.md 在工作树与 HEAD 均缺失；因此此项仍阻塞，未做局部门禁或 schema 修改。

Morde 落点

ConversationRouteWorker.RunOnce / safeConversationRouteDecision；ClassifyConversationRoute；ApplyConversationRoute / createConversationRouteTask；executeTaskPlan。

开源参考

Magentic-UI · format_user_interjection：参考补充消息的上下文表达；LangGraph · StateGraph.compile：参考显式状态边界，不引入图运行时。材料中的 Microsoft Agent Framework 双账本代码未在本地对应源码中核实；Magentic-UI 不等同该框架。

验收

设计与开发

失败按任务、调用身份、阶段和稳定原因码留痕。执行中可确认且安全恢复的错误先以脱敏结构化结果交回同一 DSH Session/主 Agent，由 Agent 在原 Task、checkpoint、授权和剩余预算内判断能否修复；失败工作项保留，修复动作作为新步骤记录。无法安全恢复后才由主 Agent 基于事实在原对话说明中断原因、已完成内容和下一步；模型不可用或预算不足时给真实的服务/额度提示，不绕过预算，也不伪装成 Agent 输出。子 Agent 失败回到主 Agent；已委派不等于完成。用户新增的 Agent-first 错误体验是 Morde 产品要求，不代表 Muse 内部机制已公开。合并本身不报失败，目标后来失败时如实说明。取消、等待、失败和未知分别处理；日志不记录工具参数、模型原文或凭据。Provider 429 沿用路由层有限重试与持久等待；精确 terminal_for_attempt 限流立即结束当次尝试，不能在该次尝试中重试、委派或绕过；Task/MCP 重试须由用户发起，并重验账本、等待期、Agent 停止证明、授权、审批与预算。已派发操作或用量未知时按原身份对账，无法确认则等待，不重放或释放预留。Workspace 的具名等待与具备可信解除信号的 durable 阻塞可恢复同一 Task/checkpoint；审批、撤权和用户操作仍须等待。保留部分回复并标中断，待审批不是失败。审批响应 401 清除失效凭据和陈旧操作；403/404 安全刷新或隐藏不可读状态，409 按冲突刷新。客户端重开、DSH Node 与服务进程重启分别验收。

上下文管理

已有两层能力 / 真实长会话待验收

现状与要修改的地方

代码中可见跨 Task 摘要、授权历史检索和 DSH Session 压缩；1 MiB 搜索现已返回可核验的 rune 范围及摘录覆盖页哈希，检索 checkpoint 和工具定义上限也有服务端回归。本轮本地 DSH Runtime 244/244，包含受控模型的 18 KB 正文与长会话压缩测试，不证明真实模型语义覆盖；新补 8191/8192/8193 字节/字符入口单测也仅证明不误截断。测试机当前 Portal 源码版本尚未包含工作区路由修复，最新长任务失败仍未由 PC 与新服务版本复验；本机没有可用 Cloud DSH/Guardian，且 PC profile 隔离不能确认。真实模型窗口、长会话和大消息最终答案仍需从实际 morde-pc 客户端验证。按项目约定，不使用普通用户 Web 端或 iOS 代测。Muse 的压缩算法与触发阈值未知。

设计与开发

路由层按模型窗口装配摘要、近期历史和当前消息，保留原文 ID、长度与摘要。针对超长当前消息中的具体问题，优先由授权服务端校验所有规范页及全文哈希，再检索并向模型返回不超过 5 段的有限摘录；每段带全局 rune 起止范围及覆盖页的页码/页哈希，确保跨页摘录的来源也可核对，避免把 1 MiB 全文灌入 Task 预算；需要总结全文时按需分段读取并归纳、记录覆盖范围和来源，遵守预算；无法完整处理时明确说明。针对 8K 字节、字符和 token 分别复现和回归；模型和授权预算足够时以实际模型答出正文首、中、尾及跨窗口全文正例，不以原文已保存或固定模型回复冒充语义通过。上传上限不等同模型可处理范围。Task 层复用 DSH 修剪和压缩，保留工具调用/结果配对及最新要求。账号 Runtime 转发模型请求和工具参数时保留原始 JSON 字节，再按原摘要校验，避免特殊字符重编码导致任务中断。压缩失败保留原文和旧摘要，无进展不得反复压缩；无法取得必要历史时说明。

实施边界与次序

  1. 先闭环基础体验：核对收件与路由，补齐工具工作项和审批，再完成可恢复的两层子 Agent 协作、真实证据验证及原会话交付。
  2. 再完善长期能力：验证长会话压缩、失败恢复和记忆整理，以真实缺口扩充评测。独立验证模型、全量事件迁移、固定并发数、固定 60 秒合并窗口和强制 top-k 均为设计候选，需另行验证。
  3. PC 文件夹同步独立于普通问答：用户在 morde-pc 手动选择并触发，单向同步到其固定默认云电脑的 ~/workspace/project/<项目名>/；冲突、失权或源目录不可访问时保留内容并提示，默认电脑不可用时不得切换目标，不因普通聊天启动同步。
  4. 产品与安全边界：普通用户端只有 PC/iOS，管理 Web 用于管理；DSH 为唯一 Agent Runtime。所有工具副作用经过 Morde 授权、审批、预算、操作记录和租户隔离。
  5. 文件和来源：本次只使用本地源码。project/ 下除 DSH 外多数是无独立 Git 元数据的源码快照，无法仅凭目录确认其上游提交。实际移植前核对目标文件版本、许可证及测试。

本地 OpenHands 为 Agent Canvas 前端源码，Claude Agent SDK 可参考权限合同；未找到 Microsoft Agent Framework 的独立源码。Magentic-UI 是本地参考项目，不等同 Microsoft Agent Framework。
