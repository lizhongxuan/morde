# 会话 E-01：PC 对话、审批与任务动态

**目标：**完成 R04/R06/R22/R23/R24 的 PC 呈现与交互；与其他 `01` 同时启动。先读[并发总览](<00-并发实施总览.md>)、[体验目标](<../Morde AI对话目标体验.md>)及[原方案](<../Morde 复刻 Muse 一体化实施与验收 TODO.md>)的 PC 补充和 T13–T15、T19–T21、T51–T54、T57。

**写入范围：**`web/portal/src/` 中 PC 内嵌界面 / 测试及 `clients/desktop/harness/desktop/`；E 是这些文件和实际 `morde-pc` 测试 profile 的唯一操作方。后端数据、OpenAPI / MCP 资源所需改动交 A，终态 / 验证事实交 D；不创建独立普通用户 Web 页面。

**设计与交接：**按[审批卡与工作项](<01-复杂链路设计与交接.md#approval-activity>)处理双入口的一致身份、断线待确认及通用资源沙箱；终态事实见[交付设计](<01-复杂链路设计与交接.md#terminal-validation>)。

- [ ] **E01-1 对话与任务控制。**复用现有 `Assistant.tsx`、会话和澄清接口：普通问题自然回复，明确任务继续 / 停止经 B 的语义路由；失败 / 等待 / 合并依据实际事实呈现，不恢复机械中断状态行。
  - 验收：T45–T48、T51 中目标明确 / 歧义 / 合并 / 停止不串任务；思考状态、消息气泡与键盘交互符合体验目标。后端或真实模型未就绪时按层记录待验。
- [ ] **E01-2 双入口 MCP Apps 审批。**复用 `TaskApprovalMcpApp.tsx`、`TaskApprovalCard.tsx` 和 `Reviews.tsx`；原对话与审核区共享后端审批 ID / revision，任务动态无审批 / 停止 / 任务验证按钮；后端通用资源能力需要时交 A。
  - 验收：T19–T21、T52–T53 的允许 / 拒绝、过期、撤权、重复提交、刷新 / 重连及沙箱隔离；断线时先核对服务端决定，通用资源加载失败不自动批准。批准不等于执行成功。实际 PC 与真实 DSH 分开记录。
- [ ] **E01-3 精简、真实的工作项。**显示搜索词、来源、浏览对象、文件 / 命令、目录、退出码、耗时、输出与状态的适用项；低价值调度噪音不占主要视图。只展示后端已授权事实，未知和截断明确标记。
  - 验收：T13–T15/T54 展开内容与实际账本一致，失败项保留，未知不展示未确认输出；缺字段时列给 A，不自行编造。
- [ ] **E01-4 实际客户端回归。**复用组件测试并运行 typecheck；启动源码 `make pc`，在隔离 profile 操作受影响的界面。
  - 验收：实际 PC 对话、审批和任务动态有操作证据；不能用独立 Portal 浏览器 / iOS 代测。Playwright Electron 和 Trace 仅在能控制同一真实客户端时作为辅助，失败记录可行性，不代替真实 DSH 或账本证据。
- [ ] **E01-5 可读流程图交付（未开始，对应 R23-A / T57）。**核对 `ChatMarkdownContent.tsx` 和既有产物查看能力，为 AI 输出的流程图接入可读图形：在对话直接显示，或在 Morde PC 客户端内打开。图形渲染失败时说明并保留可复制源码；纯代码块不算图形验收通过。E 独占客户端实现，若需要后端产物接口由 A 协调。
  - 验收：实际 `morde-pc` 可读图、结论及来源；安全处理不可信图表内容和非法语法，失败不影响其他消息，不放宽现有 CSP。组件测试仅作辅助，真实代码分析由 E02/A02 按 T57 验收。

**依赖 / 状态：**现有界面与 fixture 可立即核对；通用 MCP 资源、R20 终态和新增详情字段分别依赖 A/D 的合同。视觉权威规范缺失时沿用现有样式并单列待验。

**定向回归：**在 `web/portal/` 运行 `npm test -- src/routes/Assistant.test.tsx src/routes/Reviews.test.tsx src/components/TaskApprovalMcpApp.integration.test.ts` 和 `npm run typecheck`；另在仓库根目录启动 `make pc` 实测，组件回归不能替代实际 PC。
