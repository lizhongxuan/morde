**目标：**持续集成五会话成果，收口 R13/R14/R18；A-01 基线就绪后即可开始，不等待其他会话整份任务完成。先读[并发总览](<00-并发实施总览.md>)、[体验目标](<../Morde AI对话目标体验.md>)和[原方案](<../Morde 复刻 Muse 一体化实施与验收 TODO.md>)第四、六、七节。

**设计与交接：**以[复杂链路设计](<01-复杂链路设计与交接.md>)的跨会话身份、事务和各层验收为联调基准。

- [ ] **A02-1 增量集成。**按 A-01 分项合同接收 B/C/D/E 的文件、版本和测试证据，协调共享状态 / schema / API 和版本兼容；保留其他会话的未提交修改。完成一项即可联测，不等所有分支汇总。
  - 验收：字段、调用方与状态机一致；任何冲突定位到具体文件及所有者，不能靠回退别人的修改解决。
- [ ] **A02-2 本地服务与恢复测试。**运行与改动相关的 Go / Runtime / Portal 定向回归，再按原方案执行 `server make test`、`make race`、隔离 PostgreSQL `make it`、Runtime `npm test` 及客户端检查。

- [ ] **A02-3 核心实际体验。**和 E 按 T43 实际操作源码 `morde-pc`，贯通普通问答及复杂任务的收件 → 路由 → 两个 worker → 工具 → 审批 → 验证 → 原会话交付；覆盖 T45–T56 的长消息、状态、失败和晚到验证，并按下方补充 T57。

  - 补充 T58/T59：与 E02-7 核验用户交办修复的按需检查、明确要求未满足时的状态，以及文档结论的真实来源、对话要点和撤权行为；B/C/D 提供各层证据。
