# 会话 A-01：基线与公共合同

**定位：**五会话的集成和共享文件负责人，对应 R00、R00A、R01 及 R02/R04/R06/R20/R21 的公共合同。与 B-01、C-01、D-01、E-01 同时启动。先读[并发总览](<00-并发实施总览.md>)、[体验目标](<../Morde AI对话目标体验.md>)、[原任务](<../Morde 复刻 Muse 一体化实施与验收 TODO.md>)及 `AGENTS.md` / `server/AGENTS.md`。

**写入范围：**总览规定的 A 公共文件、数据库迁移、OpenAPI、跨会话集成测试和统一文档；不改 B–E 的专属文件或任务文档。共享文件正在由其他会话修改时先记录现状，不覆盖其变更。

**设计与交接：**按[复杂链路设计](<01-复杂链路设计与交接.md>)逐项定稿；尤其区分原文身份与投递指纹、计划修订与真实结算、终态事件与验证结论事件。

- [ ] **A01-1 基线与隔离。**记录 `git status`、HEAD、未提交 / 未跟踪文件、DSH 锁文件版本及各会话使用的代码快照；准备独立 PostgreSQL / 测试配置和 PC 验收所需环境。已有未提交修改及新 Markdown 必须进入各会话基线；不能从旧 HEAD 直接开 worktree 造成内容缺失。
  - 验收：B–E 能定位同一份基线；保留已有工作，列出可用环境、版本和阻塞，未启动真实服务不得称已联通。
- [ ] **A01-2 核对权威合同并逐项交接。**核查 `docs/实施/00-总览与公共约定.md` 当前缺失的现行来源；不凭旧版本擅自恢复。若无现行文件且依据现有代码、项目规则和用户目标足以确定受影响合同，可新编当前版本，标明已验证事实、拟改设计与来源；不足以确定的部分单列阻塞。整理：① R19-A 的结构化文件交付意图；② M02-14 的 `(plan_revision, plan_step_id)` 与调用结算；③ R21 的原文 ID / hash、manifest 指针、delivery applied、checkpoint；④ R20 的终态事件、outbox 去重 / claim / 模型预算；⑤ R07 的验证事实、版本及审批绑定。
  - 验收：受影响接口、状态和迁移按 `server/AGENTS.md` 同步权威文档、实现与测试；每项明确输入 / 输出、持久身份、错误与权限、调用方和已有 / 拟新增项。不足以确定时在交接栏标阻塞，B–E 继续独立工作；草稿不是已核实的权威合同。
- [ ] **A01-3 统一落地共享状态。**相关合同可用后，在 A 独占的 `task_execution.go`、`task_stop.go`、Broker、`TaskService`、预算网关及必要迁移 / OpenAPI 中，按 B/C/D 的交接实现对应事实写入、读取和版本栅栏。R20 终态与 outbox 入队保持同一事务；R21 不用短 prompt 替换原 message ID 的内容身份；计划步骤只由真实结算解锁。
  - 验收：失败 / 取消 / unknown、旧 revision、重放、越权和崩溃恢复不伪装成功、不重复副作用；晚到 FAIL 的独立事实身份与 outbox 在同一事务中提交，并覆盖与首次结果发布竞态；新增合同、迁移、事件消费方和调用方同时一致。受合同阻塞的子项不得勾选完成。
- [ ] **A01-4 对齐工作项和审批接口。**复核既有 `TaskStepDetail`、`PendingRequest`、`POST /tasks/:id/approvals/:approval_id/responses`；只在现有事实不足时补可追溯字段、MCP UI 资源所需后端能力和 OpenAPI，交 E/D 使用。缺成本、来源或审批覆盖时保持 unknown。
  - 验收：两处卡片使用同一审批 ID / 版本和决定，拒绝 / 过期 / 撤权不派发；详情仅返回授权事实和正确截断标记。对应 T13–T15、T19–T21、T52–T54。
- [ ] **A01-5 预算与回归。**复核 ModelGateway 预留、结算和 unknown；与 D 对齐终态说明的调用身份，使用项目已接入 DSH 插件及现有 Broker，不另造循环。
  - 验收：预算不足如实反馈；结果或用量未知不释放占用、不重派；执行相关 app / Store 定向测试，记录 PostgreSQL 是否实际运行及 T01/T36 边界。
- [ ] **A01-6 修复门禁和来源合同（R25/R26）。**会同 B/D 按[交接设计](<01-复杂链路设计与交接.md#fix-evidence>)核对计划、授权范围、适用检查、真实执行证据、当前修订和工作区版本；A 独占 Broker 及 `cloud_dsh_failing_test_gate.go`、`cloud_dsh_minimal_diff_gate.go`、`cloud_dsh_test_gate.go` 等共享门禁。资料来源缺字段时先确定现有能力和 A 持有的接口。
  - 验收：不普遍强制红测/全量，用户或项目要求的检查仍须满足；不能执行或证据不足不判 PASS、可如实交付部分结果；写入仅限当前授权，新增必要文件先更新计划并复核。相关合同及调用方同步前保留现有门禁。按 T58/T59 分层记录，跨层合同缺失则标阻塞。
