## 启动次序

同时启动 **A-01、B-01、C-01、D-01、E-01**。B–E 先审查现有代码、补不依赖新合同的缺陷和测试；涉及数据库、公开接口或跨层状态的实现，等待 A 发布可用合同后再接入。`01` 不要求所有内容都完成才开始 `02`：

- **A-02** 可在 A-01 建好基线后持续集成；最终收口等待各会话的实际交接及验收。
- **B-02、C-02、D-02、E-02** 分别在本会话上一批的对应接口稳定后启动；各文件注明的跨会话依赖按交接点执行，不以其他会话整份文档关闭为前提。

## 工作树、合同和环境

- 当前工作树已有其他会话的未提交修改及未跟踪文件。先由 A 清点并保留当前状态，确认各会话基于包含这些内容的同一快照；不能从旧 `HEAD` 直接新建 worktree 后当作完整基线，也不能覆盖、清理或回退他人工作。
- A-01 已新建[公共合同 v1](<../../../../docs/实施/00-总览与公共约定.md>)，依据当前代码、迁移、OpenAPI、项目规则与用户目标，逐项区分已验证事实、目标合同和未实现项。B–E 可按已发布分项合同接入；文件未覆盖或证据不足的接口/状态继续记录为阻塞，不能把合同文档本身当成实现验收。
- `docs/design/ice-cream-blue/morde-icecream-blue-ui-spec.html` 当前缺失；沿用现有样式完成可验证功能，无权威规范时将视觉规范一致性单独标为待验。
- E 独占实际 `morde-pc` GUI 与其测试 profile；其他会话用独立的本地端口、数据库和合成数据，避免相互污染。E 的一次实际 PC 验收可覆盖多项改动，但各项须记录对应代码版本、操作和结果，不能用组件测试代替。跨端与真实云端各自记录环境和结果。文件传输的全局禁止已撤销，实际传输按任务和授权目标执行。
- DSH 是唯一 Agent Runtime；模型走网关，副作用走 Broker / 授权 / 预算 / 账本。复用项目已接入的 DSH 插件，不能以第二套 Runtime 或绕过门禁提速。

## 交接与完成判定

每个任务文件末尾按模板记录：修改文件、输入输出 / 合同版本、测试命令与真实结果、已知限制、下一会话需要的动作。只在实现和该项验收均通过时勾选；fixture、跳过、失败和真实 PC / DSH 必须分开。权限或环境缺失标阻塞，继续独立工作，不编造结论。

PC 核心关闭以 A-02 的 T01–T43、T45–T59 适用场景及实际 PC + DSH 证据为准；T44 的真实云端和 iOS 跨端独立记录。完整一体化方案还包含 R15–R18 / A01–A05 和必要长期观察，不能因主链演示成功就宣称全部完成。
