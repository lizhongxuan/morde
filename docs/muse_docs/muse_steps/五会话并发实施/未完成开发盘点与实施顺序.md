### 实施约束

- 按表顺序逐项推进；先核对该项依赖和代码边界，再改对应实现与权威合同。
- 完成代码实现后，将状态记为“代码已实现，待后续用户校验”；不因本轮跳过功能验证而勾选源 TODO 的验收项。
- R17 只对当前可读的失败/部分事实生成带 gap 的图；没有成功 R13 事实时不得构造成功样本。
- R16 的规则绑定只限同一 owner、明确选定的 schedule 和精确 revision；不扩大 Task 权限，也不跳过现有审批、预算和取消/unknown 对账。
- H07 将用户完整性声明与 runner coverage receipt 分开：用户声明不是 runner 事实，runner receipt 也不能证明要求清单完整；二者任一缺失或不匹配时 fail closed。既有 Runtime producer / Store verifier 直接复用。
- R17 的 PC 观察回执不得存储消息正文或代替人工理解证明；Runtime snapshot 和当前授权快照必须各自标记来源与采集时点，不能把当前状态回填成历史执行事实。
