# 会话 D-01：失败恢复与验证事实

**目标：**完成 R07、R10、R20 的 Agent 恢复和验证事实部分；与其他 `01` 同时启动。先读[并发总览](<00-并发实施总览.md>)、[体验目标](<../Morde AI对话目标体验.md>)和[原方案](<../Morde 复刻 Muse 一体化实施与验收 TODO.md>)中 R07/R10/R20、T22–T25、T47、T55–T56。

**写入范围：**`server/internal/worker/cloud_dsh_executor.go`、`task_validation_review_worker*.go`、`server/internal/app/task_validation_review*.go`、`task_validation_verdict*.go`、`server/internal/store/postgres/task_validation_review*.go`、`conversation_result_review.go` 及专属测试。终态事务 / outbox、`task_execution.go`、`task_stop.go`、Broker、模型网关和迁移由 A 写；会话树 / Runtime 由 C 写；PC 显示由 E 写。

**设计与交接：**按[验证失败与终态交付](<01-复杂链路设计与交接.md#terminal-validation>)处理当前结果事实、晚到 FAIL 和首次发布竞态；验证事务需要的公共事件/outbox 修改交 A。

- [ ] **D01-1 确定失败回 Agent。**复核既有同 Session `tool_result` 及授权 / 预算 / checkpoint 栅栏；只对可以确认且安全处理的失败提供脱敏事实，让 Agent 判断是否继续，失败工作项保留。
  - 验收：T55 中可修复只读失败可继续，子 Agent 失败回主 Agent；普通未知错误、`terminal_for_attempt`、撤权和预算不足不盲目重试 / 委派。固定模型只算协议层。
- [ ] **D01-2 真实验证事实。**复用现有验证 Worker、claim / revision / 证据和审批绑定；补足超过 4 KiB 的可验证内容读取或保持 pending。验证 FAIL 的具体差异及来源在授权下进入主 Agent。
  - 验收：正确 / 错误 / 仅元数据 / 长正文分别得到有证据的 PASS、FAIL 或 pending；不能用 hash 代替内容正确。T22–T25，旧修订或撤权后旧 PASS 失效。
- [ ] **D01-3 终态和晚到 FAIL 对接。**按 A 的 R20 / 验证合同，对接已持久化事实与结果整理；失败、取消、等待与 unknown 不伪装成 completed；批次包含 FAIL 可以如实交付未通过结果。
  - 验收：T47、T55、T56 覆盖结果先 pending 后晚到 FAIL、FAIL 先于发布以及双方并发；同一结论只交付一次，重复事件 / 重启 / 新 steer / 撤权均按合同处理。模型或预算不可用时明确事实回退，不伪称 AI 已处理。终态事务由 A 实现。
- [ ] **D01-4 局部验证和交接。**执行本目录 app / worker / PostgreSQL 定向测试，明确哪些需要真实 DSH 和实际 PC。
  - 验收：记录命令、结果、跳过原因及可重放证据；不得以 mock / fixture 声称用户体验完成。界面所需真实状态及文案事实交 E。
- [ ] **D01-5 按需修复验证（R25）。**会同 A/B 将独立 H07 对齐已确认的适用检查、真实运行事实和当前工作区版本；明确必要检查未满足、失败、未知及有依据通过的区别。
  - 验收：T58 的测试失败为 FAIL、未执行或覆盖不足为 pending，真实证据不足不因取消统一红测/全量门而变为 PASS；新修订或撤权不能沿用旧结论。跨层字段和 Broker 修改交 A。

**依赖 / 状态：**D01-1 和现有验证合同内测试可先做；D01-2/3 的新字段、持久事件和终态预算依赖 A-01 分项合同。无法确认时保持 pending / 阻塞，继续独立验证。

**定向回归：**在 `server/` 运行 `go test ./internal/app ./internal/worker -run 'TaskValidation|DefinitiveToolFailure' -count=1`；数据库和真实 DSH 场景另记实际结果。
