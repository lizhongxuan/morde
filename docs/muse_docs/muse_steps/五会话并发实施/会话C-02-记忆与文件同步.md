### 2026-11-26 R16 实现推进

- **代码状态：已实现，待用户后续校验。**Schedule API 支持明确选择/清除一个 `rule_candidate`，服务端只接受候选 ID 与 revision，并在同一事务内解析并锁定候选及其来源 memory 的当前精确 revision；已启用 schedule 每次触发前重新核对候选状态、来源版本和 memory 授权。运行账本保存该次精确绑定、`not_bound/validated/revoked` 状态与验证/撤权时间，计划页和运行记录展示来源快照。
- **撤权收敛：**候选删除、来源 memory 改动/删除或 memory 明确关闭时，事务锁定受影响的 schedule；禁用仍绑定该授权的计划、将对应活跃运行记为 revoked，并仅对使用该受影响绑定的活跃 Task 发出现有标准 stop request。触发栅栏也会在创建 Task 前拒绝过期绑定。没有把普通 memory 自动转成规则，也没有扩大 schedule Task 的个人数据权限。
- **产品语义：**项目已有的 Muse 逆向记录没有原生 Routine 概念；R16 是 Morde schedule 对既有“候选 → 验证 → 用户启用”规则的显式 opt-in 延伸，不据此声称复刻 Muse 的原生例行任务行为。
- **验收状态：**Schedule App 与隔离 PostgreSQL 定向回归已在后续续验中通过，覆盖显式绑定、owner/revision 栅栏、逐 run 来源快照和撤权时停止活动 Task/禁用后续 Schedule；详细命令见统一验证记录。此状态只表示代码和局部账本合同通过，不代表规则语义效果、PC/真实 DSH 或长期运行已验收。原 C02-3 勾选项保持未勾选。
