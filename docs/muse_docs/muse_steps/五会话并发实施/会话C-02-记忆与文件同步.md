### 2026-11-26 C02-2 本地实现与回归

- 更新前检查确认，Host `unknown` 回执的持久化与同项目 unresolved fence 逻辑已有实现；此前缺少的是 PostgreSQL 集成断言。本地新增 `TestWorkspaceProjectUploadReceiptRejectsConcurrentBaselineAdvance` 后半段：验证陈旧 `applied` 回执先被拒，恢复此前已确认基线后接纳真实 `unknown` 回执，再核对 source baseline 的 session/revision/digest 未推进，并验证同项目新 session 返回 `workspace busy`。
- PostgreSQL 定向回归通过：`cd server && GOPROXY=off GOSUMDB=off go test ./internal/store/postgres -run '^TestWorkspaceProjectUploadReceiptRejectsConcurrentBaselineAdvance$' -count=1 -timeout=8m`（1.443s）。
- App 同步定向回归通过：`cd server && GOPROXY=off GOSUMDB=off go test ./internal/app -run 'WorkspaceSync|ProjectUpload' -count=1 -timeout=8m`（0.857s）。
- 记忆、Workspace 同步与项目上传回归通过：`cd server && GOPROXY=off GOSUMDB=off go test ./internal/app ./internal/store/postgres -run 'PersonalMemory|WorkspaceSync|ProjectUpload' -count=1 -timeout=10m`（App 1.100s；Postgres 0.916s）。
- 新增 `TestApplyLiveProjectUploadRetriesAfterPartialFilesystemApply`，在已有源基线的增量上传中注入第二个文件写入的临时 I/O 错误，确认首个文件的已落盘内容在重试时被识别并跳过，剩余文件成功后才记录完整 baseline；`TestProjectLiveBaselinePendingUploadKeepsUnrelatedCloudChangesAsConflicts` 确认未匹配本次清单的云端内容及原生元数据变化仍产生冲突。两项定向测试通过（1.376s）。更新后同一记忆/同步/上传组合复跑通过：`cd server && GOPROXY=off GOSUMDB=off go test ./internal/app ./internal/store/postgres -run 'PersonalMemory|WorkspaceSync|ProjectUpload' -count=1 -timeout=10m`（App 1.198s；Postgres 0.909s）。
- `TestWorkspaceProjectSourceRebindsWithStableAgentWorkspace` 的用例先把原 binding 显式置为 unbinding/detached 并停止旧 Host，再创建 replacement Host、复用 Workspace/Folder 并重新绑定；它覆盖的是显式迁移，不证明服务可在默认 Host 不可用时自动切换。真实默认 Host 选择及 PC 端到端仍待验。
- **待验与风险：**本地 App 注入证明一次性中途 I/O 失败可在已有源基线时通过重试按已落盘内容逐项收敛，不匹配的已有云端文件仍冲突，且不会提前推进 baseline；这不是跨进程/主机重启或多路径并发云端修改的持久化对账证明。真实 PC、实际固定云电脑、断网/重启恢复、Agent 读取同步文件以及用户端冲突提示尚未验收，C02-2 保持未勾选。
