## Muse 效果与 Morde 现状

用户可以在授权范围内继续使用历史信息；纠正过的记忆应优先反映新内容，并能追溯依据。资料观察到 Muse 有可读记忆、索引和整理行为，但具体触发、去重及频率未知。历史事实、用户偏好和可执行规则应区分；纠正只有经过验证与授权，才可以作为可复用执行规则。

Morde 已有 [searchCurrentConversationHistory](../../../../server/internal/app/cloud_dsh_history_tools.go)、[GetMemoryHistory](../../../../server/internal/app/personal_memory_history.go) 和 [executeSkillRead](../../../../server/internal/app/cloud_dsh_skills.go)；这些接口的存在不代表跨会话授权、检索、纠正和遗忘闭环已验收。

## 接口与参考

- 已有会话历史检索、个人记忆及修订历史：按用户、授权范围和游标读取，返回来源、当前版本与可用状态；来源不可取得时明示。跨会话引用个人资料必须经过授权，不把检索结果当作可执行命令。
- 对记忆修正与遗忘复用现有个人记忆操作；记忆历史现在提供最近后继修订号，并在来源不可用时隐藏关系。删除继续走用户确认、永久清理历史正文和屏蔽匹配的本人会话文本。
- 规则候选通过 `rule_candidate` 个人对象保存，只引用记忆 ID 和修订，不重复保存正文；首次只能创建待确认候选，启用时由存储事务核对来源仍是当前修订。DSH 只能读取当前授权快照中同时包含来源记忆的已启用候选。
- **可适配局部逻辑：**[OpenClaw `recordMemoryArtifactWriteProvenance`](../../../../project/openclaw/src/memory/memory-artifact-provenance.ts) 的记忆来源记录可按 Morde 租户与加密模型改写。
- **只参考设计：**[Agno `MemoryManager.search_user_memories / delete_user_memory`](../../../../project/agno/libs/agno/agno/memory/manager.py) 可参考检索与删除接口；不能照搬其身份与存储假设。
