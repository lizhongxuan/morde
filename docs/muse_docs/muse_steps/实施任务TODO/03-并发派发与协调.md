## Muse 效果与 Morde 现状

Muse 资料观察到主 Agent → 协调员 → worker 的两层派生；独立 worker 可并行，成功和失败结果逐级回传。Muse 的并发上限及是否存在第 3 层未知。Morde 仍使用当前 DSH Runtime，并已接通两层持久子会话；工具与授权继续经 Morde 服务端控制。

实现后：[engine.mjs `validDelegateArguments` / `validateChildSession`](../../../../runtime/morde-cloud-runtime/src/engine.mjs) 支持协调员继续委派，并保留深度上限；[CreateAgentChildSession](../../../../server/internal/store/postgres/agent_sessions.go) 和 [AgentChildSessionService](../../../../server/internal/app/agent_sessions.go) 对父 Session、调用身份、权限子集、祖先取消和检查点栅栏作事务校验。[createCloudDSHChildSession](../../../../server/internal/worker/cloud_dsh_session_tree.go) 为协调员生成 DSH 委派/工作项控制，不把这些控制权限传给最末层 worker。

## 任务

- [x] **M03-01 子树合同与持久化**：保存 root → child → grandchild 的父身份、调用身份、允许工具、根检查点基线和状态。PostgreSQL 回归验证幂等创建、同任务内授权祖先访问、跨用户/任务隔离、最大深度和取消/最终派发的事务栅栏。
- [x] **M03-02 DSH 两层委派**：在现有 `dsh_delegate` 上允许协调员继续委派，孙 worker 只获得其直接父级已授权的普通工具；不能把 `dsh_delegate`、工作项控制或结果证据作为普通工具继续传递。PG + 本地 DSH 进程实测 root→协调员→worker，第三层被拒绝；检查点过期、身份不符和祖先取消时拒绝或失败关闭。上游包未直接安装，原因见“上游插件评估”。
- [x] **M03-03 协调、并发与汇总**：两个互不冲突的 nested worker 模型回合由屏障测试证明确实重叠；协调员通过 DSH 工作项读取实际持久结果，并能把已分类模型失败与成功结果一起汇总，未知失败不能误报完成。Morde 仍串行处理工具 Broker 请求，避免共享云电脑/工作区动作互相覆盖；因此本次不声称独立外部工具调用已并行。
- [x] **M03-04 取消与恢复**：真实 DSH 进程停止/重认领测试覆盖父任务取消、兄弟 Task 隔离、已完成副作用不重放以及“孙 worker 已请求取消但仍 running”恢复为持久 `unknown`；原父 Session/spawn_key 保持，重启不会重新启动该孙 worker。取消与最终操作派发由数据库锁确定顺序，已派发副作用仍须按原身份对账。

## 端到端验收

**服务端 / Runtime 集成证据：** 本地 PostgreSQL + DSH 子进程的五项 nested 测试通过：两 worker 实际并发、父/子工具范围与深度隔离、父取消不影响独立 Task、已分类失败逐级汇总且未知错误不误报完成、重启不重复已确认副作用、取消后重放返回 `unknown`。并发与取消恢复定向用例通过 `go test -race`；并发预算被拒绝时，Task 模型请求只对有结构化 `reason=model_concurrency_limit` / `stage=reservation` 的未派发错误等待后使用原调用 ID 重试，取消可打断等待。
