## Muse 效果与 Morde 现状

主会话直接呈现结果和必要结论，详细过程放在任务详情；缺少决策、授权或资料时清楚提问。交付必须说明真实完成情况、可核查来源及未完成部分；用户可继续自由输入，不被卡片限制。

现有 [publishConversationResultReviewInTx / conversationTaskResultReceipt](../../../../server/internal/store/postgres/conversation_result_review.go) 负责发布和去重；PC/iOS 的对话和任务界面仍需核对是否呈现实际结果、证据和验证状态。

## 接口与参考

- 已有 [Task 完成栅栏](../../../../server/internal/store/postgres/task_execution.go) 和 [结果发布](../../../../server/internal/store/postgres/conversation_result_review.go)：完成候选需在锁内复核 pending/applied steer、修订和检查点；该 Task 有尚未被完成候选覆盖的 steer 时，交回原 DSH Session 继续，独立新请求按步骤 02 路由。结果与回执绑定原用户、会话、任务、来源和当前修订，在事务内幂等持久化；服务端持久化不等于用户已读。
- 已有消息、任务详情和审批响应：PC 消费步骤 04–06 的服务端事实，展示执行中、待审批、失败/结果未知、待验证和验证结果；iOS 数据合同保持一致。本轮交互及端到端验收只使用实际 `morde-pc`，iOS 未实测不标通过。
- **可适配局部逻辑：**[OpenHands `groupEvents`](../../../../project/OpenHands/src/components/conversation-events/chat/group-events.ts) 可参考将相关动作分组、让主对话突出结果的展示逻辑；适配 Morde 时间线和 UI，不照搬状态模型。
- **只参考设计：**[LibreChat `createChannelArtifactService`](../../../../project/LibreChat/packages/api/src/channels/artifacts.ts) 与 [artifactByIdSelector / visibleArtifacts](../../../../project/LibreChat/client/src/store/artifacts.ts) 可参考产物与会话的关联和可见性；Morde 权限及产物存储保持原有边界。

## 任务

- [ ] **M07-01（未开始，依赖 M01-01、M05-05、M06-03）结果合同**：保留任务修订、实际来源、可用产物、执行、审批和验证状态；主会话直接给出结果要点和未完成事项。验收：批准/拒绝只代表对本次操作的决定，不代表副作用已执行或任务已完成；审批覆盖未知、已拒绝/过期、执行结果未知或验证待定时，如实呈现且不认定通过；过期证据、模型自述和不可用产物不冒充完成或可访问。
- [ ] **M07-02（未开始，依赖 M07-01）完成栅栏与原会话幂等发布**：核对 `TaskAgentCompletionFence`、`conversationTaskResultReceipt` 和 `publishConversationResultReviewInTx`；在提交完成时重检 pending/applied steer 与检查点，该 Task 的新 steer 回原 Session 处理，独立请求按步骤 02 路由，再以事务持久化回执和消息。验收：完成候选生成后注入新 steer、重复事件或重启，旧结果不覆盖新要求；独立任务不被中断，相同结果只在发起会话发布一次，不重复副作用。
- [ ] **M07-03（未开始，依赖 M07-01、M04-03、M05-03）客户端交付与提问**：在 [PC Assistant](../../../../web/portal/src/routes/Assistant.tsx) 和任务详情展示结果要点、可访问证据、待决定事项及真实状态，保持 iOS 数据合同；明确区分允许/拒绝反馈与 Task 的后续运行/终态。验收：用户可自由追问或拒绝，过程与任务详情一致；审批等待、拒绝后仍在处理、失败、结果未知和待验证均不显示为任务完成或验证通过。
- [ ] **M07-04（未开始，依赖 M07-03）交付可靠性**：任务已受理后客户端离线不取消；原始消息、任务状态和回执持久化。验收：执行期间关闭并重连实际 PC，同一会话显示真实进度及结果，重复刷新或恢复不重复交付；iOS/跨端未实测时保持待验证。

## 端到端验收

优先用 `make pc` 启动实际 `morde-pc`，覆盖普通问答、通过验证、部分失败、待审批、需要澄清和证据不可用；在结果生成与提交之间分别插入同一任务的补充和独立请求，检查任务归属、原会话回复、来源及恢复去重。禁止使用普通用户 Web 或 iOS 代测；仅用本地合成数据，不发送文件，环境不可用时保持待验证。
