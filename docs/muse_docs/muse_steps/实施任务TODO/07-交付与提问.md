### E11 交付真实性校验（2026-11-25）

- 新增纯函数门禁 `app.ValidateConversationResultDelivery`（`server/internal/app/conversation_result_delivery_gate.go`）：一批次任一来源的当前验证结论为 FAIL 即整批拒绝发布，返回 `CodeInvalidState`、stage 细节 `result_validation_gate`；PASS/PASS+NOTES 照常发布，pending 照常发布但收据如实标注状态、首部仍声明“不代表独立验收”。
- 接线在 `publishConversationResultReviewInTx` 收据构建之前、任何发布写入之前：拒绝是原子的，路由以 `routing_action_unavailable` 失败、批次置 failed、授权重试可重新发布（复核通过后重跑即交付）。pending 不拦的理由：批次在任务完成即入队、独立验证仍在异步跑，拦 pending 会把正常交付也拖进手动重试，且目前没有验证完成后重触发发布的机制；pending 是否也拦是待定项，不在此处自作主张。
- checkpoint digest 栅栏仍由既有层保证：发布时复核加载器重验修订、结果字节、turn、授权与依赖，摘要对不上即 supersede，不进入门禁。回执指令收紧为只说修了什么、哪些文件、怎么验证的，不宣称验证结论未支持的验收。
- 验证：门禁表驱动 UT（空/PASS/PASS+NOTES/pending/混合通过、单 FAIL 与多源中 FAIL 整批拒绝、数量不匹配非法）通过；集成测试 `TestConversationResultReviewRefusesFailedValidation`（PASS+FAIL 同批整批拒绝、路由失败原因、零发布零助手消息，复核改 PASS 后授权重试即发布）与既有 `TestConversationResultReceiptSeparatesCompletionFromCurrentValidation` 的重构（FAIL 任务改走独立批次、断言拒绝）随 CH_TEST_DATABASE_URL 未设置而本地跳过，待有库环境跑。既有 FAIL 收据行标注仍保留在纯收据函数测试里，作为万一渲染时的诚实标注。
