## Muse 效果与 Morde 现状

完成任务后用真实检查、读回或 checking worker 对照目标确认结果，用户能区分已执行、验证通过、失败与证据不足。模型自述、文件存在、文件哈希或“执行完成”本身不证明内容正确。

本轮已在 [reviewInput](../../../../server/internal/worker/task_validation_review_worker.go) 接入当前 Task 产物的有界读回：校验整文件 SHA-256，只向复核包提供最多 4 KiB 文本预览；二进制或不完整内容只能作为不足证据。验证读取受当前 claim、Task 修订、结果事件、来源调用、工作区权限和固定产物版本约束；提交时复核授权及工作区状态，旧文件内容不再展示为有效验证结论。数据库迁移、当前验证态投影和 PC 展示已同步实现；本轮在隔离的本地 PostgreSQL 16 上通过定向迁移、栅栏及文件版本失效用例。实际 PC 页面端到端验收仍待完成。

## 接口与参考

- 已有 `GetTaskValidationReviewStepDetail`、`OpenTaskArtifactContent`：前者供受控验证读取步骤证据，后者有用户可见/已验证产物约束，不能简单复用于验证前读取。已新增 `OpenTaskValidationReviewArtifactContent` 内部读取合同：worker 仅按当前 [review claim](../../../../server/internal/app/task_validation_review.go) 读取被结果证据引用、且绑定唯一成功来源调用的产物；读取前后复核有效 claim，提交时复核用户授权、Task/结果和工作区栅栏。App/Worker 本地测试通过；隔离本地 PostgreSQL 16 的步骤 06 定向集成通过，完整 PC 业务入口验收仍待做。
- 已有 `EvaluateTaskValidationReview` / `SummarizeTaskValidationEvaluations`：复用服务端对实际检查和来源的判定。执行完成、验证通过/失败/待验证分开；单项 `N/A` 只能由服务端依据事实判定，不能把模型建议或引用存在当作通过。
- 证据内容按需要有界读取和脱敏，来源、文件/位置、版本及截断情况可追溯；外部内容与模型输出都当作不可信数据，不能改变授权或执行指令。
- **可适配局部逻辑：**[Magentic-UI `decide_verifier_class`、`parse_stat_output`、`diff_states`](../../../../project/magentic-ui/src/magentic_ui/teams/omniagent/_verifier.py) 的操作前后检查和差异计算可按 Morde 的工具/文件证据格式改写；不以此替代业务内容检查。
- checking worker 可以用 DSH 子会话完成独立核对，但“必须使用另一模型”并无 Muse 证据，也不能替代可复现的检查。

## 端到端验收

使用本地合成任务制造正确文件、错误内容、运行失败、无权限读取、授权撤销和产物变更；优先通过 `make pc` 启动实际 `morde-pc`，查看执行状态、验证状态及来源。禁止使用普通用户 Web 或 iOS 代测，不向外发送文件；本地 PostgreSQL、客户端夹具或安全启动条件不可用时保留待验证，不得宣称完整验收通过。
