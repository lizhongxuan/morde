## Muse 效果与 Morde 现状

完成任务后用真实检查、读回或 checking worker 对照目标确认结果，用户能区分已执行、验证通过、失败与证据不足。模型自述、文件存在、文件哈希或“执行完成”本身不证明内容正确。

本轮已在 [reviewInput](../../../../server/internal/worker/task_validation_review_worker.go) 接入当前 Task 产物的有界读回：校验整文件 SHA-256，只向复核包提供最多 4 KiB 文本预览；二进制或不完整内容只能作为不足证据。验证读取受当前 claim、Task 修订、结果事件、来源调用、工作区权限和固定产物版本约束；提交时复核授权及工作区状态，旧文件内容不再展示为有效验证结论。数据库迁移、当前验证态投影和 PC 展示已同步实现；本轮在隔离的本地 PostgreSQL 16 上通过定向迁移、栅栏及文件版本失效用例。实际 PC 页面端到端验收仍待完成。

### R07 本地续验与剩余缺口（2026-11-24）

- **回归：**`go test ./internal/app -run 'TaskValidation|TaskArtifact|VerifyCommittedArtifact' -count=1`、`go test ./internal/worker -run 'TaskValidationReview|TaskValidation|CloudDSHTaskValidationReview' -count=1` 通过；一次性 PostgreSQL 16（仅绑定 `127.0.0.1`、无数据卷）上，11 项证据修订绑定、审核 outbox/claim、live fence、来源/Artifact 对应及网页内容边界用例通过；`TestTaskValidationReviewWorkerPersistsGatewayResultWithPostgres` 通过。临时数据库容器已停止并删除。
- **核验结论：**正确文件版本与摘要有服务端验证事实；当前 Workspace 文件变化后旧 PASS 回到 pending，claim/授权/提交栅栏和未知执行保护有定向 PostgreSQL 证据。合成模型协议能把复核结果写入当前审核记录。没有用真实模型证明正确内容 PASS 或错误内容能指出差异。
- **长文限制：**Worker 可完整流式读回并核对最多 8 MiB 的单个 Artifact，但当前只向模型发送最多 4 KiB 文本预览。>4 KiB 文本的 `ContentComplete=false`，只能作为不足证据；这可防止仅凭哈希或截断内容错误 PASS，却也意味着完整长文本内容复核能力尚未实现。不能把 pending 的安全处理计作 T25 完成。超读取预算、二进制、撤权、并发修改和模型/预算不可用均不得降级成 PASS。
- **状态：**M06-01/03 服务端合同与定向回归通过，PC/并发撤权/完整入口仍待验；M06-02/04 部分完成，真实语义、>4 KiB 完整复核和 PC + DSH 待实现/验收。T22–T25 均为部分通过，不关闭 R07。
- **本会话复核与依赖：**重新运行 App 的报告/内容证明及 Worker 的独立只读复核、产物读取定向测试，通过；这些使用本地替身和合成结果。当前 [内容证明校验](../../../../server/internal/app/task_validation_review_artifact.go) 限制预览最多 4 KiB，并要求 `ContentComplete` 对应完整预览；[持久化事实判定](../../../../server/internal/store/postgres/task_validation_review.go) 也依据该证明判断覆盖。完整长文本分段复核需要明确每段模型输入、连续覆盖、预算、来源修订与提交时授权/文件版本栅栏的共同合同；仅扩大 worker 预览或把整文件哈希设为完整会错误授予 PASS。这些证明/存储文件不在本会话可写范围，因此保留该依赖和 pending，未修改数据库合同。
- 预算根因核对：两条 Task 的模型额度均为 50,000；各自唯一一次 settled 模型调用预留约 40,298 / 40,273 token，提供方实际用量约 10.4k。源码 [model_gateway.go](../../../../server/internal/app/model_gateway.go) 的 `modelRequestInputTokenReservation` 将说明、消息、工具名称/描述/schema 的 UTF-8 字节数逐字节计入输入预留，再加输出上限；[model_usage.go](../../../../server/internal/store/postgres/model_usage.go) 先按预留检查 Task 剩余额度，结算后才按实际用量回补。因此首轮文件写入后，后续 DSH 请求仍可能因保守预留超过剩余额度而在发送前被拒绝。日志与账本确认了预算错误及首轮预留/实际用量差；“后续请求因字节预留大于余额而失败”是据此和源码得出的原因判断，未拿到被拒绝请求的预留明细。
- 修复条件：不能降低预留系数或绕过 50,000 上限，这会削弱模型调用前的账号/项目/Task 预算保护；当前接入没有所选模型通用的精确预分词接口。后续应先采用所选 provider/model 可验证的 token estimator，或从 DSH 请求中安全减少每轮重复的系统提示/工具 schema，再以真实两轮以上调用验证预留、实际结算及 hard limit。远端无任何提额、数据库或部署修改。
