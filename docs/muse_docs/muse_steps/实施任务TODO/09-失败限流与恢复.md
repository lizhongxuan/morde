## Muse 效果与 Morde 现状

失败工作项保留原因，限流有等待状态；可恢复任务继续推进，无法确认的操作不谎报成功。Muse 的具体退避、超时和配额策略未知。Morde 已有 [conversationRouteRateLimitDelay / failRoute](../../../../server/internal/worker/conversation_route_worker.go)、[cloudDSHModelErrorCategory](../../../../server/internal/worker/cloud_dsh_executor.go) 和 [Broker.Reconcile](../../../../server/internal/app/cloud_dsh_tool_broker.go)，各链路是否统一仍待验证。

## 接口与参考

- 已有模型/工具错误、工作项及任务状态：调用方需区分认证/授权失败、限流及 `retry_after`、可重试的暂时错误、已确认失败、结果未知、取消与预算耗尽；保留尝试身份、次数及下一次可执行时间。确认仅一层拥有重试责任，避免多层放大。
- 已有 `Broker.Reconcile`：对可能已执行的副作用，用原调用身份查询或等待；无法确认则保持未知，需要人工或可验证的后续对账，不得盲目重放。
- **可适配局部逻辑：**[Hermes `parse_retry_after_seconds / jittered_backoff`](../../../../project/hermes-agent/agent/retry_utils.py) 可改写解析服务端退避提示和带抖动的有限退避；限额、最大次数和时钟以 Morde 自己的策略及实测确定。
- **只参考设计：**[Hermes `classify_api_error`](../../../../project/hermes-agent/agent/error_classifier.py) 和 [nanoMuse `ToolLoopDetector.check/record`](../../../../project/nanoMuse/android/src/ios/Agent/ToolLoopDetector.swift) 参考错误分类和无进展检测；服务端使用任务隔离、持久状态和实际授权，不能依赖单机内存。

## 任务

- [ ] **M09-01（未开始，依赖 M04-01）错误分类与可见状态**：统一 route worker、执行器、Broker 和客户端对上述错误的映射与持久记录；不得将未知等同成功或确定失败。验收：注入限流、鉴权错误、超时、取消和预算耗尽，任务/工作项显示正确原因。
- [ ] **M09-02（未开始，依赖 M09-01）限流与有限恢复**：在唯一重试责任层处理 `retry_after`、有限退避及预算，保留任务和尝试身份；不可重试错误结束本次尝试。验收：连续限流不会紧密循环，取消立即停止后续重试；服务重启后恢复不新增重复任务。
- [ ] **M09-03（未开始，依赖 M04-04、M09-01）未知副作用对账**：通过 `Broker.Reconcile` 查询原调用结果，状态明确后才决定继续；对不能查询的操作保留未知状态。验收：模拟执行成功但回执丢失，不重复执行；对账无法确认时不误报。
- [ ] **M09-04（未开始，依赖 M09-02）重复无进展保护**：对同任务中重复调用且没有新结果的循环设置有界停止和可解释提示，不误伤正常分页或其他任务。验收：模拟循环可停止；合法多页读取和另一独立任务继续运行。

## 端到端验收

使用本地可控的假模型和假工具模拟 429、暂时失败、鉴权失败、执行后丢回执、无法对账及取消，在实际 PC/iOS 查看状态；重启后核对调用次数、下一次重试时间与操作账本。
