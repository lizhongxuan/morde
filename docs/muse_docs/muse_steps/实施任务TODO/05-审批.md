## Muse 效果与 Morde 现状

需要用户决定的敏感操作在执行前暂停，展示实际要做什么、对象与影响；拒绝或未确认不执行。Muse 可见一次性或限定范围的审批，但完整卡片和超时细节未证实。Morde 的授权策略独立于沙箱，绝不由模型自行批准。

Morde 已有 [PendingRequest](../../../../server/internal/domain/task/types.go)、[审批服务](../../../../server/internal/app/task_approvals.go)、[审批存储](../../../../server/internal/store/postgres/task_approvals.go) 和 [Broker](../../../../server/internal/app/cloud_dsh_tool_broker.go)：已有部分调用身份、请求摘要、Task 修订和控制版本校验，不代表预算、撤权及客户端完整链路已验收。

## 接口与参考

- 已有 [审批响应接口](../../../../server/internal/api/tasks.go) `POST /tasks/:id/approvals/:approval_id/responses`：请求为 `version`、`decision` 和 `Idempotency-Key`；继续使用当前服务端审批与账本。绑定用户、Task 修订、调用 ID、工具名、请求哈希、目标、控制/授权版本及有效期；目标合同还需在批准后、派发前复核当前预算和新消息栅栏。参数、目标、权限或版本变化时旧批准失效，重复响应不得重复执行。
- 默认一次性批准；仅在产品已提供且用户明确授权时支持范围批准，执行仍需校验范围和有效期。PC [TaskApprovalCard](../../../../web/portal/src/components/TaskApprovalCard.tsx) 与 iOS 数据适配共用服务端状态；本轮交互和端到端验收只使用实际 `morde-pc`，iOS 未实测不标通过。
- **优先核对 DSH：**[ToolExecutor.execute](../../../../project/deepseek-harness/packages/core/tools/src/executor.ts) 和已接入的 [NativeToolExecutor.execute](../../../../project/deepseek-harness/packages/core/tool-executor-native/src/index.ts) 用于工具执行与取消；审批和副作用仍必须经过 Morde Broker，不以插件执行代替业务授权。
- **只参考设计：**[Claude SDK `PermissionResultAllow/PermissionResultDeny` 和 `PreToolUseHookInput`](../../../../project/claude-agent-sdk-python/src/claude_agent_sdk/types.py)、[Query._handle_control_request](../../../../project/claude-agent-sdk-python/src/claude_agent_sdk/_internal/query.py) 参考允许/拒绝的显式合同；SDK 中某些允许规则可能遮蔽回调，不能作为 Morde 安全边界或替代 DSH。
- **只参考设计：**[Codex `AskForApproval` / `SandboxPolicy`](../../../../project/codex/codex-rs/protocol/src/protocol.rs) 和 [Hermes `request_tool_approval`](../../../../project/hermes-agent/tools/approval.py) 用于对比审批与沙箱边界，不复制其单用户或绕过授权配置。

## 任务

- [x] **M05-01（依赖 M04-01）审批合同及策略**：审批记录和需审批的 Host、外部 MCP、Workspace/media 操作绑定账号、Task 修订、pending-request 版本、CallID、工具/参数摘要、目标与授权 fence；派发/提交事务再核对绑定，预算、授权与用户审批分开判断。API、Broker 与 PostgreSQL 定向用例通过，覆盖错误参数/目标/修订、过期、重复批准及批准后再派发。只代表已接入的逐次审批路径，未声明逐次审批的动作类别与其他独立账本见 M05-05。
- [x] **M05-02（依赖 M05-01）等待与恢复**：审批前持久化待执行调用；批准恢复时复核身份、目标、授权、预算、Task 修订和 steer；拒绝、过期、撤权、取消、超预算或同 Task 新 steer 均不能继续旧调用，结果未知时不重放，独立 Task 不受影响。Broker 精确调用、并发/过期响应、取消及同 Task steer 使待批申请失效的 API/PostgreSQL 回归通过。
- [ ] **M05-03（依赖 M05-01）客户端审批卡**：PC 卡片说明审批仅覆盖本次动作、拒绝后果及批准不代表完成；详情可提交允许/拒绝。费用等缺乏可信来源时显示“未知”；成功反馈需区分允许与拒绝，同时不把响应受理写成任务已完成。组件/Review 测试、类型检查和 PC 构建通过；实际 `morde-pc` 本地合成请求已核验 pending 后拒绝，拒绝 POST 到达本地 API，Task 回到 `running` 等待后续处理；该 fixture 不模拟拒绝后的 Agent 回复，因此不是完整 E2E。iOS 交互仍待验收。
- [x] **M05-04（依赖 M05-02）逐次审批边界回归**：本地用例覆盖精确绑定、参数/修订变化、并发决定、到期、预算不足、拒绝不派发、取消及 steer 失效；API、app 和 PostgreSQL 定向回归通过。该结论仅覆盖现有逐次审批路径，不表示所有不可逆动作都已纳入审批。
- [ ] **M05-05 审批策略与独立账本覆盖**：为每类副作用明确逐次审批、固定只读授权或目标/Task 授权的产品规则，并逐一映射到持久账本与事务门禁；不得把 Host/Hub grant 等同于本次用户批准。优先补查 Hub `command`/`file.put`、Workspace live write 等独立账本，以及 `runtimeToolRisk` 中 moderate 动作的审批边界。验收：每种动作有明确的策略与账本证据；所有规定需逐次批准的副作用都能绑定唯一 approval ID/version、Task revision、调用身份和授权 fence；无法证明时继续 `unknown` / fail-closed。此项完成前不宣称 H05 全动作覆盖。

## 端到端验收

优先用 `make pc` 启动实际 `morde-pc`，使用本地模拟敏感动作覆盖批准、拒绝、重启、修改目标、新消息、预算不足、撤权和失效；检查界面、Task 和操作账本一致。禁止使用普通用户 Web 或 iOS 代测，不实际发送消息或上传文件；环境不可用时保留待验证。

## 实施与验证记录

- PC `TaskApprovalCard` 补充单次操作范围、拒绝后果和批准后仍以 Task 实际状态为准的说明；Review 详情可直接允许或拒绝本次操作；成功反馈明确显示“已允许本次操作”或“已拒绝本次操作”，并说明 Task 后续状态待更新。后端未提供可信 action-level 成本估值时继续显示“未知”。
- 通过：审批卡与 Review 定向测试 13 项；Assistant/Review/审批卡相关测试共 236 项通过；`npm run build:pc`、API/app 审批及 Broker 用例、PostgreSQL 精确绑定/到期/并发/steer 回归均通过。最新工作区的步骤 06 编译问题已消除，不再作为本步骤阻断。
- ESLint：审批卡及其组件测试定向 lint 通过；扩展到整份 `Assistant.tsx` / `Reviews.tsx` 的 lint 仍报已有 React Hooks/ref 规则错误（共享路由中旧代码，不在本次新增决策提示行），不记为整路 lint 通过。
- PC 实测：使用隔离 profile 和 loopback 合成服务启动 `make pc`；实际客户端显示待审批卡和允许/拒绝操作，调用夹具 `verify/approval` 先确认 `waiting_user/pending`，随后在 PC 点“拒绝”，本地审批响应 POST 到达 API，Task 进入 `running` 等待后续处理。测试夹具不模拟 Agent 消化拒绝后的结果；本次 fixture 到 5 分钟上限后超时，故只记实际 UI/响应观察，不计自动 E2E 通过。服务端 Broker 拒绝不派发用例通过；iOS 交互仍待验收。
- 未完成边界：H05 的全动作策略与账本覆盖仍未闭合；Hub grant 不等于逐次审批，未枚举的 action class 不得推断已获批，继续保持验证 `unknown` / fail-closed。未访问远端服务或 Host、未调用真实 Provider、未使用用户提供的密钥、未发送/上传文件。
