## Muse 效果与 Morde 现状

需要用户决定的敏感操作在执行前暂停，展示实际要做什么、对象与影响；拒绝或未确认不执行。Muse 可见一次性或限定范围的审批，但完整卡片和超时细节未证实。Morde 的授权策略独立于沙箱，绝不由模型自行批准。

Morde 已有 [PendingRequest](../../../../server/internal/domain/task/types.go)、[审批服务](../../../../server/internal/app/task_approvals.go)、[审批存储](../../../../server/internal/store/postgres/task_approvals.go) 和 [Broker](../../../../server/internal/app/cloud_dsh_tool_broker.go)：已有部分调用身份、请求摘要、Task 修订和控制版本校验，不代表预算、撤权及客户端完整链路已验收。

### M05-05 动作策略矩阵

| 动作类别 | 授权/审批策略 | 持久化账本与派发门禁 |
|---|---|---|
| Host 固定只读工具（文件读取/列举、截图、观察） | 固定 `computer.observe` Task scope；不逐次审批 | Host `task_operations` 绑定 Task revision、调用键、工具/请求摘要和 Host control fence；授权及运行时状态在执行前复核 |
| Host moderate 工具（Workspace 文件写、AI 自有浏览器开页/导航/点击、窗口聚焦及除 Enter/Backspace/Delete 外的按键） | 仅在当前 Task 已获 `computer.operate` 且 Host/Workspace fence 有效时执行；不把 Task scope 说成逐次用户批准 | `runtimeToolRisk` 分类；每次操作仍有 Host `task_operations` 账本与最终派发栅栏 |
| Host sensitive 工具（shell、浏览器/桌面输入、Enter/Backspace/Delete 和未知工具） | 必须逐次批准，批准只绑定当前 Task revision、CallID、tool/参数哈希及 Host runtime/control fence | `task_pending_requests` 与 Host operation 在创建/派发事务中精确关联；`requireApprovedTaskOperationBinding` 重验审批、响应人、版本、身份及 fence |
| Hub 截图/文件读取/文件提取 | Task `computer.observe` scope + 在线目标当前 grant；授权与审批分离，不声称 per-call approval | `task_hub_operations` 独立记录稳定调用键、目标/授权版本、请求摘要、lease 与结果；prepare/dispatch 复核 Task/目标，目标端再次检查 grant |
| Hub `morde_hub_command` | Task `computer.operate` scope + 用户授权的目标当前 grant，并且必须来自当前用户任务；目标 grant 不是逐次批准，也不构成可跨 Task 复用的授权 | 与 Hub 读操作相同的独立 Hub ledger；任务 scope 在定义、执行和派发前检查，Task 授权版本/lease 与目标有效性在事务中复核，新 steer 阻止旧操作派发；目标以 `TaskContext` 验证 scope 版本和 grant |
| 外部 MCP、Workspace live write、media publish | 逐次精确批准；内置只读 search/read 依赖固定定义和 Task scope，不逐次批准 | MCP operation、Workspace publish reservation/receipt 与 pending approval 绑定 CallID、tool/request hash、Task revision、approval ID/version、授权 fence；prepare/dispatch 或 reserve/commit 事务重验 |
| 个人资料、记忆、SOUL 与目标写入 | 仅限 owner 发起的个人 Task 和用户明确要求的写入；这属于 Task 意图授权，不把模型自行推断当作长期许可 | 目标修订/CAS、Task/Session/CallID 生成的 mutation identity 与 Task 事件在同一提交中持久化；记忆开关与当前个人上下文资格复核 |
| DSH 未注册或无法分类的工具；Hub `file.put` | 不开放或拒绝，保持 fail-closed | Hub parser 仅接受显式注册的 action；`file.put` 是独立用户触发的 Workspace 同步能力，不可由聊天工具调用 |

逐次审批只用于矩阵明确要求逐次批准的类别；Task scope、目标 grant、预算和沙箱/运行时 fence 分别校验，不相互替代。仅凭“审批通过”不证明副作用已执行；独立 ledger 或覆盖证据缺失时，步骤 06 仍须判 `unknown/pending`。
