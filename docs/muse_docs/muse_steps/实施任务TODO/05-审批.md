## Muse 效果与 Morde 现状

需要用户决定的敏感操作在执行前暂停，展示实际要做什么、对象与影响；拒绝或未确认不执行。Muse 可见一次性或限定范围的审批，但完整卡片和超时细节未证实。Morde 的授权策略独立于沙箱，绝不由模型自行批准。

Morde 已有 [PendingRequest](../../../../server/internal/domain/task/types.go)、[审批服务](../../../../server/internal/app/task_approvals.go)、[审批存储](../../../../server/internal/store/postgres/task_approvals.go) 和 [Broker](../../../../server/internal/app/cloud_dsh_tool_broker.go)，还需验证作用域、撤权和两端体验。

## 接口与参考

- 已有审批请求/决定合同：绑定用户、任务修订、调用 ID、工具名、请求哈希、目标、权限版本和有效期；展示实际操作内容和可知费用，未知费用显式标识。若参数、目标、权限或版本变更，旧批准失效；重复决定幂等，过期、拒绝、撤权或身份不匹配不得执行。
- 默认一次性批准；仅在产品已提供且用户明确授权时支持范围批准，执行仍需校验范围和有效期。PC [TaskApprovalCard](../../../../web/portal/src/components/TaskApprovalCard.tsx) 与 [iOS MIFApprovalViews](../../../../clients/nanoMuse/android/src/ios/NanoMuse/MIFApprovalViews.swift) 消费同一服务端状态。
- **只参考设计：**[Claude SDK `PermissionResultAllow/PermissionResultDeny` 和 `PreToolUseHookInput`](../../../../project/claude-agent-sdk-python/src/claude_agent_sdk/types.py)、[Query._handle_control_request](../../../../project/claude-agent-sdk-python/src/claude_agent_sdk/_internal/query.py) 参考允许/拒绝的显式合同；SDK 中某些允许规则可能遮蔽回调，不能作为 Morde 安全边界或替代 DSH。
- **只参考设计：**[Codex `AskForApproval` / `SandboxPolicy`](../../../../project/codex/codex-rs/protocol/src/protocol.rs) 和 [Hermes `request_tool_approval`](../../../../project/hermes-agent/tools/approval.py) 用于对比审批与沙箱边界，不复制其单用户或绕过授权配置。

## 任务

- [ ] **M05-01（未开始，依赖 M04-01）审批合同及策略**：在审批服务、存储和 Broker 中核对用户、请求摘要、工具参数、目标、任务修订、授权版本、范围及期限的一致绑定。验收：改变任一必要条件后旧批准不可用；读操作按现有策略执行，需审批操作不提前执行。
- [ ] **M05-02（未开始，依赖 M05-01）等待与恢复**：审批前先保存待执行调用；收到批准、拒绝、到期、撤权时核验当前身份和状态，重复响应不产生新执行。验收：等待期间服务重启后状态仍在，拒绝/到期/撤权及重复点击均不造成副作用。
- [ ] **M05-03（未开始，依赖 M05-01）双端审批卡**：调整上述 PC/iOS 卡片和服务端响应，显示动作、目标、作用范围、影响和已知或未知成本；提交后展示真实等待/批准/拒绝/失效。验收：两端状态一致，权限变更时显示失效而非误报批准。
- [ ] **M05-04（未开始，依赖 M05-02）边界回归**：以本地模拟工具构造修改目标、会话切换、并发审批及权限撤销；验收：仅精确获批的调用可执行一次，其他任务和账号均不能消费该批准。

## 端到端验收

在实际 `morde-pc` 与 iOS 各使用本地模拟的敏感动作，覆盖批准、拒绝、等待时重启、修改参数、撤销授权和失效；检查操作账本与界面一致。验收不实际发送消息或上传文件。
