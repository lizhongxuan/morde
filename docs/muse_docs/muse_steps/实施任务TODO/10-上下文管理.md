## Muse 效果与 Morde 现状

长会话超过模型窗口后仍能找回用户此前的重要要求，用户可查看原始聊天记录；不能取得所需历史时明确说明。按最终流程图分两层处理：路由层用带来源的会话摘要、近期历史和当前消息完成分类；Task 层使用 DSH 修剪/压缩执行上下文，并按需读取授权原文。两层目标不同，不能把压缩后的执行上下文当成会话原文。Muse 的窗口、压缩触发及具体保留策略未证实，Morde 应根据实际模型窗口和测试确定。

现有 [fitConversationRouteContext](../../../../server/internal/worker/conversation_route_worker.go)、[compactConversationSummary](../../../../server/internal/worker/conversation_summary_maintenance.go)、[摘要输入与版本合同](../../../../server/internal/app/conversation_summaries.go)、[历史检索及分段读取](../../../../server/internal/app/cloud_dsh_history_tools.go) 与 [MordeCompactionEngine](../../../../runtime/morde-cloud-runtime/src/engine.mjs) 是基础；已有分段读和压缩代码不等于大消息及超长任务端到端已通过。

## 接口与参考

- **路由层（会话历史摘要）：**复用会话级摘要和近期记录装配上下文，保留原消息 ID、序号、字节数、摘要版本/摘要哈希/来源哈希及 `HistoryIncomplete`。`fitConversationRouteContext` 按模型上下文窗口拟合：先减少候选，再把旧历史变为带 ID 的首尾预览，再清空旧历史正文但保留 ID/序号/Task 引用，然后才舍弃摘要；仍超限时当前消息只能作为带原始 ID/长度/哈希的截断预览交给分类，不能把预览当成可执行全文。摘录不完整时提示 Agent 检索原文。实际顺序以该函数当前实现为准，改动时同步更新验收。
- **Task 层（单个 DSH Session）：**任务启动时传入任务简报，不把整份聊天历史塞进提示；需要旧要求时通过 [当前会话历史搜索/分段读](../../../../server/internal/app/cloud_dsh_history_tools.go) 按授权取回。沿用 DSH ToolResultPruner 与会话压缩，压缩范围须保留最新 Task 目标及完整的工具调用/结果组；摘要须能追溯来源。跨会话/用户历史遵循原有授权。
- **长当前消息：**已有 [executeCurrentConversationMessageRead](../../../../server/internal/app/cloud_dsh_history_tools.go) 使用固定会话/Task 授权、`message_id`、全文 `sha256` 和 `rune_offset` 分段读取，返回连续 offset、全文总字符数及 `complete`。逐块沿用同一全文摘要并校验 offset 连续；读完可重建全文并对照该 SHA-256。若源消息变化、块缺失/重复、授权失效或预算耗尽，停止处理并明确反馈。
- **摘要提交与失败：**会话摘要以版本、来源证明和摘要哈希提交，基于读取时的摘要版本/输入哈希做冲突校验；旧摘要与原消息继续可查。生成失败、输出无效、摘要变大或版本已变化时保留旧摘要并继续带 `HistoryIncomplete` 运行或明确降级，不覆盖好版本、不假装完整，也不循环重试。
- **优先复用 DSH 插件：**[BasicCompactionEngine.compactIfNeeded / compactRegion](../../../../project/deepseek-harness/packages/compaction/compaction-basic/src/index.ts) 与现有 [MordeCompactionEngine.compactWithHermes / selectRange](../../../../runtime/morde-cloud-runtime/src/engine.mjs)、[selectHermesCompactionRange / originalToolResultsForRange](../../../../runtime/morde-cloud-runtime/src/hermes-compaction-window.mjs) 和 `ToolResultPruner`；核对真实 provider context window、响应预留、工具调用成组边界、`pinTask`、压缩有进展判断、重试冷却、检查点及恢复。
- **可适配局部逻辑：**[Hermes `_plan_compaction_window / summary_view`](../../../../project/hermes-agent/agent/context_compressor_window.py) 可参考选择压缩窗口与恢复原始来源；[ContextCompressor.should_compress / compress](../../../../project/hermes-agent/agent/context_compressor.py) 可参考预算判断和失败处理。相关窗口选择和工具结果还原已在 Morde 的 `hermes-compaction-window.mjs` 中，优先维护并验证此实现；只在 DSH 身份、存储与检查点内适配，不照抄 Hermes 固定阈值或原地改写历史。

## 任务

- [ ] **M10-01（未开始，依赖 M01-01）路由层摘要和来源完整性**：核对会话快照、`compactConversationSummary`、摘要版本/输入来源哈希及 `fitConversationRouteContext`；确保路由带近期历史、摘要和当前消息的稳定引用，截断或摘要覆盖不全时保留 ID、序号、字节长度和 `HistoryIncomplete`。验收：模拟摘要缺失、摘要解封失败、摘要版本并发变化及上下文刚好超预算；旧摘要/原文保持可查，分类器知道历史不完整，当前消息不因预览而被误当成全文。
- [ ] **M10-02（未开始，依赖 M10-01）按需读取授权历史**：用 `searchCurrentConversationHistory` 按授权检索当前会话历史和来源；任务输入以简报为主，不注入不必要的整份 transcript。验收：早期、中间、最近的关键要求均能定位到原消息 ID/序号/来源；用户隔离和撤权有效；历史缺失时说明而不编造。
- [ ] **M10-03（未开始，依赖 M10-02、M02-01）1 MiB 单条消息链路**：核对收件、路由当前消息预览、任务简报及分段读取的各处限制；沿用 `message_id` + 全文 `sha256` + `rune_offset` 连续读取，不把全文放进单次模型上下文。验收：1 MiB 纯文本三个不同页锚点均能正确回答并给出可追溯页/来源；每块 offset 连续、总字符数一致，按块重建后的全文 SHA-256 与服务端原文一致；损坏、缺块、重复块、原文变化或撤权时停止且明确说明；超时报告已处理进度，不静默跳过。PC/iOS/API 收件限制同步核对。
- [ ] **M10-04（未开始，依赖 M03-01）Task 层 DSH 压缩与恢复**：在 `engine.mjs` 核对 `MordeCompactionEngine.compactIfNeeded`、`selectRange`、`compactWithHermes`、`ToolResultPruner` 与 `hermes-compaction-window.mjs` 的实际触发和调用；按模型窗口留响应空间，压缩不拆散工具调用/结果组并固定最新 Task。验收：多轮工具输出触发压缩后可继续，压缩有实际 token/上下文收益；无安全区间或无进展时停止并保留原会话，取消/重启后 checkpoint 一致，不重复操作或引用不存在的压缩结论。
- [ ] **M10-05（未开始，依赖 M10-01、M10-04）摘要失败与模型预算恢复**：核对摘要生成错误、限流、上下文溢出、压缩无进展和 provider 未提供窗口信息的分支；失败不反复调用，旧摘要和未压缩原文可读，错误沿 09 如实呈现。验收：超限任务能按安全压缩路径重试一次或明确失败；模型窗口不可解析时不假定无限预算；新消息/摘要版本改变后旧压缩产物不覆盖最新状态。
- [ ] **M10-06（未开始，依赖 M10-03、M10-04、M10-05）真实长会话与大消息验收**：在实际 `morde-pc` 和原生 iOS 使用同账号，分别构造累计历史超过模型窗口的多轮会话及 1 MiB 当前消息，核对早期要求、来源和原始聊天记录。验收：准确回答早期锚点；无法取回时明确说明；任务层工具历史可追溯；断线/恢复后没有重复执行。分别用小/大模型窗口和含中文内容验证，不把 Hermes 阈值当成验收标准。

## 端到端验收

按最终流程图分开验收路由层和 Task 层：在实际 PC/iOS 使用同一账号进行超过所选模型窗口的多轮对话，询问早期要求并核对消息来源及原始记录；再用本地合成 1 MiB 消息验证连续分段和全文 SHA-256。另构造长工具会话触发 DSH 压缩，确认最新 Task 目标、完整工具调用/结果组及 checkpoint 得以保留。无权限、摘要失败或原文不可用时不得编造；使用本地测试环境，不外发文件。
