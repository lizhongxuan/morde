## Muse 效果与 Morde 现状

长会话超过模型窗口后仍能找回用户此前的重要要求，用户可查看原始聊天记录；不能取得所需历史时明确说明。按最终流程图分两层处理：路由层用带来源的会话摘要、近期历史和当前消息完成分类；Task 层使用 DSH 修剪/压缩执行上下文，并按需读取授权原文。两层目标不同，不能把压缩后的执行上下文当成会话原文。Muse 的窗口、压缩触发及具体保留策略未证实，Morde 应根据实际模型窗口和测试确定。

## 接口与参考

- **路由层（会话历史摘要）：**复用会话级摘要和近期记录装配上下文，保留原消息 ID、序号、字节数、摘要版本/摘要哈希/来源哈希及 `HistoryIncomplete`。`fitConversationRouteContext` 按模型上下文窗口拟合：先减少候选，再把旧历史变为带 ID 的首尾预览，再清空旧历史正文但保留 ID/序号/Task 引用，然后才舍弃摘要；仍超限时当前消息只能作为带原始 ID/长度/哈希的截断预览交给分类，不能把预览当成可执行全文。极限情况下仍可能移除部分已清空的历史引用，但不删除原始消息；需按 M10-08 标记不完整并验证可授权检索。实际顺序以该函数当前实现为准，改动时同步更新验收。
- **Task 层（单个 DSH Session）：**任务启动时传入任务简报，不把整份聊天历史塞进提示；需要旧要求时通过 [当前会话历史搜索/分段读](../../../../server/internal/app/cloud_dsh_history_tools.go) 按授权取回。沿用 DSH ToolResultPruner 与会话压缩，压缩范围须保留最新 Task 目标及完整的工具调用/结果组；摘要须能追溯来源。跨会话/用户历史遵循原有授权。
- **长当前消息：**路由器看到的是有界预览；预览开头明确要求总结、分析或解释文章/原文时，应路由到新 Task，不能要求用户重发服务端已保存的原文（M02-09）。Task 按需优先用 [executeCurrentConversationMessageSearch](../../../../server/internal/app/cloud_dsh_history_tools.go)：固定当前会话与 Task 授权，逐页读取并校验 manifest 页哈希及全文 SHA-256，在服务端扫描后最多返回 5 段、每段不超过 600 字符的原文摘录及页号/页哈希；全文不会进入模型上下文。`complete` 只表示完成原文扫描，不代表模型处理了全文；同页有未展示的关键词匹配或超过结果数上限时 `partial=true`，应缩小问题继续检索；检测到凭据时不返回摘录。仅当问题确实需要全文时，才用 [executeCurrentConversationMessageRead](../../../../server/internal/app/cloud_dsh_history_tools.go) 按 `next_rune_offset` 分段读取：每次仍先完整校验原规范页，转义后超限的页再拆成多个有界片段，记录连续字符范围与哈希。规范页数不等于工具调用数，已返回片段不等于模型已理解全文。源消息变化、页损坏、授权失效或预算耗尽时停止并明确反馈，不能把局部摘录说成全文处理结果。
- **摘要提交与失败：**会话摘要以版本、来源证明和摘要哈希提交，基于读取时的摘要版本/输入哈希做冲突校验；旧摘要与原消息继续可查。生成失败、输出无效、摘要变大或版本已变化时保留旧摘要并继续带 `HistoryIncomplete` 运行或明确降级，不覆盖好版本、不假装完整，也不循环重试。
- **优先复用 DSH 插件：**[BasicCompactionEngine.compactIfNeeded / compactRegion](../../../../project/deepseek-harness/packages/compaction/compaction-basic/src/index.ts) 与现有 [MordeCompactionEngine.compactWithHermes / selectRange](../../../../runtime/morde-cloud-runtime/src/engine.mjs)、[selectHermesCompactionRange / originalToolResultsForRange](../../../../runtime/morde-cloud-runtime/src/hermes-compaction-window.mjs) 和 `ToolResultPruner`；核对真实 provider context window、响应预留、工具调用成组边界、`pinTask`、压缩有进展判断、重试冷却、检查点及恢复。
- **可适配局部逻辑：**[Hermes `_plan_compaction_window / summary_view`](../../../../project/hermes-agent/agent/context_compressor_window.py) 可参考选择压缩窗口与恢复原始来源；[ContextCompressor.should_compress / compress](../../../../project/hermes-agent/agent/context_compressor.py) 可参考预算判断和失败处理。相关窗口选择和工具结果还原已在 Morde 的 `hermes-compaction-window.mjs` 中，优先维护并验证此实现；只在 DSH 身份、存储与检查点内适配，不照抄 Hermes 固定阈值或原地改写历史。

### R21 长初始消息投递边界审计（修复前历史记录，2026-11-25）
