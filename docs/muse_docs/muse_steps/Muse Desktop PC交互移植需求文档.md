# Muse Desktop PC 交互移植需求

## 目标与边界

在 `morde-pc` 中补齐以下6项交互，参考 Muse Desktop 的界面与操作方式，接入 Morde 自有的会话、Task、审批和 DSH 能力。界面遵循 Morde 统一设计规范和标识。

除下文已确认的变更外，保留现有功能的入口和行为，包括普通消息自动路由、独立任务并行、任务停止方式、审批与澄清、附件限制和草稿、语音识别、账号隔离及跨端会话。新增接口或字段需兼容现有客户端。实施中若发现其他现有行为、权限或数据处理方式必须改变，先说明影响并取得用户确认。

## 功能要求

1. **折叠式工具活动组**：将同一任务、同一执行主体的连续工具调用汇总为可展开卡片，按原顺序显示每步状态、输入、输出和耗时；有可靠数据时显示文件增删行数。摘要须能看出运行、等待或失败；缺失的信息显示未记录，保留原任务详情入口。
2. **长工具输出**：先显示摘要，用户可按需读取有权限访问的完整输出。对新产生的输出新增受现有授权和脱敏保护的完整内容保存，保留原有有界详情；源头已截断、未保存或保存失败时明确说明，不将片段称为完整输出。历史上未保存的内容无法恢复；保存失败不改变工具执行和任务结果。
3. **结构化追问卡片**：在现有澄清卡片上支持单选、多选和自由文本；选项和选择规则由服务端提供。用户可跳过问题，包括现有必答澄清；服务端记录“跳过”并让任务继续处理，不伪造答案。缺少关键目标或授权时，只继续可安全执行的部分并说明无法完成的内容。沿用问题身份、版本和幂等保护，提交失败或结果未知时保留状态。
4. **附件拖放与预览**：在输入区拖放文件时提供可见反馈，加入现有附件列表并支持预览、移除；沿用现有允许的类型、数量、大小、读取和上传规则，以及按会话保存的草稿。拖放无效文件应提示原因。
5. **录音波形与转写状态**：语音输入时显示真实电平、聆听及转写状态，并可取消本次输入；继续使用现有语音识别方式，已写入草稿的文字和其他内容保留。用户启动后可为电平显示额外采集麦克风音频，仅在本机计算，不保存或上传采样音频；停止或取消时释放采集。PC 只对受信任的语音输入界面按需开放麦克风权限。波形采集失败不影响原有语音识别；麦克风或波形不可用时说明状态，文字输入仍可使用。
6. **任务完成桌面通知**：PC 窗口不在前台时，已确认完成的任务显示系统通知，设置中可关闭。刷新、重连或重复收到同一完成事件不重复通知；通知权限不可用时，任务状态和会话结果仍正常显示。

## 验收条件

- 在实际 `morde-pc` 内完成上述操作：工具组可展开，完整输出可按权限读取，截断和保存失败真实显示；审批状态真实。单选、多选、自由文本可提交，必答澄清也可显式跳过并继续处理。
- 同一会话中并行运行任务时，排队和引导只作用于所选任务；普通发送仍按原规则处理，重连或重复提交不重复执行已确认的操作。
- 拖入允许及不允许的文件，检查预览、移除、限制提示与草稿保留；语音电平反映真实输入，开始、停止、取消及不可用状态可辨认，取消后已写入的草稿保留。
- 窗口切到后台后任务完成，仅出现一次通知；关闭通知后不再弹出。重新打开会话仍可查看真实结果。
- 回归现有普通对话、多会话、审批双入口、澄清答复、附件发送、语音输入、云端电脑和跨端会话；无法实测的范围单独记录，不算通过。

## 已确认的原有行为变更

- 原有工具详情为有界、脱敏记录；用户同意新增受保护的完整输出保存。
- 原有澄清要求非空答复；用户同意必答问题也可由用户显式跳过并继续处理。
- 用户同意为波形新增仅本机电平采集。原浏览器语音识别的处理方式保持不变。
