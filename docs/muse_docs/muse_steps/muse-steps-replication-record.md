# Muse 步骤复刻记录

本文把 Muse 的 11 个步骤整理成 Morde 的复刻目标，便于逐项实施与回看。

**使用说明：**“Muse 做法”按[逆向工程](muse-harness-reverse-engineering.md)中的证据等级表述；未知或推断项不当作事实。“Morde 复刻目标”描述预期行为，不代表已经实现。测试编号仅供追溯，其中包含 Muse 探查、Morde 回归及方法论用例，不自动等同于 Morde 的验收范围。具体差距、开发设计和代码入口见[最终流程与开发设计](Morde%20复刻%20Muse%20最终流程与开发设计.html)，逐步任务及验收见[实施任务总大纲](实施任务TODO/00-总大纲.md)。

| # | 步骤 | Muse 做法 | Morde 复刻目标 | 参考用例 |
|---|---|---|---|
| 1 | 收件与会话 | 多端消息进入同一会话；任务列表显示进度。收件去重和定序细节未知。 | PC 与 iOS 共用服务端会话；消息、任务和进度持久保存，重试幂等且顺序稳定。不扩展到 Morde 未规划的用户端或渠道。 | TC-1.1–1.8 |
| 2 | 意图路由与任务拆分 | 按请求选择 Skill/Connector；复杂请求由协调员拆分。分类算法及多条消息如何归并未知。 | 区分普通回复、任务查询、追问/修改、停止和新任务；任务记录目标、范围、验收与预算。指代不清时澄清，归并阈值按 Morde 实测确定。 | TC-2.1–2.12 |
| 3 | 并发派发与协调 | 主 Agent 处理简单对话，复杂工作交给后台子 Agent；实测子 Agent 可嵌套两层，协调员汇总实际结果。 | 沿用 DSH，支持主 Agent → 协调员 → worker 的受控派生；独立工作可并行，主 Agent 核对并汇总结果。隔离授权、预算、取消和恢复，不另建 Runtime。 | TC-3.1–3.13 |
| 4 | 工具执行工作项 | 每次工具调用形成工作项；保留进行中、失败和取消状态，可查看命令、退出码、耗时、目录、输出和结论。 | 复用服务端 Broker 与操作账本；执行前持久化意图，执行后保存回执，结果未知时先对账。任务详情展示可核查的执行证据。 | TC-4.1–4.14 |
| 5 | 审批 | 写入和付费等操作需要审批；可见审批范围包含一次性或限定范围等形式。审批卡细节部分未知。 | 审批绑定具体用户、目标、操作和版本；清楚展示证据、影响及可用成本，未知成本明确标示。撤权、拒绝或超时不得继续执行。 | TC-5.1–5.17 |
| 6 | 验证 | 通过实际检查和读回确认结果；部分任务使用 checking worker 检查证据与结论。 | 验收依赖真实检查结果；证据绑定当前 Task 修订、产物版本和环境。模型自述或“任务已完成”不能代替验收。 | TC-6.1–6.9 |
| 7 | 交付与提问 | 主对话以最终结果为主，过程留在任务详情；在阻塞或需要用户决定时提问。 | 将结果发回原 PC/iOS 会话；任务详情呈现进度、审批、失败和证据。按 Morde 统一 UI 规范呈现，普通问答不被后台任务阻塞。 | TC-7.1–7.12 |
| 8 | 记忆与纠正沉淀 | 记忆有可读文件和索引；纠正保留新旧关系，并定期整理。具体写入与去重规则部分未知。 | 先保证授权历史可检索、摘要有来源、原始记录可查看且租户隔离。纠正只有经过验证和授权后，才成为可复用规则。 | TC-8.1–8.12 |
| 9 | 失败与限流 | 失败工作项留痕，任务不因单项失败而丢失；存在限流和等待状态。重试细节未知。 | 失败原因和真实状态持久可见；仅对可重试错误做有界恢复。重试副作用前先对账，不把未知结果说成成功或失败。 | TC-9.1–9.8 |
| 10 | 上下文管理 | Muse 的上下文窗口、压缩触发和保留策略未知；不能把其他项目的实现当作 Muse 事实。 | 通过摘要、授权历史检索和 DSH 会话压缩支持长对话；保留原文来源，取不到必要历史时明确说明。阈值按 Morde 的模型和实测确定。 | TC-10.1–10.20 |
| 11 | Bug 发现与处理 | 没有足够证据证明这是 Muse 的产品机制；材料总结的是调试方法。 | 按“发现—复现—验证根因—补回归—记录结果”处理问题，并同步必要的实现规格与验证记录。此项是工程流程，不是用户侧 Agent 功能。 | TC-11.1–11.10 |

## 实施边界

- 复刻目标是 Morde 范围内可观察的体验和可靠性；产品端为服务端、PC、iOS 和管理后台。
- 保留 DSH 作为唯一 Agent Runtime，以及 Morde 现有的服务端授权、审批、操作账本和多租户隔离。
- 每一步先核对现有实现，再补真实缺口；Muse 未知项先验证，不照搬推测、阈值或单机实现。
