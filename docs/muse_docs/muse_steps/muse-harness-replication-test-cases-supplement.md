## SUP-0 跨步骤量化总线（跑真实用量后按分布验收，单次运行不算通过）

**SUP-0.1 主对话回复长度分布** — Muse 依据：已证实，assistant 944 条，中位 142–160 字符，≤141 占 47.7%，平均 312.7，最大 3,656。操作：取最近 100 条 Morde 主对话回复，统计长度分布。断言：中位落在 100–200 字符区间；超过 1,000 字符的回复占比 <5%；长回复都有明确原因（交付要点、错误说明），不是过程噪音。

**SUP-0.2 提问率** — Muse 依据：已证实，回复以 `?` / `？` 结尾 6.8%，`waiting_for_user` 6.8%，两个独立口径一致。操作：统计最近 200 条回复的提问率与任务等待率。断言：提问率落在 3%–12% 区间；既不是每条都问，也不是从不问；每次提问都对应阻塞或需拍板，且载体是选项卡。

**SUP-0.3 任务失败率与失败留痕** — Muse 依据：已证实，442 个任务，失败 14 个（3.2%）；failed actions 214 条（1.3%）全部保留。操作：统计最近 100 个 Morde 任务的 finish_status 与失败工作项保留情况。断言：失败任务占比 <8%；每个失败任务的失败步骤都在详情里可查，未被删除或改写；主对话没有原始错误文本。

**SUP-0.4 事件可见性** — Muse 依据：已证实，5,478 条事件，internal 75.0%、public 25.0%；subagent 通道 1,030 条 100% internal。操作：统计最近 500 条 Morde 事件的可见性。断言：internal 事件占比 >60%；用户看不到过程噪音，只能看到最终结果与必要的提问、审批。

**SUP-0.5 协调员安静程度** — Muse 依据：已证实，20,787 次协调员决策，`nothing_to_do` 61%、`completed` 38%、`notify_main_agent` 仅 1.2%。操作：Morde 接入协调员决策计数后，统计最近 200 次决策。断言：通知主 agent 的占比 <5%；不是每条子 agent 事件都打扰主 agent。注：Morde 尚未接入该计数，本用例先记为“待接线”，不谎称已验收。

## SUP-1 收件与会话

**SUP-1.1 同一账号 PC 与 iOS 接续同一会话** — Muse 依据：已证实，多端同一会话。操作：在实际 morde-pc 发三条消息，切到原生 iOS 同一账号打开同一会话，再发一条。断言：两端看到同一份持久历史、同一任务进度；没有重复建任务；任务数与数据库一致。对应 TODO M01-02/03（待验证）。

**SUP-1.2 断线重连不丢不重** — Muse 依据：合理推断（恢复机制存在，细节未知）。操作：执行任务中关闭实际 morde-pc 客户端，重连后查看。断言：消息不丢失、不重复；任务显示真实进度和结果；没有因重连新建任务。对应 TODO M01-02。

**SUP-1.3 切换账号不串数据** — Muse 依据：Morde 自研（租户隔离）。操作：同一设备切到另一账号，查看会话与任务列表。断言：看不到上一账号的任何会话、任务、消息；数据库按账号隔离查询返回空。对应 TODO M01-03。

**SUP-1.4 发件箱重试幂等** — Muse 依据：Morde 自研（`client_message_id` 幂等）。操作：断网时在 PC 发一条消息，联网后发件箱自动重试两次。断言：服务端只存一条消息；第二次重试返回原消息，不新建；相同 ID 不同内容返回冲突。对应 TODO M01-01（已完成，补端到端）。

## SUP-2 意图路由与任务拆分

**SUP-2.1 普通问答不建 Task、不启动云电脑** — Muse 依据：已证实（普通问答直接回复原会话）。操作：问“今天天气怎么样”类普通问题。断言：路由动作为 `reply`；没有新建 Task；云电脑没有新的 DSH 会话。对应 TODO M02-01/03。

**SUP-2.2 简单工具走隐藏内部 Task** — Muse 依据：Morde 自研（02 文档首切片）。操作：明确要求“搜索一下 X”只读网页搜索。断言：走短命内部 Task 调 Broker，跳过 DSH；该 Task 不出现在用户任务列表、会话任务面板、路由候选、公开详情；结果作为普通助手消息回到原会话，无 `task_id`。对应 TODO M02-06。

**SUP-2.3 同话题补充只产生一个任务** — Muse 依据：已证实（行为），829 链接 / 352 任务，平均 2.36 条 / 任务；归并规则未知。操作：向运行中任务连续发两条同话题补充（第二条在聚合窗口内）。断言：只产生一个任务、一次最终答案；两条消息都挂在同一任务下。注意：本用例不预设窗口时长，只测“窗口内同话题补充合并”这一行为；窗口值按实测调。对应 TODO M02-04。

**SUP-2.4 不同话题补充开新任务** — Muse 依据：已证实（行为）。操作：向运行中任务发一条明显不同话题的新请求。断言：新建独立 Task；原任务不受影响；新任务有自己的目标与验收。对应 TODO M02-04。

**SUP-2.5 窗口外补充开新任务** — Muse 依据：合理推断（窗口存在，时长未知）。操作：等聚合窗口完全过去后，再发一条同话题补充。断言：开新任务，不追加到已结束的任务。注意：窗口时长不写死，测试时按当前实现值执行并记录实测值。

**SUP-2.6 追问、修改、停止只作用于目标任务** — Muse 依据：已证实。操作：同会话两个相似运行任务 A、B，对 B 说“停下来”或“改成 X”。断言：只有 B 被更新 / 停止，A 继续执行；任务列表里 B=`停止`、A=`执行中`。对应 TODO M02-02（iOS 模拟器已通过，PC 自然语言接续待验收）。

**SUP-2.7 Planner 产出 brief 四件套，缺一件不派发** — Muse 依据：Morde 自研（复刻设计 P0-3；02 文档：计划是建议记录，`depends_on` 不门控执行）。操作：给一个复杂任务，看 Planner 产出的 brief。断言：brief 含目标、范围、验收标准、验证方法四件套；缺验收标准时，只在缺失影响执行 / 安全 / 成本 / 不可逆结果时才问用户要最少信息——不是每次都追问（02 文档原文）；执行 Agent 自报的 plan 只作参考，不替代 brief。注意：本用例不预设独立 Planner 文件，职责在 Harness 内即可。

**SUP-2.8 无 brief 不派发** — Muse 依据：Morde 自研。操作：构造一个 brief 为空的派发请求。断言：协调员拒绝派发，返回明确原因；没有子 agent 被启动；拒绝事件进任务账本。

**SUP-2.9 高风险修改不走兜底补充** — Muse 依据：Morde 自研（M02-05）。操作：分类失败兜底时，文本涉及换电脑、工作目录、收件人、模型、权限、审批、预算或计划。断言：不按低风险 `steer` 应用，转为澄清；标题、措辞类轻量补充仍可接续。

**SUP-2.10 长消息明确请求路由新 Task 并绑定原文** — Muse 依据：Morde 自研（M02-09）。操作：在实际 morde-pc 发一条超路由预览的长文，开头明确要求“总结这篇文章”。断言：路由到新 Task，不要求用户重发；Task 绑定已保存的消息 ID、字节数与 SHA-256；模糊内容、指向已有任务的控制请求仍安全澄清。对应 TODO M02-09（服务端通过，PC 验收待做）。

## SUP-3 并发派发与协调

**SUP-3.1 第一个任务不挡第二个** — Muse 依据：已证实，主 agent 派发两个子 agent 后自己继续做 git 检查，时间戳重叠。操作：发一个复杂任务（派发子 agent），在其未完成时发第二个无关任务。断言：第二个任务立即开始，主 agent 不被第一个阻塞；两个任务的时间戳重叠。对应 TODO M03-03。

**SUP-3.2 协调员→worker 两层委派，第三层被拒绝** — Muse 依据：已证实（Muse 嵌套到 2 层，71/230 次）；Morde 自研（M03-02 本地通过）。操作：本地 DSH 进程实测 root→协调员→worker，再试 worker 继续委派。断言：两层成功；第三层被拒绝并记录原因；孙 worker 只获得直接父级已授权的普通工具，不能传递 `dsh_delegate`、工作项控制或结果证据。

**SUP-3.3 协调员汇总成功与失败，不误报完成** — Muse 依据：已证实（协调员汇总实际结果）。操作：派两个 worker，一个成功一个失败。断言：协调员把已分类模型失败与成功结果一起汇总；未知失败不能误报完成；汇总结果进任务账本。

**SUP-3.4 Handoff 三件套齐全** — Muse 依据：已证实（后台结果以 hidden handoff 交回）。操作：子 agent 完成后检查交回主 agent 的 handoff。断言：含已完成什么、证据在哪、还差什么三项；handoff 对用户不可见，由主 agent 决定用户看到什么；worker 不能要求主 agent 做更多工作。

**SUP-3.5 一个 coordinator per objective** — Muse 依据：已证实（官方推荐，明确反对从 root 直接扇出多个平级 worker）。操作：一个复杂目标只建一个 coordinator。断言：没有从 root 直接扇出多个平级 worker 的派发记录。

**SUP-3.6 不谎称并行** — Muse 依据：Morde 自研（TODO 03 原文：Broker 请求仍串行）。操作：派两个独立外部工具调用，检查 Broker 执行记录。断言：如实现仍为串行，文档与状态如实写“串行”，不得宣称“已并行”；并行化完成前，本用例保持待验证，不许用模型回合重叠冒充工具并行。

## SUP-4 工具执行与工作项

**SUP-4.1 任一工具调用点开详情，七要素齐全** — Muse 依据：已证实，report 结构固定（在哪执行 + 完整命令 / 参数原文 + 退出码 + 耗时毫秒 + 工作目录 + 输出原文 + 一句人话结论）。操作：在实际 morde-pc 点开一次文件写、一次终端命令、一次模拟失败的工作项。断言：七要素缺一不可；长输出截断并注明截了多少行；不适用的字段明确标注“不适用”，不留空。对应 TODO M04-02/03（M04-03 代码完成，客户端待验）。

**SUP-4.2 失败步骤保留不删不改写** — Muse 依据：已证实，failed 214 条（1.3%）全部保留，任务没有因此停下。操作：一个任务里先让 `ls` 之类调用失败（退出码非 0），再继续完成任务。断言：失败步骤原样留在清单里；后续成功步骤与失败步骤并存；任务 finish_status 按最终结果定，不因单步失败直接判 failed。

**SUP-4.3 取消是常规终态** — Muse 依据：已证实，cancelled 96 项是常规终态。操作：执行中取消一个任务。断言：状态为 `cancelled`，不是 `failed`；已确认的副作用不重放；取消事件进账本。

**SUP-4.4 未知结果不显示输出、不自动重放** — Muse 依据：Morde 自研（M04-01/04）。操作：构造回执丢失的工具调用。断言：步骤保持 `unknown`，详情隐藏输出；不自动重放；先对账（Broker.Reconcile），确认未派发才可结算取消。

**SUP-4.5 大输出预览 + 编号取回** — Muse 依据：Morde 自研（M04-03：详情加密明文最多 256 KiB，PC/iOS 默认显示 2,000 字符预览）。操作：一次输出超 64 KiB 的工具调用。断言：详情显示预览 + 截断字节数 + 安全回查方式；展开最多显示每路 64 KiB 已记录内容；Runtime 截断与详情容量截断分别记录。

**SUP-4.6 工作项 id 前缀即归属** — Muse 依据：已证实（`root-tool-…` / `root-subagent-dispatch-…` / `subagent-start-…` / `child-tool-…` / `subagent-finish-…`）。操作：检查一次多 agent 任务的全部工作项 id。断言：前缀与归属一致；仅凭 id 就能分清是谁干的活。

## SUP-5 审批

**SUP-5.1 审批卡面六项齐全** — Muse 依据：已证实（卡片制）；卡面字段未知（U8），Morde 自研补齐。操作：在实际 morde-pc 触发一次敏感操作（shell / 浏览器输入 / 外部 MCP 写）。断言：卡面同时有待批动作、证据指针、本次成本、累计成本、触发规则、拒绝后果；缺成本数时明确显示“未知”，不显示 0。对应 TODO M05-03（披露层已有，见缺口文档 05 节）。

**SUP-5.2 成本数字与账单对得上** — Muse 依据：Morde 自研（成本事实来源是 `model_call_ledger`）。操作：批一次带成本的动作，事后核对卡面数字与账本。断言：本次成本与累计成本与 `model_call_ledger` 一致；对不上的差额进告警，不静默抹掉。

**SUP-5.3 不可逆动作每次都出卡** — Muse 依据：已证实（购买每次新批，永无 lasting 默认；发帖每次批）。操作：连续两次做同一不可逆动作（发消息 / 发帖 / 购买）。断言：第二次仍出新卡，不复用第一次的批准；`always` 档位只对写操作开放，不可逆永远逐次批。

**SUP-5.4 批准绑定修订、CallID 与请求哈希** — Muse 依据：Morde 自研（M05-01/04）。操作：批准后、派发前改一次参数 / 修订 / 目标。断言：旧批准失效，必须重新批准；重复响应不得重复执行（幂等键）。

**SUP-5.5 拒绝不执行，且 Agent 要消化拒绝** — Muse 依据：已证实（拒绝或未确认不执行）。操作：在实际 morde-pc 点“拒绝”。断言：操作不派发；Task 不进入“已完成”；Agent 给出后续处理（不是静默卡住）。注：TODO 05 原文——PC fixture 不模拟 Agent 消化拒绝后的回复，本用例要求补这一环。

**SUP-5.6 审批不等于完成** — Muse 依据：已证实（批准只代表对本次操作的决定）。操作：批准一次动作，观察任务状态文案。断言：界面文案写“已允许本次操作”，不写“任务已完成”；Task 后续状态按实际执行结果更新。

**SUP-5.7 撤权、过期、超预算都不能继续旧调用** — Muse 依据：Morde 自研（M05-02）。操作：待批期间撤权 / 等批准过期 / 把预算花超。断言：旧调用不能继续；结果未知时不重放；独立 Task 不受影响。

## SUP-6 验证

**SUP-6.1 写后读回，SHA 对得上才算数** — Muse 依据：已证实（read-back 是统一验证模式）。操作：任务写一个文件，验证 worker 读回。断言：整文件 SHA-256 比对通过；模型输入最多 4 KiB 文本预览；正文不持久化。对应 TODO M06-01/02。

**SUP-6.2 旧文件不再冒充 PASS** — Muse 依据：已证实（证据绑定版本）。操作：验证通过后改一次文件内容，再查验证状态。断言：验证状态回到 `pending`；旧 PASS 不复用；任务详情与原会话的验证状态同步剔除失效证据。对应 TODO M06-03。

**SUP-6.3 审批覆盖 unknown 时验证不得给 PASS** — Muse 依据：Morde 自研（M06-03）。操作：构造一次审批覆盖或动作分类未知的副作用，跑验证。断言：验证保持 `pending/unknown`；不能仅凭已批准记录、目标授权或验证模型自述标为 PASS。注：TODO 06 原文——这条还没有回归用例，本用例就是补它。

**SUP-6.4 错误内容要被指出，不是只看文件存在** — Muse 依据：已证实（checking worker 标无支撑断言）。操作：用正确内容、错误内容、仅元数据三类合成 Task 跑验证。断言：错误内容判 FAIL 并指出差异；仅元数据（哈希、二进制、截断预览）判 pending，不能支持通过；大于预览上限的内容保持待验证。对应 TODO M06-02（PC 验收待做）。

**SUP-6.5 复核独立于执行** — Muse 依据：Morde 自研（纠正后：家族不同是建议，不是 Muse 证据）。操作：检查一次验证复核的会话与证据。断言：复核用独立的 `task_validation_review` 会话，不复用执行会话；只读受 claim 约束的证据；verdict 锁版本——版本一变旧 verdict 作废重验。家族不同只记为加分项，不作为通过 / 拒绝的硬条件。

**SUP-6.6 覆盖率要报数** — Muse 依据：已证实（wide-research 必须报 verified coverage `success_count/total`，区分 pending / failed / stopped / never-started）。操作：一次多项核查任务结束，检查验证报告。断言：报告含已验证数 / 总数与四类状态分布；没有“全部通过”的笼统结论。

## SUP-7 交付与提问

**SUP-7.1 主对话只出最终结果 + 要点** — Muse 依据：已证实（assistant 回复中位 142–160 字符；一次 morde 任务 54 条工作项全在任务详情里，主对话只有“图正在画”和最后交付）。操作：跑一次多步骤任务，看主对话。断言：主对话只有进度提示与最终交付；要点贴在消息里，不只给链接；过程噪音全在任务详情。对应 TODO M07-01/03（全未开始）。

**SUP-7.2 批准 / 拒绝只代表决定，不代表完成** — Muse 依据：Morde 自研（M07-01 合同）。操作：批准一次动作后立即看主对话文案。断言：文案不把“已允许”写成“已完成”；审批覆盖未知、已拒绝 / 过期、执行结果未知或验证待定时，如实呈现，不认定通过。

**SUP-7.3 交付幂等，不重复副作用** — Muse 依据：Morde 自研（M07-02）。操作：结果生成与提交之间插入同一任务的补充；完成后重复刷新。断言：旧结果不覆盖新要求；相同结果只在发起会话发布一次；重启后不重复交付。对应 TODO M07-02（全未开始）。

**SUP-7.4 提问只在阻塞或需拍板时，载体是选项卡** — Muse 依据：已证实（提问率 6.8%）。操作：跑一次需要用户决定的任务。断言：提问出现在阻塞或需拍板时；点选后行为立即生效；含糊指令先问清，不猜。对应 TODO M07-03。

**SUP-7.5 离线不取消已受理任务** — Muse 依据：Morde 自研（M07-04）。操作：执行期间关闭并重连实际 morde-pc。断言：同一会话显示真实进度及结果；原始消息、任务状态和回执持久化；恢复不重复交付。

## SUP-8 记忆与纠正沉淀

**SUP-8.1 纠正后新值胜出，旧值标被替代** — Muse 依据：已证实（纠正留痕，`supersedes:` 字段；新 claim 覆盖旧 claim）。操作：用户更正一条偏好（例如“以后周五不安排会”），新开会话再问相关事。断言：新会话按授权读取新值；历史能识别旧值已被替代；别的账号看不到。对应 TODO M08-02（全未开始）。

**SUP-8.2 单次随口纠正不能变成越权命令** — Muse 依据：Morde 自研（M08-03 验收核心）。操作：随口说一句纠正，不经过验证与授权，看它会不会变成可复用规则。断言：不变成规则；获授权且经验证的规则才可复用；有冲突时询问用户。

**SUP-8.3 事实、偏好、规则分开存** — Muse 依据：已证实（记忆分层；历史事实、用户偏好、可执行规则应区分）。操作：检查一次记忆写入的分类。断言：事实、偏好、规则三类分开；规则执行前核验来源、授权和适用范围。

**SUP-8.4 遗忘要确认范围，索引不再召回** — Muse 依据：已证实（遗忘正式流程：展示范围 → 一次直接确认 → 执行；沉默 / 含糊 = 未确认）。操作：用户要求遗忘一段记忆。断言：先展示范围并一次直接确认才处理；索引不再召回已遗忘内容；未确认或部分失败时真实提示，不误删其他人的内容。对应 TODO M08-04（全未开始）。

**SUP-8.5 记忆同步不阻塞对话** — Muse 依据：Morde 自研。操作：记忆整理进行时发一条新消息。断言：对话正常回复，不等待整理完成；整理在后台串行跑。

## SUP-9 失败、限流与恢复

**SUP-9.1 失败留在任务详情，主对话只给简短状态** — Muse 依据：已证实（失败 214 条全保留，主对话不受污染）。操作：一次工具调用失败，看主对话与任务详情。断言：详情有失败步骤与原因码；主对话只有简短状态或必要的用户操作提示，不透出原始 Provider 错误、堆栈或凭据。对应 TODO M09-01。

**SUP-9.2 `terminal_for_attempt` 当次终止，不绕过** — Muse 依据：已证实（只认 `isError` + `code=connector_rate_limited` + `terminal_for_attempt=true` + 整数 `retry_after_seconds` 1–86400 四条件同时满足）。操作：触发一次结构化限流终止。断言：当次连接器工作立即终止；不睡眠重试、不委派、不换动作绕过、不按 `retry_after_seconds` 自动重排；普通 `isError` 不触发终止。对应 TODO M09-02。

**SUP-9.3 超 24 小时等待结束当前尝试，不截短重派** — Muse 依据：Morde 自研（M09-05）。操作：模拟 48 小时 `Retry-After` 与未来 HTTP 日期。断言：当前路由尝试写为失败；新 Worker 启动后不再领取该路由；PC/iOS 显示失败并提供显式重处理入口；点击后旧消息保留，同键重放不重复排队。

**SUP-9.4 未知结果先对账，不重放、不释放预算** — Muse 依据：Morde 自研（M09-03）。操作：模拟操作已成功但回执丢失、模型用量未知、对账失败三种情况。断言：前两者经账本确认后只结算一次；无法确认时明确等待且不产生第二次副作用 / 模型请求；`unknown` 期间预算预留保持。注：丢回执 Broker 用例与 PostgreSQL MCP ledger 用例尚未合并验证，本用例要求合并后验收。

**SUP-9.5 显式重试复用原消息，不绕过任务级对账** — Muse 依据：Morde 自研（M09-02/06）。操作：在实际 morde-pc 点一次失败消息的“重新处理”。断言：服务端复用原消息；同一幂等键重放不创建第二次尝试，新键递增 `route_attempt`；Task 已创建或调用 / 副作用未知时，路由入口不可绕过任务级对账。

**SUP-9.6 `waiting_user` 不是失败** — Muse 依据：已证实（审批、澄清和用户操作等待不应归成失败）。操作：一个任务在等审批时看 PC 与 iOS 状态。断言：两端都不显示“失败”；审批任务不显示失败，用户批准后只执行一次；中断回复保留已生成部分并标 `interrupted`，不冒充完整回复。对应 TODO M09-04。

## SUP-10 上下文管理

**SUP-10.1 跨过触发线的会话实际产出摘要版本** — Muse 依据：Morde 自研（触发条件：未覆盖源字节 ≥72 KiB 或 token 压力 ≥ 预算 3/4；摘要 ≤16 KiB）。操作：构造一个累计历史超过触发线的真实会话，等一次摘要维护。断言：`conversation_summary_versions` 增加；新摘要 ≤16 KiB；旧摘要文本 + 去掉已被摘要覆盖的历史行。注意：小会话本来就不会触发，不得以“版本数仍为 0”直接判管线坏；本用例只验收跨过触发线的会话。对应缺口文档 10 节的 live 矛盾。

**SUP-10.2 摘要失败有冷却，不再每条消息重试一次** — Muse 依据：hermes 补齐（失败冷却 600s + terminal 清单）。操作：让一次摘要维护失败，连续发三条消息。断言：冷却期内不再触发摘要派生；terminal 五类失败直接 abort；3 次过载后走确定性 fallback 摘要。对应复刻设计 P1-4。

**SUP-10.3 上下文溢出先压缩重试一次，再失败** — Muse 依据：hermes 补齐。操作：构造一次 provider 报 `context_length_exceeded` 的分类。断言：先触发一次摘要压缩再重试分类，限一次；仍失败才报失败；`context_overflow` 单独分类，不走通用重试 / 换模型。

**SUP-10.4 1 MiB 单条消息：锚点答对且引用页码** — Muse 依据：Morde 自研（M10-03/09 服务端通过，PC 待验）。操作：在实际 morde-pc 发一条 1 MiB 长文，问三个分布在不同页的细节。断言：三个锚点都答对并引用页码；每页 sha256 校验通过；JSON 结果硬上限 20 KiB；损坏页时无部分结果。对应 TODO M10-03/06。

**SUP-10.5 历史搜索只返回有界摘录，不瞎答** — Muse 依据：Morde 自研（M10-02）。操作：问 20 条前的细节。断言：走授权历史搜索，不凭预览编造；返回最多 5 段、每段 ≤600 字符，带全局 rune 范围与页哈希；取不到必要历史时明确说明。对应 TODO M10-02。

**SUP-10.6 `HistoryIncomplete` 诚实标记** — Muse 依据：Morde 自研（M10-01/08）。操作：摘要缺失或来源不可验证时问历史问题。断言：回复明确提示历史不完整、建议按授权检索原文；不把摘要或预览冒充原文。

**SUP-10.7 任务循环 10 轮后不因输出累积撞 128 KiB** — Muse 依据：hermes 补齐（确定性剪枝进任务循环 + 轮首 preflight + turn 后 micro-compact）。操作：跑一个 10 轮以上的长任务。断言：第 10 轮后仍正常推进，不报 `context_length_exceeded`；每轮工具输出有剪枝记录。对应复刻设计 P1-6(e)。注：剪枝只接已有的 `hermes-compaction-window.mjs` 调用点，不重写压缩逻辑。

## SUP-11 Bug 发现与处理

**SUP-11.1 选一个真实缺陷走完四项** — Muse 依据：Morde 自研（M11-01–04 全未开始）。操作：取一个真实发现的缺陷，按“发现并记录现象 → 最小复现 → 确认根因并修复 → 回归与记录”走完。断言：记录含版本、账号 / 会话 / 任务身份、环境、输入顺序、预期与实际结果；另一位开发者能确定受影响步骤与可复现入口；记录不含凭据或外发内容。

**SUP-11.2 单变量对照复现** — Muse 依据：Morde 自研（Bug 3 案例：只改一个变量有无）。操作：复现时每次只改一个变量。断言：修复前最小用例能稳定展示故障；环境受限时写明未验证而非猜测。

**SUP-11.3 回归测试先行才算修完** — Muse 依据：Morde 自研（五步法收尾纪律）。操作：修一个缺陷。断言：新回归测试 PASS 才算修完；同类调用者、隔离与幂等未被破坏；相关测试通过，未能实测的 PC/iOS 或外部环境明确标待验证，不谎称全过。

**SUP-11.4 误诊写进记录，标明被证伪的旧结论** — Muse 依据：Morde 自研（五步法“之前说错的话”一栏）。操作：复盘一次误诊（例如 Bug 3 的 node 路径误诊）。断言：复盘含“之前说错的话”一栏，明确写出被证伪的旧结论；沉淀至少一条 lint / 检查 / skill，防止旧说法复活。
