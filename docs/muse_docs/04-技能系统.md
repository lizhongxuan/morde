# 04 技能系统（Skills）

## 4.1 什么是技能

技能 = **可复现的任务剧本**：某类任务按什么流程走、先调哪个连接器、
用什么工具、结果怎么呈现、错了怎么处理。
技能以 `SKILL.md` 为入口，放在 `/opt/muse/skills/<名字>/`（系统技能，
只读，每次部署会被替换）或 `~/workspace/custom-skills/`（用户自定义技能）。

选用规则（系统指令原文大意）：
1. 请求涉及产品、服务、专业领域或可复用流程时，先找技能/连接器文档，
   再上网搜索或说做不到。
2. 列表里有明显匹配的，读它的 `SKILL.md` 并照做。
3. 几个都可能匹配时，选最具体的，读并照做。
4. 都没有时，用 `muse.skill_search` 找；再没有，就用终端、浏览器
   现找、现装、现建，测通后存为自定义技能。
5. 用户偏好的技能/连接器优先用，除非用户另有要求。

## 4.3 技能的结构（以 app-creation 为例，已验证）

`app-creation/SKILL.md` 的真实结构：

1. **Decide what to build**：先问谁用、要做什么、好结果长什么样；
   先找现有 App/页面/项目，优先扩展，不行再新建；
   按“谁用、是否存数据”选落点：
   - Muse 静态页：可公开分享，每位访客独立运行，输入不保存；
   - Muse 全栈 App：存数据、可刷新实时数据、私有、无公开链接；
   - 托管 builder（Lovable、Replit、Vercel 等）：别人也要用、要存数据、
     要自定义域名、要团队或已有代码库。
   - 公开链接与存数据两者都要时，先讲清取舍，让用户选。
2. **Build it**：按 `~/docs/artifacts.md` 走；改现有工件用 `artifact.edit`；
   要换种类（静态 ↔ 全栈）时新建，数据不迁移。
3. **Check that it works**：按用户的方式走主流程，再走空态、加载态、
   错误态、不同屏幕尺寸、无障碍；构建成功不等于能用，要从运行中的
   App 或已部署的 URL 上确认。
4. **Deliver it**：通过构建完成卡交付；公开分享只在用户明确要求时做，
   给确切 URL；讲清是哪种（私有 App / 公开页 / 托管部署）、是预览还是已发布；
   列出用户还需做的事（接账号、加域名、批准发布）。

这个结构就是全部技能的通用模板：**决策 → 执行 → 验证 → 交付**，
每一步都有“先做什么、用什么工具、错了怎么办”。

## 4.4 技能与连接器的分工

- 技能回答“怎么做这件事”；连接器回答“怎么调这个服务”。
- 例如订机票：`flight-booking` 技能定流程（先查已接机票库存，
  没有或不全时用 Google Flights，用户问时也用；按总价与总时长订），
  `duffel` 连接器提供具体的查、订、取消操作。
- 例如购物：`shopping` 技能定流程（找、比、买、评价），
  `meta_catalog_search` / `shopify-ucp` 等连接器提供商品数据与下单。
- 技能可以调多个连接器；连接器可以被多个技能调。

## 4.5 自定义技能

- 任务可复用、但没有现成技能时，用 `custom_connector_setup` 的模板，
  在 `~/workspace/custom-skills/` 下新建技能。
- 自定义技能与系统技能同等对待；用户偏好的优先用。
- 后台自改进任务也会创建与改进技能（见 08）。
