# 10 数据模型、存储、多端、订阅

## 10.1 数据实体（从全部资料提炼的核心实体）

| 实体 | 关键字段 | 来源 |
|---|---|---|
| 用户 User | 名字、称呼、时区、偏好 | `USER.md`、`MEMORY.md` |
| Agent 身份 | 名字、性格、氛围、签名 emoji | `IDENTITY.md`、`SOUL.md` |
| 对话 Conversation | 主聊天 / side chat、消息、压缩摘要 | 系统指令“Conversation Context” |
| 记忆 Memory | 事实、偏好、决定、承诺、来源、置信度、替换关系 | `MEMORY.md`、`muse.memory_search` |
| 人物 Person | 名字、关系、事实 | `~/memory/people/<名字>.md` |
| 群组 Group | 成员、关系、事实 | `~/memory/groups/<名字>.md` |
| 目标 Goal | slug、描述、状态、GOAL.md、文件 | `~/workspace/goals/<slug>/` |
| 跟踪项 Tracked item | 类型（预约/交付/提醒）、状态、截止、证据 | tracking 系统 |
| 技能 Skill | 名字、描述、SKILL.md、偏好标记 | `/opt/muse/skills/` |
| 连接器 Connector | 名字、文档、连接状态、权限 | `/opt/hatch/connectors/` |
| 工件 Artifact | slug、种类（静态/全栈/文件）、版本、卡片、公开链接 | artifact 系统 |
| 定时任务 Cron | id、标题、周期、owner、状态文件、正文 | cron 系统 |
| 审批 Approval | approval_id、原命令、请求/决定时间、结果、来源 | permissions 系统 |
| 订阅 Subscription | 套餐、用量、token、重置时间 | `subscription-status` 技能 |
| 文件 File | 路径、来源对话、Library 位置 | `~/workspace/` |
| 设备 Device | device_id、类型、命令、位置 | 配对设备系统 |

## 10.2 存储设计

### 文件系统
```
~/
AGENTS.md # 本工作区操作手册（Agent 自己维护）
SOUL.md # 人格与语气
IDENTITY.md # 名字、性格、氛围、emoji
USER.md # 用户：名字、称呼、时区、关心什么
MEMORY.md # 策展长期记忆
PROACTIVE_PREFERENCES.md # 主动提醒偏好
memory/ # 每日日志、人物、群组、bank/index（运行时管理）
workspace/
your_files/ # 给用户看的文件（按任务分子目录）
goals/<slug>/ # 目标：GOAL.md、files/、hidden_files/
downloads/ # 保留的安装包（WeChat.deb、Telegram.tar.xz）
user/ # 用户交给 Agent 保管的东西
system/
system_prompt.md # 主聊天系统提示词副本
docs/ # 产品文档（~/docs/，只读参考）
.ssh/ # SSH 配置与密钥（默认 Ed25519）
```

### 持久化边界（已验证）
- 保留：`~` 下的全部内容（home 目录在 VM 更换后保留）。
- 不保留：`/tmp`（临时）、`/usr/local/bin`、`/etc`、`/root`、`/var`
等系统外路径；系统安装（如 `/usr/bin/wechat`、`/opt/Telegram`）
在 VM 更换后丢失，需用 `~/workspace/downloads/` 里的安装包重装。
- 本用户实例：微信 4.1.13.26.deb（222M）、Telegram tsetup.tar.xz
（83M）均保留在 downloads 里，2026-10-27 至 2026-11-05 多次重装
均用同一安装包，无需重新下载。

### 数据库
- 工件数据库：SQLite（`app.db`），每全栈 App 一个；
表结构用 Drizzle migration（`drizzle/0002_*.sql`）+ `schema.ts` 定义。
- 运行记录数据库：PostgreSQL，可用 `muse.db` 做只读 SQL 查询
（transcript、消息、Agent 执行、工具调用、目标、记忆、定时任务、
Feed/Ideas、工件、设备同步等），见 `muse_db` 技能。
- 记忆索引：`~/memory/bank/` 与 `~/memory/index/` 由运行时管理，
Agent 只读不改。

## 10.4 订阅与商业模式（已验证：docs/muse.md + subscription-status）

- 产品：Muse，Meta 出品；2026-09-08 上线。
- 模型：Muse Spark 1.3（当前对话在跑）、Muse Wonder（2026-10-12 发布，
最强模型，面向个人超级智能与长程多步工作）。
- 套餐：免费（有用量上限）+ 付费月订阅（用量更多）；用量按预定重置日刷新，
不提前重置、不能手动重置；自动按月续订，除非取消。
- 付费套餐跑 Muse Spark 与 Muse Wonder；免费套餐跑 Muse Spark，
部分账号无需付费也可获得 Muse Wonder。
- Muse Wonder 其他渠道：Meta Model API（$0.20/百万缓存输入 token，
$4.00/百万输入 token，$20.00/百万输出 token）；Muse Code 的
Power Usage（$50/月）、Maximum Usage（$200/月）含 Muse Wonder Full。
- 判断用户套餐的唯一依据：`subscription-status` 技能；
绝不用网络搜索代替；说不清时直说查不到，不猜。
- 升级入口：https://muse.ai/subscriptions（仅在用户问如何升级/
如何获得 Muse Wonder、且技能显示无付费套餐或查不到时分享）。

## 10.5 商业模式设计要点（从产品形态反推，标的部分已注明）

- 收入来自订阅，不是按任务、按 token 向用户另收费；
钱包（Shop Pay / Stripe Link）是用户在外部商家结账用的，
与 Muse 订阅无关。
- 成本结构：模型调用 + 每人一台 VM + 浏览器 + 存储；
免费套餐的用量上限即成本控制手段。
- 护城河：记忆 + 目标 + 文件 + 工件的沉淀（换 Agent 即丢失
上下文），而非单一功能。
