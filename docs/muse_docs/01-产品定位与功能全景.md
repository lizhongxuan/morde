# 01 产品定位与功能全景

## 1.1 产品定位

Muse = **Meta 的个人 AI Agent**。官方定义（`docs/muse.md` 原文大意）：
每位用户拥有一台自己的专属电脑，上面跑着一个只属于他一个人的 Agent；
Agent 在 Web、iOS、Android、Mac 应用里与用户对话，帮用户完成跨应用、
跨设备的长期任务。

定位的三句硬话：

1. **严格个人化**：每个对话都是一位用户与他自己的 Agent 之间进行，
   应用内没有群聊、没有共享对话、没有“其他人”功能。
   别人做的 3D 办公室 Space（Agent Office）是用户自己建的网页，
   不是 Muse 的原生团队功能——这一点在 2026-11-07 已向用户澄清过。
2. **Agent 不是聊天机器人**：它有电脑、有浏览器、有文件系统、有日程、
   有记忆、有目标，能把一件事做完并把产出物留下来，而不是只给一段文字。
3. **模型是底座，不是产品**：Muse Spark / Muse Wonder 是模型家族，
   产品是“模型 + 电脑 + 技能 + 连接器 + 审批 + 记忆”整套。

## 1.2 面向谁

- 已验证（文档）：美国、加拿大、日本、新加坡的用户；iOS App Store、
  Android Google Play、Mac 应用、Web（muse.ai）均可下载。
- 使用场景（从技能与连接器反推）：个人日常（提醒、日程、邮件、购物）、
  出行（机票、酒店、租车、行程）、工作（文档、会议、任务、财务）、
  健康（运动、睡眠、体检）、创作（图片、视频、播客、文档）。
- 不面向（文档明确）：团队协作、多人共享、群聊管理。

## 1.3 功能全景（按系统分组，共 10 组）

### A. 对话与理解
- 多轮对话、语音对话（voice.md：语音、听写、语音消息）、
  语音选择（用户可换声音；本用户已定“声音 1、说中文”）、
  消息通道：主应用 + WhatsApp（`chat-connections/whatsapp.md`）。
- 语言：按用户使用的语言与文字回复；本用户用简体中文。

### B. 记忆与个性化
- 长期记忆 `MEMORY.md` + 每日日志 `~/memory/` + 人物 `~/memory/people/` +
  群组 `~/memory/groups/` + 目标与偏好。
- 记忆是“ durable understanding ”：谁、关心什么、偏好、决定、承诺、
  已验证的结果；不是逐字 transcript，不是交易流水。
- 背景自改进：定期维护记忆、校准与用户的关系、生成帮助用户的想法、
  跟踪目标进度、创建/改进技能与连接器文档（`docs/self_improvement.md`）。
- 遗忘：用户明确要求忘记的信息，要从记忆及其副本、衍生品、
  未来可能带回它的生产者里清除（`forget` 技能）。

### C. 目标（Goals）
- 持久目标：每个目标有独立工作区 `~/workspace/goals/<slug>/`、
  `GOAL.md`、文件与隐藏文件；目标有活跃/完成状态，无暂停态。
- 跟踪项（tracking）：预约、交付、提醒、进行中的项目等具体承诺，
  完成后要关闭，不能因一步成功就标记整个目标完成。
- 主动性：背景系统按目标、日程、记忆生成建议与更新。

### D. 电脑与浏览器
- 每人一台 Linux 云端电脑（VM）：终端、文件系统、互联网访问、
  真实 Chromium 浏览器（保留 cookies、标签页、会话状态）。
- 浏览器可登录、填表、走 JS、处理验证码与机器人检查（按浏览器自身的
  挑战与恢复规则）；用户可随时观看或接管实时会话。
- 设备：配对手机（本用户配对一台 iPhone）、Home Link 家庭网络桥
  （`docs/devices/home_link.md`）、Tailscale（`docs/devices/tailscale.md`）。

### E. 技能（56 个，详见 04）
- 可复现的任务剧本：订机票/酒店、订餐、购物、找地方、管邮件日历、
  跟进会议、记账、做文档、健身、翻译、管任务、发社交媒体、开小店等。
- 技能先于通用搜索：有技能先读技能，再决定用哪个连接器或浏览器。

### F. 连接器（79 个，详见 05）
- Gmail、Google 日历/文档/云盘、Duffel 机票、Spotify、Instagram/
  Facebook/Threads/Messenger、Shopify、Stripe、Plaid、Ticketmaster、
  Shop Pay / Stripe Link 钱包等。
- 每个连接器有自己的 `CONNECTOR.md`：怎么连接、支持哪些操作、
  结果与错误怎么处理。使用前先读当前文档、跑状态检查；
  未连接时分享连接链接，不承诺结果。

### G. 工件与 Space（详见 07）
- 工件（artifact）：网页/应用、文档、PDF、演示文稿、电子表格。
- Space = 工件中的网页/应用的新名字，长在 Muse 应用的 Library 或侧边栏，
  没有独立 App。静态 Space 可经用户批准分享为公开链接；
  能存数据的交互型 Space 不能公开，只能在 Muse 内使用。
- Feed：个人报纸，短篇编辑帖，按固定排期由 Agent 在后台写。
- Ideas：想法卡片，用户点一个就开工。

### H. 定时与后台（详见 08）
- cron：按时钟跑的定时任务、提醒、定期检查。
- hooks：按事件触发的轻量脚本，条件满足时唤醒 Agent。
- systemd 服务：需持续运行的程序（流监听、指标收集、本地服务）。
- 后台自改进：定期维护记忆、关系、目标、技能。

### I. 审批、权限与安全（详见 09）
- 审批卡：敏感/不可逆操作先经用户批准，卡片上写清批什么。
- Secure Vault：密码、API 密钥等凭据的安全录入与存储，
  不在聊天里明文出现，不记入记忆与普通文件。
- 钱包：Shop Pay / Stripe Link，支付前经用户批准，可选支付方式。
- 隐私：数据收集、使用、查看、训练 opt-out、导出等
  （`docs/data-handling.md`、`docs/privacy-and-credentials.md`）。

### J. 媒体与文件
- 生成图片、视频、音频（TTS、播客）；视频每条用户消息限 6 条。
- 文件：附件上传、浏览器下载、系统文件、Library；
  用户的文件可导出，导出内容见 `docs/privacy-and-credentials.md`。

## 1.4 与竞品的区别（基于 2026-11-08 的竞品对比研究）

| 维度 | Meta Muse | OpenMausBot（开源） | Morde（用户项目，未建成） |
|---|---|---|---|
| 定位 | 一人一机的个人 Agent | 聊天应用里的一队 Bot | 个人 Agent + 场景定制 + 钩子（设计中） |
| 电脑 | Meta 云端 Secure VM，每人一台 | 主要跑在用户本地电脑 | 云端电脑为主（设计） |
| 模型 | Muse Spark / Wonder | Claude / Codex / Grok（自带登录） | DSH 运行时派发 Codex/Claude（未定） |
| 审批 | Sentinel 独立权限方 | 权限 broker，inline 卡片 | 审批卡 + 事件链（设计） |
| 手机 | 原生应用 | MausBot 伴侣应用（需电脑开机） | nanoMuse iOS（代码已对接，未验证运行） |
| 团队 | 无 | 部门文件分享 | 团队交付层（已降为非主定位） |

结论：Muse 与竞品表面像（一句话进来、Agent 干活、敏感操作先问人），
分界在“为谁干活、电脑归谁、审批归谁”。Muse 的答案是：
为一个人干活、电脑归这个人、审批归这个人。

## 1.5 明确不做的事（文档与行为共同证明）

- 不做群聊、团队席位、共享对话。
- 不远程操控用户 iPhone 里的任意 App、不直接读手机微信。
- 不用非官方办法绕过登录或验证；账号问题用用户已有账号处理，不新注册。
- 不在未确认的情况下发送消息、下单、付款、领券。
- 不把模拟、演示数据说成真实结果；不把助手提议说成用户决定。
