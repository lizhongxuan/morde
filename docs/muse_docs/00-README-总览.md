## 一句话定位

Muse 是 Meta 的个人 AI Agent 产品（2026-09-08 上线，美国、加拿大、日本、新加坡可用）。
每位用户拥有一台**专属云端电脑**，上面跑着一个**只属于他一个人的 Agent**；
Agent 用一句话入口接活，用技能、连接器、浏览器、子 Agent 去干活，
敏感操作先经用户批准，结果沉淀为文件、工件、目标和记忆。
产品形态是“对话 + 电脑 + 工具”，不是“聊天框 + 插件”。

## 设计总原则（从全部资料里提炼出的 7 条）

1. **一人一机**：严格个人化，没有群聊、没有共享对话、没有团队席位。
每个用户的对话、文件、记忆、目标、订阅都是隔离的。
2. **一句话入口**：用户只说要什么，剩下的系统兜底——拆任务、选工具、
选模型、处理异常、回填进度。用户不应该先选技能、再选模型、再填表单。
3. **电脑是本体**：Agent 不是无状态的问答机，它有一台持久的 Linux 电脑
（文件系统 `~/workspace`、SQLite、home 目录在 VM 更换后仍保留），
产出物落在电脑上，而不是只落在聊天记录里。
4. **技能是剧本，连接器是插头**：技能（Skill）规定“某类任务按什么流程走”，
连接器（Connector）规定“怎么接某个外部服务、能调什么方法”。
两者分离：换一个服务不用重写流程，换一个流程不用重接服务。
5. **子 Agent 是执行单元**：主 Agent 负责理解、拆解、验收；
具体的长任务派给子 Agent 在后台跑，主 Agent 保持对用户响应。
6. **先验证，再交付**：写完、测、改、再测。探针断言真实标识符、
真实调用一次后端、审计一致性，全部通过才把卡片发给用户。
一次写对不是设计目标，可验证才是。
7. **批准是安全边界**：发消息、下单、付款、领券、删数据、对外发布等
不可逆操作，必须先经用户确认具体方案。Agent 不能替用户拍板花钱、
不能替用户对外承诺。

## 系统分层总图（文字版，图见《Muse 架构与工作流程图》Space）

```
┌────────────────────────────────────────────────────────────┐
│ 入口层：iOS / Android / Mac / Web 应用、WhatsApp 消息通道 │
├────────────────────────────────────────────────────────────┤
│ 主 Agent 层：Muse Spark 1.3（付费为 Muse Wonder） │
│ 记忆 MEMORY.md / 每日日志 / 人物与群组 / 目标 Goals / Feed / │
│ Ideas / Library │
├────────────────────────────────────────────────────────────┤
│ 能力层：56 个技能 Skills ＋ 79 个连接器 Connectors ＋ │
│ 真实 Chromium 浏览器 ＋ 配对设备 ＋ 钱包（Shop Pay / Stripe Link）│
├────────────────────────────────────────────────────────────┤
│ 执行层：子 Agent（subagent）＋ 定时任务 cron ＋ hooks ＋ │
│ 后台任务（background work） │
├────────────────────────────────────────────────────────────┤
│ 底座层：每人一台专属云端电脑（Linux VM、~/workspace、SQLite、 │
│ 持久化 home 目录）＋ 审批卡 / 权限 ＋ 安全 vault │
└────────────────────────────────────────────────────────────┘
```

数据流（正常一次请求）：
用户一句话 → 主 Agent 理解并拆解 → 选技能/连接器/工具 →
派子 Agent 或直接执行 → 工具结果回填 → 主 Agent 验收/审计 →
敏感步骤弹审批卡 → 用户批准 → 交付（文件/工件/消息/提醒）→
写入记忆、目标、日志，沉淀下来。
