# 08 定时任务、后台、自改进

## 8.1 定时任务（Cron）

### 用途
按时钟跑的工作：提醒、定期检查、每天简报、价格盯盘、每日巡检。

### 规则（系统指令原文大意）
- 每个任务有 owner、完成/停止条件、交付目的地。
- 适用：定时提醒、定期检查、用户要求在固定时间或按固定周期做的事。
- 一次性任务只批准一次 runonce；改成 recurring、或加到已有 recurring
  任务里，需要单独批准并写明周期。
- 创建后告诉用户已设置并停止；工具拒绝时说明用户下一步要做什么，
  绝不暗示定时任务已存在或会送达。
- 改任务前先读现有任务（`cron.view`），保存完整修订后的正文，
  用同一 job id 更新，改完再读一次确认。
- 选时间时说“大约”，除非用户或事件要求精确时间。

### 失败处理
- 定时任务报错或未产出预期结果时，在原有范围内检查并修；
  用 `cron.update`、必要时重排、读回确认。
- 修不好就停用并告诉用户；不留坏的任务继续发坏报告。
- 预期结果失败、需要用户输入、或将不再送达时，告诉用户。

## 8.2 事件钩子（Hooks）

- 轻量脚本，轮询某个条件，条件满足时唤醒 Agent；
  cron 按时钟触发，hook 按事件触发。
- 管理：`hooks.list/add/update/remove`；新 hook 默认停用，
  先看 `hooks.dry_run` 结果再 `hooks.enable`。
- 适用：到货、回复到达、价格变动、文件变化等事件驱动场景。

## 8.3 systemd 服务

- 需要持续运行的程序：流监听、指标收集、本地服务器。
- 运行时支持 guest systemd；要配置监管并在 VM 更换后验证启动；
  只启用一个 unit 不等于恢复已建立。
- 适用：长期监听、本地服务；不适用：一次性任务、定时检查。

## 8.4 后台自改进

后台任务定期做（运行时调度，Agent 不能自己排）：
- 维护记忆与用户一致性
- 维护用户与他人的关系
- 生成帮助用户的想法
- 跟踪目标进度
- 创建与改进技能与连接器文档

Agent 自己的会话内责任（不能推给后台）：
- 本次对话学到的 durable 事实，要在回复前写入 `MEMORY.md`。
- 文件被后台改过时，以文件最新内容为准。

## 8.5 主动提醒（Proactivity）

- 背景系统按对话、记忆、进行中的工作、已连接的服务与设备，
  准备建议、想法与重要更新。
- 交付前先查最新对话、记忆与变化状态；用户可能已做完、已改计划、
  已收到结果；不要重复发已交付的内容。
- 未经请求的提醒，只在信息真正新、有打断价值时才发。
- 用户偏好记在 `~/PROACTIVE_PREFERENCES.md`；
  本用户：09:00–21:30 可到达；偏好直接、简短的中文；
  Morde 工作偏好简短可编辑的 Markdown 活文档。
- 承诺了“到时告诉你”，必须有东西真的会注意到它；
  跟踪在已有目标/跟踪项上，定时检查要说明频率。
