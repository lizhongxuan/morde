# 02 系统架构总图

## 2.1 五层架构（已验证：docs + 实际构建日志）

```
┌──────────────────────────────────────────────────────────────────┐
│ L1 入口层 │
│ iOS App / Android App / Mac App / Web (muse.ai) / WhatsApp │
│ 语音通话、文字聊天、文件上传、位置、语音消息 │
├──────────────────────────────────────────────────────────────────┤
│ L2 主 Agent 层 │
│ 模型：Muse Spark 1.3（当前对话） / Muse Wonder（付费更强） │
│ 记忆：MEMORY.md + ~/memory/ + 人物/群组 + 偏好 │
│ 目标：Goals + tracking（预约/交付/提醒） │
│ 内容：Feed（个人报纸）/ Ideas（想法卡）/ Library（文件与工件） │
│ 身份：SOUL.md（人格）/ IDENTITY.md（名字与形象）/ USER.md（用户） │
├──────────────────────────────────────────────────────────────────┤
│ L3 能力层 │
│ 技能 Skills：56 个（见 04） │
│ 连接器 Connectors：79 个（见 05） │
│ 浏览器：真实 Chromium（云端 + Chrome 扩展 + 应用内浏览器） │
│ 设备：配对手机、Home Link、Tailscale │
│ 钱包：Shop Pay / Stripe Link（支付方式、地址、审批） │
│ 媒体：图片 / 视频 / 音频生成 │
├──────────────────────────────────────────────────────────────────┤
│ L4 执行层 │
│ 子 Agent（subagent.spawn / list / send / resume / close） │
│ 浏览器任务（browser.browse，独立窗口，一次一个结账） │
│ 定时任务 cron / 事件 hooks / systemd 服务 │
│ 后台自改进任务（记忆维护、目标跟踪、技能改进） │
├──────────────────────────────────────────────────────────────────┤
│ L5 底座层 │
│ 每人一台专属 Linux VM：终端、文件系统、互联网 │
│ home 目录持久化（~/workspace、~/memory、~/.ssh 保留； │
│ /tmp、/usr/local/bin 等系统外路径不保留） │
│ 数据库：SQLite（工件 app.db）、PostgreSQL（运行记录，muse.db） │
│ 审批卡 / 权限 / Secure Vault / 审计 │
└──────────────────────────────────────────────────────────────────┘
```

## 2.2 层间接口（每层只通过规定的接口调下一层）

| 调用方 → 被调用方 | 接口 | 约束 |
|---|---|---|
| 用户 → 主 Agent | 聊天消息、语音、文件、位置 | 一句话入口；用户不选工具 |
| 主 Agent → 技能 | 读 `SKILL.md`，按技能流程走 | 有技能先读技能，再搜通用方案 |
| 主 Agent → 连接器 | 读 `CONNECTOR.md`，跑状态检查 | 未连接先分享连接链接，不承诺结果 |
| 主 Agent → 子 Agent | `subagent.spawn` + 简短任务书 | 子 Agent 继承当前上下文；结果异步回传，不轮询 |
| 主 Agent → 浏览器 | `browser.browse`（task_id:new 或已有） | 自包含任务书；一个窗口一次一个结账；不同站点开不同窗口 |
| 主 Agent → 定时任务 | `cron.add/list/update/remove` | 每个任务有 owner、完成/停止条件、交付目的地 |
| 子 Agent → 工具 | 与主 Agent 同一套工具 | 不能绕过审批；不能做浏览器任务（应交回主 Agent） |
| 工件 → 数据库 | 服务端 actions + Drizzle/SQLite | 静态页无数据库；全栈 App 绑 `app.db` |
| 全部 → 审批 | 审批卡（approval card） | 敏感/不可逆操作先批后做；批复只覆盖当时批准的内容 |

## 2.3 一次完整请求的数据流（已验证：投资空间构建日志）

以“做一个投资空间”为例，实际发生的步骤：

1. 用户一句话：“我想创建一个关于投资的空间……”
2. 主 Agent 判型：要存自选、每天刷新 → 走全栈 App（不是静态页）。
3. 主 Agent 派子 Agent（builder）建 App，任务书里写明：原话、名字、
能力（public_web_read）、刷新触发（每天早上）。
4. Builder 写代码：
- `drizzle/0002_market_tables.sql` + `server/src/schema.ts`（3 张表）
- `server/src/actions.ts`（抓行情、算信号、生成简报、加自选）
- `client/src/App.tsx` + `theme.css`（行情板、信号台、事件课、大佬动态）
- 构建并绑定 `SQLite app.db`。
5. Builder 自测：
- 写探针 `tmp/probe4.ts` / `probe-ctx.js`，断言 600183.SS、300750.SZ、SPY 真在页面上；
- 真实调用一次后端动作，抓到 16 个标的的真实价格/涨跌/日线；
- 算出茅台 RSI 72、创业板 RSI 16，与原始日线一致。
6. 审计抓错并改：第一版简报方向与行情板矛盾 → 给简报任务加口径纪律
（先读行情板、方向必须一致、引用旧报道须点明日期）→ 重新生成，对齐。
7. 装定时任务：每天 08:30 自动刷新，`cron.status` 确认启用。
8. 交付：把构建完成卡发给用户，主 Agent 用一句话讲清里面有什么、
哪个数据较旧（SPX 与黄金源时间戳为 11/5，已标注）、信号仅供参考。

## 2.4 关键设计决策（每条都有出处）

1. **一句话入口，系统兜底**：用户不选技能、不选模型、不填表单。
出处：`docs/muse.md` + 全部技能的“先读技能”规则 + 本次对话的
Morde UX 复核结论（Muse 的标准是“进来就能说一句话，剩下的系统兜底”）。
2. **主从分离**：主 Agent 保持对用户响应，长任务交给子 Agent 后台跑；
结果异步回传，主 Agent 不轮询、不预测完成时间。
出处：系统指令“Subagents”一节 + 构建日志（异步派发、结果自动回传）。
3. **静态 vs 全栈二分**：不存数据 → 静态页（可公开分享）；
存数据 / 刷新 / 调模型 → 全栈 App（私有，无公开链接）。
两者不可互相转换，数据不迁移。出处：`docs/artifacts.md`、
`docs/spaces.md`、app-creation 技能。
4. **验证门禁**：构建完成 ≠ 可用。必须经过探针 + 真实调用 + 审计，
全部通过才交付。出处：投资空间、抖音空间、产品雷达、牙科空间的
四次构建验证记录。
5. **审批只覆盖当时批准的内容**：批准一个动作，不等于批准一类动作；
内容变了要重新展示、重新批准。出处：系统指令“Purchases and Payments”、
“Secure Vault”各节。
6. **持久化边界**：`~` 保留，`/tmp` 与系统路径不保留；VM 更换后
系统安装丢失，但 `~/workspace/downloads/` 里的安装包保留。
出处：系统指令“Filesystem”一节 + 本次对话的微信/Telegram 安装记录
（2026-10-27 至 2026-11-05 多次因 VM 更换丢失安装）。

## 2.5 故障模式与恢复（已验证的行为）

| 故障 | 表现 | 设计上的处理 |
|---|---|---|
| 子 Agent 慢/卡住 | 长时间无活动 | 不关闭、不轮询；用户问进度时查一次 `subagent.list`，只报观察到的状态 |
| 浏览器任务被验证墙挡住 | 验证码、登录墙 | 浏览器自己尝试通过；实在过不去用替代站点或请用户接管；不说“做不到”就停 |
| 工具调用失败 | 返回错误 | 报失败的步骤和下一步可用动作；不把失败说成“不存在”；不可逆操作先查实际结果再决定是否重试 |
| 定时任务失败 | 简报未生成、价格未更新 | 查保存的状态、日志与最近输出再修；在原有范围内修；修不好就停用并告诉用户，不留坏的定时任务继续发 |
| VM 更换/重启 | 进程被杀、系统安装丢失 | home 目录保留；后台任务由运行时恢复；自定义进程靠自己的启动配置，不靠“装过一次” |
| 审批被拒/过期 | 动作未执行 | 尊重用户决定；不绕过、不重复申请同一权限 |

## 2.6 规模与性能（已验证的数字，未验证的不写）

- 已验证：一次构建约 10–20 分钟（含自测与审计）；投资空间 16 个标的
一次抓全；产品雷达一次刷新新增 52 条信号；牙科空间全闭环 7 步
（建病例 → 切片组 → 上传 → 临床表单 → AI 初诊 → 医生定稿 → 患者讲解）。
