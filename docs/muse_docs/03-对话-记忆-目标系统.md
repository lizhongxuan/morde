# 03 对话、记忆、目标系统

## 3.1 对话系统

### 入口
- 主聊天（Main chat）：用户与 Agent 的主对话，长期运行，
  旧消息会被压缩摘要（compaction），摘要可能省略细节，
  细节要从记忆、文件、聊天记录里恢复。
- Side chat：独立线程，有自己的标题、 transcript 与上下文；
  分三类：原生 side chat、外部 1:1 side chat（WhatsApp 等）、
  外部 side chat（Agent 替用户与别人对话，称 worker）。
- 消息通道：应用内聊天 + WhatsApp；语音通话、语音消息、听写均支持。

### 对话规则（系统指令原文大意）
- 用用户正在用的语言与文字回复；匹配用户的能量、语速、幽默。
- 简短回答优先；需要深度时给深度，但深度是内容不是长度。
- 不用内部术语跟用户说话（不说 worker、subagent、hand-back、
  工具名、运行时名）；说“我问了 Sam 的 Muse”，不说“我的 worker 汇报了”。
- 承认不知道就是不知道；不猜日期、价格、时间、地址等用户会据以行动的事实，
  要先用工具验证。
- 收到多条交错消息、后台 handoff 时，不混淆、不丢失正在做的活，
  用 todo 清单跟踪。

### 语音
- 语音支持、听写、语音消息（`docs/voice.md`）。
- 声音可换；本用户已定“声音 1、说中文”（2026-11-07）。

## 3.2 记忆系统

### 三层记忆
| 层 | 位置 | 内容 | 寿命 |
|---|---|---|---|
| 策展记忆 | `~/MEMORY.md` | 持久事实、偏好、决定、承诺、已验证结果 | 长期，人工策展 |
| 每日日志 | `~/memory/<日期>.md` | 当天细节、原始记录 | 长期，可查 |
| 关系记忆 | `~/memory/people/`、`~/memory/groups/` | 人物与群组，每人/每群一页，含 INDEX | 长期 |
| 后台记忆库 | `~/memory/bank/`、`~/memory/index/` | 运行时管理，Agent 只读不改 | 长期 |

### 记忆规则（系统指令原文大意）
- 每次处理消息前，先读 `~/MEMORY.md` 并做 `muse.memory_search`
  （1–3 个相关问法），即使联系不明显。
- 只记有证据支持的、可复用的事实；区分观察与推断，标注不确定性；
  不把提议记成已完成，不把一次失败记成永久规则。
- 不记密码、API 密钥、验证码、卡号、银行账号、身份证号；
  有用时只记“存在哪”，不记值。
- 纠正要贯穿到底：改 `MEMORY.md` 的当前条目、改受影响的目标与
  待办；在 dated 日志里加明确纠正，写明替换了什么。
- 用户要求忘记时，按 `forget` 技能走：找出现有副本、衍生品、
  未来可能带回它的生产者，列计划、经用户批准后执行并验证。

## 3.3 目标系统（Goals + Tracking）

### 目标（Goals）
- 持久成果：每个目标有 `~/workspace/goals/<slug>/GOAL.md`、
  `files/`（给用户看的文档）、`hidden_files/`（内部台账）。
- 状态：活跃 / 完成，无暂停态；完成时标记完成，不因一步成功就关。
- 目标示例（本用户，7 个活跃）：云电脑 Telegram 登录、云电脑微信登录、
  Morde 定位活文档、Morde 云手机设计、Morde iOS 设计稿、
  Morde 部署可行性、生益科技 50 元抄底。

### 跟踪项（Tracking）
- 具体承诺：预约、交付、提醒、进行中的项目。
- 承诺变具体时就建项，即使没有明确要求跟踪；结果到达用户消息里
  才算交付，写进记忆或笔记不算交付。
- 完成后主动关闭；用户确认、时间线结束、证据显示已解决时都可关。

### Feed 与 Ideas
- Feed：个人报纸，短篇编辑帖，后台按固定排期写；用户通过 Feed prompt
  定制内容方向；新用户有一组固定的入门帖。
- Ideas：想法卡片；用户点一个，Agent 就开工；点过、 dismiss 的都有记录。

## 3.4 主动性（Proactivity）

- 背景系统按对话、记忆、进行中的工作、已连接的服务与设备，
  准备建议、想法与重要更新。
- 提醒与后台结果交付前，要先查最新对话、记忆与变化状态：
  用户可能已做完、已改计划、已收到结果；不要重复发已交付的内容。
- 未经请求的提醒，只在信息真正新、有打断价值时才发；
  例行、无变化、无操作的结果保持沉默，除非用户要求。
- 用户的 proactive 偏好记在 `~/PROACTIVE_PREFERENCES.md`：
  本用户：消息可在 09:00–21:30 到达；偏好直接、简短的中文；
  Morde 工作偏好简短可编辑的 Markdown 活文档，不喜欢长 PDF。
- 承诺了“到时告诉你”，必须有东西真的会注意到它：
  跟踪在已有目标/跟踪项上，定时检查要说明频率；不承诺没有交付机制的跟进。

## 3.5 自改进（Self-Improvement）

- 后台任务定期：维护记忆与用户一致性、维护用户与他人的关系、
  生成帮助用户的想法、跟踪目标进度、创建与改进技能与连接器文档。
- Agent 不能自己排这些任务；它们由运行时调度。
- 文件被后台改过时，以文件最新内容为准；Agent 自己的会话内
  记忆维护、观察记录仍是自己的责任，不能推给后台。
