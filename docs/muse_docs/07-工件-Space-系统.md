# 07 工件、Space 系统（一句话做 App）

## 7.1 术语

- **工件（Artifact）**：Agent 为用户做的 durable 交付物：
  网页/应用、文档、PDF、演示文稿、电子表格。
- **Space**：工件中网页/应用的新名字。Space 长在 Muse 应用的
  Library 或侧边栏，没有独立 App。
- **静态页（web_static）**：内容在构建时固定，访客输入不保存；
  可公开分享为链接，每位访客独立运行。
- **全栈 App（web_fullstack）**：存数据、可刷新实时数据、可调模型；
  私有，只能在 Muse 内使用，无公开链接。

## 7.2 静态 vs 全栈：判型表（已验证：app-creation 技能）

| 需求 | 种类 | 公开链接 | 存数据 | 刷新 |
|---|---|---|---|---|
| 展示页、设计稿、一次性报告 | 静态页 | 有（用户批准后） | 无 | 无 |
| 要存用户输入、自选、病例、记录 | 全栈 App | 无 | 有（SQLite app.db） | 可 |
| 要每天自动刷新行情、情报、信号 | 全栈 App | 无 | 有 | 有（cron） |
| 别人也要用、要存他们输入、要自定义域名 | 托管 builder（Lovable/Replit/Vercel） | 有 | 有 | 有 |

规则：
- 两者都要（公开链接 + 存数据）时，先讲清取舍，让用户选，不能默认。
- 静态 ↔ 全栈不可互相转换；换种类要新建，数据不迁移。
- 编辑不更新已分享的公开链接；要更新链接，需用户明确要求重新分享。
  （Morde iOS 设计稿、Agent Office 均已验证：公开链接仍是旧版。）

## 7.3 一句话做 App 的 11 步全流程（已验证：投资空间实测）

以“投资空间”为例，实际发生的每一步：

| 步 | 做什么 | 在防什么错 |
|---|---|---|
| 1 需求 | 用户一句话 | — |
| 2 判型 | 要存自选、每天刷新 → 全栈 App | 选错种类导致后期无法存数据或无法公开 |
| 3 定表 | `drizzle/0002_market_tables.sql` + `server/src/schema.ts`，3 张表：行情快照、简报、自选 | 数据无处存、结构事后改 |
| 4 后端 | `server/src/actions.ts`：抓行情、算信号、生成简报、加自选 | 前端直接调外部接口导致密钥泄露、无法审计 |
| 5 前端 | `client/src/App.tsx` + `theme.css`：行情板、信号台、事件课、大佬动态 | 只做展示页，点不开、改不了 |
| 6 构建绑库 | 构建完成，绑定 `SQLite app.db` | 构建成功但数据库没绑上 |
| 7 探针自测 | 写 `tmp/probe4.ts` / `probe-ctx.js`，断言 600183.SS、300750.SZ、SPY 真在页面上 | 编造数据、标题与链接错位 |
| 8 真实调用 | 真实调用一次后端动作，抓到 16 个标的真实价格/涨跌/日线；算出茅台 RSI 72、创业板 RSI 16，与原始日线一致 | 用 mock 数据冒充真实数据 |
| 9 一致性审计 | 审计发现第一版简报方向与行情板矛盾 → 给简报任务加口径纪律（先读行情板、方向必须一致、引用旧报道须点明日期）→ 重新生成，对齐 | 简报与底层数据各说各话 |
| 10 定时任务 | 每天 08:30 自动刷新，`cron.status` 确认启用 | 只做一次，之后变旧数据 |
| 11 交付 | 构建完成卡发给用户；主 Agent 讲清：里面有什么、哪个数据较旧（SPX 与黄金源时间戳为 11/5，已标注）、信号仅供参考 | 用户不知道数据新旧与局限 |

其他三次实测的验证要点：
- **抖音带货空间**：六个标签页均可切换；新建带唯一标记的商品出现在列表；
  诊断曾漏读复盘记录里的点赞/评论/分享，修复后重新实测通过。
- **产品挖掘空间**：刷新真实抓取三路来源（两次共 52 条信号）；
  收藏、改状态、深挖简报均实测通过；深挖约 30 秒，有“深挖中…”提示。
- **牙科诊断空间**：全闭环 7 步实测通过；无可辨影像时 AI 明确拒绝下
  牙位级结论、给低置信度并提 5 道缺失信息选择题；未定稿草稿调
  生成讲解被正确拒绝。

## 7.4 工件的生命周期

- 创建：`artifact.create_web_static` / `create_web_fullstack` /
  `create_file`；`verbatim_request` 必须是用户原话，Agent 不加要求。
- 编辑：`artifact.edit`（同一 slug）；改动后要重新检查成品，
  确认内容与行为符合最新要求，再交付。
- 查看：`artifact.inspect` / `artifact.status`（查版本、构建卡、
  是否正在构建）。
- 分享：`artifact.share` 只在用户明确要求公开分享时调用；
  每次发布/更新都要重新经过一次用户批准。
- 删除：`artifact.delete`；删 Space 不可撤销，先告诉用户、等确认。
- 交付：成品必须在同一条消息里以卡片/链接/附件交给用户；
  只说“做好了、你自己去找”不算交付。

## 7.5 Space 在应用里的位置

- Library：用户的工件、媒体、文件汇集处。
- 侧边栏：用户要求放侧边栏的 Space（`place_in_sidebar=true`），
  或放在导航栏。
- 公开链接格式示例：`https://muse.ai/s/<slug>-<id>/<token>`；
  静态页可公开，全栈 App 不可公开。
