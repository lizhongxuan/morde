# Morde 跨端核心功能验收用例与问题记录

> 版本：2026-11-14（2026-11-15 补充执行）；范围：PC 客户端、iOS 原生客户端、服务端 Agent、指定云端电脑及本机 Codex 会话。本文是验收目标，不表示功能已经实现或验收通过。

## 1. 执行约定

- 本轮和后续复现均只使用本机或本机隔离虚拟机中的服务、电脑和合成数据；关闭对外网的文件传输，不上传、发送或外发文件、真实会话、截图、日志或凭据。Codex 测试使用专用的临时配置和虚构会话，不连接个人配置。截图、录屏、数据库记录和测试文件只留在本地。
- 准备两个独立的普通测试账号 A、B，A 在 PC 和 iOS 登录同一服务实例；A 的两端及 B 的数据均使用不同的虚构标记。准备两台相互隔离的本机测试电脑 H1、H2。准备 PC 客户端、Morde iOS 原生 App、可用的本地 DSH Runtime 和本地模型；记录版本、功能开关及服务实例标识的脱敏值。不使用生产账号或生产数据。
- 准备测试目录 `morde-acceptance/`：`readme.txt` 内容为 `initial`、`nested/a.txt` 内容为 `A1`、`empty/` 为空目录。目标项目名先使用默认值 `morde-acceptance`。另备与测试无关的云端哨兵文件以及冲突文件，以便证明没有误删或覆盖。
- 记录每次执行的日期、版本、设备、模型、账号代号、功能开关、用例 ID、结果、消息/会话/任务/电脑 ID 的脱敏值和本地证据位置。并发测试须记录两个任务均处于运行中的重叠时间或独立的服务端事件；连续点击、界面出现两条消息、只有排队状态均不算并行。
- 结果仅用 **通过 / 失败 / 阻塞 / 未执行**：观察到完整的实际行为和预期结果才算通过；有可复现的不符合预期记失败；所需环境、权限或功能尚不可用且无法判定行为时记阻塞；尚未操作记未执行。模拟接口、静态预览和单元测试只能作为补充证据，不能单独证明跨端端到端用例通过。
- P0 均通过且无未解决的 P0/P1 缺陷时才可建议核心闭环验收；P1/P2 的未通过项需明确影响和处理决定。分端、分账号记录结果，不以 PC 页面的浏览器预览代替实际 PC 客户端，也不以 Mock 回复代替真实 DSH 与模型处理。
- 在失败条目下按第 7 节登记问题。可安全复现的缺陷直接修复并补充必要回归；修复后重跑原用例和受影响的关联用例，在同一条记录保留修复前后的证据。涉及其他工作中改动或不能安全验证时保留现状并记录阻塞。

## 2. 云端 Agent 对话、隔离与并发

以下步骤中的对话均为虚构文本；“PC”和“iOS”分别指实际桌面客户端和原生 App。真实回复须来自本地部署的 DSH 与模型，不能使用固定 Mock 文本。

|---|---|---|---|
| CHAT-01 | P0 | A 在 PC 新建会话，不选择电脑，发送“用两句话解释缓存”；在 iOS 新建另一会话发送“用两句话解释队列”。 | 两端均能发送并收到对应的实际回复；消息受理、处理中、完成/失败状态可信；纯文字问答不要求启动电脑。记录两端消息和回复。 |
| CHAT-02 | P0 | A 在 PC 的会话中先约定“只用简短中文”，再追问前一个话题；在 iOS 打开同一会话并继续追问，随后返回 PC。 | 两端看到同一会话的完整消息、进度和结果，后续回复理解前文；顺序和会话归属正确，无重复消息。 |
| CHAT-03 | P0 | A 建立会话 A1、A2，分别输入不同标记并启动不同任务；在两端反复切换。 | 消息、任务、进度和结果只出现在各自会话；切换不取消后台任务或丢失未发送草稿。 |
| CHAT-04 | P0 | A 在 A1 写入 `A-BLUE-731`；B 登录并尝试从列表和 A1 的脱敏链接/标识访问，也询问该标记。A 再检查 B 的 `B-GREEN-482`。 | 两账号不能读取对方会话、消息、任务、事件或结果；直接访问被拒绝或不可见，Agent 不泄露另一账号标记。 |
| CHAT-05 | P0 | A 和 B 分别从各自客户端同时启动可观察的长任务，记录运行起止与结果。 | 两个账号各有独立执行上下文并实际重叠运行；消息、进度、结果、取消和授权互不影响。 |
| CHAT-06 | P0 | A 在 A1、A2 各启动一个不争用资源的长任务，在两端查看状态。 | 两个会话的任务实际并发，结果和事件各归各的会话；停止 A1 不影响 A2。 |
| CHAT-07 | P0 | A 在 A1 启动可观察长任务 T1；其运行中发送互不依赖的长任务 T2，再发送普通追问，记录运行时间。 | T2 不必等 T1 结束即可开始；追问可继续受理和得到回应；两个任务实际重叠且各自结果、进度正确，输入框不被持续锁死。 |
| CHAT-08 | P0 | T1、T2 都在运行时，明确对 T1 追加“最终结果最多三条”；再只停止 T2。 | 补充要求只影响 T1；T2 确认停止，T1 继续；任务状态和结果与实际执行一致，不误停其他任务。 |
| CHAT-09 | P1 | 同一会话有两个进行中的不同任务时发送“把它缩短一些”；回答澄清并指定一个任务。 | 关联不明确时先澄清，不擅自中断或修改任一任务；指定后只处理目标任务。 |
| CHAT-10 | P0 | 任务已经受理并开始后关闭 PC 或 iOS，另一端检查；再重新打开原客户端。 | 服务端任务继续，重连后恢复真实进度、状态和结果；同一任务不重复创建，也不重复执行已确认的操作。 |
| CHAT-11 | P0 | 在隔离环境模拟发送响应丢失或短暂断网，恢复后按界面重试同一条消息。 | 未确认状态可见，消息与草稿留在原会话；以同一请求身份恢复，不重复创建消息、任务或已完成操作；未知结果不伪报成功或失败。 |
| CHAT-12 | P1 | 模拟模型或服务不可用、授权失效，尝试发送消息并恢复。 | 显示实际失败、等待或重新登录状态；错误不暴露凭据、不伪造回复；恢复时不重复提交。 |
| CHAT-13 | P1 | 建立超过所用模型单次上下文窗口的多轮会话，开头写入虚构约束，之后询问该约束，并查看原始历史。 | 能依据授权历史回答并查看原文；必要历史不可用时说明，不编造。记录模型容量、构造规模及回答。 |
| CHAT-14 | P1 | 要求主 Agent 并行委派两个互不冲突的只读文本分析子任务，再汇总；另模拟其中一个失败。 | 能观察两个子任务实际启动及重叠，汇总真实结果；失败被明确报告，“已委派”不等于已完成。 |

## 5. PC 本机 Codex 会话与 iOS 接续

使用本机 Codex 桌面应用及独立测试配置，预先创建有多轮文字、工具过程的虚构会话；服务端和 iOS 均连接本机隔离实例。不得读取、同步或发送个人 Codex 历史。验证工具真实公开且当前授权范围允许的过程，不要求暴露工具未公开的内部推理。

| ID | 优先级 | 操作 | 预期与证据 |
|---|---|---|---|
| CODEX-01 | P0 | 在 PC 客户端进入本机 AI 会话入口，选择专用 Codex 配置，检查授权范围后确认连接。 | 入口可发现；连接状态、账号/设备和读取、实时同步、发送等授权范围清晰；没有确认前不上传会话。 |
| CODEX-02 | P0 | 测试配置准备多个既有及归档会话，其中一组超过单页；连接并等待初次同步，在扫描中再新增一条。 | iOS 和 PC 显示该配置下全部可访问会话，无遗漏或重复；初次同步未完成、分页和失败有明确状态。记录来源线程数及两端清单对照。 |
| CODEX-03 | P0 | 在真实 Codex 桌面应用继续一条既有会话，产生新消息及工具调用；同时在 iOS 打开同一条会话观察。 | iOS 按顺序展示同一原生线程的历史与实际新增过程、可见工具输入输出及其状态；不只显示终态快照，也不把缺失过程标为完整。 |
| CODEX-04 | P0 | 在 iOS 向 CODEX-03 同一会话发送一条虚构文字，观察本机 Codex 桌面应用及两端结果。 | 消息进入原生同一线程并得到实际处理；发送状态可辨、只出现一次；不新建替代线程。 |
| CODEX-05 | P0 | Codex 正在执行时从 iOS 发送追问；工具不支持当前运行中追加时记录实际结果。 | 支持时进入正确线程和轮次；不支持时明确提示或等待，不伪称已执行，不中断无关会话。 |
| CODEX-06 | P0 | 关闭 PC、断网或丢失服务端确认，恢复后重新打开 iOS 和 PC；对未知发送状态按界面重试。 | 历史和实时事件按游标补齐、排序去重；未确认状态保留，消息或命令不被盲目重复执行。 |
| CODEX-07 | P0 | 撤销配置授权或只移除发送权限，分别尝试新事件同步和从 iOS 发送。 | 撤权立即阻止对应的新操作；已授权保留的历史按实际权限展示；没有权限不伪报发送成功。 |
| CODEX-08 | P0 | A 连接专用配置后，B 尝试访问 A 的会话、事件与发送命令；A 切换到另一个本机配置。 | 不同账号、PC 安装和工具配置的数据及命令隔离；不串线程、内容或权限。 |
| CODEX-09 | P1 | 产生多页长历史、较长工具输出及工具允许读取的附件；滚动 iOS 时间线并切换会话后回来。 | 公开且已授权的内容可完整读取、正确排序；未支持的事件或附件明确提示，不能静默截断并显示同步完成。 |
| CODEX-10 | P1 | 在可控测试配置中触发一次审批/提问；如工具未提供可响应的原请求句柄，尝试查看状态。 | 可处理时目标、内容和版本对应原请求，操作只生效一次；不可处理或句柄过期时明确显示，不能冒充已批准。 |
