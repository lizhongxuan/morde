目标主机：`hk3rikyw`，博客服务：`/home/gem/workspace/fake-blog`、端口 `18080`。

## 处理状态（2026-10-25）

缺陷已在服务端修复，自动化验证通过；真实 Portal 登录后的内置浏览器流程仍待验收。

- 未登录预览现在跳转到 Portal 域，由有效 Portal Session 为 Host 所有者签发一次性预览票据。
- 票据绑定 Host 与一个有效的预览目标端口。兑换时核对原子消费回执；Gateway 再核对当前 Host 和端口，阻止普通 Host ticket 进入预览、预览 ticket 进入 Workbench 或其他端口。
- 新增 `00030_preview_ticket_audience.sql`，并同步 OpenAPI 与 `docs/实施/00-总览与公共约定.md`。
- 验证：Server 全量单元测试、目标包 race、`go vet ./...`、SQLC 生成与 PostgreSQL 16 全量存储集成包通过。

- 容器内 `GET /`、`GET /api/health` 均返回 200；通过一次性 Host ticket 直接进入私有预览域后，首页、文章 API、JS 资源也均返回 200。
- 未持有预览域 Cookie 时，请求 `http://18080-hk3rikyw.hosts.localhost/` 先跳转到主机域 `/__ch/preview-auth`，随后返回 `403 portal session required`。用户已经通过 Portal 进入该主机，并持有有效的主机 Cookie。
- 原因：`server/internal/gateway/control.go` 的 `previewAuth` 使用主机 Cookie 身份调用 `Hosts.IssueTicket`；`server/internal/app/host.go` 的 `IssueTicket` 只允许 Portal session。Portal Cookie 为 host-only，不会随主机域请求发送。
- 影响：普通用户打开私有预览链接会失败；直接在云端电脑浏览器访问 `http://127.0.0.1:18080` 不受影响。该问题涉及所有使用相同鉴权链路的私有预览端口。
- 以上为修复前的现象记录；新链路没有放宽通用 `IssueTicket` 的 Portal Session 要求。修复后真实登录流程尚未实测。
