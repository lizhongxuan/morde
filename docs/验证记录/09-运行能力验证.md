## 4. 在途与后台操作停止（T09.02）

由更新后的 `deploy/single/verify/09-runtime-capabilities.sh` 在一次性固定镜像 sandbox 中完成以下合成探测，脚本退出码为 0，创建的 sandbox 随后删除。

| 探测 | 实测结果 |
|---|---|
| 前台长命令 `sleep 60`，`timeout=1`、`hard_timeout=2` | 首次响应为 `running`；等待结果为 `hard_timeout`，进程终止 |
| 脱离 Shell session 的合成子进程 | `/v1/shell/kill` 返回 terminated，但子进程仍存活；脚本随后按记录的测试 PID 清理进程和标记 |

## 5. 服务端输入边界（T09.03）

固定 AIO 实例实测：未带 `X-AIO-API-Key` 的 `/v1/browser/actions`、`/v1/file/write`、`/v1/shell/terminal-url` 和 `/vnc/index.html` 均返回 401；带本次合成 AIO key 后，GUI 输入、文件写入、终端 URL 与 VNC 页面均返回 200。临时文件仅写入 sandbox `/tmp` 并清理。

这证明 AIO 对直接 API 做 key 认证，但同一 key 可执行 GUI、文件和终端操作；接口没有人类只读/AI 可写角色，也没有 Morde 控制版本。Morde API/Gateway 配置端口 `127.0.0.1:7080`、`127.0.0.1:7081` 在探测时没有监听；为避免修改现有数据库与 Docker 存储，没有启动完整 Morde 服务。

对生产 Gateway handler 做了隔离 HTTP 探测：用现有 `newTestDeps`/真实 `gatewayHandler`、合成 Host Cookie、同源 Origin 和假 AIO 上游发送 `POST /v1/browser/actions`。handler 返回 200，假上游捕获到原样动作体及注入的合成 AIO key，证明当前代理链没有只读门禁。临时探针测试文件已删除，没有留下代码改动。`go test ./internal/gateway/...` 与定向 WebSocket 测试通过；WebSocket 证据只覆盖授权连接、活动跟踪及服务关闭，不代表控制权变更时可撤销旧连接。

因此 T09.03 的能力核查完成，结果是服务端只读/控制版本缺口，不是安全验收通过。完整部署进程下的 GUI 输入、noVNC 剪贴板和权限变化后的旧 WebSocket 实机路径仍未验收；T12.08 必须补齐这些用例。不能将 AIO key 认证或 noVNC `viewOnly` 误记为用户/AI 控制权隔离。

## 6. 持久资料与安装范围（T09.04）

使用固定 AIO 镜像、合成 key、唯一命名卷和一次性 OpenSandbox sandbox；没有连接外部网站或真实账号，也没有安装软件。本节只核对镜像自带浏览器，没有安装其他应用，因此不声明其他应用配置的持久路径。第一次卷挂载后 AIO 就绪，检查到工作目录权限及浏览器运行目录如下：

| 项目 | 实测结果 | 结论 |
|---|---|---|
| 运行用户 | `gem`，UID `1000` | AIO Shell 以非 root 用户执行 |
| workspace 卷 | OpenSandbox 将 named volume 挂到 `/home/gem/workspace`；目录为 `root:root`、权限 `755` | Shell 写入合成文件返回 `Permission denied`；AIO `/v1/file/write` 返回 HTTP 200 但 `success=false`，文件未创建。测试容器 root 写入的唯一标记在删除并重建 sandbox、重挂同一卷后仍可读，证明卷数据会保留且启动没有覆盖该标记；普通用户仍不能保存文件 |
| 浏览器 | `/v1/browser/info` 返回 200、VNC/CDP 信息可用；实际 Chromium 进程为 `/opt/browser/chrome`，`--user-data-dir=/home/gem/.config/browser` | 在隔离 profile 目录写入的唯一标记不在 workspace 卷内，删除并重建后消失；当前卷配置不持久化浏览器 profile |
| 软件安装 | `apt-get`、`dpkg-query`、`sudo` 存在；`sudo -n true` 失败 | 普通 `gem` 会话没有免密提权；本次没有安装任何软件，apt 包安装/跨重建恢复能力未通过 |
| 架构 | 固定实例为 Ubuntu 26.04.1 LTS、aarch64；镜像 digest 见第 1 节 | 首批应用安装与镜像支持矩阵需按架构声明，不能假设 x86_64 软件包可用 |

探测发现当前 `server/internal/storage/docker.go` 仅实现容量检查和卷删除，没有卷 UID/GID 初始化；`server/internal/orchestrator/client.go` 发送 workspace 挂载路径，模板仅声明 `/home/gem/workspace`。这与 `gem` 的写入身份不匹配，Shell 和文件管理 API 都无法保存。浏览器 profile 也没有独立卷映射。卷底层确能保留 root 写入的数据，但这不证明用户能保存；未测试启动脚本覆盖真实用户资料，本次只核对唯一合成标记。

**结论：T09.04 核查完成，当前功能有高优先级缺口，影响 P0 的文件保存、浏览器登录态/设置恢复和应用安装体验。** 需要在 Morde 自有运行/存储边界解决卷初始化权限，不让普通任务获得 root；为 profile 和声明支持的应用配置增加明确持久路径，并在实现后重跑普通 `gem` 写入、删除、重建、重挂读取验证。当前证据不要求修改 AIO/OpenSandbox/noVNC 核心源码。

## 11. T21.12 AIO 终端重连验证

使用固定 AIO `ghcr.io/agent-infra/sandbox:1.11.0` 镜像，在 `--network none` 容器中挂载空临时 `/home/gem`；没有连接 Portal、真实 Host 或外部网络。检查 `/opt/terminal/index.html` 确认页面从查询参数读取 `session_id`，WebSocket 连接 `/v1/shell/ws` 时继续传递此 ID，并在异常断开后使用原 ID 重连。`GET /v1/shell/terminal-url` 每次返回新的 session ID；`GET /v1/shell/sessions` 展示的是 `/v1/shell/sessions/create` 命令任务，不列出交互终端。

容器内用 AIO API 取得 URL，以该 ID 建立 WebSocket，在 shell 中关闭终端回显后启动合成命令 `printf marker; sleep 8; printf tail`。命令运行时强制中止 WebSocket 传输，等待后使用同一 ID 重连。收到 `restore_output` / `terminal_restored`；命令尾标记与重连后输入均成功，PID 在断线前后相同。探测输出只记录布尔结果，没有记录 session ID 或用户资料。容器由 `--rm` 自动删除。

Gateway 的 `TestWebSocketEchoTracksActivityAndClosesOnShutdown` 现同时断言 `/v1/shell/ws?session_id=...` 的原始查询参数到达上游，定向 Go 测试通过。**结论：**WebSocket 暂时断开时复用 AIO 的 PTY 与 session ID 可恢复同一 shell，不需要另建终端后端。Morde 持久登记与跨页面 / 设备接回后续已实现，详见下文；AIO / Host 重启后的 PTY 存活仍未验证，真实 Portal Host 生命周期验收待用户登录后进行。

补充合同探测仍在同一个无网络临时容器中完成：生成随机 UUID 直接连接 `/v1/shell/ws` 会收到 AIO `error`；只用 AIO `/v1/shell/terminal-url` 实际签发的 ID 才能接回 PTY。对同一签发 ID 同时开两条 WebSocket，第一条收到 `terminal_restored`，第二条收到 `error`，错误为 `Session already has an active WebSocket connection`。因此只能按“上一端断开后，下一端用已存 ID 顺序接回”实现；AIO 不提供同一终端的多端并发观看。探测仅输出错误类型与固定错误文本，不记录 ID 或用户资料；容器仍使用 `--network none` 与空临时 profile，并已自动清理。

### 11.3 T21.14 紧凑事件页与终态 SSE 收口

`GET /api/tasks/{id}/events` 的首次读取和每秒轮询改用轻量事件页：只取 Host、任务状态、当前事件序号及有限事件批次；授权仍在每次轮询时重新核验，不再为读取事件加载完整 Task 详情、步骤、附件和待处理请求。任务已终态时先回放游标之后的事件，读至当前序号后关闭连接；重连游标已等于当前序号时返回 HTTP 204，让 EventSource 停止重连。若事件历史全部缺失而请求游标落后，服务端返回游标过期（HTTP 409），避免误把缺失事件视为正常终态。
