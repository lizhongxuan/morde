# Morde PC 端设计稿对齐与用户 Web 下线设计方案

2026-11-15。方案稿，用于指导后续实施和验收，不表示相关功能已经完成。

## 1. 目标与产品边界

普通用户使用 **Morde PC 客户端或 iOS 原生客户端**登录和使用 Morde。PC 是主要工作端：界面按[PC 对话与云端电脑设计稿](<设计图/Morde-PC对话与云端电脑设计稿.html>)调整，现有用户 Web 的业务能力在 PC 内保留并接通服务端。后续下线独立的普通用户 Web 和手机 Web，**管理后台 Web 保留**。

项目产品端仍为服务端、PC、iOS 和后台 Web 四个；工作台与云端电脑是其中的实现能力。PC 与 iOS 使用同一账号和服务端数据，两端各自登录；不要求用户先在网页或另一设备登录。iOS 保留原生界面，本方案不要求其照搬 PC 布局，也不把 PC 特有的本机文件夹操作强加给 iOS。

此方案处理界面承载、能力接入和下线顺序，不把现有 Agent、会话、文件同步等未完成事项视为已完成。云端 Agent 继续使用项目约定的 DSH Runtime；相关业务和验收仍遵循根目录 `AGENTS.md`。

## 2. 现状与依据

原[PC 端统一设计草稿](morde-pc-unification-design-2026-11-15.md)以 `origin/main` 的 `264b5f04` 为基线：旧版 PC 从服务端加载用户 Portal 页面，因此直接关停用户页面会影响旧版 PC。文档中“PC 是唯一的用户端”的表述由本方案修正为“PC 和 iOS 都是用户客户端”。

本次只读检查的本地工作区已有未提交的相关改动：桌面打包配置已包含 Portal 用户资源，主进程已有从本机服务加载 Portal 的代码；服务端无匹配路由的处理也已有调整。它们是待集成和验证的工作区状态，不代表安装包、工作台或下线流程已经通过验收。实施前应重新核对实际代码、部署版本和在途修改，避免覆盖其他工作。

视觉和交互以指定设计稿为准；业务能力以迁移时的现有用户 Web 及其实际状态为基线。设计稿中的示例内容和模拟状态不作为真实数据。设计稿未画出的现有功能仍需在 PC 内有可达入口；既有功能未接通或有缺陷时应记录差距并完成修复，不能因截图相似就视为通过。

参考[PC 端布局与云端电脑体验需求](<Morde PC端布局与云端电脑体验需求文档.md>)、[PC 端设计稿对齐技术设计](<Morde PC端设计稿对齐技术设计方案.md>)及[第一里程碑收口设计](<Morde第一里程碑收口技术设计方案.md>)；它们涉及独立用户 Web 交付或旧同步方式的内容，与本方案和根目录约定冲突时，以后者为准。

## 3. PC 界面和功能设计

### 3.1 对齐设计稿

- PC 窗口以对话为中心：左侧主导航、会话列表，中间对话，右侧为当前会话的工作区。顶部集中后退、前进、侧栏和工作区标签操作；侧栏可以展开、收起和放大，缩放不丢输入或改变任务、电脑控制权。
- 会话列表展示主会话和可折叠的旁聊；支持新建、切换、搜索。消息、未发送草稿、附件及所选模型按服务实例、账号和会话隔离；切换页面或会话后可恢复。
- 右侧工作区承载云端电脑、当前会话任务动态、文件和已打开文档；可添加、切换及关闭标签。切换会话时任务和文件归属随之切换，不显示其他会话的结果。接管、交还和连接状态以服务端与网关实际确认结果为准。
- 审核、个人数据、目标与计划、设置与授权使用设计稿的左侧分类和对应内容；离开对话页时保留原会话和草稿。对话历史按第 3.2 节上滑加载；长消息、表单、窄窗口和键盘操作不能丢内容或遮挡输入。
- macOS 和 Windows 使用真实系统窗口控件，并保留拖动、缩放和全屏退出；不将原型里的示意按钮当作系统控件。所有产品端使用 `images/morde-logo-reference.png` 的蓝色 M 标识，PC 的颜色、字号、间距及状态样式对照指定设计稿。
- 设计稿所示电脑画面、任务、审批、附件和快捷操作均接入真实业务；示例文件、示例账号、设计预览切换和模拟进度不进入正式用户流程。

### 3.2 设计稿中的组件改动

1. **独立审核入口。** 左侧主导航增加“审核”，有待审核事项时显示提示；进入后在“审核事项”查看来源会话、任务、请求内容、授权范围和可用的风险、费用及到期信息，执行“批准并继续”或“拒绝”。同一事项也可在对应对话的审核卡片中处理，两处共享真实审批状态。设计稿以单个任务演示，本方案按当前账号有权处理的任务审批跨会话汇总，展示时仍校验项目及任务权限；不能把某一个会话已加载的事项当作全部事项。其他类型的审批保留已有可用入口，不混用任务审批权限。审核选择由服务端确认后才显示已处理；任务后续仍以真实状态为准，不能把“审核已处理”等同于“任务已完成”。过期、撤权、其他设备已处理、网络失败或结果未知时显示实际状态并支持安全恢复。
2. **任务动态。** 右侧只显示当前会话的任务，使用不分组的列表：进行中的任务优先，每类再按最近更新时间倒序排列；每项显示真实状态及进度，仍能查看详情和执行有权限的任务操作。等待审核的任务保持“等待审核”等真实状态，用户可在对应对话卡片或左侧审核入口处理；审核提示与任务本身的失败或状态未知提示分别处理。切换会话时旧结果不能串入新列表。
3. **聊天历史。** 消息区使用上下滚动；向上到达已加载内容的顶部时按游标加载更早的历史，加载后保持原阅读位置。用户正在阅读历史时，新消息和流式回复不强制跳到底部；切换会话再返回时恢复各自的阅读位置。首次加载、历史已到头、加载失败和重试都应有真实反馈。设计稿的本地示例批量只是演示，不能代替服务端历史或固定生产批量大小。
4. **默认电脑。** 对话输入框和新建定时计划表单不再放电脑选择下拉框；云端电脑设置显示并允许管理默认电脑。普通文字对话无需启动电脑；确需电脑而用户未指定目标时，按现有授权规则使用默认电脑。用户明确指定的电脑优先，默认电脑不存在、不可访问或授权失效时说明并等待处理，不切换到其他电脑。已经受理的任务和已有计划绑定的目标不因更改默认电脑而改变；隐藏选择控件不能丢失已有计划目标，也要保留用户指定电脑的可用路径。
5. **文件夹同步卡片。** 同步入口以默认电脑作为预选目标，不在卡片中重复放置“选择目标电脑”按钮；开始前仍要明确展示并确认目标电脑、项目名和同步范围。用户可在云端电脑设置中选择或更改默认电脑；无可用目标时引导设置。已建立的同步关联固定原目标，默认电脑变化不得静默改绑，具体同步规则见第 6 节。
6. **消息已收到。** 用户消息得到服务端持久受理回执或通过服务端记录确认后，在该条消息气泡左下角显示 `👌🏻`，表示“Morde 已收到消息”，普通文字问答也适用；它不表示任务已启动、操作已完成或附件已上传。本机待发送、发送失败及结果未知时不显示已收到；已有的发送、附件和错误状态继续真实显示。原有仅对任务开始显示的同一表情应调整为此收到语义，不出现两个含义不同的相同标记。
7. **AI 思考状态。** 在当前会话中，由服务端确认该轮回复或 Agent 正在处理且尚无可展示的回复内容时，显示带 Morde 标识的动态省略号；回复开始后切换为真实内容。排队、等待审核或用户输入、失败、取消、断线和状态未知不冒充思考中，应显示对应真实状态。按会话及消息/任务关联状态，切换会话不串显示；尊重系统减少动态效果设置，并提供可访问的状态名称。
8. **对话审核卡片。** 当当前会话的任务提出审核时，在相应对话时间线以 Morde 消息样式展示卡片，显示请求标题、内容和必要的授权范围、影响及可用风险/费用信息，提供“允许”和“拒绝”。卡片与左侧审核入口及任务状态共享同一任务、审批 ID 和版本；在任一入口处理后各处同步，服务端确认后显示决定已记录及后续状态等待更新。过期、撤权、其他端已处理、断线或提交结果未知时禁用不安全的重复操作并提示；重开或重新进入会话后从已授权的服务端记录恢复卡片及结果，不伪造历史或泄露其他会话的审批。

审核入口与对话卡片应先复用现有任务查询和 `POST /api/tasks/{id}/approvals/{approval_id}/responses`；当前任务列表返回摘要，审批详情在任务详情中，且当前会话任务接口按活动/最近结束视图返回。现有任务详情会隐藏已批准、拒绝或取消的审批，任务事件也不包含审批内容，因此不能假设仅凭当前 `pending_request` 就能在刷新后恢复已处理卡片。实施时核实查询能否完整、高效地提供有权查看的事项、结果和时间线归属；不足时扩展现有服务端查询及 OpenAPI/客户端类型，不能只统计当前已加载页面，也不能用客户端排序冒充完整的服务端结果。提交审批继续使用原有请求版本和幂等机制；重复请求、其他端已处理及结果未知须先查询确认。

### 3.3 用户 Web 能力迁入 PC

以下为检查时用户路由的功能基线，具体操作、权限与状态在实施前根据现有版本逐项盘点；路由名称仅帮助定位来源，PC 可按设计稿调整入口和布局。

| 现有能力 | PC 内的目标 |
| --- | --- |
| 登录、注册、修改密码、退出 | 在 PC 完成用户认证和账号操作；注册或改密的接口及错误处理沿用现有业务规则。 |
| 对话、消息、附件、任务、审批、结果 | 在对话、会话工作区和独立审核入口完成全流程；保留历史、发送状态、事件流、失败与恢复。 |
| 云端电脑、创建与管理、共享及文件版本 | 在云端电脑分类和会话工作区提供入口；保留操作权限、确认、进度和失败处理。 |
| 桌面、终端、Workspace、主机文件、VS Code | 保留五项工作台能力，见第 5 节；Workspace 与主机文件不能混为一项。 |
| 项目及项目对话、Codex 会话 | 保留有权限时的可达入口和现有会话边界；不因为设计稿没有画出项目分组而删除项目数据或把项目会话并入个人会话。 |
| 个人数据、目标与定时计划 | 保留资料、AI 个性、记忆、动态、灵感、资源库、偏好、目标及计划的已有操作；遵守保存确认、授权、冲突及跨端同步规则。 |
| 模型与工具、MCP、API Key | 保留添加、编辑、授权、启停及可用的检查等操作；密钥不回显，按原有权限处理。 |
| 客户端与设备、通知、账户设置 | 保留设备查看和撤销、通知及已读状态、隐私、记录和额度等入口。 |
| 本机文件夹同步 | 在 PC 中通过受控原生入口选择文件夹和目标电脑，按第 6 节执行。 |

迁移前按[用户路由](../web/portal/src/App.tsx)和实际界面逐项记录入口、可用操作、权限、正常与异常结果，并与部署中的用户 Web 核对。当前源码中的重定向和历史链接也要有受权限约束的 PC 内可达路径，不能误当成需要重新实现的独立功能。

## 4. 客户端、服务端和构建

```text
PC 客户端：本地打包的用户界面 + 工作台 + 原生能力
           └── 认证、业务 API、事件流和授权后的电脑连接 ──┐
iOS 原生客户端 ── 认证、业务 API 和事件流 ───────────────────┤
                                                            服务端
浏览器 ── 管理后台 Web、后台 API、临时 PC 安装包下载入口 ──┘
```

### 4.1 构建与加载

继续复用 `web/portal` 中的用户界面代码和 `web/workbench`，而不是再实现一套平行 PC 业务界面。**用户界面仍要构建**，其构建产物提供给 PC 安装包；管理后台另有服务端可发布的构建产物。这里的“构建用户界面”是生成客户端内部资源，与用户能否登录无关，也不意味着继续交付独立用户 Web。

PC 安装包打入用户 Portal 和 Morde 工作台的界面资源；启动后从本地加载，业务数据、任务事件和云端电脑能力通过现有服务端/网关合同获取。构建拆分须让后台的 HTML、脚本、样式和静态资源在其实际 URL 下仍可访问，不能因为禁止用户路由而误删后台共用资源。下线后服务端部署只包含后台 Web 产物；PC 构建仍生成其用户界面产物。

现有工作区中的本机回环服务可作为复用起点：只监听本机、使用受控端口，校验 Host 和来源，只转发明确允许的业务请求；不提供任意地址代理，不将凭证提供给不可信页面。工作台如经本机桥接访问网关，目标必须由当前账号已授权的指定 Host 确定，隔离不同 Host、会话和凭证；禁止由页面自由指定代理目标。客户端的 API、SSE、WebSocket 和文件操作分别验证连接、鉴权与失败恢复。是否沿用该实现由实施时的安全与功能验证决定，不能只因它存在就视为接通。

特别注意本地资源的来源变化：随机回环端口及临时 Electron 会话可能改变网页存储的来源或生命周期。未发送草稿、附件、消息发送队列和页面偏好不能假设会随旧网页存储自动保留。实施时要核实实际存储，复用适当的本机私有持久化，按服务实例、账号和会话隔离，并在升级时安全迁移可识别的旧状态；来源不明、迁移失败或结果未知的内容保留并提示，不自动重发或删除。

### 4.2 登录、会话和管理后台

- 用户在 PC 或 iOS 分别使用客户端原有登录流程。PC 复用客户端凭证、安全存储、短期会话与登出/撤销机制；iOS 使用其原生凭证机制。权限、账号状态和安装授权仍由服务端校验。
- 同一账号可在两端接续同一会话并查看已确认的消息、任务进度及结果；关闭客户端或短暂断网不取消已受理任务。重连先恢复状态和事件，重试沿用原请求身份，不重复执行已确认操作。
- PC 升级应保留仍有效的旧凭证，不因界面资源迁移要求重新登录；凭证已过期、被撤销或无法安全读取时按实际状态提示。数据库和已保存的会话不因本方案迁移或删除。
- 管理员继续通过 `/admin/*` 登录并使用后台；PC 中的后台入口可按原行为打开浏览器。后台权限在服务端校验，普通用户客户端会话不因内嵌页面获得管理权限。管理后台提供临时 PC 安装包下载入口，需核对安装包可用性、版本和校验方式，并确认普通用户有获得安装包的途径，不为此扩大管理后台权限。

### 4.3 数据和服务依赖

对话、任务、个人数据和权限以服务端为准；PC 本地保存必要的草稿、待确认操作与界面状态。服务端不可达时，界面显示真实的离线或待确认状态；本地页面能打开不代表聊天、远程电脑或任务可离线执行。Agent 工具、搜索、长会话及子 Agent 继续使用现有服务和 DSH 能力，界面只展示实际进度与结果。

## 5. 云端电脑与工作台

在 PC 对话的右侧工作区打开用户指定且已授权的云端电脑，按设计稿展示名称、画面、连接状态和控制权；终端、Workspace、主机文件及 VS Code 均保留可用入口。接管成功后可放大，交还成功后按设计稿恢复布局；面板关闭或切换不等于交还控制权、取消任务或改变目标电脑。不可用、无权限、断线和结果未知分别提示，不能自动切换其他电脑或宣称成功。

工作台自己的界面资源随 PC 打包，仍复用现有的网关授权、一次性票据、控制租约、只读观察和文件权限；不能为了本地加载关闭 Web 安全、放宽跨域或绕过授权。桌面画面、终端及远端应用需要的运行数据和交互仍来自指定云端电脑。

实施前必须先解决以下实际兼容问题，再进入工作台对齐验收：

1. 现有工作台代码包含 `/vnc/index.html`、终端页面和 `/code-server/` 等嵌入入口，并非只调用 API。逐项确认这些界面和依赖如何满足客户端本地打包、远程连接与五项能力保留；先复用现有组件和协议，核查所需资源、版本及许可。不能把工作台外壳打包就认定所有界面资源已本地化。
2. 本地页面与远端网关可能跨源、跨站；将页面从 `file://` 改为 `127.0.0.1` **不能单独证明**原有 `SameSite=Strict` Cookie、嵌入授权或 WebSocket 可以正常工作。应在保持用户、安装、Host、会话、权限及租约隔离的前提下，验证完整票据交换、Cookie、CSP、嵌套页面、流连接与撤权链路。
3. 对无法按上述目标接通的功能，保留错误与恢复提示并记录阻塞；不能静默改为远程加载 Morde 工作台页面，也不能把独立窗口恢复入口当成设计稿同窗体验已验收。相关问题未解决前不下线旧工作台页面。

## 6. PC 本机文件夹同步

用户在 PC 选择本地文件夹，界面以已选默认电脑作为预选目标；开始前展示并确认目标电脑、项目名和同步范围，再由用户点击同步。用户可通过电脑设置选择或更改默认电脑，不能省略目标确认。项目名默认使用本地文件夹名，目标为该电脑的 `~/workspace/project/<项目名>/`，保留相对目录结构。只允许用户授权的范围，项目名和路径不得越出 `project`；已有同步关联固定原目标，默认电脑变化不会自动改绑。

同步为**用户点击触发的单向同步**：本机新增、修改或删除已同步内容后，须再次点击才应用变化；云端变化不反向修改 PC。删除只影响该来源已确认同步的对应内容。目标有未协调内容、本机删除与云端独立修改冲突、根目录不可访问、授权失效或结果未知时，保留受影响内容并提示，不静默覆盖或误删；根目录不可访问不等于全部文件删除。状态区分进行中、完成、待处理和失败，只有目标电脑确认应用后才显示完成。

复用现有同步引擎、授权与恢复点；PC 界面通过最小受控桥接选择目录并发起同步，不向工作台 iframe 或普通页面暴露任意本机文件访问。旧配置、待处理内容和恢复点在身份、范围或结果未确认时保留，不因界面迁移自动启动、覆盖或清理。具体冲突基线与数据保护遵循[第一里程碑收口设计](<Morde第一里程碑收口技术设计方案.md>)。

## 7. 实施与下线顺序

### 阶段一：PC 对齐与兼容

1. 固定设计稿版本，盘点现有用户 Web 的页面、操作、权限和已知缺口；确认当前工作区、部署版本及旧 PC 所依赖的页面。
2. 完成 PC 用户界面和工作台的本地构建、打包及加载，按设计稿调整布局，逐项接通第 3 节能力及原生文件同步入口。保留 iOS 现有登录与跨端使用，管理后台保持可用。
3. 处理登录态、旧网页本地草稿和发送队列迁移，核查客户端更新方式和后台下载入口。新客户端必须能独立于用户 Web 资源完成业务流程。
4. 在真实 `morde-pc` 中按第 8 节验收，并回归 iOS 与管理后台。此阶段服务端继续保留旧 PC 所需的用户 Web/工作台入口；不得因本地代码已改为 404，就在对齐完成前部署下线。

### 阶段二：旧版过渡

提供可获得、可安装的新版 PC 和明确的升级指引；验证从依赖服务端页面的旧版升级后，凭证、会话及需要迁移的本地状态按规则保留。评估旧客户端仍在使用的情况；未完成过渡时继续保留其必要页面。若无法确认旧版本覆盖情况，不把新版验收通过直接当作旧版已完成迁移。

用户页面最终下线后，未升级的旧 PC 将无法再加载其依赖的页面，必须事先使其能获得新版并明确提示；不能假定安装了 `electron-updater` 就代表自动更新已经可用。自动更新未接通时可先使用管理后台下载入口人工升级。

### 阶段三：下线普通用户 Web

在 PC 对齐、工作台本地化、升级过渡和 iOS/后台回归通过后，再调整部署与服务端静态路由：停止对浏览器提供用户 Portal、`/app/*` 和 Morde 工作台页面，旧用户页面地址返回 404；保留 `/admin/*`、后台静态资源、必要下载入口、业务 API 和已授权网关连接。不要将用户页面的 404 规则误用于 PC 的本地路由、管理后台或 iOS API。

同步调整构建脚本、静态资源配置、部署文档和更新检查；PC 构建继续产出用户界面供安装包使用。下线后复查后台登录、全部管理页面、安装包下载及 PC/iOS 业务流程。下线与部署应安排可回退路径；如果发现旧客户端不可升级、工作台或后台受损，暂停下线并恢复兼容入口。

## 8. 验收标准

验收记录应区分“设计、代码、自动化测试、本机模拟、真实客户端及真实服务”的证据；未覆盖的环境和能力标记待验证，不以页面截图、浏览器打开或构建成功代替 PC 验收。

1. **外观与交互：**在真实 `morde-pc` 中对照指定设计稿，检查窗口顶栏、左侧导航和审核入口、会话列表、中间对话、右侧工作区及各状态；覆盖宽窗口和窄窗口、侧栏操作、原生窗口控件、键盘和输入法。设计稿未画出的业务页也有可达入口并保持风格一致。
2. **功能覆盖：**逐项核对第 3 节功能清单，从 PC 客户端入口完成正常操作及错误恢复；项目、Codex、通知、设备等不因原型未显示而丢失。管理后台从浏览器独立登录和操作。
3. **两端会话：**PC 与 iOS 分别登录并发送消息、收到真实回复；同账号在另一端打开相同会话，查看消息、进度与结果。至少两个会话切换时草稿、阅读位置和任务不串；上滑加载历史不跳动、不重复，阅读历史时新消息不强制滚到底部。任务列表按进行中优先和更新时间展示；断网、关闭重开或重试不重复创建任务、不重复执行已确认操作。长会话、指定电脑、搜索、终端和子 Agent 协作按根目录第一里程碑条件单独验收。
4. **工作台：**在真实 PC 的同窗工作区逐项使用指定且已授权电脑的桌面、终端、Workspace、主机文件和 VS Code；核对接管、交还、失权、断线恢复和目标隔离。记录桌面应用实际资源来源，确认 Morde 界面来自安装包且未绕过安全边界。
5. **文件夹同步：**选择测试文件夹，确认默认或更改后的目标、项目名和范围并点击同步，验证目标、相对路径和状态；变更默认电脑不静默改变已有同步目标。本机增改删在再次点击前不改变云端，点击后正确应用；云端变化不反向修改 PC。冲突、目录不可访问和授权失效不误删、不误报完成。
6. **升级与下线：**旧版 PC 升级后有效凭证、服务器会话及可识别的本地草稿/队列按规则保留；新版可在用户 Web 页面不可用的条件下使用。完成过渡并下线后，浏览器中的用户页面及 `/app/*` 返回 404，后台与下载入口、PC 和 iOS 仍可用。
7. **审核与默认电脑：**在多个会话产生有权处理的审核事项，确认左侧提示和审核列表完整，批准与拒绝使用正确任务和请求版本；审核处理后任务状态以服务端更新为准，过期、撤权及结果未知不误报。输入框与新计划表单没有电脑下拉；普通对话不启动电脑，需要电脑时使用经授权的默认目标，明确指定的目标不被替换，默认电脑变化不迁移已受理任务或已有计划。
8. **对话反馈与审核卡片：**在真实 PC 中验证普通消息及任务消息受理后，`👌🏻` 出现在各自消息左下角；未受理、发送失败或结果未知不误显示。AI 实际处理时显示动态省略号，回复开始、等待审核、失败及断线等状态切换正确；在对话卡片及审核页分别处理审批，切换会话、刷新和另一端处理后状态一致，且不重复执行。

涉及文件的验证只在本机或本机隔离环境使用测试数据，不外发或发送文件；若某项真实云端验收受此限制无法进行，应注明未覆盖，不把本机替身结果写成真实云端验收通过。

## 9. 风险与待核实事项

- 工作台远端页面资源及跨站鉴权的本地化方式尚未证明；按第 5 节先验证，不能靠假设取消安全限制。
- `electron-updater` 是否配置并跑通、安装包签名和后台下载入口是否可用，需要实施时核实；旧版过渡依赖实际可用的升级路径。
- 不同来源和临时会话对草稿、附件和待发送队列的影响需实测；迁移前保留旧状态，避免丢失或重发。
- 新建计划不再提供电脑下拉后，默认电脑在何时绑定需结合现有计划和任务合同核实；旧计划目标不得被静默改变，执行中也不能擅自换电脑。
- 设计稿当前 `.message-reaction` 使用右侧定位；用户明确要求消息左下角，本方案和实施验收以左下角为准。
- 旧用户 Web 的部署版本、完整能力清单及已知缺口需在实施前冻结；本方案引用的路由是源码盘点，不等同于真实服务已全部可用。
- 本次通过 HTML 源码和既有说明梳理设计稿，未完成设计稿的浏览器视觉预览；具体像素、布局和视觉效果以实施时的设计稿对照及真实 PC 验收为准。
