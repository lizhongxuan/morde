# Morde 任务动态执行过程设计方案

> 2026-11-13。依据 [任务动态需求](Morde任务动态需求文档.md)编写，描述拟议实现，不表示能力已经接通。本文替代[旧任务动态设计](Morde任务动态重新设计方案.md)中与主 Agent、子 Agent 和工具详情有关的示意，其余不冲突的交互继续沿用。

## 1. 设计结论

以现有 Task 为唯一的任务入口，以 `task_steps`、`task_agent_sessions`、任务事件和各工具现有操作记录为事实来源。为步骤补充执行者、任务修订及稳定调用关联，并增加按需读取的安全工具详情；不新建一套任务、工具执行器或状态权威。

PC 和 iOS 先展示当前会话的任务列表，进入某个任务后，把其工作过程按“主 Agent → 子 Agent”分组；每次真实工具调用形成一条可查看详情的动作。任务状态、审批、结果和操作继续使用现有接口。重复消息是否关联到同一任务由会话路由决定，任务动态只展示已确认的关联，不在页面自行合并任务。

```text
DSH 主／子会话、已确认的工具调用与结果
        ↓  经过 Morde Worker、工具代理、授权和操作记录
现有任务步骤与会话关系 + 步骤执行者/调用关联 + 安全详情
        ↓  任务快照 + 现有事件流提示更新
当前会话任务列表 → 主／子 Agent 工作过程 → 单次动作详情
```

## 2. 现状和 DSH 复用

- [Task 详情](../server/internal/store/postgres/task_execution.go)在同一数据库快照读取任务和步骤；[TaskStep 契约](../server/openapi/portal.yaml)已有步骤 ID、顺序、类型、状态、标题和摘要，但没有步骤执行者、修订或工具详情。[子 Agent 会话](../server/internal/store/postgres/agent_sessions.go)保存父会话和委派步骤；现有 `child_jobs` 投影只包含当前修订，不能直接还原全部历史层级。
- [DSH Worker](../server/internal/worker/cloud_dsh_session_tree.go)接收工具调用时已有 Task、当前会话、调用 ID 和检查点围栏；子会话调用 ID 会按任务和会话命名空间处理。当前部分恢复路径会重新创建步骤，不能仅靠步骤 ID、工具名称或前端时间戳合并同一次调用。
- 当前依赖和锁文件固定使用 DSH `0.2.2-rc.1` 的 `dsh-session`、`dsh-session-projection`、`dsh-tools` 和 `dsh-tool-executor-native`。已安装的 DSH 会话提供 `tool/call`、`tool/result` 关联，`dsh-tools` 提供 `presentCall`/`presentResult` 展示类型和接口；Morde 现有[工具代理注册](../runtime/morde-cloud-runtime/src/engine.mjs)尚未接入这些展示接口，安装组件不等于详情已可用。
- 本机 DSH 上游检出 `fcc0ad462172` 中的 `dsh-agent-tool-presentation` 是已弃用的执行器选择器，不是现成的任务动态页面；上游 Web 等工具也不能直接替代 Morde 的工具代理与授权。实现时沿用已安装的 DSH 事件和展示约定，通过 Morde 适配，当前方案不新增或升级插件；如另需插件，再按仓库规则核验版本、许可证及隔离。
- 当前 Worker 的委派入口限制父会话为根会话。界面和数据投影应保留实际存在的父子层级，但本方案不宣称或新增多层委派执行能力。

## 3. 界面与交互

### 任务列表

继续使用当前会话的任务列表，按“待你处理、进行中、已暂停、最近结束”分组；最近结束默认折叠。卡片显示任务标题、真实状态、最近一条可展示进展和更新时间。无进展时使用实际状态；列表不完整或读取失败时提示状态不可用，不把缺失数量显示为零。

列表只显示 Task，不把消息、工具调用或子 Agent 当作新的顶层任务。已关联的多条消息共用对应 Task；关联尚未建立时不推断。纯文字对话未创建 Task 时不造任务卡片。

### 任务与动作详情

点击任务后显示任务目标、状态、时间、待用户处理事项、默认可见的工作过程和结果。工作过程先显示主 Agent，再根据真实父子关系显示子 Agent；同层子 Agent 按委派步骤顺序编号，编号由稳定的会话关系和步骤顺序确定。每个分组内按步骤序号排序，多个并发步骤可同时显示进行中。归属无法确认的历史步骤放在“归属待确认”，不猜测属于主 Agent 或某个子 Agent。

界面的“主 Agent”分组展示能证明属于该任务的主协调动作及该任务根执行会话的动作；会话协调器和任务根执行会话是不同执行上下文，不因页面分组合并其身份。尚不能确认任务归属的协调消息不写入此任务过程。

每个动作显示状态图标和文字、标题、可展示的对象或简述；点击后查看该次动作的工具、时间、可展示的输入和结果或失败原因。没有记录、记录已过期、部分截断及没有权限分别提示；不提供未经核实的内容。主 Agent 整理最终结果前，子 Agent 完成只表示该子任务完成。Task 已完成但结果整理仍为待处理或进行中时显示“任务已完成，回复整理中”；整理失败时显示失败，最终回复发布后链接到实际会话消息。

PC 复用现有侧栏，宽度不足时覆盖聊天历史但不压住输入框；iOS 复用任务详情页，动作详情进入下一级页面或弹层。返回保留分组和滚动位置；新事件不强制滚动或关闭详情。状态同时使用文字和图标，按钮支持键盘与屏幕阅读器。

## 4. 记录和关联

### 步骤身份

在现有 `task_steps` 上增加可为空的执行会话、任务修订、调用关联键及其必要的只读展示元数据；历史步骤允许为空。执行会话通过 `(task_id, session_id)` 关联 `task_agent_sessions`，父子关系仍以该表为准。每次调用以 **Task + 执行会话 + 已规范化的 DSH 调用身份**确定同一动作，内部关联键复用现有 `AgentOperationKey` 的稳定哈希；调用名称和参数摘要用于冲突核验。对有调用身份的步骤建立唯一约束，接口不向用户暴露内部调用键。

同一次调用的准备、派发、结果和恢复更新同一 `step_id`；恢复代次变化不生成新动作。实际重新发起且使用新调用身份的操作生成新步骤。同一调用身份对应不同工具或参数时按冲突处理，不把两次操作合并，也不重复派发。请求摘要以 Worker 收到并校验的原始 DSH 调用为准；MCP 分支随后将 `mcp_call` 解析为具体工具别名时，仍复用该调用身份，不能被误判为另一次调用。步骤序号在持有任务的事务锁时分配，以避免两个子 Agent 并发取得相同序号。

调用所属修订在首次受理时固定；迟到的旧修订结果只能更新有合法来源的旧步骤，不能修改当前修订的状态或结果。未经现有租约、Agent 代次、会话、检查点和授权围栏确认的迟到结果不能当作已完成，按现有操作账本核对；结果不明显示“结果待确认”。

委派动作复用创建子会话时已有的 `subagent` 步骤及父子关联；子会话的运行、终止及结果回传仍以现有会话和步骤记录为准，不将“已创建子会话”解释为“子任务完成”。主协调器的受理或委派动作仅在消息与 Task 的关联已经持久确认后投影，不能把整个会话的协调日志复制到任意任务。

### 工具动作的产生

在 [Worker 的工具调用入口](../server/internal/worker/cloud_dsh_session_tree.go)将当前执行会话、稳定调用身份和修订传到 [CloudDSH 工具代理](../server/internal/app/cloud_dsh_tool_broker.go)。在现有代理分支中覆盖 Workspace、搜索、命令、电脑、MCP、技能等实际调用，以及由子会话管理器处理的委派；不能只覆盖普通 Host 工具。准备、审批、派发、终态和恢复仍经过各自现有的授权及操作账本，不由展示层执行或重试工具。

DSH `tool/call` 只证明模型提出调用；收到它后至多显示“等待／准备中”。确认实际派发后才显示“进行中”；有可核验的成功或失败结果后才显示对应终态，结果状态以工具代理和操作账本的结构化记录为准，不能仅凭 DSH `tool/result` 是否存在或文本推断成功。代理直接返回且没有既有操作账本的只读分支，也须先将该次调用的可验证结果与步骤持久关联，才能显示结束。拒绝或校验失败应注明未派发，不能显示曾执行。

有既有操作账本时，它仍是执行状态和恢复的权威。步骤在派发前绑定对应操作键；步骤关联、可展示资料和对应更新事件在同一事务提交，提交前不派发新操作。派发前提交失败时，任务显示真实等待或失败状态，待安全恢复后继续。任务快照在同一数据库读快照中投影步骤与操作状态，操作状态发生变化继续产生现有 `task.operation` 或 `task.step` 更新信号。若操作已成功入账但步骤更新前进程中断，恢复时按同一键读取账本修复该步骤；若外部结果未能确认，则保持未知并走既有对账，不为了补显示重新执行。结果已确认但展示资料写入失败时，保留账本结果并提示详情暂不可用，安全修复展示记录，不能重做工具操作。

DSH 的 `presentCall`/`presentResult` 可复用为工具展示语义：对 Morde 已授权的代理工具提供或适配简短标题、类型和必要字段，再由服务端按工具类别校验、脱敏并持久化。现有代理尚无这些回调，需要实际接线和测试；DSH 默认回退到原始结果的行为不能直接用于 Morde 用户界面。未适配的工具只显示安全的名称、状态和“详情不可用”，不得把原始参数或结果直接透传。

### 状态投影

沿用 `TaskStatus`、`TaskStepStatus` 和各操作账本，不新增独立的执行状态机：

| 已确认依据 | 动作显示 |
|---|---|
| 已受理但未派发，或操作处于 `prepared` | 等待中／准备中 |
| 操作已派发且未确认终态 | 进行中 |
| 真实存在待处理的审批或澄清 | 等待用户处理，并链接到对应事项 |
| 已确认操作成功或失败 | 已完成／失败 |
| 已确认中断，或结果无法确认 | 中断／结果待确认；无证据时不推断成功 |

子 Agent 状态依据其会话关联的步骤。主执行会话在创建及 DSH `agent/status` 变化时，将 `idle`/`running` 最近观察值通过现有受围栏保护的 Worker 通道持久化到会话展示元数据，并产生现有任务事件以刷新快照；携带执行代次和观察时间，当前 Runtime 尚未接线，实施时需同步调整协议与测试。Worker 退出、租约或授权失效时，旧观察不再视为当前状态。DSH 的 `idle` 只表示当前空闲，不能作为任务完成或“正在等待某个子 Agent”的证据；观察失效或缺失时显示状态待确认。该观察只是展示信息，不改变 Task 状态。单个步骤或子 Agent 的完成不改变任务总状态，最终回复仍以现有结果整理和消息发布记录为准。

## 5. 工具详情和访问边界

为 `task_steps` 增加一对一的可选详情记录，作为只读展示资料，不作为执行账本。只保存经工具类型白名单选择、校验和脱敏后的必要字段与资源引用；不保存完整原始参数、凭据、模型内部推理或原始检查点。详情正文使用项目现有密钥管理与认证加密，绑定 owner、Task、步骤和修订；关联摘要用于校验。详情至少保留到任务不再可查看或恢复，任务删除时随任务清理；来源被删除、授权失效或按既有规则过期时保留步骤并标明详情不可用。

工具适配按已确认结果提供有限信息：

| 工具类别 | 可展示的信息 | 约束 |
|---|---|---|
| 文件读取／写入 | 操作、授权范围内的相对路径、可查看的结果或错误 | 校验当前 Workspace/文件权限；读取、写入和生成产物分别表述 |
| 搜索／网页读取 | 可展示的查询、结果摘要、可用来源链接或空结果 | 不展示提供商凭据、内部服务地址；链接按现有安全策略处理 |
| 命令 | 可安全展示的命令、输出摘要、实际退出码或中断原因 | 命令和输出可能含密钥；不能安全识别时隐藏对应内容，不能从文本猜测退出码 |
| 云端电脑／MCP | 实际授权目标、操作类型、可展示的结果或错误 | 当前设备、连接器和资源权限均须有效；不展示凭证、Cookie 或未验证路径 |

详情分段保存并限制大小，列表只返回短摘要，点击详情才读取可展示内容；展示更长内容时明确标记截断。只允许普通文本和经过现有处理的安全链接，不能把工具输出当 HTML 执行。图片、文件及产物使用已有授权资源入口，不通过任务事件流发送原始二进制。

每次读取同时校验当前账号/客户端身份、`task:read`、会话或项目成员资格，以及具体文件、电脑、连接器等资源的当前权限；能读取任务不代表能读取其所有工具资源。任务快照中的标题和摘要同样不能泄露受限资源，必要时仅返回通用操作名称。无权访问任务或步骤时沿用现有隐藏资源的错误语义；仅部分详情受限时不泄露受限内容。详情响应禁止共享缓存；PC/iOS 在登出、切换账号或收到授权失效后清除对应详情缓存并丢弃旧请求的迟到响应。

## 6. 接口和同步

| 接口 | 设计 |
|---|---|
| `GET /api/conversations/{id}/tasks` | 沿用当前会话的 active/recent 列表和分页；只请求列表摘要，不逐个读取工具详情。 |
| `GET /api/tasks/{id}` | 扩展 `TaskStep` 的可选执行者引用、修订、可确认的执行阶段和详情可用性；增加该任务的主／子执行者及父子关系投影。步骤、关系及 `event_sequence` 在同一快照读取。保留现有 `steps`、`child_jobs` 和其他字段语义。 |
| `GET /api/tasks/{id}/steps/{step_id}` | 新增只读步骤详情，返回 Task/步骤身份、同快照的事件序号、可展示的工具名称、对象、时间、输入／结果分段，以及不可用或截断状态；读取前执行上述授权。 |
| `GET /api/tasks/{id}/events` | 沿用现有 SSE 游标与 `task.step`、`task.operation` 等事件；事件只通知状态变化和安全标识，不增加原始工具参数或输出。 |

`TaskStep` 新字段和执行者投影是现有任务事实的只读表示，不是另一套 Task API 或独立任务。`child_jobs` 保持当前修订的既有用途；新投影可包含已确认的历史子会话，使旧修订过程可查看。现有 Task 快照已返回全部步骤；前端对长列表分段渲染、按需展开详情，不在每张任务卡片上加载详情。

客户端先取任务快照及同快照 `event_sequence=S`，再从 `S` 订阅；事件只用于使快照或当前打开的动作详情失效并重新读取。重复序号忽略，出现缺口或 `task.snapshot_required` 时重新取得完整快照并从新序号继续。并发请求返回较旧快照时不得覆盖较新结果；步骤详情也以 Task、步骤、会话范围和返回序号核对，避免切换会话或授权失效后显示迟到内容。

保留现有事件流断线重连和终态处理；未订阅到事件的活动任务仍须通过当前会话列表刷新状态，打开的任务优先订阅，不能因现有并发流数量限制而永久停留在旧状态。打开面板、刷新和重新读取均是只读操作。

## 7. 变更边界与历史数据

- 数据层扩展 `task_steps` 的关联字段及一对一详情；`task_agent_sessions` 继续负责父子关系，并补充主执行会话的状态观察元数据。现有 `task_events` 和工具操作账本继续为执行事实来源。Schema 变更通过迁移完成，与 [公共约定](实施/00-总览与公共约定.md)、OpenAPI、服务端实现及测试在实施变更中同步。
- 服务端在 DSH Worker、工具代理及各实际分支传递会话和调用身份，在持久化边界生成安全投影；列表和详情读取沿用 Task 的访问检查并增加资源级检查。现有 `TaskStep` 生成、审批、操作账本和恢复路径必须一起调整，不能只在前端按标题猜测。
- PC 的 [Assistant](../web/portal/src/routes/Assistant.tsx)和 iOS 的 [任务详情](../clients/nanoMuse/android/src/ios/NanoMuse/MIFTaskViews.swift)消费同一投影。两端保留现有审批、暂停、继续、停止、成果和本机文件读取入口；消息、工具详情和任务状态缓存按账号及会话隔离。
- 迁移添加新详情表和可空关联字段，不清空现有步骤和会话。历史步骤仅在已有记录能唯一证明调用和执行者时关联；不能证明时保留并显示“归属待确认／详情未记录”，不从工具名猜测，也不直接把旧检查点解密给客户端。升级时正在运行的旧调用，若能由其持久操作键与步骤事件唯一对应则复用原步骤，否则保留旧记录并标明信息不足，不通过重放制造一次新操作。
- 重复消息自动归并属于[对话体验需求](<Morde AI助手对话与任务执行体验需求文档.md>)的会话路由能力，是“重复请求只显示一个任务”的前置依赖；本方案不通过隐藏多张任务卡片掩盖后台重复建任务。

## 8. 验证

1. 在隔离测试环境运行真实 DSH：主执行会话调用工具并委派至少两个并行子 Agent，各自实际调用工具和回传结果。PC、iOS 对同一 Task 显示正确的主／子归属、状态、动作详情及最终结果；文件读取、搜索和命令的可展示字段与实际调用一致。
2. 两个会话中使用相同工具和相同调用 ID 时保持两条动作；同一会话同一调用恢复只保留一条，参数冲突不合并。覆盖审批前拒绝、空结果、明确失败、结果未知、并发执行、停止和旧修订迟到结果。
3. 分别在调用已记入检查点但未派发、已派发但结果未知、结果已入账但步骤尚未更新时中断并恢复；核对不会重复执行，步骤不重复，结果未知不伪报成功，已确认结果可以恢复展示。
4. 覆盖 SSE 重连、事件重复/乱序/游标过期、跨端刷新、切换账号或会话后的迟到响应，以及权限撤销期间打开详情；确保进度和详情不串任务、不泄露凭据或受限资源。长文本、恶意 HTML、失效链接和详情截断均有明确处理。
5. 使用旧任务和升级时在途任务验证可空字段及唯一证据关联；缺失信息显示未知，历史记录不丢失。验证同一会话重复请求在会话路由关联后只出现一个 Task，独立任务的暂停和停止互不影响。
