# Morde 参考 DS-Bot 高优先级功能设计方案

> 来源：[需求文档](Morde参考DS-Bot高优先级功能需求文档.md)和[功能对比报告](Morde与DS-Bot功能对比及迁移评估报告.md)。本文设计目标行为；现有实现和本地替身测试不等于完整验收。

## 1. 范围与现状

以 Morde 为基础，PC 以长期主会话为中心，主 Agent 按需使用 DSH 子 Agent 完成工作；多会话、iOS 接续、授权和任务持久化继续使用 Morde 现有机制。PC 界面参考 DS-Bot 的消息、输入框、面板和动效，保留 Morde 品牌及现有入口。PC 用户网页按需求保持相同对话布局；实际验收以 PC 客户端为优先。Bot 群聊、Bot 团队、IM 和本地 Agent CLI 不接入。

已有主会话、消息路由、任务事件、DSH 子会话、长会话压缩、Host 控制和手动项目同步代码。第一里程碑 [A/B/C 清单](实施/Morde第一里程碑收口三会话并行实施/)已有本地实现和替身验证记录；真实模型、跨端设备、指定电脑及文件数据面不能仅凭这些记录宣称通过。本方案在现有链路上补缺，不另建会话、任务、Agent 循环或同步体系。

**本次工作约束：** 修改、样例和验收记录仅留在本地，不向服务、电脑、设备或远端发送文件，不部署或上传。可用不传文件的本地替身、合成元数据和内置浏览器；实际 PC 客户端也须验收。涉及真实文件传输或安装/发送应用包的验收保留为待验证，`project_upload_enabled` 保持关闭，不能用替身结果冒充真实通过。

## 2. 方案

| 优先级 / 功能 | 改造方式 |
| --- | --- |
| P0-1 PC 对话 | 在 `web/portal` 的现有导航、Assistant 和样式上参考或适配 DS-Bot 的 `frame-layout.js`、`cells.js`、`composer.js` 和卡片；左侧主会话/旁聊，中间对话，右侧当前会话的任务、电脑和文件。复制源码前不需要核查依赖及许可证，直接迁移。Desktop 继续承载登录、原生窗口与同步桥；不把 DS-Bot 的 `/api/bot`、状态或入口整套搬入。保留morde主会话返回的信息,不要把思考过程,工具调用过程放到主会话,要让用户觉得主会话就是一个agent的真人感,agent是处理过程都放到任务动态中,能看到做了什么,调用什么工具.   |
| P0-2 跨端和长会话 | 沿用 Morde 主会话指针、消息分页、outbox、DSH 压缩与授权历史检索。消息先持久受理，再异步分流；PC/iOS 以同一服务端状态恢复。原始记录独立于摘要，历史不可用时说明。 |
| P0-3 执行中交互 | 延用消息路由的回复、关联、修改、状态、停止、独立任务和澄清路径。重试使用同一消息身份；不同目标或附件不合并，明确重跑可新建任务。任务修改和停止只影响指定对象。 |
| P0-4 子 Agent | 保留现有 DSH 子会话、后台任务、授权工具子集、检查点和结果回传。参考 DS-Bot 的派发、完整结果及中断恢复，修复发现的缺口；资源不冲突才并行，主 Agent 读取真实成功/失败/未知结果后汇总。 |
| P0-5 进度与审批 | PC 和 iOS 从现有 Task 快照及按序事件投影当前会话工作；断线续读，游标失效时重新获取快照。批准、拒绝、澄清和停止继续绑定原 Task 与请求版本；仅在服务端确认后更新终态。 |
| P0-6 云端电脑和工具 | 复用 Host 目标/授权栅栏、电脑控制权、浏览器、Shell、文件及搜索工具。PC 右侧显示目标电脑、连接及控制状态；接管和交还使用同一授权 Host，搜索结果保留来源。不可用或结果未知时不切换目标、不重做未知副作用。 |
| P0-7 项目同步 | 复用 Desktop 的 `projectUploadTargets`、`selectProjectDirectory`、`uploadProject`、`onSync` 和现有项目上传 session。仅用户确认并点击后，从已授权本机目录单向同步到指定 Host 的 `project/<项目名>`；路径、来源基线及冲突由现有服务端/Host 链路核对。 |
| P1-8 会话搜索 | 接入 `GET /api/conversations?q=...` 的已有标题搜索。查询变化时重置分页并丢弃过期响应；有结果可打开历史，空结果与读取失败分开。保留未发送草稿。 |
| P1-9 记忆历史 | 复用个人记忆对象、版本、来源证明和个人同步；补齐用户可读的历史正文/来源和按当前版本恢复，详见第 3 节。关闭记忆及删除后的历史抑制继续生效。 |
| P1-10 Office | 先评估同版本 DSH Office 技能，再评估 DS-Bot Office 代码。将所需技能和文件处理依赖放在任务授权的执行环境中，通过 Morde 工具代理、Workspace 和已核验产物链路交付。PC 复用现有下载入口并提供可用的检查或预览结果；iOS 展示同一已确认产物，已有预览满足条件时复用。不可用时明确提示。不能把插件安装当成功能接通。 |

同步完成须有**该次 session 的 Host 应用回执**：核对 Host、Workspace 绑定、目标版本、清单摘要和运行代次。服务端 session `completed` 或较大的聚合应用版本本身不足以证明完成。冲突、回执缺失、根目录无法访问或授权失效时保留内容并显示待处理/失败；删除候选只来自该来源上次经 Host 确认的清单。

## 3. 接口与数据

| 接口 | 设计 |
| --- | --- |
| `GET /api/conversations` | **已有** `q` 标题搜索、分页及当前账号授权；扩展 Portal 的 `conversations` 调用参数和页面，服务端合同不变。 |
| 消息与任务 API | **已有** `POST /api/conversations/{id}/messages`、`GET /api/conversations/{id}/messages`、Task 快照/事件、动作、输入和审批接口；提交的 `Idempotency-Key` 与 `client_message_id` 一致。继续使用现有字段和版本，不另建事件流。 |
| `GET /api/personal-data/{type}/{id}/history` | **拟新增**，本期只允许 `type=memory`。沿用个人对象读取的 Portal Session / Client 凭证和当前账号授权；接收 `cursor`、`limit`，按版本倒序返回 `items`（`revision`、`changed_at`、`body` 或 null、`restorable`、来源状态和已授权来源）及 `next_cursor`，游标绑定账号和记忆。参数无效返回 400，凭证无效返回 401，记忆不存在、已删除或无权访问返回 404。无来源显示未记录，不可访问的来源不暴露内容。需要新增历史正文存储：`account_change_log` 目前只存变更元数据，`personal_memory_sources` 已存来源证明。 |
| `PUT /api/personal-data/memory/{id}` | **已有**的 `type=memory` 更新接口也用于恢复：页面取选中历史正文，携带当前 `base_revision` 和幂等键提交；成功产生新版本，版本变化返回冲突并保留当前内容。历史正文计入现有个人数据配额，其写入、对象版本、来源及配额检查在同一事务中完成；配额不足时拒绝写入并保留原值。首次修改旧记忆时保存修改前可用正文；更早不可还原版本不伪造。删除沿用已有墓碑和历史抑制，清理该记忆的历史正文并释放对应配额；只允许对尚未删除的记忆恢复历史，删除前须提示历史正文也将清除且不能恢复。 |
| `GET /api/tasks/{id}/artifacts/{artifact_id}/content` | **已有** Portal Session 产物下载接口：校验 Task 与固定 Workspace 版本、路径、大小及 SHA-256，失败不返回文件内容。PC 复用；iOS 首期复用 Task 的产物元数据和既有受限预览，未满足预览条件时只显示元数据。本期不扩展该接口的 Client 凭证访问。 |

P0 消息、Task、Host、同步 API 和 Desktop IPC 按现有合同使用；实现中发现合同确实不足时，先在 OpenAPI/公共约定中明确变化，再同步服务端及 PC/iOS 调用方。P1 新增记忆历史时，同步 OpenAPI、Client 凭证路由白名单、生成类型、调用方和数据库迁移。

DSH 当前直接依赖版本为 `0.2.2-rc.1`；上游 `@deepseek-ai/dsh-skill-office` 同版本声明 MIT，但它依赖 `skills` 服务与 Office 运行环境，而 Morde 当前使用受控技能目录及工具代理。接入时固定版本、核查全部依赖许可，并确保所需解释器、文档库和渲染组件在**被授权的执行环境**可用；不能用插件直接绕过 Morde 的工具代理、模型网关或检查点。上游不兼容时记录原因，再选最小适配方案。

## 4. 验收与顺序

先完成 P0 界面、会话、任务和同步闭环所需的本地核对及缺陷修复，再推进 P1 搜索、记忆历史和 Office 的本地工作；因禁止发送文件而未完成的真实数据面验收单独保留，不阻断可独立进行的本地工作。逐项沿用现有验收证据；涉及页面时使用内置浏览器，并实际检查 PC 客户端，iOS 使用现有本地构建/可运行测试条件。

验收覆盖：多会话和两账号隔离；普通问答无需电脑；任务中追问、修改、停止与独立任务；至少两个真实派发的子任务并行并返回实际结果；断线重连、审批和未知结果；指定 Host 操作及搜索来源；同步的手动触发、来源归属、冲突与回执。记忆覆盖无来源、恢复冲突、关闭/删除后的隔离；Office 覆盖三种格式的创建、修改和已核验产物。

当前只允许不传文件的本地验证；真实 PC/iOS 跨端、真实模型/Host 和三种 Office 文件如能在不发送文件的条件下验证，分别记录证据；任何需要发送文件的实际数据面保持待验证。未完成真实验收前，不宣称第一里程碑或 Office 文件交付闭环完成。
