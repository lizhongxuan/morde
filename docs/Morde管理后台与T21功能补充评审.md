## 结论

T21 已覆盖共享工作区的存储、绑定、同步、PC App、Portal、Host 生命周期、Site 和 Host 成员共享；T18 单独负责多物理节点承载与跨节点迁移。需要补充的是**管理员跨用户、Host、Workspace 的联查与限制能力**，以及资源池和创建策略的服务端合同。Kubernetes 托管不在 T21 或 T18 的已列任务内，应单独确定实施范围。

## 需要补充的管理功能

### 1. 资源归属联查与状态解释

管理员应能从用户查看其全部 Host、Workspace、绑定记录、活动任务/会话、共享成员和承载位置；从 Host/Workspace 反查所有者。Host 列表不能用单个“工作区名称”表达一对多关系。Workspace 列表须显示未绑定、绑定中、Host 已应用、项目已就绪等不同状态；服务端已保存不代表 Host 已应用。容量也须区分 T21.21 的**单 Workspace 当前版本逻辑用量**与**所有者块文件已分配物理额度**，不能相加或互作余量。只读取容量、版本、状态等元数据，不默认开放用户文件正文或凭证。

**验收：** 同一 Host 绑定两个 Workspace、一个 Workspace 未绑定、一个绑定待应用时，三个页面数量与状态一致，列表和详情能互相跳转；权限不足时整条关联查询被拒绝。

### 2. 平台级限制与恢复

分别定义用户**冻结操作**、用户**禁用登录**、Host **禁用操作**、Workspace **隔离**四种管理状态，和运行/同步状态分开展示。新请求须在 Portal、Gateway、Runtime、任务、API Key、MCP、PC 设备同步及 Host 共享入口统一复核。现有 owner 级 AI 停止入口和用户 `disabled` 字段可复用，但不足以证明所有长连接、设备和原生进程已退出。禁用 Host 应保留 Workspace 数据及绑定；隔离 Workspace 不应删数据或自动解除其他资源的限制。解除某一层限制只撤销该层，不自动续跑旧任务。

**验收：** 限制动作有原因、影响预览、幂等操作 ID、阶段结果和审计；未确认退出的桌面/终端/同步/原生进程显示“处理中/未知”，不可标记“已完成”。冻结所有者后，受邀成员不能绕过所有者的限制继续控制 Host；用户恢复后，独立禁用的 Host 与 Workspace 仍受限。

### 3. 多 Workspace Host 的隔离边界

T21.06 已明确：同一 Host 的桌面应用共享 `gem` 系统账号，Shell bind mount 也不能隔离已有跨 Workspace 硬链接。目前只能保证 Morde 工具按绑定路由，**不能承诺 Host 内 Workspace 间机密隔离**。因此管理员隔离一个 Workspace 时，服务端必须先验证其 Runtime 路由、设备同步与在途写入已被阻断；如桌面/终端/共享账号仍可访问该 Workspace 文件，应扩大为 Host 级限制或保持“隔离中”，并在影响预览中列出同 Host 的其他 Workspace、成员与 Site。

**验收：** 共享账号访问路径未被证明隔离时，后台不显示“仅该 Workspace 已隔离”；失联、外部写入者未停或旧绑定版本未退场时保留保护性拒绝与待核实状态。

### 4. 资源池、放置策略与承载边界

物理机池的节点注册、心跳、容量、维护和迁移应衔接 T18；后台补充池级暂停新分配、受影响 Host 清单和容量解释。K8s 集群接入、namespace/Quota/StorageClass/网络能力、调度与隔离需另立范围；不能因设计稿画了 K8s 池就认为已交付。创建策略需有版本、优先级、适用范围、规格/并发/租期上限、允许池与镜像、预演结果、失败原因；新版本只影响新建或明确重建的 Host，不能静默迁移存量 Host。

**验收：** 禁用用户、池暂停、容量不足、存储不可达、架构不匹配、K8s Quota 拒绝分别显示准确原因且不预留资源；节点失联不推断 Host 已停止，也不在另一节点启动同一可写 Workspace。

### 5. 操作记录与审计闭环

每个禁用、恢复、维护、迁移和策略发布动作都应保存操作者、原因、对象、影响预览、请求键、逐阶段结果及最终核验时间。查询按目标、操作者、时间和状态过滤；失败或未知可从已生效阶段恢复/重试，不重复执行已完成步骤。审计只给元数据与操作证据，不包含 Workspace 文件正文、密钥和用户凭证。

**验收：** 并发管理员操作不会覆盖更新后的管理状态；重复请求返回同一操作结果；“请求已接受”“准入已封锁”“进程已停止”可分别查询。

## 设计稿调整与待决事项

[管理后台设计稿](设计图/Morde-管理后台设计稿.html)已补上 Host 对多个 Workspace、未绑定 Workspace、绑定版本/应用/就绪状态、逻辑与物理容量口径，以及共享成员和 Site 对禁用影响的参与；新增物理节点详情，承载节点失联时展示待核验的 Host 与迁移条件。资源池页面标明物理节点管理对接 T18、K8s 托管待实施。管理动作保持折叠，影响预览呈现无法证明的停止或隔离结果。

仍需产品与实施负责人确定：① 冻结用户时，对绕过 Morde 启动器的原生进程采取何种处置；② K8s namespace 按用户、团队还是资源池划分；③ 共享 `gem` 账号下能否提供可验证的单 Workspace 文件隔离。确定前，界面和 API 均不得承诺这些边界已经成立。
