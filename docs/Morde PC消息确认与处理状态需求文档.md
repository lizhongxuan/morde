# Morde PC 消息确认与处理状态需求

## 目标与范围

让用户在 `morde-pc` 对话中看清消息是否已被主 Agent 接下，以及主 Agent 是否仍在处理。本文补充[对话与任务执行体验需求](<Morde AI助手对话与任务执行体验需求文档.md>)，涉及 PC 消息展示和主 Agent 的处理状态；同一会话的消息与状态继续遵循跨端接续规则。

## 功能与规则

1. **用户消息。** 用户发出的消息文字不显示系统添加的下划线，文字下方也不显示装饰横线。保留用户输入的原文，包括下划线字符，链接仍可使用。
2. **👌🏻 确认。** 主 Agent 收到消息后，若判断工作需要较长时间，并已接下开始处理，应主动在对应用户消息下方标记 👌🏻，表示“收到，正在做”。预计很快完成的工作直接处理并回复，不标记。是否标记只由主 Agent 对本次工作预计耗时的判断决定，与消息主题、关键词或操作类型无关；消息发出、服务端受理或等待一定时间都不能自动触发标记。
3. **确认含义与保存。** 👌🏻 表示主 Agent 已接下处理，不表示任务已完成或成功；实际进度和结果仍以任务状态及回复为准。标记属于对应的用户消息，应随消息记录保存；刷新或从其他客户端打开同一会话时显示一致。需要时仍可在对话中反馈实际进展、提问或请求审批。
4. **处理气泡。** 主 Agent 实际开始思考、执行或协调该消息对应的后台工作时，在对应会话的消息流中显示 AI 处理气泡。处理期间持续显示，即使已经出现中途回复或进度；处理结束、失败、停止，或该工作进入等待用户答复、授权等非处理状态时，停止显示对应气泡并呈现真实状态，恢复处理后再显示。气泡与 👌🏻 相互独立，未标记 👌🏻 的短任务处理期间也显示气泡。
5. **状态准确。** 消息待发送、已受理但主 Agent 尚未开始，或断线导致处理状态未知时，不显示为正在处理；应显示实际等待、失败或状态未知。断线不等于取消任务，恢复连接或重新打开会话后按服务端真实状态显示。并发工作时，气泡应能关联对应的消息或任务，一项结束不影响其他仍在处理的工作。
6. **样式和动效。** 处理气泡的样式与动画遵循[冰淇淋蓝 UI 规范](design/ice-cream-blue/morde-icecream-blue-ui-spec.html)中的“消息气泡”和“动画规范”：左侧白底描边气泡、淡蓝吉祥物和依次跳动的蓝色圆点，并按系统减少动态效果设置调整动效。气泡显示时段以本需求的实际处理状态为准；文案应符合当前阶段，如“思考中…”或“处理中…”。

## 验收条件

- 在实际 `morde-pc` 发送消息，正文没有自动下划线或装饰横线，用户输入的下划线字符仍在，消息链接可用。
- 快速工作由主 Agent 直接完成并回复，不出现 👌🏻；预计耗时较长的工作由主 Agent 接下并作出标记决定后，👌🏻 才出现在对应消息下方。仅发送消息、服务端受理或等待一段时间均不会自行出现标记；同类工作按预计耗时判断，不按内容关键词判断。
- 主 Agent 正在处理短任务或长任务时，在相应对话中看到符合规范的动态气泡；是否显示气泡不依赖 👌🏻。已有中途回复或后台工作仍在执行时，气泡继续显示；处理完成、失败、停止或等待用户时，对应气泡消失并显示真实状态。
- 消息未送达、尚未开始处理或处理状态未知时，不误显示正在处理。断线重连、刷新、重新打开会话或在同账号另一端查看时，消息及 👌🏻 与记录一致，处理提示与实际状态一致，不重复创建任务。
- 同一会话中两项独立工作并发时，处理提示能区分所属工作；其中一项结束后，另一项仍在处理的提示保留。开启系统减少动态效果后，气泡按 UI 规范减少或停止动画。
