# Morde PC 输入框优化需求文档

## 目标与范围

优化 `morde-pc` 对话输入框的聚焦样式、多行输入体验和底部控件尺寸，使输入区更清爽、紧凑。本次范围为 PC 对话输入框；附件、模型选择、语音、工具入口和消息发送等现有功能保持可用。

## 功能与规则

1. 点击或使用键盘进入文字输入区时，不出现参考图中输入区内部的蓝色聚焦边框或光圈；输入框整体保留原有浅蓝外框和冰淇淋蓝风格。通过光标和非蓝色文字提示体现输入焦点，底部控件仍须有可辨识的键盘焦点。
2. 输入、粘贴、语音转写、恢复草稿或调整窗口宽度后，文本超出当前可见行数时，输入区随实际显示行数自动增高，最多显示约六行；超过上限后输入区保持高度，内容可在输入区内滚动查看和编辑。删除内容后，输入区随之回缩，但不低于初始高度。自动换行和手动换行都计入显示行数。
3. 压缩输入框底部操作栏的高度与间距，尤其缩小发送按钮，同时保留附件、模型选择、语音及按需出现的工具等入口；按钮、附件和状态信息不能被遮挡或挤出可操作区域。
4. 保留现有输入和发送方式：Enter 发送、Shift + Enter 换行；中文输入法正在选字时，Enter 用于确认输入，不应误发消息。附件等现有发送条件、草稿和功能状态不因界面调整而改变。
5. 当用户已将对话信息区滚动到底部时，输入区因内容增高或回缩，对话布局应同步重排。消息列表的可视区域边界跟随输入区上沿变化，最新消息保持显示在输入区上方；不得让输入区覆盖、遮挡或裁切消息。用户不在底部时，沿用现有滚动位置行为。

## 设计稿建议

- 初始输入区约两行，最多六行；设计稿按 24px 行高展示，输入区高度从 48px 增至 144px。
- 发送按钮由现有 40px 缩为 32px，底部图标使用紧凑尺寸；保留可操作的点击区域和清晰的禁用、悬停及键盘焦点状态。
- 可交互设计稿：[Morde PC 输入框优化设计稿](design/Morde-PC输入框优化设计稿.html)。其中发送、附件、模型及语音仅展示界面，不连接实际服务。

## 验收条件

- 聚焦输入区并输入文字，内部不出现蓝色描边或光圈，外框样式不因输入而亮起；可以从光标和输入提示辨认焦点，使用键盘切换底部控件时焦点清楚可见。
- 输入或粘贴超过初始高度的内容，输入区随内容增加，约六行后不再增高；继续输入可在内部滚动，删除内容后高度回缩。窗口宽度变化引发自动换行时同样成立。
- 底部操作栏和发送按钮比现状紧凑；有附件、工具入口或状态信息时，相关内容与控件仍可见、可操作，不与文字重叠。
- Enter、Shift + Enter 和中文输入法选字行为正确；附件、模型、语音、工具和原有发送条件不受影响。
- 对话信息区滚动到底部后，输入区逐步增高至六行并再回缩，最新消息始终完整显示在输入区上方；消息列表随输入区高度变化调整可视区域，不出现消息被覆盖、遮挡或跳离底部的情况。
