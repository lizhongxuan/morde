# Morde PC 端设计稿对齐技术设计方案

> 方案稿，描述如何把现有 PC 产品调整到设计稿，不表示改造或验收已经完成。界面以 [PC 对话与云端电脑设计稿](<设计图/Morde-PC对话与云端电脑设计稿.html>) 的当前版本为准，业务规则以 [PC 端布局与云端电脑体验需求](<Morde PC端布局与云端电脑体验需求文档.md>) 和项目根目录 `AGENTS.md` 为准。

## 1. 目标与现状

PC 客户端和 PC 用户网页共用设计稿的布局、样式和交互：左侧主导航与二级菜单、中间对话、右侧跟随会话的工作区，以及统一窗口顶栏。以真实数据和可执行操作替换设计稿的示例数据；“窗口预览”“设计预览”和模拟状态选择器不进入产品。iOS 和管理后台不改布局，但个人数据自动更新需要两端配合。

本次检查的是当前工作区源码，并在本地演示数据下查看了 PC 对话与任务面板；没有据此认定真实服务、远程桌面或跨端同步已通过。当前 PC 安装包入口是 `clients/desktop/harness/desktop/src/morde-main.ts`：登录后在 `WebContentsView` 中打开 `web/portal` 的 `/assistant`。云端电脑则由独立的 `web/workbench` 在 Host 网关下提供。旧的 `clients/desktop/harness/dsh-nanomuse` 页面不是本次截图对应的主页面，不应再实现一套平行 UI。

| 区域 | 现状 | 对齐后的处理 |
| --- | --- | --- |
| 窗口和导航 | `PortalLayout.tsx` 为文字主菜单和面包屑；`/` 默认进入 `/hosts`；桌面窗口使用普通标题栏 | 改为设计稿的窄图标栏、顶部操作和左侧二级栏；默认进入对话；macOS、Windows 使用真正的系统窗口控件 |
| 会话 | `Assistant.tsx` 内有主会话与旁路会话，但切换时会清空未发送输入；模型和电脑选择为组件级状态 | 一个主会话在上、旁聊在下，新建只创建旁聊；按账号、服务和会话保存草稿、选择及面板状态 |
| 任务动态 | 目前是助手页内独立面板，默认查看账号全部任务，还提供范围切换 | 移到顶栏右侧标签对应的会话侧栏，只显示当前会话；移除范围切换和面板内重复标题 |
| 云端电脑 | `/host-entry/:id` 取得一次性票据后跨 Host 跳转；桌面端当前打开独立窗口 | 在当前会话右侧承载真实工作台；接管后放大。网页和桌面端都需要完成受限跨域嵌入，不是改 CSS 即可 |
| 设置和其他页面 | 模型、电脑、客户端、API Key、账户、个人数据及目标各有独立页面 | 保留现有功能和接口，按设计稿归入左侧分类；非对话页隐藏会话及右侧工作区 |
| 个人数据 | 先写本地队列，再受同步开关控制异步提交；手机端也有独立同步开关 | 保存后自动向云端提交，服务端确认后才显示已保存；离线、旧草稿、冲突与跨端刷新需单独处理 |

## 2. 布局和窗口

### 2.1 共用布局

在 `web/portal/src/components/PortalLayout.tsx` 和 `web/portal/src/styles.css` 中重构用户端壳层，复用 `web/portal/src/assets/morde-logo.png`；不要覆盖同一 CSS 文件中的管理后台样式。将主导航、左侧栏和右侧工作区拆成独立区域，所有页面复用同一套尺寸变量。

- 顶栏高 44 CSS px；左侧图标栏在宽窗口为 54 px，窄窗口为 50 px。会话列表与页面子菜单使用同一位置、宽度、标题起点和首项位置：宽窗口 244 px，`≤1100px` 为 210 px，`≤660px` 为 155 px。主色、背景、圆角、字号、图标和间距取设计稿实际样式，避免复制一份会逐渐偏离的颜色表。
- 对话页显示“主会话”及可折叠的“旁聊”，加号位于旁聊分组；不显示项目、最近或重复的电脑、文件和任务菜单。右侧面板使用云端电脑、任务动态、文件及已打开文档标签。面板展开时由其顶栏关闭，收起时才显示右上角的展开按钮；对话正文不再另放任务动态和云端电脑按钮。
- 设置、个人数据、目标与计划页面使用与会话栏对齐的左侧分类，不显示会话列表、对话和右侧面板。展开分类栏时不重复显示当前分类标题；收起后保留可识别当前内容的标题。必要的分组标题、字段名称、错误和状态继续显示。
- 顶栏不显示页面或会话名称，只放后退、前进、左侧栏收起／展开及会话工作区操作。返回与前进针对真实的页面、会话和面板历史；没有历史时禁用，不把票据放入 URL 历史。
- 宽窗口同时显示会话栏、对话和右侧面板；窄窗口按设计稿切换可用区域，收起面板释放空间。布局变化不改变输入焦点、草稿、已受理任务或电脑控制权。
- 左下角账户入口承载退出、通知、手机端和有权限时的管理后台入口；这些现有功能不再占用一排顶栏按钮。通知入口和未读提示是设计稿尚未画出的必要补充，保留通知筛选、标记已读、历史分页、权限和失败重试。创建电脑、文件版本、通知详情和其他附属页面沿用同一视觉规范；登录、注册、下载及独立工作台按其使用场景保留独立页面，不强行展示会话。

`web/portal/src/App.tsx` 保留 `/assistant`、`/personal`、`/goals`、`/connections`、`/hosts`、`/clients`、`/apikeys`、`/settings` 等既有地址作为直接访问或兼容入口，映射到相应新分类；从根地址进入对话。旧 `/workspaces`、`/host-entry/:id` 和历史项目链接仍需有受权限约束的可达路径或迁移提示，不能因移除导航而删除用户数据或把项目对话自动并入个人会话。管理后台、登录和下载路径维持原边界。

设计稿未单独画出的用户页面也要适配：`/hosts/new` 和 `/workspaces` 从云端电脑分类进入，沿用非对话壳层；创建电脑保留幂等及结果未知时的核实／恢复。`/notifications` 从账户入口打开并可返回来源；`/host-entry/:id` 的独立恢复页面保留返回电脑列表。`/login`、`/register`、`/settings/password` 和 `/download` 保持各自认证及公开访问边界，使用一致的 Logo、字体、按钮、紧凑布局和错误恢复，不重复绘制系统窗口控件。上述页面均检查重复标题、输入、可访问性与分页，不能把原型未展示当成无需处理。

### 2.2 macOS、Windows 与网页

`morde-main.ts` 的 `makeWindow` 目前创建普通系统标题栏，不能把 HTML 中示意的红绿灯或 Windows 三个图标当作真实系统按钮。桌面端改用系统支持的标题栏与覆盖区：macOS 保留原生红绿灯，Windows 在右侧保留原生最小化、最大化／还原和关闭按钮；其余空白区域可拖动，所有网页按钮为非拖动区。根据实际窗口覆盖区为顶栏预留空间，避免遮挡。可参考同目录旧 `src/main.ts` 的平台分支，但应在实际 `morde-main.ts` 入口接入并验证。

`positionWeb` 随窗口大小变化保持 Portal 视图正确覆盖内容区；检查系统缩放、最大化、全屏、最小窗口、显示器切换及无边框模式。网页端由浏览器管理系统窗口，不额外绘制伪系统按钮。现有菜单、下载和文本复制／粘贴能力必须保留。

## 3. 会话、任务与内容分页

### 3.1 会话和草稿

重构 `web/portal/src/routes/Assistant.tsx`，把会话列表、对话正文、输入框和右侧工作区分成可独立维护的组件，但继续复用现有消息 outbox、附件上传、语音、Markdown、消息状态和任务事件处理。工作区的状态和需要保留租约的连接由认证后的持久壳层持有，切换 `Outlet` 页面时隐藏而不是随 `Assistant` 卸载；非对话页仍不展示会话内容。主会话继续使用服务端主会话指针；旁聊使用现有会话接口及幂等键，不在切换、刷新或重试时重复创建。

当前 `startNew`、`selectConversationID` 会清空输入，而 outbox 只覆盖已提交消息。新增按“服务实例／账号／会话”隔离的未发送草稿，包含文字、模型、下一条消息的电脑选择和附件状态；新建但尚未创建服务端会话时使用稳定的本地草稿标识。切换页面、会话、分页、断网和刷新后可恢复，账号或服务切换不能带出其他范围的数据。需要跨刷新保留的附件使用受限本地持久化并处理容量／读取失败，不能假设 `File` 对象可存入普通字符串存储；发送队列与未发送草稿保持独立。

会话侧栏以服务端主会话为唯一主项，其余个人会话为旁聊。现有会话列表是游标分页且 UI 只支持“显示更多”；增加上一页／下一页与搜索。搜索必须覆盖有权访问的全部旁聊：为 `/api/conversations` 增加受账号约束的搜索参数和稳定游标，而不是仅搜索已加载的一页。主会话初始化继续处理未初始化、旧历史需要用户选择和失败状态；同步修正 OpenAPI 中主会话 `ensure` 路径与实际 `/api/me/main-conversation/ensure` 不一致的问题。

### 3.2 当前会话任务

右侧任务面板由 `conversation_id` 驱动，切会话时取消／隔离旧请求、清空旧详情，防止迟到结果和角标串到新会话。保留现有待处理、进行中、暂停、完成、失败、审批、澄清、补充、停止及结果入口，执行与停止仍以真实任务 ID 和服务端状态为准。

现有 `/api/conversations/{id}/tasks` 只返回活动任务，而 `/api/tasks` 当前没有会话筛选。为前者增加可选的最近结束任务查询及稳定游标，默认语义仍是活动任务；由服务端按同一会话、账号及现有项目／Host 权限过滤，返回当前会话待处理数量和必要的事件游标。更新 `server/openapi/portal.yaml`、生成的类型及相关服务／存储测试；不能用前端筛选当前加载的账号任务冒充完整历史。事件流断线后先按游标或快照恢复，重复事件去重。

### 3.3 会话文件和文档

文件标签展示当前会话可访问的消息附件、任务产物和已授权的电脑文件；数据分别来自现有消息附件、任务文件获取和 Workspace 接口，以会话／任务归属及 Host 权限校验后组合。标明来源和上传、准备、失败等真实状态，不能把所有 Workspace 内容都当成当前会话产物。打开文档时在右侧增加对应标签，按文件身份和版本复用标签；下载、预览、复制和访问失败继续遵守原有权限、文件类型及大小限制。示例稿中的文件名和示例同步状态不进入产品。

### 3.4 屏内分页

Morde 自身页面和面板不依赖上下滚动条。壳层固定可用高度，列表按实际可用高度和条目尺寸分页；窗口、字体或内容变化时保留当前条目锚点，再重新计算页数。筛选、搜索、增删和实时更新后页码有效，不漏项、不重复；页码和上一页／下一页始终可键盘操作。云端电脑内的浏览器、终端和 VS Code 保持各应用自身的滚动与键盘操作。

现有目标和计划接口已有游标；模型、电脑、共享电脑、MCP、客户端和 API Key 列表目前返回完整 `items`，先在已取得的完整结果上分页，不伪造不存在的服务端游标。数据规模需要时再扩展对应接口。消息按服务端游标分批读取，替换 `conversationHistory` 递归全量读取；查看历史时新消息不强制跳到末页。

长消息、任务详情和文档按内容块分段；超过一屏的单块要能继续阅读、选择和复制。长表单按明确步骤或页面分段，表单状态位于分页组件之外，翻页不丢输入；不可见页不接收键盘焦点。不要直接将设计稿的 CSS 多列分页用于所有真实表单：它只是视觉演示，必须先解决焦点、编辑、附件和超长内容的可访问性。

## 4. 云端电脑同窗方案

### 4.1 现有边界与选型

`web/portal/src/routes/HostEntry.tsx` 从服务端取得 Host 一次性入口，校验目标 Host 和权限后跳转；`web/workbench/src/app/Workbench.tsx` 已实现 noVNC 桌面、终端、主机文件、Workspace 和 VS Code，以及接管／交还、控制版本、租约续期和错误恢复。

现状不能直接嵌入：Portal 的 CSP 默认只允许自身资源，Host 工作台响应的 `frame-ancestors` 只允许自身；Host 使用独立、仅本 Host 可读的 HttpOnly Cookie。两者还可能不是同一个 schemeful site。直接插入跨域 iframe 会被 CSP 或浏览器 Cookie 策略阻止，桌面端的独立窗口保护也不能自动继承到 iframe。

采用**受控 Host 工作台嵌入**作为网页和桌面端的共同方案，复用工作台内部真实能力，避免在 Portal 重写远程桌面和控制逻辑：

1. Portal 根据当前会话明确选择的 Host 和使用目的向服务端请求短时、单次嵌入票据。票据绑定账号、Host、目标权限、服务实例、可信 Portal 来源和有效期；所有权、共享权限与客户端安装状态由服务端检查。建议新增专用嵌入票据和交换入口，不改变现有独立窗口票据的默认语义。
2. 在内存中取得票据，通过受限表单向对应 Host 的交换入口提交，交换成功后以 Host-only、HttpOnly Cookie 建立独立嵌入会话，经 303 跳转到不含票据的工作台地址；票据不写入地址栏、历史、持久存储、日志或跨窗口消息。交换入口只接受配置的精确 Portal 来源，并检查单次票据与 Host 匹配。失败、重放、过期和权限撤销均拒绝访问；刷新或历史导航需重新取得票据，不能重放已消费票据。
3. 嵌入会话绑定 Host、访问者、安装身份、可信来源、权限上限和期限；不能直接把现有未绑定这些范围的 `ch_host` 当作嵌入授权。工作台及其嵌套代理入口均验证嵌入会话，操作时再复核当前共享权限和租约。明确区分现有 `ch_host`、任务只读 `ch_task_read` 和嵌入会话的名称、路径及认证优先级，避免同一 Host 同时存在多种 Cookie 时混用身份、误拒绝或扩大权限。
4. 仅在部署配置验证 Portal 和 Host 为不同 origin、同 HTTPS schemeful site，且浏览器允许所需 Cookie 时启用网页嵌入。Portal 的 `frame-src`／表单提交范围限于经过配置校验的 Host 后缀，具体 Host 仍须由授权接口和 URL 校验确定；Host 的嵌入工作台文档只允许配置的精确 Portal origin 作为祖先。限定 iframe 所需的最小能力。不得使用不受限的 `*`、共享 Cookie Domain、把 Host 凭据交给 Portal JavaScript、关闭 `webSecurity` 或绕过现有网关授权。
5. 检查整个 Portal → Workbench → noVNC／终端／VS Code 嵌套链的 CSP、`X-Frame-Options`、Cookie、WebSocket Origin、下载和全屏；如某层禁止嵌入，只针对受信入口和具体资源设计最小范围的服务端适配，不能全局删除安全头。Portal、管理后台和手机端目前共用部分 CSP 代码，需拆分策略，避免放宽非 PC 文档；嵌入页面响应不可与独立页面共享放宽后的缓存。独立工作台和任务只读观察会话保持原规则，观察票据不得升级成普通 Host 操作权限。
6. 父页面不能读取跨源工作台 DOM。需要通知布局或接管结果时，使用版本化的少量消息，双方校验精确 `origin`、`source`、Host 和会话随机标识；消息只表达 UI 状态，不能作为授权或控制权凭证。切换会话或 Host 后，旧消息只能更新原对象状态，不能更改当前面板；账号切换、退出及权限失效时关闭相应连接并隔离状态。只有可信工作台的就绪握手能说明嵌入页已加载，远程桌面还需独立的连接状态确认；iframe 的 `load` 事件不能当成连接成功。

域名不满足同站条件、第三方 Cookie 被阻止、嵌入权限或任一层安全头不满足时，在会话面板内提示并提供重试与经过现有授权保护的独立窗口入口；跨源加载超时而无法确定具体原因时显示“无法打开”，不能猜测原因、显示空白或宣称连接成功。该恢复方式是兼容路径，不等于完成设计稿的同窗验收。上线前必须在目标部署域名、真实浏览器和 Electron 中验证完整链路。

接口可按 `POST /api/hosts/{id}/embed-tickets` 实施：提交目标视图和当前会话标识，返回校验过的 Host 交换地址、一次性票据及到期时间；Host 以专用交换入口消费票据，不接受客户端指定的任意回跳地址。服务端应清楚区分拥有者、共享成员和任务观察会话，验证已有 Host Cookie 同时存在、账号切换和重放时不会混用身份。OpenAPI 和生成客户端随接口一起更新。

### 4.2 画面与控制

将 Workbench 拆出可嵌入模式，在该模式隐藏其重复的导航、长说明和版本标签，保留电脑名称、连接状态、画面、控制权胶囊及必要的错误恢复。桌面按可用空间等比例放大；普通浏览器、终端、文件和 VS Code 快捷入口映射到现有 Workbench 视图或已验证的启动能力。当前应用启动接口并不证明这四项都支持直接启动；不可用时禁用并说明，不能用示意按钮冒充成功。Workspace 与主机文件仍是不同视图。

接管请求仍使用现有 `request_id`、`expected_control_version` 和租约。只有网关确认当前用户持有有效控制权才放大面板并允许输入；失败、结果未知、他人控制、只读、租约到期和断线分别显示。交还确认成功后，若用户没有手动改变布局，恢复接管前布局；打开、关闭标签不等于交还。`Workbench.tsx` 当前把 AI 控制显示为“Codex 正在操作”，需要改为真实控制状态，只有有操作事件时才显示正在操作。

当前工作台由前端定期续租。普通折叠、切页、切会话或关闭标签时，对仍由当前用户控制的电脑保留必要的后台续租状态，并阻止隐藏画面接收输入；不能因卸载面板就悄悄丢失控制。浏览器后台限时、断网或应用退出仍可能使续租失败，返回时重新查询网关并展示真实控制权，不声称仍持有或自动接管。未持有控制权的画面可停止连接并在重新打开时恢复；后台状态按账号和 Host 隔离，不续租其他人的电脑。

严格区分三种目标：会话当前打开的电脑面板、输入框给下一条消息选的电脑、已受理任务实际使用的电脑。现有会话可选 `host_id` 可能被任务提交更新，不能当作长期面板绑定或授权凭证；切换电脑和面板不得迁移已有任务。会话的面板选择可按账号和会话保存为 UI 偏好，恢复时重新检查权限与可用性。

从设置中的电脑列表点击“打开电脑”时，回到当前已选会话并打开所选 Host；若尚未确定会话，则先取得主会话，旧数据需要选择主会话时先让用户选择。不得自动切换到其他电脑，也不得把该动作当作发起或停止任务。独立工作台保留明确的返回入口。

## 5. 设置、个人数据与本机文件

### 5.1 保留现有业务

设置左侧菜单为“模型与工具、云端电脑、客户端、API Key、账户”。复用 `Connections.tsx`、`MCPConnectorsPanel.tsx`、`Hosts.tsx`、`Clients.tsx`、`ApiKeys.tsx` 和 `AccountSettings.tsx` 的 API 和业务逻辑，重排为紧凑列表和必要的详情／操作区：

- 模型保留个人与团队列表、预设、编辑、密钥不回显、连接与能力检查；MCP 保留授权、凭据、启停、删除和失败状态。检查产生用量时保留提示。
- 电脑保留我的／共享电脑、权限、状态、创建、续期、释放、恢复、复制、删除、文件与版本、共享成员及其确认和冲突处理。设备撤销、API Key 一次性展示与吊销、账户隐私、记录和额度等现有能力不能因为示例稿没画出而消失，可放在对应分类的详情或更多操作中。
- 个人数据保留个人资料、AI 个性、记忆、动态、灵感、资源库和偏好；目标与计划分别保留编辑、状态、计划时区、预算、启停及运行记录。权限、加载失败、空列表和未确认状态应区分。

### 5.2 保存即提交云端

调整 `PersonalData.tsx`、`personal-data-store.ts` 和 `AccountSettings.tsx`：移除个人数据的同步开关及“立即同步”，保留已存在的账号／服务隔离、本地 outbox、`base_revision`、幂等键、附件上传和冲突处理。用户保存后立即排队并串行提交；服务器确认前显示“保存中”或“待提交”，失败和离线保留草稿，只有收到成功回执才显示“已保存”。同步期间新进入队列的项目要触发下一轮 drain，不能因正在同步而遗漏。

沿用 `/api/sync/snapshot` 和 `/api/sync/changes` 的快照水位与增量游标：连接、重连、回到前台时拉取；在线且页面活跃时定期增量检查（初始建议 30 秒，失败退避），有变化再获取对象。拉取不覆盖正在编辑的本地草稿；服务端版本变化时保留双方内容并提示用户处理。修复当前编辑器按远端 revision 重建可能丢失输入、以及新增记忆／动态在本地入队失败前就清空输入的问题。

对以前明确关闭同步的账号，保留旧的未提交草稿和附件，提供逐项查看、处理或明确继续上传的入口；不能静默上传旧队列。旧暂停队列与新保存操作不能直接混入同一发送序列：若两者涉及同一对象，先隔离旧草稿并读取服务端确认版本，再基于该版本生成新操作；不能假定旧操作已成功、虚构版本或覆盖冲突。新编辑并点击保存的内容走新的自动提交流程。同步调整 `clients/nanoMuse/android/src/ios/NanoMuse/NanoMuseMordePersonalData.swift` 等实际调用方：迁移旧暂停偏好，连接、重连和前台恢复时获取最新已确认数据，在线期间自动检查更新，同时保留手机未提交草稿。iOS 的界面设计不在本次改造范围。

### 5.3 本机文件夹同步

设计稿中的同步入口需要调用桌面端真实能力：现有 `resources/morde.html`／`morde.js` 的本地同步页通过 `morde-preload.ts` 调用 `selectProjectDirectory` 和 `uploadProject`；当前 IPC 只信任本地 `mainWindow.webContents`，Portal `WebContentsView` 没有这些接口。

为 Portal 单独提供最小受控桥接，只暴露选择目标、由系统对话框选择文件夹、确认项目名、手动开始和读取状态等必需操作；主进程核对 sender、可信 Portal 顶层 frame 及 origin、当前账号、Host／Workspace 和本次目录选择授权，Host iframe 不能调用。目录由原生对话框选择，不暴露任意本机文件访问或整套 preload。账号切换、选择失效和窗口关闭后拒绝旧页面句柄，但不删除已保存的长期映射或恢复点；重开后须重新核验账号、目录身份及目标，再由用户点击同步。

同步目标固定为所选云端电脑的 `~/workspace/project/<项目名>/`，仅在用户点击时将本机新增、修改及已同步文件的删除单向应用；保留相对目录，不反向同步、不定时或监听自动同步。不可访问根目录、目标冲突、服务端状态未知和授权失效时保留内容并显示待处理／失败。旧版双向、实时同步配置及恢复点必须保留和可安全处理，不能在界面迁移时自动启动、删除或覆盖。普通网页若不具备同等目录授权能力，明确引导使用 PC 客户端，不显示虚假的同步成功。

## 6. 异常、输入与实时回复

在 `PageErrorBoundary.tsx`、`RecoverableError.tsx` 和各数据组件中分层处理失败：接口或面板失败只影响对应区域，保留其他导航、对话和草稿；需要整页恢复时提供重试与可用的返回／首页入口。独立工作台无来源时返回电脑列表。处理异常模型地址等不可信响应时降级显示，不能让单个数据项使整个页面白屏。Electron 主文档和 Host 页面仍保留现有导航校验与文档错误恢复。

所有普通输入框、密码／密钥框支持系统复制、粘贴、剪切、全选及右键；不拦截输入法组合事件，不输出或回显密钥。远程桌面剪贴板遵守控制权及权限。不要为了粘贴放宽所有网页的剪贴板读取授权。

普通问答继续复用服务端已有的不创建 Task 的回复路径，不在界面上用关键词决定是否建任务。当前直接回复由 `server/internal/app/conversation_route_decision.go` 构造模型请求，其中没有可信当前时间或时区；要在该请求中加入服务端采样时间和经校验的用户时区，缺失或不明确时如实说明，不能只给 DSH 任务注入时间就认为普通问答已解决。实际模型对“笑话”和“现在几点”的效果仍需真实验证。

DSH 任务若同样需要时间上下文，优先评估本地上游源码 `project/deepseek-harness/packages/context/time-context` 的 `@deepseek-ai/dsh-time-context`：该快照声明 `0.2.2-rc.1`、MIT，支持时区和注入间隔，默认间隔为 10 分钟；当前 `runtime/morde-cloud-runtime/package.json` 和锁文件尚未接入它。实施前以锁定的 DSH 版本核对上游插件、peer 依赖和许可证，验证时区来源、刷新精度、会话隔离、检查点、取消及恢复；只有真实接通后才声明可用。复杂任务和子 Agent 继续使用现有 DSH Runtime，不新增第二套 Agent 循环。

## 7. 修改边界和实施顺序

1. **壳层与视觉：** `web/portal/src/App.tsx`、`components/PortalLayout.tsx`、`styles.css`、相关布局组件及测试；先打通顶栏、左侧分类、路由兼容、尺寸与分页容器，避免影响管理后台。
2. **对话与任务：** `routes/Assistant.tsx` 及拆出的组件、消息草稿和测试；服务端会话搜索／任务历史及 `server/openapi/portal.yaml`、生成类型、相应接口和存储测试。保留消息 outbox、任务事件和授权链。
3. **电脑同窗：** `routes/HostEntry.tsx` 与新增面板承载组件、`web/workbench/src/app/Workbench.tsx`、网关票据／安全头／权限和代理；先完成同站点安全证明与异常处理，再接入真实桌面、控制与嵌套功能。
4. **业务页与跨端数据：** Portal 各设置、个人数据、目标计划组件及其测试；个人数据服务接口如有变更同步更新 OpenAPI，iOS 仅改自动刷新与兼容逻辑。保留旧草稿和迁移入口。
5. **桌面窗口与本机能力：** `clients/desktop/harness/desktop/src/morde-main.ts`、受限 preload、同步页和测试；处理原生标题栏、Portal 可信 sender、本机目录授权与窗口恢复。使用同一 Portal 页面，不另做一套桌面业务视图。

以上是设计边界和依赖顺序，不是已经完成的任务清单。具体实施时应先确认当前工作区状态，并同步调整受影响的调用方和测试。

## 8. 验证与完成标准

- 固定示例数据分别在 1440×900、1024×768、952×861、800×600 及窄窗口下，对照 HTML 设计稿检查四个区域、按钮、颜色、字体和留白；会话栏与页面子菜单边界及首项位置对齐，顶栏没有页面名称。逐页检查创建电脑、文件版本、通知、登录／注册、密码、下载及独立工作台的视觉与恢复入口。分页、长文本、长表单和系统文字放大后内容均可访问，无控件遮挡。
- macOS 和 Windows 实机检查原生窗口按钮、拖动区、最大化、全屏退出与侧栏控制；网页不出现模拟系统按钮。检查各输入框、输入法、快捷键及右键粘贴。
- 至少两个旁聊来回切换，分别保留文字、附件、模型和电脑选择；刷新、后退／前进、切换设置、离线和账号切换后数据归属正确。发送重试不重复创建会话、消息或任务。
- 同一会话创建进行中、待审批和已结束任务，切换另一会话后任务、角标和详情不串；断网恢复与重复事件不重复。普通问答与真实执行任务使用真实服务验证，时间说明来源与时区。
- 在同一窗口打开已授权的真实云端电脑，验证桌面、终端、主机文件、Workspace、VS Code、接管、交还和放大；隐藏面板超过续租周期再返回，核验控制权及隐藏期间不能输入。检查后台限时、断线、租约过期、共享权限撤销、Host 切换、票据重放、普通会话与任务只读 Cookie 同时存在、非可信父页面以及嵌套安全头。无权限或 Cookie 策略不支持时显示恢复入口，不误报成功。
- 个人数据在 PC 保存后从同账号手机连接和在线刷新看到服务端确认版本；同时编辑、离线、旧暂停队列、附件和版本冲突时草稿不丢失。重点验证旧暂停草稿与新保存属于同一对象、同时发生跨端修改时不会误传旧草稿或覆盖云端版本。文件夹同步验证只有再次点击才应用新增、修改和删除，冲突、根目录不可访问及授权失效均不误删。
- 运行 Portal、Workbench、桌面客户端及涉及的服务端测试、类型检查和 lint，并做真实服务端到端验收。当前基线 `web/portal/src/components/PortalLayout.test.tsx` 有一项失败：测试仍要求“工作区”导航链接，但现有 `PortalLayout.tsx` 已没有该链接；实施时应按新入口和保留能力更新测试，不能把该失败归因于本方案的代码改动。
