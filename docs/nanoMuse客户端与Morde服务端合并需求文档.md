# nanoMuse 客户端与 Morde 服务端合并需求文档

> 状态：目标需求，尚未实施完成。云端 Agent 运行位置、账号级归属和客户端边界以[云端 Agent 运行时统一化需求](Morde云端Agent运行时统一化需求文档.md)为准；该需求覆盖本文此前保留本机 Agent 及切换本机/云端执行的要求。已有实施记录只说明当时做过什么，不能据此判定新需求已完成。

## 目标与范围

最终向用户提供同一套 nanoMuse PC 端和 iOS 手机端：在原版源码及原有功能上进行二次开发,加入 Morde 能力，而不是另外做一款只使用 nanoMuse 外壳的 Morde 应用。对外业务服务只有 Morde `server/` 一套；将客户端仍需使用的 nanoMuse Cloud、Hub 等服务能力整合进去，不再要求用户部署或登录第二套 nanoMuse 服务。融合后命名统一叫做Morde PC 端和Morde  iOS 手机端

| 范围 | 最终代码归属与交付边界 |
|---|---|
| PC 端、iOS 端 | 只在 `project/nanoMuse/` 的原有客户端上开发和发行；每个平台只有一个正式应用入口。客户端负责会话、状态、获准的云端电脑操作和用户选择的文件传输，不承载 Agent 运行时或模型与工具循环。 |
| 服务端 | 业务 API、账号、跨端连接与服务端状态只在本仓库 `server/` 实现和部署。管理后台可作为服务端配套界面存在，不构成第二套用户客户端。 |
| 当前过渡实现 | `project/morde-desktop/`、`project/morde-sync/`、独立 `Morde.xcodeproj` 与独立 Morde 客户端模块中的有效能力并入 nanoMuse 对应端；不作为最终独立安装包或长期维护的第二套用户界面。现有用户 Web/Workbench 的用户功能也须收敛到 nanoMuse 客户端，不保留两套相同业务页面。 |

本次明确要求 PC 和 iOS；Android 若继续发行，也必须遵守同一客户端归属原则，其是否纳入本次验收见文末待确认项。

## 功能与规则

1. **迁移仍适用的 nanoMuse 能力。** 以合并前 PC/iOS 版本建立功能与数据基线；聊天界面、记忆与目标、授权确认及跨设备连接等适用能力接入 Morde。Agent、模型/工具循环和子 Agent 统一迁到云端，不再承诺客户端本机 Agent 工作能力。除已确认清理的旧自带模型 API key 外，原数据保留并按用户选择处理。
2. **在同一应用中加入 Morde。** PC 和 iOS 使用同一云端会话、任务、电脑、Workspace、通知和设置；消息经服务端持久受理后由云端 Agent 执行，需要电脑操作时选择有权使用的 Host。客户端展示 Agent 与 Host 的各自状态。本机文件只有在用户明确选择并上传或启用同步后才进入 Workspace。
3. **统一账号和跨端状态。** PC/iOS 使用一套账号进入整合后的服务；用户、安装授权、云端电脑、Workspace、云端会话及 Task 以 `server/` 为唯一权威来源。每个账号在当前服务实例有一个独立常驻的个人 Runtime 进程或容器，同账号多设备共用归属与历史，不同会话任务可按配额并行，账号间隔离；本机私有数据可以留在设备上，但不得伪装成已同步的云端状态。
4. **合并服务而非并行代理。** nanoMuse Cloud/Hub 中为保留功能所必需的账号、跨端消息/连接、模型中继及个人资料等服务能力，应在 `server/` 内与 Morde 现有服务整合；相同业务对象只保留一套可写状态和对外契约。不得让正式客户端同时依赖独立 nanoMuse Cloud 与 Morde Portal，或把两个服务简单并排启动后称为合并。客户端与服务端版本不匹配时应给出明确错误，正常部署必须提供客户端实际调用的登录与业务接口。
5. **保留已有数据和权限边界。** 合并不得清空现有 Morde 数据或客户端本地 nanoMuse 数据；已有数据若需要转换，应在确认映射和可恢复办法后实施。跨端同步和远程控制按用户身份、资源权限及授权范围执行；退出、撤销安装或失去权限后不得继续使用相应云端能力。
6. **统一模型连接。** 移除用户自带模型密钥的设置与使用；云端 Agent 使用 Morde 管理的模型连接。已确认直接删除 PC/iOS 各设备上本应用保存的自带模型 API key，包括 iOS 同步与非同步 Keychain 项；同步项删除可能影响同一 Apple ID 的其他设备。平台模型凭据、登录/同步凭据与 MCP OAuth 继续保留。

7. **新用户模型额度与奖励。** 用户最新确认：新注册账号首次经管理员审核通过时，自动分配管理员配置的默认模型额度；额度数值及并发上限由管理员设置。已有人工配置的账号预算与账本保留，重复审核或恢复已禁用账号不重复发放。邀请奖励、贡献奖励仍不自动发放；Host 和 Workspace 资源上限不因模型额度改变。此规则覆盖 2026-11-01 关于新用户不自动分配模型额度的决定。

8. **PC 设备受控操作。** 用户于 2026-11-01 确认，本期保留云端 Agent 请求目标 PC 截图、查看文件和执行命令的能力；目标设备需要授权，各类能力分别实施和验收，未通过的能力不可用。用户进一步确认，写文件只允许写目标 PC 已选择的 Workspace，沿用同步限额和覆盖前安全副本，F02-T10 通过后开放。PC/iOS 不启动或委派本机 Agent。

9. **普通个人数据容量。** 用户于 2026-11-01 确认，头像、记忆、目标、动态、资源库等普通个人同步数据及其附件，默认每账号 5 GiB、单附件 300 MiB，管理员可调整；超限保留已保存内容。普通聊天、Workspace 和额外完整记录不计入该额度，各自遵守原有规则。

10. **账号注册与后台审核。** 用户注册仅需用户名和密码，不要求邀请码或短信认证。注册后账号处于待审核状态，不签发登录会话或客户端凭证；管理员在 Morde 后台审核通过后，账号自动获得第 7 条的默认模型额度，用户才能登录并使用服务。默认额度未配置时，后台提示管理员先设置，不将账号标为已审核通过。待审核、拒绝、禁用状态必须明确呈现；注册限流和密码校验继续生效。

## 验收条件

- PC 和 iOS 各只有一个基于 nanoMuse 原工程的正式构建及入口；安装后在同一应用内能使用迁入的界面和 Morde 云端能力，客户端不启动本机 Agent 或模型/工具循环。独立 Morde PC/iOS 工程不进入最终发行流程。
- 用同一账号分别在 PC 和 iOS 登录后，看到一致的云端电脑、Workspace 和云端会话；在一端创建或变更的云端资源，另一端刷新后显示相同结果，不产生第二份业务记录。
- 用户用用户名和密码注册后等待管理员审核；审核通过时自动获得一次默认模型额度，重新审批、账号禁用后恢复和请求重试不重复发放，不覆盖已有人工预算。
- PC 可选择本机目录与 Workspace 同步；iOS 可显式上传用户选择的文件；两端均可进入有权限的云端电脑。断网、无权限或服务端不可用时显示真实状态；客户端关闭不等于云端任务停止。
- 只部署 `server/` 提供的业务服务即可完成登录、原 nanoMuse 跨端能力和 Morde 云端能力；正式客户端不请求独立 nanoMuse Cloud/Hub 服务。客户端调用的接口在相应服务端版本上可用，登录不因缺失接口返回 404。
- 按新需求逐项验收保留或迁入的 nanoMuse 功能和 Morde 用户场景；切换应用版本后，已有 Morde 数据与客户端本地数据仍可读取，权限撤销后相关请求被拒绝。
