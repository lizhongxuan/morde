MORDE · AI 对话架构

四种对话处理流程

Morde 图突出持续会话与多个任务的关系；三个参考项目按消息入口、会话、上下文、Agent、工具和结果交付的顺序展示。

阅读范围：Morde 是目标设计；Hermes 使用官方公开文档与 main 分支；DS-Bot 与 nanoMuse 使用本地源码。流程经过概括，压缩、授权和并发条件见下方对比与设计文档。

Morde

目标设计

关系：一个会话可有零个或多个 Task；一项 Task 可关联多条后续消息。A、B 表示两个可独立运行的任务，每个任务内的 DSH 执行 Agent 可按需调用工具或子 Agent；任务运行期间仍可继续对话。

目标示例：“整理报告”创建 A；“报告改用英语”关联 A；“讲个笑话”直接回复；“另外整理预算”创建 B。停止 A 不应停止 B。

图中的会话协调 Agent 表示逻辑职责；当前每条分类消息使用独立的 DSH coordinator session，任务结果通过事件再次进入协调路径。

Hermes Agent

官方文档 / main

官方行为：默认同一 Session 原位压缩并保留可搜索原文；Gateway 对解析后的 Session 使用回合租约。

DS-Bot

本地源码

本地源码：未完成工作倾向原位检查点，适合切换时建立新会话段并交接；其他 Bot 的回复可作为后续消息返回。

nanoMuse

本地源码

本地源码：同一线程的普通追加入队，可在下次模型调用前进入运行中回合；会话文件在回合收尾时保存。

线条含义：实线表示消息、任务操作或进度；蓝线表示回复或交付；虚线表示任务、工具或协作结果回流。

主要差异

会话身份：Hermes 默认在同一 Session 原位压缩；DS-Bot 的长期 Bot 对话可以跨多个 DSH Session 段；Morde 的目标是稳定的产品会话关联零个或多个独立 Task，并为每个 Task 使用自己的 DSH 执行会话。

长上下文：Hermes 使用压缩和原文搜索；DS-Bot 由上下文管家选择检查点或换段；本地 nanoMuse 的对话入口按消息数量选择近期窗口，并注入相关记忆。

执行与协作：Hermes 运行自己的 AIAgent；DS-Bot 通过 DSH 和 Bot 消息协作；nanoMuse 使用本地 Python MuseAgent；Morde 目标只使用 DSH，任务和工具各自保持授权边界。
