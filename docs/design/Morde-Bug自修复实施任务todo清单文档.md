## 1. 范围与顺序

用户通过现有 `morde-pc` 对话说“帮我修复 Morde 的某个 Bug”，本机 DSH Agent 在已授权的源码目录直接分析、修改和验证，进度与结果继续使用现有会话和 Task。**本次不修改 PC/iOS 页面、按钮或既有交互，不新增目录选择、差异预览或逐项批准界面。**

这里的不改界面是本次自修复能力的接入范围；以后用户明确要求修复界面 Bug 时，按那次请求和项目规范处理，本次验收使用非界面 Bug。

源码、日志、测试材料及模型输入只留本机，不上传、推送或发送文件。首版要求当前 `morde-pc` 会话连接同机服务，DSH、模型、任务记录和源码操作也在同一可信本机；不会自动切换云端会话或迁移数据。本机服务启动时固定并授权本地 Morde 源码根目录；用户明确的修复请求作为该 Task 范围内常规本地修改和必要测试的授权依据，不自动扩大其他任务或工具权限。无法访问源码、隔离不成立或本机模型不可用时，在原会话说明阻塞。

已有会话路由、Task、DSH、模型网关和面向 Host Workspace 的工具；本机模型、源码访问及受限执行仍需接通，不能把现有工具或文档当作自修复已实现。

**开发顺序：** S01 接单与目标 → S02 本机能力与授权 → S03 直接修复 → S04 验证与复核 → S05 运行验证 → S06 现有会话交付 → S07 真实闭环。S08 为可选后续项，不阻塞首版。保留第一里程碑的 PC/iOS、云端电脑、文件夹同步和双子 Agent 要求。

## 2. 接口与内部边界

- **现有 `POST /api/conversations/{id}/messages`、`GET /api/tasks/{id}` 与 Task 事件：** 不新增请求字段、HTTP API、PC IPC 或前端交互；沿用 `client_message_id = Idempotency-Key`、现有任务/步骤状态和原会话结果。`202` 只代表消息已受理。
- **本机修复目标与执行端口（拟新增内部能力）：** 服务端根据启动配置解析固定源码根目录，核验当前用户、Task、授权版本及同机执行身份，向现有 DSH 工具代理提供读取、受限文件修改和本机测试。内部调用绑定 Task/步骤/尝试与目录身份；结果使用现有步骤和事件投影，不暴露原始日志或文件内容到外部。
- **授权边界：** 仅对已认证、已获本机仓库授权且明确请求修复的 Task，新增可审计的受限授权，用于范围内的可逆文件修改与受限测试；不改变普通 Host Workspace 的 `file_write`、`shell_exec` 等既有风险分级和审批，也不伪造现有逐条审批记录。越权、不可证明安全或用户未授权的不可逆操作仍按现有规则处理。

## 3. 实施任务

- [ ] **S01（未开始）复用现有消息路由并确定本机目标**
  - 修改：优先复用 `server/internal/app/conversation_route_decision.go` 及现有 Task 创建/存储，仅补足实际验证出的路由缺口；接入本机启动配置。识别明确的 Morde 修复请求，服务端从部署时配置的唯一授权源码根目录解析实际路径，绑定当前用户、Task、授权版本和本机执行身份；不依赖模型猜路径或用户每次选择。普通对话和其他任务的路由不变。
  - 验收：本机实际会话 API 接收“帮我修复 Morde 的 X Bug”，沿用同一消息和 Task，无开始确认；重复请求按现有幂等规则对账。源码未配置、账号无权或执行环境不在同一可信本机时说明原因，不选择其他仓库或云端电脑；云端会话不自动切换到本机服务。

- [ ] **S02（未开始，依赖 S01）接通本机 DSH、模型和受限工具**
  - 修改：`runtime/morde-cloud-runtime/`、`server/internal/app/cloud_dsh_tool_broker.go`、`runtime_tool_executor.go` 和本机适配。对照已接入依赖与本地上游 DSH 插件，复用相应工具和授权机制；仅为本次 Task 建立绑定用户、源码根目录、修订和预算的受限授权，不伪造现有精确命令审批。路由、执行及复核的模型请求均经本机 Morde 网关调用本机模型；为本机模型接入提供受限配置，不放宽一般模型连接的内网/SSRF 防护。文件修改走受控补丁能力；测试使用源码只读、临时目录可写的受限环境，需写构建产物时在与当前源码一致的本机临时副本中运行。
  - 验收：真实本机模型可读取并修改合成仓库、执行本地测试，常规操作无重复审批；越权路径、符号链接、未授权用户、外网请求及本机代理转发均被拒绝。路由、执行或复核的沙箱或本机模型不可用时不降级远端；普通 Host Workspace 的既有审批仍生效。

- [ ] **S03（未开始，依赖 S01、S02）在当前本地工作区直接修复**
  - 修改：本机源码读写适配及 `server/internal/store/postgres/` 的 Task 步骤/操作记录。先读取当前目标文件和已有工作区状态，再在授权范围内应用最小改动；不因已有未提交或未跟踪文件而一律拒绝，也不将用户已有修改记作本次成果。补丁绑定文件基线和 Task 版本；实际冲突或写入结果未知时停止相关操作并保留现有内容，不自动 `stash`、`reset`、`clean` 或盲目重放。
  - 验收：测试仓库中已有修改与未跟踪文件保留，能在同一文件现有内容上完成不冲突的修复；模拟并发改动、路径越界、撤权及操作回执丢失，不覆盖他人内容、不重复执行。补丁直接落在授权源码目录，无候选应用确认。

- [ ] **S04（未开始，依赖 S03）运行测试并沿用现有复核**
  - 修改：现有 Task 步骤、证据、`server/internal/app/task_validation*.go`、`server/internal/worker/task_validation_review_worker.go` 和 `server/internal/store/postgres/task_validation_review.go` 等必要适配。记录修前依据、修改文件、本机测试及真实环境；修复完成后按现有 `task.result` 独立复核机制处理。现有 Worker 只复核已完成 Task，模型身份目录要求可核验的不同家族，且复核队列有重试上限；本机复核身份和模型恢复后的重试需适配。缺少合格模型时 `validation.state` 保持 `pending`，但不作为开始或写入源码的前置条件。
  - 验收：必要测试通过/失败和未验证项如实返回；旧结果、模型自述、错误环境和缺证据不能成为验证通过。只有一个本机模型时仍能开始并完成授权修改，回复说明复核待完成；重试耗尽后，合格本机模型恢复且任务版本未变时仍可重新复核，并按现有 Task 机制更新状态。

- [ ] **S05（未开始，依赖 S03、S04）按现有流程验证运行版本**
  - 修改：本地测试/启动适配及运行记录；必要时用隔离测试数据构建、启动候选版本以验证实际行为。源码修改与运行版本生效分别记录；需要重启正在使用的实例时沿用现有授权及任务恢复机制，不新增更新器或确认页面，不部署线上。
  - 验收：实际测试记录能对应本次修改；构建或启动失败保留原工作和错误信息，不误报运行版本已修复；本地服务短暂中断后任务不重复执行，其他已受理任务不被取消。

- [ ] **S06（未开始，依赖 S01、S03、S04）复用现有对话与 Task 交付**
  - 修改：服务端现有任务结果汇总/投递与必要安全投影；不修改 `morde-pc`、iOS 或 Portal 界面代码。使用当前进度、错误和原会话消息表达实际状态，结果说明修改文件、测试、未完成项及运行版本是否生效。
  - 验收：实际 `morde-pc` 的现有对话能看到任务进度和结果；iOS 已安全连接同一服务时可按现有能力查看安全摘要，不为此自动迁移云端会话。常规修复不会出现选目录、预览或逐项审批；断线重连不重复创建任务或最终结果。

- [ ] **S07（未开始，依赖 S01–S06）完成真实本机闭环**
  - 修改：本机隔离测试数据和验收记录，不部署外部环境；先在 Morde 本机测试副本中确定一个真实可复现的非界面 Bug。
  - 验收：实际 `morde-pc` 连接同机服务并发送自然语言修复请求，使用真实本机模型和现有界面观察 DSH 读取、直接修改已授权的 Morde 测试源码、运行相关测试并在原会话交付；不增加确认步骤。对照未提交改动、权限撤销、缺模型/源码、真实冲突和服务重启，确认不误删、不外发、不重做已确认操作。受影响的 PC 交互须在实际 `morde-pc` 验证；缺真实模型或客户端时标阻塞/待验证。

- [ ] **S08（未开始，P1，依赖 S07）复用已有纠错经验**
  - 修改：按实际重复问题复用现有项目内容或回归测试，保存适用范围和来源；不新增页面，也不作为本次直接修复的前置条件。
  - 验收：同类任务可使用适用规则和本次新证据；权限失效或范围不匹配时不套用，不跨项目泄露。

## 4. 验收约定

实施前检查并保留已有工作区改动。服务端按 [server 开发规范](../../server/AGENTS.md)完成必要 lint、测试、race、生成物检查及本地 PostgreSQL 集成验证；DSH 插件核对版本、许可证、授权、取消和恢复。每项记录真实环境与未覆盖范围，只有实现和验收都完成才勾选。不得以独立浏览器或构建结果代替实际 PC 客户端验收。
