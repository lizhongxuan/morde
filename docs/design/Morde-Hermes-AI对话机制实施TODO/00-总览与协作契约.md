## 共同边界

- 所有修改和测试产物仅在本地；不要上传、发送文件或部署到远端。使用隔离的本地测试数据和数据库，不读取或修改生产数据。
- 先查看 `git status`，保留已有未提交修改。各会话只改自己负责的文件；确需改别人的文件，先记录依赖并在其完成后整合。各文档只由对应会话更新，H07 最后统一核验状态和证据。
- 可使用独立分支或 worktree，但必须先确保工作区已有未提交代码、本文档和 `project/hermes-agent/` 源码快照可安全保留；不要用 reset、clean 或覆盖方式处理他人修改。
- 继续使用 DSH、现有 PostgreSQL 会话/Task/事件/检查点、模型网关和授权审批机制。任务数据与会话消息保持关联，不另造一套 Agent Runtime 或 Task 生命周期。
- DSH 基线以 `runtime/morde-cloud-runtime/package.json` 和锁文件为准，当前依赖为 `0.2.2-rc.1`；不得仅因 `project/deepseek-harness` 的最新代码存在某接口就假定当前部署已经接通。
- 公开 API 默认不变。若 H03 确需修改 `server/openapi/portal.yaml` 和生成的 `web/portal/src/api/schema.d.ts`，由 H03 统一负责；H05/H06 消费合入后的契约，不并行改生成文件。

## 跨任务接口契约

### 会话上下文

H01 负责现有路由和跨 Task 摘要的上下文；H02 负责 DSH Session 内压缩。两层作用范围不同：会话历史从 PostgreSQL 取得，Task Session 使用 DSH 检查点。继续使用现有摘要、来源序号/摘要校验值和历史搜索接口；若需要新增内部字段，H01 在自己的文档记录字段与调用方，不能静默把摘要标为覆盖全部历史。H02 保持现有服务端压缩请求/响应兼容；如确需改共享协议，记录具体差异交 H07 集成。

### 任务消息投递（H03 与 H04）

这是**拟新增的内部 IPC 契约**，不是现有 HTTP API：

1. 扩展既有 `message_delivery`。版本 3 沿用版本 2 的 `task_id`、`owner_id`、`agent_id`、`generation`、`authorization_version`、`session_id`、`message_id`、`content`、`attachment_ids`，新增必填 `mode: "steer" | "followup"`。版本 1/2 继续按原来的 `followup` 行为处理。
2. `mode` 由服务端路由确定并与该消息和目标 Task 持久绑定。`steer` 使用 DSH `agent.steer()`，`followup` 使用 `agent.followup()`；相同消息 ID 的内容、附件或模式不一致必须拒绝。Runtime 与 Worker 都校验 Task、Owner、Session、Agent generation 和授权版本。
3. 消息先在服务端保存；DSH `agent/inbox/spliced` 插入事件经检查点持久化后才有“已入队”证据；被领取并写入根 Session 的 `user/message` 检查点后才可沿用现有 `delivery_status=applied`。入队或领取都不表示模型已完成工作。丢失回执时按消息 ID、内容/附件、模式和检查点对账，不能重复投递或重复执行。
4. 保持现有公开 `delivery_status`：`pending` 表示尚未证实领取，`applied` 对任务消息表示已在根 DSH Session 检查点中确认，`unknown` 表示状态无法确认；普通直接回复沿用现有语义。入队和领取的细分证据先放在现有服务端状态/检查点中，不新增公共枚举。若确有必要调整公开 API，由 H03 修改 OpenAPI 并通知 H05/H06 一起适配。
5. 只有目标明确、可在下一步安全应用的补充进入 `steer`；涉及授权、审批动作、已发起副作用或需要替换执行计划时，使用现有受控版本切换或等待。不可确认的操作先对账；不能因新输入重复执行。

### 验收与状态

每项只使用 `未开始 / 进行中 / 待验证 / 完成 / 阻塞`。实现和本项要求的验证都完成才打勾；记录本地提交或工作树、命令、结果、测试环境和未覆盖项。合成模型结果不等于真实 Provider 验收；浏览器页面不代替实际 `morde-pc`，构建不代替客户端交互。
