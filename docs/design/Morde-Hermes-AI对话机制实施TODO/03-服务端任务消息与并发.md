## 持久化与协议契约

- 迁移：`server/migrations/00223_task_agent_message_delivery.sql`。
- `conversation_messages.delivery_mode`：非空，默认 `followup`，允许 `steer` / `followup`。
- `task_agent_message_deliveries`：以 `message_id` 唯一关联消息，保存 `task_id`、`owner_id`、`initiator_id`、`agent_instance_id`、`agent_generation`、`authorization_version`、`session_id`、`mode`、`enqueued_through_seq`、`claimed_through_seq` 和时间戳。代次/授权版本为正数，序号非负；领取检查点必须晚于入队检查点。
- Runtime v3 帧示例：

  ```json
  {"type":"message_delivery","version":3,"task_id":"t1234567","owner_id":"u1234567","agent_id":"a1234567","generation":2,"authorization_version":3,"session_id":"root-session","message_id":"m1234567","content":"Also include a short introduction.","attachment_ids":[],"mode":"steer"}
  ```

- 旧 v1/v2 帧继续按 `followup` 解释；相同消息 ID 的正文、附件或 mode 不一致时拒绝。公开 HTTP 状态枚举没有改变。
- **契约文档缺失**：`server/AGENTS.md` 指定的 `docs/实施/00-总览与公共约定.md` 当前不存在。上述 schema 和协议事实先登记在本任务文档；未声称权威总览文档已同步，需在该文档恢复后补同步。
