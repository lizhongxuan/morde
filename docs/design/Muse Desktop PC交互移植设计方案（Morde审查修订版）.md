# Muse Desktop PC 交互移植设计方案

**审查基线：** `lizhongxuan/morde` 的 `release@936389c`。范围仍是原文六项，不新增审批系统、不改路由、模型预算或 Harness 状态机。此前的任务中断与对话体验修复继续单列。这里移植的是交互做法，不要求移植 Muse 的运行时、账号、文件路径或权限模型。

## 结论：六项值得做，但不该一起上

| 优先级 | 功能 | 给 Morde PC 的收益 | 实施判断 |
|---|---|---|---|
| P0 | 附件拖放与预览 | 省掉选文件的步骤；草稿和错误反馈仍可靠 | **先做**。复用选文件路径；拖放不能触发 Office 文件上行。 |
| P0 | 折叠工具活动 | 工具很多时不用翻整页；失败和卡点更容易看见 | **先做**。纯 UI 二级分组，保留原详情。 |
| P1 | 结构化追问 | 用户可直接点选，比来回确认更省力 | **扩展 Morde 现有澄清**。不把外部插件列为上线依赖，不再维护两套待答状态。 |
| P1 | 任务完成通知 | 切出 PC 窗口后仍知道已交付 | 做增量合约和去重后上线；锁屏默认不显示任务内容。 |
| P2 | 语音波形与取消 | 确认麦克风在收音，避免旧转写写入别的草稿 | 先做取消与隔离，真波形需单独通过设备和权限验证。 |
| P2 | 长工具输出 | 查长构建日志时能找回截断后面的关键证据 | 保留需求，先试点一个明确支持的来源；不把全量日志存储当成 PC 样式改动。 |

## 证据：哪些方向已经证实，哪些还不能下结论

以下 E1–E4 是本轮在固定提交执行的合成实验，不是新功能已合并，也不是签名 PC 的交付验收。

| 编号 | 实际证据 | 支持的判断 |
|---|---|---|
| E1 | 用 Node 24 从真实 `Assistant.tsx` 取出 `taskAgentActivityGroups` 执行：12 条连续工具步骤仍为 12 个项目；二级分组参考实现变成 1 个组，组内仍有 12 条。另验证隐藏步骤造成的序号断点、Agent、修订、归属未知及失败不会被抹平。 | 折叠确实可减少初始可见项目。未测 React 界面时延或真实用户完成时间。 |
| E2 | 执行实际 `previewPersonalOfficeText`，替换传输层后捕获到 `POST /api/personal-data/office-preview`，请求体就是原始 File/Blob；整个实验无网络上传。 | 这项现有预览是服务端解析，不能把它当成本机预览，也不能让拖放自动调用。 |
| E3 | 用 Electron 替身执行实际 `installDownloadAndClipboard`：可信 Assistant 的 `media` 被拒，受信剪贴板写保留。Electron 文档也明确需要同时管权限检查与请求。 | 真波形不是只画动画就能做；需要明确的音频门禁。未验证实际 OS 授权或双路收音。 |
| E4 | 在 PGlite 执行当前通知列表的排序条件：先可见 09:00:03 的通知，后出现 09:00:01 的通知，只扫最新并在旧头停止会漏后者；按样例提交可见顺序的游标可以取回。 | 当前列表未必有 bug，但不能直接用「最新一页／最新时间戳」当桌面增量协议。该实验模拟可见顺序，非生产并发事务验收。 |
| E5 | 仓库默认 Shell 共用 64 KiB 输出保留预算，达到上限继续排空；另有仅供可信 Go runner 使用的有界内部采集。PC/服务端已有限长与脱敏。 | 纯前端不能恢复缺失字节；也不能把内部测试证据缓存开放成公开日志读取接口。结论来自源码，未运行新采集链。 |
| E6 | 原设计记录：两项上游 DSH 0.2.2-rc.1 插件可独立加载并通过定向测试；工具 schema 与 Morde 当前严格合同不同，`timed` 重建以新用户消息续接，而 Morde 恢复原调用。当前源码仍以 `ask_user` 做同轮独占/子 Agent 限制。 | 这是「可以参考」而非「可直接移植」的证据。本轮未重跑上游实包或真实跨端联测。 |

## 1. 折叠工具活动：PC 侧新增二级分组

保留现有 MAIN / SUBAGENT 和 `TaskStepDetails`。只在同一 Task、明确的 Agent 与修订、连续原始序号内合并工具步骤；原日志有非工具步骤、隐藏步骤的序号断点，或身份/修订不明，就分开。不要直接合并过滤后的相邻行。按步骤 ID 处理更新，快照是重连后的事实来源。

默认折叠已结束且无异常的连续组，显示「12 项工具操作」。正在运行、失败、待核对等在标题醒目标示；可定位到相应步骤，不会被多数成功覆盖。少于两项不建组。展开才渲染行，进入单步才加载详情；组展开不发 12 次详情请求。增删行数只有服务端有证据才显示。不是把步骤计数搬到聊天气泡。**收益门槛：**12→1 个初始可见条目，所有 12 项可回看，异常不多于一次展开即可找到。

## 2. 长输出：默认仍是有界详情，完整性必须有定义

保持工具返回、模型输入、退出码和现有详情契约。PC 首先正确区分「源头截断」「详情有界」及「无可读取输出」；对既有缺失不假装可恢复。新增诊断支路仅对明确支持的 Shell 场景或已授权的文件产物做试点。通用 Shell 支路必须在原截断前取样，使用有界队列和独立预算；满、断连、取消或保存失败时停止支路，原执行继续排空，不能等待网络写入、重跑命令或改变执行结果。

按账号、Task、授权版本、修订、步骤、原调用及 stdout/stderr 绑定；对持久化数据先处理脱敏，再加密，逐页重新鉴权，清除会话缓存并随 Task 生命周期删除。跨块脱敏不得只靠逐块正则；对条件不明、无法安全脱敏或无法验证来源的输出不保存全文，也不把原始日志挂到普通附件 URL。摘要和分页可用性必须独立于工具成功。只有收到源头结束、连续分块和完整性元数据，且没有截断，才能标「已完整保存可披露输出」；敏感内容仍可能被遮盖。禁止把旧输出补采或默认给所有工具开全量存储。

## 3. 结构化追问：复用 Morde 的待答和恢复链

保留旧 `ask_user({question})` 和原单题语义。首版做同一持久模型的附加结构或单独版本化结构，沿用 Broker、数据库待答、API 授权及原调用恢复。可参考上游的选项及自由文本格式；只在后续独立技术试验有明显收益，且证明任务隔离、重启和原调用等价时，再决定是否引入插件。不要放宽全局工具 schema，不把插件 `timed` 的新用户消息冒充原工具结果。

问题、选项使用稳定 ID，同题标签不重复；答复绑定 Task、请求版本及幂等键，原工具调用只恢复一次。旧客户端在能够保持语义时逐题投影，否则通过能力协商使用旧单题交互；不能让旧客户端提交一个答案就意外完成整批。`skip` 是明确事实，不是空答案或授权。保留「用户可跳过」目标，但第一批仅放行能继续安全子集的追问；审批、文件目的地、执行目标和路由前提缺失时不能因此越过门禁，提示哪些工作做不了。旧必答请求跳过作为单独的兼容验收项，不在 MVP 隐式改变。

## 4. 附件：拖放只进草稿，预览与发送各有明确操作

只拦截输入区里的文件拖放，防止 Electron 导航打开本机文件；普通文本拖拽不抢。同步从 `DataTransfer` 取文件，走 `addComposerFiles` 与同一校验链（当前单条上限 16，仍以真实入口规则为准）。拖入后切会话，准备结果回到原草稿；拒绝逐项反馈，不清空其余草稿。图片和能本地处理的预览优先；对象 URL 移除、切换或注销时释放。现有 Office 文本预览走服务端，保留显式按钮并说明文件会发送给 Morde 服务解析；**拖放、自动预览或仅打开草稿均不触发它**。正在做事不表示同意发送附件。合成数据验收需断言网络请求，而不只看界面按钮。

## 5. 语音：先可靠取消，再上真波形

PC 保留现有 SpeechRecognition 和在线识别可能性的披露。先把停止和取消分清：停止可接收正常收尾；取消先注销录音代次，再 abort，保留已经进原草稿的文本。切换会话、关闭窗口、快速重启时，旧回调不能写到新草稿。

真波形作为独立增强：Electron 主进程的请求/检查均限定到受信 Assistant 主框架、当前用户明确开启的短期录音窗口且只准音频；工作台、外站、子帧、摄像头和未开始录音一律不许，保持既有剪贴板保护。Web Audio 只计算电平，不写盘、不上传采样音频；取消、出错、窗口退出及迟到的 getUserMedia 返回都要停轨。实机必须验证本地采样不会抢占转写的设备；有冲突就停用波形，不影响原听写或键盘输入。[Electron Session 权限](https://www.electronjs.org/docs/latest/api/session#setpermissioncheckhandlerhandler)

## 6. 桌面通知：以持久完成事件为准，不以页面轮询为准

现有通知列表和站内已读不变。桌面从独立的账号增量合约读取完成事件，保证顺序与提交可见性一致。可以为全部写入路径分配事务内、按账号串行的游标，或实现严格证明等价的完成通知索引；单用时间戳、ID 或提前分配序列不算证明。所有回补均复查访问权限；未授权记录不可见，但不能卡住游标。基线、翻页、重连和过期时的重建要有明确合约。

Electron 主进程持续收取，账号和服务实例完全隔离；注销或切换即撤销旧轮询和迟到回调。首次使用先给本机开关，灰度期间默认关闭，用户开启后从服务端基线起算；前台不弹，完成结果在原对话，后台才尝试系统通知。锁屏默认只显示「Morde 有一项任务已完成」，不带摘要、项目或消息内容。站内通知不受本机开关、OS 拒绝或未签名影响。用 `serviceInstance + account + notification ID` 去重；持久化记录后再交给 OS，明确「尽力且避免重复」，不承诺崩溃两侧必达。任务真正完成才弹，不替代独立的任务中断回告。macOS 要在签名包上验真实弹窗；mock 只能验调用。[Electron Notification](https://www.electronjs.org/docs/latest/api/notification)

## 发布与验收

先合并纯 UI 的活动组、附件；再交付结构化追问和桌面通知，真波形与完整输出独立开关。现有蓝色样式为临时视觉基线，原文指定的 Ice Cream Blue 规范在工程该路径未找到，不以不存在的规范判定视觉通过。用配套 TODO 记录签名/打包 PC 的实际结果；Linux/Windows/macOS 未测到哪端就如实标记。保留原文件和诊断，确保普通对话、审批、路由、任务恢复、附件发送、现有语音及 PC/iOS 共用会话不回退。
