# Morde 对话体验设计方案（精简版）

这份定义 **Personal Agent 怎么接活、做事和交付**，作为[任务中断与对话体验实施 TODO](Morde_任务中断与对话体验_实施任务TODO.md) 中 T07/T08 的补充；具体执行见[精简实施清单](Morde_个人Agent对话_实施TODO_精简版.md)。

**核对基线（2026-11-28）：**本地 `release` 的 HEAD 为 `efb05629`，相关服务端和 PC 文件同时有未提交改动；本次结论是该工作树的静态核对，不代表这些改动已提交、部署或通过实机验收。旧版引用的 `a706cf3` 在本地不可解析；`c021248` 是可查的历史提交，不再用它代表当前代码。开发和验收前记录实际服务端提交、PC 构建来源及相关未提交差异，先协调已有进行中的改动。

> **硬性约束：示例是验收目标，不是生产模板或已通过的记录。** 验收时由真实 DSH 根据用户意图、会话上下文和当前任务产生决策与模型回复；Harness 校验对象和权限，执行并记录任务、工具与交付结果。接活、改范围、取消、进展和终态说明都必须有相应的状态或证据支撑。禁止用关键词、正则、整句匹配或场景专用模板来选路由、触发工具或拼装 Agent 回复。
>
> **确定性规则照常保留：** 权限、审批、预算、状态、去重和真实按钮由程序保证；无需模型的状态提示或安全兜底，只能根据已确认的结构化事实生成，不能从用户措辞猜状态，也不能伪装成 Agent 已经执行。

## 对话怎么走

- **简单问题直接答。** 不凑一个计划，不新建后台任务，不打 👌🏻。
- **复杂任务先交代打算，再后台做。** 服务端确认首次接管后，在原消息标 👌🏻；本轮路由模型生成了有效短计划时，再显示一句贴合目标的计划，说明准备做什么、交付什么。短计划缺失或无效时只显示真实确认，不编造、不为此额外调用模型。只收到消息或还在排队，不说已经开始。用户不用留在窗口；有新发现会改变做法、需要用户决定，或用户主动问进度时才更新。
- **最后说清做了什么、结果怎样、为什么。** 成功给结论和链接或文件；只完成一部分就交付已确认的，解释缺口；失败说清卡在哪、哪些没做成。只有真的需要用户决定，才问一个具体问题并给有效入口。没法核实原因就直说，不贴内部日志，不盲目重跑。

接管确认、计划和最终交付都绑定账号、原会话、原请求和任务；涉及修订或操作时还要校验当前修订、授权和事件来源。同一来源重复投递只显示一次，后续真实恢复或新修订产生的新结果可以另行交付。用户在另一个会话或关闭 PC 时，已受理的云端任务继续；回到原会话或重连后读取持久消息。当前会话停留在最新消息时应自动看到新回告；用户正在翻看历史时不强行跳转，提供返回最新消息的入口。

执行中仅在目标明确时修改或停止对应任务；不同目标、不同用户和不同会话不得误绑。修改或取消已受理后，不再派发旧范围的新操作；已经发出的操作按账本说明真实结果或待核对，不声称已经撤销。旧修订或失效授权的迟到结果不能冒充当前结果。

## 5 个完整场景

从我们之前的对话里选场景。下面是**验收剧本**，其中具体产出、故障和回复是测试示例，不代表实机已通过。复杂任务统一验：真实接管 → 有有效短计划则展示 → 用户可以离开 → 有必要才打扰 → 主动回到原对话交付。

### 1. 「你看看今天有什么新闻」：不让用户问第二遍

- **接下**：👌🏻，然后回「我先看今天比较重要的消息，核对是今天发生的，还是旧事今天才报道，再挑两条发给你。」
- **后台**：按会话时区确定“今天”，打开原始来源。测试给两条候选：第一条今天发布，第二条是旧闻转载。用户停在原对话或切走，任务都继续。
- **交付**：「今天确认了一条值得看：A 公司发布了新版开发工具，[官方公告]。另一条是旧消息今天被转发，我没算进去。」链接必须指向实际读过的来源。
- **过关**：不是贴搜索列表；一条证据就只交付一条，理由具体。用户不用催，也不用切会话才能看到结果。

### 2. 「两份文档还在执行，看看精简版要不要改」：先对照，再下判断

- **接下**：「我先读完两份文档，再对照 `release`。已经在做的我不另开任务，只改精简版里和代码不一致的地方。」
- **后台**：固定提交，区分“源码已实现”“只有自动化通过”“真实 PC 还没过”；保留两份在执行的文件。测试里设定一处文档与代码不一致：首搜成功但没找到可用来源，代码会停，设计却写了可补搜。
- **交付**：「精简版只改了搜索验收：首搜成功但没找到可用来源，要说明缺口，不再补搜。状态和恢复继续走原 TODO。[更新后的精简版.md]。两份原文没动，真实 PC 的完整搜索链路还没验过。」
- **过关**：回的是“需不需要改、为什么”；附可打开的修订文件和代码依据，不把合入说成实机通过。

### 3. 「我表达错了，只看 Harness，预算已有人修；再给我一张图」：做着做着能接住纠正

- **接下**：「我会核对 Harness 的工具结果怎么传回对话，以及中断后怎么恢复。模型预算这块已经有人在做，我跳过；另外补一张数据流图。」
- **后台**：把更正和加图并入原审查，不另跑全项目，也不改另一条预算任务。以合成记录验证“工具已成功，最终消息还没显示”是两件事。
- **交付**：「[专项审查.md] 和 [数据流图.png]。我把工具执行、结果保存、客户端显示分开画了。这个样本在第二段有结果，第三段没显示，所以应先查回告刷新，不是让工具重跑。预算没检查，也没改代码。」
- **过关**：已确认的旧发现保留，被更正的范围不再执行；文档和图都能打开，同一审查只交付一次。

### 4. 「用 release 分支部署到云端」后又说「不搞了」：真需要决定才问，也真能停

- **接下**：「我先核对 `release` 的部署要求和启动检查。服务器目标还没确定，我先不动远端。」
- **只问必要问题**：「这次是部署到测试环境，还是替换现有实例？两种会影响的服务不同。」确认入口绑定当前任务。演练使用隔离环境，不操作实际服务器。
- **用户取消时**：「我停了。只核对了部署要求，没登录服务器，也没改配置。」仅在账本能确认时这样说；若已有动作发出但结果不明，说明哪一步待核对，不承诺已撤销。
- **过关**：未知目标不派发；取消后入口失效，不再调度。说过“不搞了”不因晚到消息重新开始。

### 5. 「为什么写着 waiting_user？我没收到入口」：说清是谁卡住，不把锅丢给用户

- **任务演练**：新闻请求已接下并展示计划；后台确实拿到网页，但最终整理预算不足，模型请求未派发。用户途中断网。
- **原对话回告**：「我找到了相关页面，但这次查询的额度不够整理出最终结论，所以还没有可直接转发的摘要。你不用做任何操作。」只有已经核实的内容才附上；原因不明就如实说原因未确认。
- **用户再问**：「刚才是在等我吗？」Morde：「没有。是我这边没完成整理，不是缺你的确认。」如果另一个测试真有待批准的操作，就写清动作和对象，并显示可用入口。
- **过关**：PC 重连后原对话自动显示一条回告，不用来回切；不重复搜索，不显示“等你处理”或无效按钮。

**轻量对照，不占主场景：**「用一句话解释 DNS，不用查。」直接答，无工具、无后台任务、无 👌🏻。它证明 Morde 不会把所有对话硬转成任务。

**反关键词验收（五个场景通用）：** 每例至少加两种未照抄示例的表达，以及一条出现相同关键词但意图不同的反例。例如「刚才那件先别做了」有明确指代时应取消；「‘不搞了’这句提示太生硬」只是讨论文案，不能取消任何任务。同一句请求在不同任务上下文里也要绑对目标。核对 DSH 决策、关联任务与版本、真实派发或未派发及最终消息来源，不以回复像示例为通过条件。

## Morde 改哪里：先验交付，再补计划

1. **先修原会话交付（T07/T08）。** 用同一组服务端和源码构建的真实 PC 跑新闻成功与失败各一轮，分别看工具派发、DSH 生成、原会话落库及当前窗口显示。已写回却看不见就修消息补读，不重跑工具。终态消息可能晚于 Task 状态事件，不能只依赖已耗尽的有限重试；离线后恢复也要重新取得持久消息。[现有复现记录](Morde_实时对话与Agent接管_设计方案.md)
2. **给首次接管的复杂任务补一条短计划（T08）。** 在 [DSH 结构化路由](../../server/internal/app/conversation_route_decision.go) 增加可选短计划，由本轮模型生成；兼顾普通 `new` 和公开搜索的 `tool` 标记转 Task 路径。服务端实际确认接管后再与原请求和 Task 绑定、持久发布并去重；已结束、已取消或过期修订不补发旧计划。快答不加计划，缺失或无效时只保留真实确认。
3. **用现有路径验证中途纠正（可并行）。** 轻量补充留在当前任务；「只看 Harness、跳过预算」改变交付范围，走同一任务的新修订。只复用仍符合新范围的已验证事实；旧修订晚到结果不得覆盖新结果。先验要求是否真的进了执行，不只验“好，我改”的气泡。

**本轮先跑两条**：查新闻后在原聊天收到一次结果；执行中改范围后只交付新范围。长期偏好参考 Hermes，延后做；「这次精简一点」只作用于当次任务。流式也不阻塞本轮。

## 实施边界

先在同一组服务端和真实 `morde-pc` 上验证接单、执行和原会话交付；普通短答不能代替长任务通过，工具成功也不能代替答案已生成、已显示。继续用现有 DSH 和授权 Broker，不改硬预算、不打开生产自动恢复。首轮网页研究以[当前 Runtime](../../runtime/morde-cloud-runtime/src/engine.mjs) 和 [Worker guard](../../server/internal/worker/cloud_dsh_web_research_guard.go) 为准：最多 2 次搜索尝试、1 次成功搜索、3 次读取、2 个来源 URL、每个 URL 2 个窗口；首搜成功却没有可用来源就说明缺口，不补搜。流式和长期记忆不进本轮。

首轮重点是 PC；服务端消息和状态仍须保持跨端合同，同账号的 iOS 接续验证单独记录，不能由 PC 通过推定第一里程碑全端通过。仓库当前可读的总流程文件是[这里](<../Morde 复刻 Muse 最终流程与开发设计.md>)；约定路径下的步骤 TODO 已删除，可按[实施清单](Morde_个人Agent对话_实施TODO_精简版.md)给出的 Git 历史查阅，并在相关开发前确认现行维护位置。UI 规范的[本机备份](../../../morde-docs-bak/ice-cream-blue/morde-icecream-blue-ui-spec.html)与删除前版本一致；项目内位置仍需确认。实施后按约定同步总流程、T07/T08 和实际验证记录。
