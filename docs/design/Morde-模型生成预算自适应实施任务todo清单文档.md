**状态：未实施。** 本文按本次讨论中推荐的方案编写，供后续开发执行；本次只编写文档。

## 1. 实施目标

- 取消普通 Task 中固定的 2,048 单次生成上限，按实际模型的最大输出能力、剩余上下文和可用额度计算每次调用的上限。
- 新建 Task 默认不再设置独立的 50,000 token 累计额度；仍可显式设置任务额度，并继续执行适用的账户、项目和模型约束。已经保存的 Task、定时任务及明确指定的额度保持原值。
- 覆盖 DSH 主 Agent、子 Agent、普通对话回复、长文本交付和截断后的安全处理；不引入第二套 Agent Runtime。
- 改善因生成额度过小导致的截断，但不把输出变长当成模型一定能解决复杂问题的证明。

## 2. 已选方案

### 2.1 每次调用的有效输出上限

为实际使用的 provider、endpoint 和 model 获取两项独立能力：上下文窗口 `W`、最大输出 token `M`。输出 token 包含 provider 计入输出的推理内容，不等于用户可见文本长度。

每次发起模型调用，先计算完整请求的上下文占用上界 `I_ctx` 和计费输入预留上界 `I_bill`，再按以下规则选出当前可发送的最大输出 `O`：

`O = min(M, W - I_ctx - 协议余量, 适用的 Task 剩余额度 - I_bill, 适用的账户剩余额度 - I_bill, 项目金额可支持的输出 token)`

- 对没有独立额度或不适用的约束，不纳入该次取最小值；项目金额根据实际模型的输入/输出费率、费率版本和舍入规则计算，不能直接把金额当成 token 相减。
- 已派发但未结算的预留、并发主/子 Agent 的调用均计入剩余额度。计算 `O` 与占用 Task、账户、项目额度必须在同一事务内完成；实际发送值、DSH 的压缩判断和账本记录使用同一个 `O`。
- `I_ctx` 和 `I_bill` 包含 system、历史消息、工具定义、协议开销和图片等实际输入；不同计量单位分别计算。无法证明某种输入的安全上界时，不得通过低估输入发起调用。
- 若上下文放不下，先按现有授权和压缩规则处理历史，再重新计算；若等待中的调用可能释放额度，等待其结算后重算；确定额度不足时明确提示，不循环等待。不可用时不得改用其他模型或绕过额度。
- 若当前推理策略要求的输出额度高于计算出的 `O`，明确报告当前额度无法满足该策略，不得在预留后抬高发送值或悄悄关闭用户选择的推理模式。
- `O` 是上限，不是模型必然生成或计费的 token 数。一次预留最大可用上限可能暂时占用更多额度、使其他调用等待，也可能让压缩更早发生；额度充足时仍允许并发，预留释放后等待调用可继续。
- 当实际模型的最大输出或上下文窗口未知时，使用 provider/模型目录的可信信息，或由有权限的用户按模型资料配置相应能力。仍未知时停止该模型调用并提示配置；不假设无限，也不静默退回固定 2,048。

### 2.2 Task 和定时任务的累计额度

- 新建 Task 默认 `model_tokens = null`，表示没有独立的 Task 累计 token 上限；新建定时任务也采用该默认值，触发时继承其当前配置。
- 用户可设置正整数上限；计量仍为该 Task 主、子 Agent 调用的累计输入加输出，包含未结算的预留。取消现有 50,000 的业务最大值，只保留数据库和跨端协议可安全表示的整数范围。
- 原有 Task、Schedule 和内部触发明确传入的数字保持原值，包括原来默认保存为 50,000 或显式设置为其他数值的记录；不将它们自动改为 `null`。
- 平台模型继续受账户/项目额度约束。个人自带模型可能不受平台账户额度约束，相关设置需说明供应商计费，并允许用户自行设置 Task 上限；`null` 不代表免费。

### 2.3 长输出与恢复

- 对正常文本的输出截断，保存已获得的文本，在剩余额度允许时最多自动续接两次；仍未完成时交付可确认的部分并说明，可由用户要求继续。每次续接都有独立调用身份和实际用量记录。
- 不执行参数不完整的工具调用。已派发但结果或计费未知时先对账，禁止自动重放可能产生副作用的操作。
- 路由分类和上下文摘要保留各自适当的专项预算；普通直接答复单独消除当前 2,000 字符限制。模型、计费和 Task 的限制都不能被绕过。

## 3. 方案依据与验证边界

1. 当前 [Task DSH 启动](../../server/internal/worker/cloud_dsh_session_tree.go#L2408)将单次上限限制为 2,048，[DSH 网关](../../server/internal/app/model_gateway_dsh.go#L62)缺省同样使用 2,048；[网关](../../server/internal/app/model_gateway.go#L996)和 [provider 客户端](../../server/internal/model/responses.go#L297)还有 32,768 校验。这些是 Morde 当前实现；所查 DSH 接口未证明要求固定 2,048。
2. 当前 [Task 预算](../../server/internal/domain/task/types.go#L98)最大为 50,000，[账本](../../server/internal/store/postgres/model_usage.go#L198)会检查已用及待结算预留。此前本地临时测试中，输入预留 40,075 时，2,048 输出对应总预留 42,123；直接改成 32,768 会达到 72,843，超过 50,000；这个例子的可预留输出上限为 9,925。隔离 PostgreSQL 测试验证了该组数值的接受与拒绝，**只能证明现有账本的这组算术，不能证明本方案已通过真实模型验收**。
3. [OpenClaw 的模型配置](../../project/openclaw/src/agents/embedded-agent-runner/model.configured-overrides.ts#L510)区分模型输出和上下文；[Hermes 的截断处理](../../project/hermes-agent/agent/turn_truncation.py#L313)区分文本续接与工具调用恢复。这里只借鉴机制，不移植其 Agent 循环。现有 Muse 资料没有证明其输出无限。[DeepSeek 模型规格](https://api-docs.deepseek.com/api/list-models/)区分上下文和最大输出；[Responses API](https://api-docs.deepseek.com/api/create-response/)说明输出预算包括推理 token。
4. 当前 DSH 固定版本的 `agent/request` 接口标记为弃用，现有运行时也只向模型适配器提供上下文窗口；逐次变更输出上限与 DSH checkpoint/压缩协调的可行性**尚未验证**。B01 是后续接入的前置条件。

## 4. 接口及数据变更

- **模型连接**：在现有 `GET/POST /api/model-connections`、`GET/PUT /api/model-connections/{id}` 增加拟议字段 `max_output_tokens`、`max_output_override_tokens`、`max_output_source`。有效值未知时为 `null`；自定义路由可设置或清除覆盖值，同一路由更新时省略覆盖字段表示保持原值，切换 provider/endpoint/model 时清除或重新解析旧能力。同步 API 类型、PC 入口和管理后台；不能泄漏凭据。
- **任务和定时任务**：调整 `POST /api/tasks`、`POST /api/conversations/{id}/messages` 相关创建路径、`POST /api/schedules`、`PUT /api/schedules/{id}` 及任务/计划读取响应。新建时整个 `budget` 省略或为 `null`，使用“无独立 Task token 上限”的新默认；预算对象存在时，`model_tokens` 必填，`null` 表示无独立上限、正整数表示显式上限、`0` 无效。现有 `ScheduleCreateRequest.budget` 必填，实施时需改为可省略；更新 Schedule 时省略预算表示不改，在预算对象内显式设置 `model_tokens: null` 表示清除 token 上限。`active_seconds` 和 `tool_calls` 沿用现有规则。
- **兼容发布**：`TaskBudget` 和 `ScheduleBudget` 响应允许 `model_tokens: null`，属于现有整数合同变化。先让 PC、iOS 和其他调用方能读取新合同且不再主动发送默认 50,000，再启用新默认；旧客户端仍显式传入 50,000 时按显式上限处理。旧客户端无法读取新响应时须明确要求升级或采用经验证的版本兼容方式，不能把 `null` 伪装成 50,000。API、数据库迁移、调度继承及回滚顺序一并验证。
- **内部模型调用和账本**：扩展现有预留操作，输入完整请求、模型能力、计费和身份，返回最终 `O` 与预留身份；记录模型路由/能力版本、输入预留、输出上限、价格和请求摘要。相同调用身份只能恢复同一确定结果；发送前不得抬高 `O`。
- **错误与恢复**：模型能力未知、上下文不足、额度不足和结果未知须提供可区分的错误原因。异步任务保留原任务和会话，显示等待配置或明确失败；同步路径提供可操作的错误，配置完成后的重试沿用现有授权和幂等规则。
