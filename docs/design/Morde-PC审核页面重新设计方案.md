# Morde PC 审核页面重新设计方案

## 设计结论

审核页只展示当前账号能够处理的、带有明确“允许 / 拒绝”决定的审批请求。普通任务等待、补充问题、执行失败或结果未知不属于审批，不应复制任务全文到审核卡片。

用户打开审核页后，应能很快回答三件事：Morde 要做什么、会作用于什么对象、允许后会有什么影响。需要处理时只提供“允许本次操作”和“拒绝”两个决定。

## 当前问题

现有页面同时读取正式审批记录和所有 `waiting_user` 任务。`waiting_user` 还包括等待补充信息、执行结果待核对、目标不可用等状态，并不代表用户需要授权。于是审核计数可能是 0，下面却出现两张内容很长的“待你处理”卡片；卡片展示的是完整任务目标和会话测试文本，也没有可直接完成的审批决定。

截图中的长任务描述属于普通任务等待信息，不是带有审批 ID、版本和决定的审批请求。它们应继续留在任务动态与所属对话中，不应出现在审核页。

## 什么事需要用户审核

只有服务端为一项具体操作创建了有效的待处理审批请求，审核页才显示卡片。典型场景包括：

- 在工作区新增、覆盖或删除文件。
- 向外部网站或服务提交内容，或调用可能读取、修改外部数据的操作。
- 产生费用、改变授权范围，或带来其他需要用户明确同意的实际影响。

是否需要审批由服务端授权和操作策略决定，界面不能仅凭任务状态自行推断。每个审批都绑定其具体操作和版本；“允许”只批准卡片所列的这一次操作，不授予长期或更广泛的权限。

以下情况不放进审核页：

- 任务需要用户补充信息或回答问题。
- 任务失败、结果未知、等待设备或等待服务恢复。
- 普通进度、排队、暂停、继续或停止任务。
- 已在授权范围内执行的普通对话和只读操作。

这些情况仍由任务动态或所属对话呈现，并使用与之匹配的补充、核对或任务控制操作。

## 卡片内容与操作

### 默认可见内容

每张卡片使用单层卡片布局，去掉重复的外层任务卡片和长任务目标，只保留：

1. **操作标题**：用动词描述具体行为，例如“保存文件到工作区”。避免显示任务编号、模型内部工具名或整段用户提示词。
2. **作用对象**：明确文件、网站、账号或其他目标；文件类操作显示相对路径。
3. **操作摘要**：用一两句话说明将执行的具体动作及可见影响。不能只写“需要审核”或“任务等待你处理”。
4. **关键风险或费用**：有已知且与决定相关的信息时简短展示；未知风险或未知费用不能伪装成“无风险”或“免费”。
5. **两个决定**：“允许本次操作”“拒绝”。不增加含义不清的第三个授权选项；暂不处理时保留卡片即可。

### 次要信息

风险依据、费用详情、替代方案、撤销方式、长参数预览等收在默认折叠的“查看操作细节”中。技术校验字段、内部 ID、请求哈希、会话事件序号和完整任务提示词不放在卡片摘要里。

需要决定的操作内容不能为了追求短而被静默截断。摘要保持简明，涉及安全判断的完整参数或文件预览仍应能在操作细节中查看。

已处理的审批记录默认折叠，用户需要追溯时再展开。没有待审批项时显示“当前没有需要你确认的操作”，不显示普通等待任务作为替代。

## 页面结构与视觉

- 页面标题为“审核”，副标题说明：“只显示需要你允许或拒绝的操作；任务追问、等待和异常状态请在任务动态查看。”
- 待处理数量只统计有效审批请求，并与服务端返回的账号级待审批数一致。
- 待处理卡片直接排列在页面主区域，不再把卡片套在另一层大型面板中。
- 卡片沿用 Morde 冰淇淋蓝规范：白色表面、浅蓝描边、柔和阴影和圆角；标题突出，状态标签次要，操作按钮靠近卡片底部且易于区分。
- 桌面端使用舒适的阅读宽度；窄窗口下卡片单列，两个决定按钮可换行并保持可点击区域。
- 维持键盘焦点、按钮禁用态、读屏标签和错误提示；提交结果未确认时保留当前状态并重新核对服务端。

## 全局范围与数据边界

审核列表面向当前登录账号，跨该账号的不同会话聚合；“全局”不代表跨账号共享。仍按既有服务端用户授权、项目成员关系和任务控制权限过滤，不能因为界面聚合而扩大读取范围。

为保证一次性授权、幂等提交和审计追溯，服务端仍保留审批请求版本、准确操作绑定、决定人与处理结果等必要记录。减少的是审核页面上的无关文字和重复信息，不删除执行安全或审计所需的数据。完整对话与普通任务状态继续由对话、任务动态承载。

## 验收标准

- `waiting_user` 任务没有明确待审批请求时，不出现在审核页；截图中的长任务提示不再被当成审批卡片。
- 当前账号其他会话里的有效审批会出现在同一个审核列表；其他账号的数据不会出现。
- 每张待审批卡片都能看懂操作、对象和影响，并且只提供“允许本次操作”“拒绝”两个决定。
- “允许”仅作用于卡片对应的审批版本；重复提交、审批已过期或授权被撤销时，不执行未确认操作，并显示真实状态。
- 已处理记录默认收起，空状态不混入任务动态内容。
- 在实际 `morde-pc` 中检查桌面与窄窗口布局、键盘可达性和审批结果反馈；同时验证无审批、跨会话审批、失效审批和网络错误状态。
