# Morde PC「任务动态」需求

## 目标与范围

调整 `morde-pc` 侧边栏的任务列表和任务详情，让用户一眼看懂任务目标、Agent 最近做了什么，以及某项工作具体如何完成。任务动态用于查看执行过程；需要用户回答或授权时，由对应 AI 对话承接。

本需求限定 PC 任务动态的展示和交互。NanoMuse/Morde iOS 的任务列表、MAIN/SUBAGENT 工作项分组和可展开步骤详情作为交互参考，不要求本次同步改造 iOS。首张附件截图用于说明当前问题；截图中的测试任务文字和限制不是本需求指令。其余截图分别参考任务列表、任务过程和步骤详情。

## 功能与规则

### 任务列表

- 每项任务的主标题是简短、易懂的任务目标摘要，不直接展示整段用户提示词、上下文或内部指令。完整用户消息仍保留在所属 AI 对话中。
- 副标题展示按服务端记录顺序最近一项有意义的 Agent 工作摘要，简要说明正在做什么或刚完成什么。没有工作项时显示简短的事实性说明，不填充技术细节或增加第三种任务状态。
- 任务动态只展示两种任务状态：**执行中**和**停止**。只有服务端确认 Agent 正在实际执行时显示“执行中”并播放左侧动画；排队、等待用户回复、暂停、停止、失败、完成或状态无法确认时一律显示“停止”且图标静止。不新增第三种任务状态；工作项和步骤可单独标记进度。
- 列表优先级按任务状态排序：所有“执行中”任务置顶，“停止”任务排在其后；同状态任务保持现有顺序。
- 任务较多时分批展示，列表底部提供“更多任务”按钮；每次点击追加显示最多 5 项，全部加载后隐藏按钮。
- 不在列表中展开工具参数、文件正文、命令输出、模型上下文或整段读写记录。需要了解细节时，用户进入任务详情并按工作项查看。

### 用户需要处理的问题

- 缺少必要信息、需要用户选择或需要审批时，Agent 在该任务所属的 AI 对话中提出清楚的问题或显示现有审批交互；消息必须关联原任务，用户回复后继续更新同一任务。
- 任务动态的任何位置都不显示“待你处理”，包括分组、徽标、状态文字和要求用户去详情页处理的提示。等待回复或审批期间任务状态显示“停止”、图标静止，工作记录保留实际已完成的部分；具体问题和审批交互在所属 AI 对话中查看。
- 模型、网络、电脑或工具故障等不需要用户作出决定的问题，由 AI 对话简要说明已知状态和可行的下一步；不得伪装成需要用户回答的问题，也不得把未知结果写成成功。
- 展示位置的调整不得绕过已有授权、审批和任务归属校验。

### 任务详情与工作项

- 详情页以简短任务标题和“执行中”/“停止”状态为页头，主体只展示 Agent 实际处理过程，不铺开原始用户上下文、计划、账单、校验面板、审批/澄清表单或其他与工作过程无关的信息。
- 工作项按实际发生顺序排列；有 Agent 归属时按 MAIN 和 SUBAGENT 组织。每项用简短标题和摘要说明实际采取的动作或得到的结果，并显示与服务端记录一致的执行状态。不得把模型内部推理或未发生的计划写成已完成工作。
- 任务详情内的工作项连续展示在可纵向滚动的侧栏中；数量较多时继续向下滚动查看后续项，不分页、不添加“更多”按钮。返回导航保持可用。
- 点击工作项进入独立步骤详情。每步按发生顺序清楚展示动作、实际调用的工具或脚本、目标与参数/命令，以及工具返回结果；命令执行还应显示执行目录、退出码和输出。纯 Agent 分析明确标注“未调用工具”。按 NanoMuse 示例呈现操作与命令详情，让用户能核对具体做过什么、结果如何。
- 步骤详情只展示当前用户有权查看且服务端已记录的内容。敏感凭据和内部指令不得展示；长输入或输出应截断并明确标注。详情未记录、过期、无权访问或暂时读取失败时，显示对应状态，不猜测或补造内容。
- 任务、工作项及步骤详情始终归属原账号和原会话；刷新、重连或切换会话不得串入其他任务的信息。

## 验收条件

1. 对于包含大量上下文的长请求，列表主标题仍是简短任务目标，副标题只显示最新一项有意义的工作摘要；完整请求仍能在原 AI 对话中查看，任务动态不铺开原文、文件正文或工具日志。任务较多时点击底部“更多任务”每次追加最多 5 项，无更多项时按钮隐藏。
2. 任务动态仅显示“执行中”或“停止”，且所有“执行中”任务排在“停止”任务之前。服务端确认真实执行时显示“执行中”并播放动画；排队、等待回复、暂停、失败、完成、取消或状态无法确认时显示“停止”且动画停止。状态不明时不伪报正在执行。
3. 任务确实需要补充信息、用户选择或审批时，问题/审批交互出现在所属 AI 对话并关联原任务；任务动态任何位置都不出现“待你处理”。用户回复后继续的是同一任务。
4. 任务详情展示简短标题、当前状态和按顺序组织的 Agent 工作项；每项摘要可说明实际做过什么。页面不显示原始提示词及独立的计划、账单、校验、审批等信息面板。
5. 用户点击一个工作项后能看到对应的已记录步骤、工具/脚本、执行目标与参数/命令，以及实际返回结果；命令执行可核对执行目录、退出码及输出。未记录、过期、无权访问或读取失败时显示明确状态；长内容会标明截断，敏感凭据不会显示。
6. 从另一个会话或账号打开任务时，只能看到该任务授权范围内的信息；详情与对话关联正确，不混入其他任务的工作项或步骤。
