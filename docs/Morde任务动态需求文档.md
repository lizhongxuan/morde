# Morde 任务动态重设计需求

> 2026-11-13。本文描述目标行为，不表示现有功能已经实现；同功能的旧设计与本文冲突时，以本文为准。

## 背景与依据

用户提供的 Muse 截图中，任务列表展示任务标题和简述；打开任务后，可看到状态、时间以及按 `MAIN`、`SUBAGENT` 分开的工作过程。每条过程有状态、标题和简述，可以进入详情；截图示例包含读取文件、搜索、启动子 Agent、运行命令和多个同时进行的步骤。工具详情展示了操作对象和结果说明。截图只能证明这些界面现象，不能证明其内部实现或每条详情都包含完整的工具输入输出。

本地 [Muse 资料](../../muse-docs/muse解析资料/06-工具执行-子Agent-浏览器.md)描述子 Agent 异步执行、状态及结果回传；[子 Agent 工具进度导出](../../muse-docs/muse_db_agent/agent/subagent_progress_tool_events.json)包含父子归属、工具名、描述、状态和结果预览，并有开始、完成与失败记录。导出中可找到与截图主题相关的搜索和读取记录，但仅凭文字匹配不能断定属于截图中的同一次任务。该导出中的 `run_id` 均为空，不能仅凭工具名猜测两条记录属于同一次调用。部分导出为空、有截断或占位行，详见[导出清单](../../muse-docs/muse_db_runtime/MANIFEST.md)；不能据此推断 Muse 的完整数据链路。

Morde 已有任务步骤、子 Agent 会话及状态；PC 当前将步骤平铺并单独列出子任务名称和状态，[iOS](../clients/nanoMuse/android/src/ios/NanoMuse/MIFTaskViews.swift)也展示步骤列表。[现有任务详情契约](../server/openapi/portal.yaml)的步骤主要提供标题、摘要与状态，不足以直接展示按执行者归属的完整工具详情。任务事件流目前只提供受限的进度信息，不能把检查点、工具原始输出或凭据直接暴露给客户端。

## 目标与范围

在 PC 和 iOS 的任务动态中，让用户看到当前会话每项任务的真实执行过程：主 Agent 做了什么、子 Agent 分别做了什么、使用了哪些工具，以及可以查看的工具详情和最终结果。

保留现有任务、会话、审批、停止和成果入口。任务动态展示已有执行记录，不因打开面板而创建任务或触发工具；纯文字对话没有实际任务时不虚构任务。继续使用 DSH 作为唯一 Agent Runtime，复用现有会话、任务、工具授权和记录能力。

## 功能与规则

1. **任务列表。** 对话中的“任务动态”展示当前会话的任务；切换会话后显示对应任务。列表按“待你处理、进行中、已暂停、最近结束”分组，空组不显示，最近结束默认折叠；同组按最近更新时间排序。每项显示任务标题、实际状态、最近一条真实进展和更新时间。列表或数量读取不完整时提示状态暂不可用，不把缺失记录显示为零。
2. **任务详情。** 点击任务进入详情，顶部显示标题、用户要求、状态及时间；按需显示待审批或待补充信息、当前进展和结果。工作过程是详情的主要内容，默认可见；较长内容可展开或继续加载。PC 在任务侧栏中查看，避免遮挡聊天输入；iOS 使用适合手机的任务详情页或弹层。返回时保留所在位置，状态有文字和图标，主要操作支持键盘及屏幕阅读器。
3. **按执行者展示过程。** 工作过程先显示主 Agent，再按实际委派关系展示各子 Agent；子 Agent 多层委派时保留真实层级。每个执行者下按其实际发生顺序列出关键动作，包含工具调用、委派和结果回传等，并显示该执行者的真实状态。多个子 Agent 或多个工具同时运行时可同时显示进行中；不能将委派成功当作子任务完成，也不能将子任务结果当作主 Agent 已交付的最终结果。
4. **一条动作一条记录。** 每条动作显示用户能理解的标题、操作对象或简述、状态和可查看详情的入口；例如“读取 README.md”“搜索项目依赖”“运行测试”。工具调用的开始和结束更新同一条动作，实际重试或多次调用则分别显示；相同工具的并发调用不得仅按工具名称合并。支持等待、准备中、进行中、待用户处理、已完成、失败、中断或结果待确认等真实状态，并用文字和图标区分。尚未实际开始时不显示为已执行，结果未知时不显示为成功。
5. **工具详情。** 点击动作进入该次工具的详情，展示实际使用的工具、作用对象、状态、时间，以及授权范围内已记录的必要输入、结果或失败原因；长内容允许展开查看，并明确标示截断。内容按工具类型呈现：读取文件显示可见的文件名或相对路径及读取结果；搜索显示查询、结果摘要及可用来源；命令显示可展示的命令、输出和退出状态；电脑操作显示实际目标及操作结果。未记录、不再可用或无权查看的内容应分别说明，不能生成看似真实的详情。
6. **进度与结果保持真实。** 只根据已确认的执行事件和结果展示内容，不从计划、模型推测或截图生成执行记录。失败原因、空结果和结果未知都如实显示；已完成的步骤不意味着整个任务完成。任务执行结束但主 Agent 尚未整理回复时，显示“任务已完成，回复整理中”；只有成果实际可用且当前用户有权访问时，才提供查看入口。
7. **持续更新与恢复。** 执行时更新状态和过程；用户查看某条详情或滚动历史时，新事件不得强制跳转或关闭详情。关闭页面、断网、刷新或从另一端打开同一会话后，已确认的任务、执行者归属和工具记录仍可查看。事件重复送达、先后乱序或任务修订后，不能重复显示同一次动作、把旧结果覆盖新要求或将动作挂到错误的执行者；可区分地保留旧修订中已确认的历史。记录暂不可用时保留最近确认状态并提示，允许重试读取。
8. **消息、任务和操作。** 同一会话中重复发送并已关联的请求只显示一个任务；需要时可查看关联消息，不能把每条消息或每个子 Agent 都误列为独立任务。独立任务分别展示，停止、暂停和继续只作用于用户选定的任务，并在服务端确认后更新状态。真正等待审批或补充时，显示具体事项并提供处理入口，不因内部状态变化虚构“等待用户确认”。
9. **权限与隐私。** 所有列表、执行者、步骤和详情遵守账号、会话、项目、任务及资源的现有授权；授权变化后不得继续读取或显示已失效的内容。仅展示对当前用户允许且经过安全处理的工具信息，密码、令牌、验证码等凭据不得进入动态详情；不直接展示模型内部推理、原始检查点或未验证路径。子任务归属暂不能确认时标明“归属待确认”，不能猜测或混入其他任务。
10. **本机文件与云端电脑。** 只有实际发生相关操作时才显示“读取本机文件”或云端电脑步骤。读取本机文件保留原有设备、授权范围、传输状态和临时副本说明；传输完成不等于内容已被成功读取。项目文件夹同步仍由用户在 PC 手动触发，任务动态不能把单文件读取说成文件夹同步，或在状态查询失败时声称发生了读取。

## 验收条件

- 在已授权的测试环境中，由 DSH 主 Agent 启动任务、使用工具，并委派至少两个可并行的子 Agent，各自执行实际工具调用；PC 和 iOS 都能在同一任务下看到主 Agent 与各子 Agent 的正确归属、实时状态和结果回传，子 Agent 不显示为新的顶层任务。
- 分别打开一次文件读取、搜索和命令调用的详情，能看到该次真实操作对象、状态和可展示的结果；失败或空结果如实显示。不可见、未记录或被截断的信息有明确提示，不展示凭据或其他账号的数据。
- 同一工具被并发调用两次时显示两条动作；一次调用从开始到完成只更新对应动作。重连、刷新和跨端打开后不出现重复步骤或错误归属；较旧修订的迟到事件不覆盖新修订。
- 任务运行中、等待审批、失败、停止和结果未知时，任务及各步骤状态与服务端一致；完成一个子任务不等于整个任务完成，等待用户事项可在详情中处理。原有单文件读取和任务控制行为无回归。
- 同一会话连续发送并关联的重复请求只出现一个任务，另一个会话或账号的任务不混入；存在多个独立任务时各自的进度、结果和停止操作互不影响。
- 任务详情、工具记录或权限读取失败时，界面标出不可用或无权查看，并可在适用时重试；历史记录没有所需细节时不编造，未实际读取本机文件时不显示读取记录。
