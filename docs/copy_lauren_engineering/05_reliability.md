# 05 任务状态、权限与恢复

**作用：** 断线或重启后不用从头做；撤权、风险和成本由服务端管。  
**用在哪里：** Morde Go 服务端，贯穿接单、运行、验证和开 PR。模型只提议动作，不决定自己拥有哪些权限。

**输入 → 输出：** 任务、步骤、执行尝试、授权与预算 → 可恢复状态、事件与审计记录。最小记录有任务 ID、步骤、当前尝试、输入 SHA、已存证据、外部 PR 关联、原会话、预算余额。

- 有副作用前先记意图并实时核权；动作结果不明时先对账，不能重复写入。旧尝试回报不能覆盖当前结果。
- 恢复只做未完成且安全的步骤。撤权后不发起下一次写操作；已在途的请求只能核查实际结果。预算耗尽不启动新尝试，重启不重置预算；费用结果不明时不按零处理。
- 人员能从 PR 查到任务、尝试、授权、提交和验证记录；不要把敏感日志写进公开 PR。

**复用与移植：** 优先复用现有 Morde Go/PostgreSQL 的任务和事件；用 [PostgreSQL 唯一约束](https://www.postgresql.org/docs/current/ddl-constraints.html#DDL-CONSTRAINTS-UNIQUE-CONSTRAINTS) 约束任务和投递记录，但数据库唯一键不能保证外部请求只发生一次，外部仍要对账。[Noodle 的恢复设计](https://github.com/poteto/noodle/blob/main/brain/architecture.md#crash-safety) 仅借「先存状态再启动」；不照搬它的文件存储或调度逻辑。P0 不引入第二套工作流引擎。最终投递用「原会话＋任务＋结果类型」去重，底层消息重发也只呈现一次。

**验收：** 注入服务重启、旧尝试迟到、过程撤权、预算耗尽；每种都能从原会话看到实际状态，不重复动作、不重新授权、不丢已持久化证据。
