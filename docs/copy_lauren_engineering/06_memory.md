# 06 项目记忆与纠错

**作用：** 下一次同类任务不用从头教；重复错误不只被记住，还能被检查拦住。  
**用在哪里：** 01 接单时读已确认规则；03 验收时执行检查；任务结束后才提取候选经验。候选不等于政策，不影响在途任务。

**输入 → 输出：** 真实任务的纠正、反例、测试和验收结果 → 版本化项目规则、回归测试，或「不适合复用」。规则记录项目、何时适用、来源、确认人、版本和失效条件。旧证据、旧权限不能复用。

- 例如两次把模拟器写成真机：先把环境变成结构化字段，再用旧误报写一个会失败的回归测试。另一项目没有同样要求，就不自动套用。
- 候选经验先用正反例验证，小范围复用；负责人确认才设为默认。不改善就停用，保留上版。
- 先用现有 PostgreSQL 存任务、规则、提交和测试的关系，即轻量本体。没有反复出现的跨仓追溯瓶颈，不建独立知识图谱或全局记忆库。

**复用与移植：** [Cursor P-Stack 的 /correct](https://github.com/cursor/plugins/blob/main/pstack/skills/correct/SKILL.md) **适配方法，不直接装 Cursor 插件**：把「找重复错误 → 程序检查 → 真反例」写成 Morde 的模板或 Codex 仓库技能；真正的拦截仍写在 03 的校验和仓库测试。若之后复制技能内容，遵循 [P-Stack 的 MIT 许可](https://github.com/cursor/plugins/blob/main/pstack/LICENSE) 并保留版权与许可声明；这次没有复制第三方源码。P0 直接复用现有存储，不移植通用记忆框架。

**验收：** 第一单保存一条验证过的规则；第二单只给新目标和基线，能说明复用了哪条并重测新证据；第三单更换项目、规则过期或不匹配，不能套用，也不共享原项目的证据。
