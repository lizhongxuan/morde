# 03 证据与验收

**作用：** 用程序判断有没有修好，不让 Agent 用自述替代测试。  
**用在哪里：** 候选提交产生后、标记 PR 就绪前；PR 新提交到来时重新判定。

**输入 → 输出：** 候选 SHA、必验项、可信测试来源 → 每项给「通过／失败／未验证」、实际结果、环境、证据链接。只有全部必验项满足，才给 04 出具该 SHA 的就绪结论。

- Bug 看修前复现和修后通过；小需求看约定的行为。必要时运行真实用户路径。
- 证明同一个提交，区分真机、模拟器、浏览器。环境由可信运行记录提供，不信 Agent 自填。
- PR 头变动时旧结论失效；历史证据保留供追溯，不给新提交沿用。

**复用与移植：** 先直接复用仓库已有测试和 CI；浏览器路径可复用 [Playwright Trace Viewer](https://playwright.dev/docs/trace-viewer) 的 trace 产物，已用 Playwright 就延续，不为一个 trace 引进第二套浏览器框架。Playwright 不是 iOS 真机工具；真机继续用项目已有原生测试路径，适用时复用 [XCUITest](https://developer.apple.com/documentation/xcuiautomation)。验证产物可能含敏感内容，沿用访问控制，不发公共预览。Morde 自己实现提交、环境、证据来源的验收规则，不从外部移植一个通用验收引擎。

**验收：** 旧 SHA 的绿灯、模拟器冒充真机、验完又推代码，三种情况都不许标「可合并」；同一 SHA 的真实通过对照样本仍放行。
